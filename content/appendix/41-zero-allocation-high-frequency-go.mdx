## The Latency War & GC Tax

In standard backend microservices, average response time (p50) is all people brag about. In financial systems and high-frequency trading (HFT), **p50 is a vanity metric; p99 and p99.99 tail latency decide survival**.

<Define term="Zero-Allocation Design">
**Zero-allocation design** is a systems programming practice where the hot path (the critical execution loop) makes **zero calls to the runtime heap allocator (`runtime.newobject` / `runtime.makeslice`)**. All memory is pre-allocated at startup, recycled via ring buffers, or scoped to memory arenas. This completely starves the Garbage Collector: with no new heap objects created, GC mark cycles never trigger, and mark-assist pauses drop to zero.
</Define>

## Zero-Copy Byte Manipulation

High-frequency market feeds (such as NASDAQ ITCH, CME MDP 3.0, or Meridian FIX) transmit binary or ASCII-delimited packets over UDP multicast or TCP.

Converting `[]byte` to `string` normally copies the entire byte array to new heap-allocated memory because Go strings are immutable, whereas slices are mutable. If you convert thousands of incoming message fields to `string`, you swamp the allocator.

<Define term="Zero-Copy String Conversion">
**Zero-copy conversion** creates a `string` header that directly points to the existing `[]byte` backing array without allocating new memory or copying bytes. In modern Go (Go 1.20+ through Go 1.26), this is achieved safely via `unsafe.StringData` and `unsafe.String`.
</Define>

### The Slice Header vs String Header

Let's look at the memory layout of slices and strings in Go 1.26:

- `string`: 16 bytes on 64-bit architecture `(Data *byte, Len int)`.
- `[]byte`: 24 bytes on 64-bit architecture `(Data *byte, Len int, Cap int)`.

```text
Slice:  [ Data Pointer ] ───► [ 'B', 'T', 'C', '-', 'U', 'S', 'D' ]
        [ Len: 7       ]
        [ Cap: 7       ]

String: [ Data Pointer ] ───► Same underlying bytes (Zero Allocation!)
        [ Len: 7       ]
```

<UnderTheHood title="unsafe.String and Compiler Map-Lookup Inlining">
Prior to Go 1.20, developers used `*(*string)(unsafe.Pointer(&b))` which violated unsafe pointer invariants if compiler struct layouts changed. Go 1.20 introduced `unsafe.String(ptr *byte, len int)` and `unsafe.StringData(str string) *byte`. 

**Critical Rule**: When creating a zero-copy string from a `[]byte`, you must guarantee that the underlying `[]byte` is **never mutated** while the string is in use, because strings are assumed to be immutable by the Go runtime, hash map implementations, and the compiler!
</UnderTheHood>

Let's test zero-copy byte slice parsing in a runnable playground:

<GoPlayground>

```go
package main

import (
	"errors"
	"fmt"
	"unsafe"
)

// BytesToStringZeroCopy converts []byte to string without heap allocation.
// SAFETY: The source byte slice must not be modified while the string is read.
func BytesToStringZeroCopy(b []byte) string {
	if len(b) == 0 {
		return ""
	}
	return unsafe.String(unsafe.SliceData(b), len(b))
}

// FastAtoiZeroAlloc parses ASCII numbers without strconv allocations.
func FastAtoiZeroAlloc(b []byte) (int64, error) {
	if len(b) == 0 {
		return 0, errors.New("empty slice")
	}
	var n int64
	neg := false
	i := 0
	if b[0] == '-' {
		neg = true
		i++
	}
	for ; i < len(b); i++ {
		c := b[i]
		if c < '0' || c > '9' {
			return 0, errors.New("invalid character")
		}
		n = n*10 + int64(c-'0')
	}
	if neg {
		n = -n
	}
	return n, nil
}

func main() {
	payload := []byte("ORDER:MERIDIAN-99214:PRICE:4950200") // Price in cents: $49,502.00

	symbol := BytesToStringZeroCopy(payload[6:20])
	priceCents, err := FastAtoiZeroAlloc(payload[27:])
	if err != nil {
		panic(err)
	}

	fmt.Printf("Zero-Copy Symbol: %s (len=%d)\n", symbol, len(symbol))
	fmt.Printf("Zero-Alloc Price (Cents): %d ($%.2f)\n", priceCents, float64(priceCents)/100.0)
}
```

## Cache Lines & False Sharing

CPUs don't read single bytes from RAM. Modern CPUs (x86-64 and ARM64) fetch memory in chunks of **64 bytes**, called a **Cache Line**.

<Define term="False Sharing">
**False sharing** occurs when two distinct goroutines running on separate CPU cores read and write to independent variables that happen to reside within the **same 64-byte CPU cache line**. Even though the variables are logically independent, the hardware cache coherency protocol (such as MESI/MOESI) invalidates the entire cache line across all cores on every write, degrading performance by up to 50x.
</Define>

### Preventing False Sharing with Cache Line Padding

To prevent false sharing, every hot concurrent atomic variable or sequence cursor MUST occupy its own dedicated 64-byte cache line.

```go
// ❌ Catastrophic: Head and Tail share the same 64-byte cache line
type UnpaddedCursor struct {
    Head uint64 // 8 bytes
    Tail uint64 // 8 bytes -> Sits in same 64-byte line!
}

// ✅ Correct: Padded to guarantee independent 64-byte cache line isolation
type PaddedCursor struct {
    Value uint64   // 8 bytes
    _     [56]byte // 56 bytes padding -> Exactly 64 bytes total
}
```

<GoPlayground>

```go
package main

import (
	"fmt"
	"sync/atomic"
	"unsafe"
)

// PaddedSequence wraps an atomic sequence cursor padded to 64 bytes
// to prevent false sharing across CPU cores.
type PaddedSequence struct {
	value atomic.Uint64
	_     [56]byte // 64 - 8 = 56 bytes padding
}

func (s *PaddedSequence) Get() uint64 {
	return s.value.Load()
}

func (s *PaddedSequence) Set(v uint64) {
	s.value.Store(v)
}

func main() {
	var seq1 PaddedSequence
	var seq2 PaddedSequence

	fmt.Printf("Size of PaddedSequence: %d bytes (Exact 64-byte Cache Line)\n", unsafe.Sizeof(seq1))
	fmt.Printf("Address of seq1: %p\n", &seq1)
	fmt.Printf("Address of seq2: %p\n", &seq2)

	diff := uintptr(unsafe.Pointer(&seq2)) - uintptr(unsafe.Pointer(&seq1))
	fmt.Printf("Memory distance between seq1 and seq2: %d bytes\n", diff)

	seq1.Set(42)
	seq2.Set(100)
	fmt.Printf("Values: seq1=%d, seq2=%d\n", seq1.Get(), seq2.Get())
}
```

## Lock-Free Ring Buffers

Why don't high-frequency trading engines use Go standard channels (`chan Order`)?

Because Go channels rely on **`runtime.hchan`**, which contains a **`sync.mutex`**. Every send and receive acquires an internal lock, invokes the Go scheduler (`gopark` / `goready`), and causes context switches. A standard Go channel maxes out at ~5–10 million operations per second under high contention.

The **LMAX Disruptor pattern** solves this using a **pre-allocated circular ring buffer** with lock-free atomic sequence numbers.

<Define term="LMAX Disruptor Ring Buffer">
The **Disruptor** is a lock-free inter-thread messaging architecture designed by LMAX Exchange. It uses a fixed-size, power-of-two array of pre-allocated event objects. Producers and consumers coordinate purely through monotonic `atomic.Uint64` sequence counters and bitwise sequence masking `(seq & mask)`, eliminating locks, heap allocations, and scheduler contention to achieve **over 25 million ops/sec**.
</Define>

### Power-of-Two Bitwise Masking

In a circular buffer of size `N`, finding an index for sequence `seq` normally requires modulo: `index = seq % N`.

```text
index = seq & (N - 1)
```

Bitwise AND executes in a **single CPU cycle (sub-nanosecond)**.

```text
Capacity N = 8 (Binary: 0000 1000)
Mask   N-1 = 7 (Binary: 0000 0111)

Seq 0  & 7 = 0
Seq 7  & 7 = 7
Seq 8  & 7 = 0  (Wraps cleanly!)
Seq 9  & 7 = 1
```

Let's inspect a complete, production-ready Single-Producer Single-Consumer (SPSC) Ring Buffer:

<GoPlayground>

```go
package main

import (
	"fmt"
	"runtime"
	"sync/atomic"
)

// MarketOrder represents a pre-allocated order event in the matching engine.
type MarketOrder struct {
	OrderID    uint64
	AccountID  uint64
	PriceCents int64
	Quantity   uint32
	Side       byte // 'B' = Buy, 'S' = Sell
}

// SPSCRingBuffer is a lock-free single-producer single-consumer circular buffer.
type SPSCRingBuffer struct {
	_        [56]byte
	head     atomic.Uint64 // Written by producer
	_        [56]byte
	tail     atomic.Uint64 // Written by consumer
	_        [56]byte
	mask     uint64
	capacity uint64
	buffer   []MarketOrder
}

// NewSPSCRingBuffer initializes a pre-allocated ring buffer. Capacity MUST be power of 2.
func NewSPSCRingBuffer(capacity uint64) *SPSCRingBuffer {
	if capacity == 0 || (capacity&(capacity-1)) != 0 {
		panic("capacity must be a power of two")
	}
	return &SPSCRingBuffer{
		capacity: capacity,
		mask:     capacity - 1,
		buffer:   make([]MarketOrder, capacity),
	}
}

// TryPublish copies data into the pre-allocated slot without heap allocation.
func (rb *SPSCRingBuffer) TryPublish(orderID, accountID uint64, price int64, qty uint32, side byte) bool {
	head := rb.head.Load()
	tail := rb.tail.Load()

	if head-tail >= rb.capacity {
		return false // Buffer full! (Drop or backpressure)
	}

	slot := &rb.buffer[head&rb.mask]
	slot.OrderID = orderID
	slot.AccountID = accountID
	slot.PriceCents = price
	slot.Quantity = qty
	slot.Side = side

	rb.head.Store(head + 1)
	return true
}

// TryConsume reads the next order in-place.
func (rb *SPSCRingBuffer) TryConsume(out *MarketOrder) bool {
	tail := rb.tail.Load()
	head := rb.head.Load()

	if tail >= head {
		return false // Buffer empty
	}

	slot := &rb.buffer[tail&rb.mask]
	*out = *slot

	rb.tail.Store(tail + 1)
	return true
}

func main() {
	rb := NewSPSCRingBuffer(1024)
	done := make(chan bool)

	const totalOrders = 100000

	// Consumer Goroutine
	go func() {
		var order MarketOrder
		consumed := 0
		for consumed < totalOrders {
			if rb.TryConsume(&order) {
				consumed++
			} else {
				runtime.Gosched()
			}
		}
		done <- true
	}()

	// Producer Goroutine
	for i := 1; i <= totalOrders; i++ {
		for !rb.TryPublish(uint64(i), 8820, 50000, 10, 'B') {
			runtime.Gosched() // Wait for consumer if ring is full
		}
	}

	<-done
	fmt.Printf("Successfully processed %d orders with 0 heap allocations!\n", totalOrders)
}
```

## Memory Arenas & Bump Allocators

While ring buffers handle fixed event streams, what happens when a complex matching engine transaction requires variable dynamic data (e.g., building an order tree or trade audit logs)?

Calling `new()` or `make()` during request processing invokes `runtime.mallocgc`, triggering size class lookups, mcache locks, and GC metadata tracking.

<Define term="Memory Arena (Bump Allocator)">
A **Memory Arena** (also called a **Region-Based Allocator** or **Bump Allocator**) is a large contiguous slice of pre-allocated memory. Allocating an object within an arena is as simple as adding the object's byte size to an integer offset (bumping the pointer). When the transaction or frame finishes, the arena is **reset to offset 0 in $O(1)$ time**, instantly recycling the entire memory chunk without freeing individual objects or involving the Garbage Collector.
</Define>

<UnderTheHood title="Go Heap Allocator vs Arena Bump Allocator">
Go's standard heap allocator is based on TCMalloc (Thread-Caching Malloc). When you allocate a struct:
1. `runtime.newobject` inspects type metadata and size.
2. It requests an open slot from the current `P`'s `mcache` span for that specific size class (67 size classes).
3. If the span is full, it locks `mcentral` to fetch new spans.
4. GC write barriers and mark bits are initialized.

A **Bump Pointer Arena** replaces this entire multi-hundred-line routine with **three machine instructions**:
```asm
MOVQ  arena_offset, %rax    // 1. Get current offset
LEAQ  (%rax, %rdi), %rdx    // 2. Add requested bytes
MOVQ  %rdx, arena_offset    // 3. Store new offset
```
No size classes, no locks, no GC mark bits. Allocation takes under **1 nanosecond**.
</UnderTheHood>

Let's build and verify a zero-allocation transaction Arena:

<GoPlayground>

```go
package main

import (
	"errors"
	"fmt"
	"unsafe"
)

// Arena is a fast, linear bump allocator for scoped lifecycles.
type Arena struct {
	buf []byte
	off int
}

// NewArena allocates a raw memory slab once at startup.
func NewArena(size int) *Arena {
	return &Arena{
		buf: make([]byte, size),
		off: 0,
	}
}

// Alloc reserves `size` bytes aligned to 8-byte boundaries.
func (a *Arena) Alloc(size int) (unsafe.Pointer, error) {
	// 8-byte memory alignment
	alignedOff := (a.off + 7) &^ 7
	if alignedOff+size > len(a.buf) {
		return nil, errors.New("arena out of memory")
	}
	ptr := unsafe.Pointer(&a.buf[alignedOff])
	a.off = alignedOff + size
	return ptr, nil
}

// Reset clears the arena instantly in O(1) time without GC scanning.
func (a *Arena) Reset() {
	a.off = 0
}

type ExecutionReport struct {
	TradeID     uint64
	ExecutionPx int64
	QtyFilled   uint32
	Timestamp   uint64
}

func main() {
	// Allocate 64KB memory arena once
	arena := NewArena(64 * 1024)

	// Simulate 3 transaction cycles
	for cycle := 1; cycle <= 3; cycle++ {
		// Allocate execution report inside arena
		rawPtr, err := arena.Alloc(int(unsafe.Sizeof(ExecutionReport{})))
		if err != nil {
			panic(err)
		}

		report := (*ExecutionReport)(rawPtr)
		report.TradeID = uint64(1000 + cycle)
		report.ExecutionPx = 4995000 // $49,950.00
		report.QtyFilled = 5
		report.Timestamp = 1719820000

		fmt.Printf("Cycle %d -> TradeID=%d, FillPx=$%.2f, ArenaUsed=%d bytes\n",
			cycle, report.TradeID, float64(report.ExecutionPx)/100.0, arena.off)

		// End of tick / transaction: Reset arena in O(1) time!
		arena.Reset()
	}

	fmt.Println("All transaction cycles completed with zero heap allocations!")
}
```

<Exercise n={1} title="Zero-Alloc Fixed-Point Decimal Parser" level="easy">

Implement `ParseFixedPointPrice(raw []byte) (int64, error)` that parses ASCII dollar prices like `"149.50"` directly into integer cents (`14950`) without allocating strings or using `strconv.ParseFloat`.

<Solution>

```go
package main

import (
	"errors"
	"fmt"
)

// ParseFixedPointPrice parses ASCII dollar strings (e.g. "149.50") into integer cents (14950).
func ParseFixedPointPrice(raw []byte) (int64, error) {
	if len(raw) == 0 {
		return 0, errors.New("empty input")
	}

	var dollars int64
	var cents int64
	var sawDot bool
	var decimalDigits int

	for i := 0; i < len(raw); i++ {
		c := raw[i]
		if c == '.' {
			if sawDot {
				return 0, errors.New("multiple decimal points")
			}
			sawDot = true
			continue
		}
		if c < '0' || c > '9' {
			return 0, errors.New("invalid character")
		}

		if !sawDot {
			dollars = dollars*10 + int64(c-'0')
		} else {
			if decimalDigits < 2 {
				cents = cents*10 + int64(c-'0')
				decimalDigits++
			}
		}
	}

	// Normalize decimals (e.g. "149.5" -> 14950 cents)
	if decimalDigits == 1 {
		cents *= 10
	}

	return dollars*100 + cents, nil
}

func main() {
	val, err := ParseFixedPointPrice([]byte("49250.75"))
	if err != nil {
		panic(err)
	}
	fmt.Printf("Parsed Cents: %d ($%.2f)\n", val, float64(val)/100.0)
}
```

**Explanation**: Iterates directly over byte values without converting to `string`. Tracks digits before and after the dot, multiplying to guarantee exact fixed-point precision with 0 allocations.
</Solution>
</Exercise>

	"fmt"

type Sequencer struct {

<Exercise n={3} title="Power-of-Two Lock-Free Ring Buffer Masking" level="medium">

Write a generic lock-free ring buffer helper `IsPowerOfTwo(n uint64) bool` and `CalculateMask(capacity uint64) uint64`. Implement an index calculation function `IndexFor(seq, mask uint64) uint64` and prove that it handles 64-bit integer overflow correctly.

<Solution>

```go
package main

import (
	"fmt"
	"math"
)

func IsPowerOfTwo(n uint64) bool {
	return n != 0 && (n&(n-1)) == 0
}

func CalculateMask(capacity uint64) uint64 {
	if !IsPowerOfTwo(capacity) {
		panic("capacity must be power of two")
	}
	return capacity - 1
}

func IndexFor(seq, mask uint64) uint64 {
	return seq & mask
}

func main() {
	cap := uint64(1024)
	mask := CalculateMask(cap)

	// Test standard sequence
	fmt.Printf("Seq 5 -> Index %d\n", IndexFor(5, mask))
	fmt.Printf("Seq 1024 -> Index %d\n", IndexFor(1024, mask))
	fmt.Printf("Seq 1025 -> Index %d\n", IndexFor(1025, mask))

	// Test 64-bit overflow wrapping
	maxSeq := uint64(math.MaxUint64)
	fmt.Printf("MaxUint64 -> Index %d\n", IndexFor(maxSeq, mask))
	fmt.Printf("MaxUint64 + 1 (Overflow to 0) -> Index %d\n", IndexFor(maxSeq+1, mask))
}
```

**Explanation**: Because binary addition in CPU registers wraps around modulo $2^{64}$, bitwise masking `(seq & mask)` produces continuous, seamless circular indexing even when monotonic counters overflow.

<Exercise n={4} title="Thread-Safe Arena Pool with Reset Lifecycle" level="hard">

Build a transaction-scoped `ArenaPool` using `sync.Pool` that leases `*Arena` instances to worker goroutines, allowing each worker to perform dozens of dynamic allocations per request, execute matching, and cleanly reset the arena before returning it to the pool.

<Solution>

```go
package main

import (
	"fmt"
	"sync"
	"unsafe"
)

type Arena struct {
	buf []byte
	off int
}

func (a *Arena) Alloc(size int) unsafe.Pointer {
	aligned := (a.off + 7) &^ 7
	if aligned+size > len(a.buf) {
		return nil
	}
	ptr := unsafe.Pointer(&a.buf[aligned])
	a.off = aligned + size
	return ptr
}

func (a *Arena) Reset() {
	a.off = 0
}

type ArenaPool struct {
	pool sync.Pool
}

func NewArenaPool(arenaSize int) *ArenaPool {
	return &ArenaPool{
		pool: sync.Pool{
			New: func() any {
				return &Arena{
					buf: make([]byte, arenaSize),
					off: 0,
				}
			},
		},
	}
}

func (ap *ArenaPool) Get() *Arena {
	return ap.pool.Get().(*Arena)
}

func (ap *ArenaPool) Put(a *Arena) {
	a.Reset() // Always reset before recycling!
	ap.pool.Put(a)
}

type OrderNode struct {
	ID    uint64
	Price int64
}

func main() {
	pool := NewArenaPool(4096)

	// Worker acquires arena
	arena := pool.Get()

	nodePtr := arena.Alloc(int(unsafe.Sizeof(OrderNode{})))
	node := (*OrderNode)(nodePtr)
	node.ID = 9001
	node.Price = 45000

	fmt.Printf("Allocated OrderNode %d at price %d in pool arena (used %d bytes)\n",
		node.ID, node.Price, arena.off)

	// Return to pool
	pool.Put(arena)

	// Reacquire — notice arena offset is cleanly reset to 0!
	reused := pool.Get()
	fmt.Printf("Reacquired arena offset after reset: %d bytes\n", reused.off)
}
```

**Explanation**: Combining `sync.Pool` with memory arenas gives you the best of both worlds: zero heap allocations during the request lifecycle, combined with reusable memory slabs across concurrent worker goroutines.
</Solution>
</Exercise>

<Recap>

- **Zero-Allocation Imperative**: In sub-microsecond HFT systems, heap allocations trigger GC mark-assist pauses and sweep stalls. Pre-allocating all memory on startup guarantees deterministic tail latency.
- **Zero-Copy Byte Manipulation**: Use `unsafe.String` and `unsafe.SliceData` (Go 1.20+ / 1.26) to construct string headers without copying underlying byte slices. Parse binary and ASCII protocols directly from slices.
- **Cache Line Padding (64 Bytes)**: Unpadded concurrent atomic variables residing in the same 64-byte line suffer from false sharing, causing hardware cache thrashing. Pad cursors with `_ [56]byte` to guarantee core isolation.
- **Lock-Free Disruptor Ring Buffers**: Replace mutex-heavy channels with power-of-two circular buffers. Use `(seq & mask)` bitwise indexing for single-cycle modulo operations and atomic sequence advancement.
- **Memory Arenas (Bump Allocators)**: Replace fine-grained heap allocations with large pre-allocated memory slabs. Bump pointer allocation executes in under 1 nanosecond, and `Reset()` clears all transaction memory in $O(1)$ time without GC involvement.

</Recap>
