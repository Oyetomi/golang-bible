## Frequency Maps

Here's the scenario that sets every interview room on fire: a data pipeline is ingesting a million user events per second. The on-call engineer needs to know — right now, in O(n) time — which event type is most common, whether any event appears more than once, and what the first unique event in the stream is. A nested loop would take three hours. A frequency map takes three lines.

**The pattern:** a `map[T]int` where the key is the thing you're counting and the value is how many times you've seen it. Build it in one pass. Answer any "how many times?" query in O(1).

<Define term="Frequency map" since={"Arrays & Strings: Two Pointers & Sliding Windows (Appendix, Chapter 2)"}>
A **frequency map** is a `map[T]int` that counts occurrences: scan the input once, increment `freq[item]` for each element. You can then answer "how many times did X appear?" in O(1) instead of re-scanning. **On the job:** any time you need counts, rankings, or duplicate detection on streaming data — counting event types in a log pipeline, checking whether two strings are anagrams, finding the top-K most-seen values.
</Define>

```go
// Count how often each string appears.
func buildFreqMap(items []string) map[string]int {
	freq := make(map[string]int, len(items)) // pre-size: avoid rehashing
	for _, item := range items {
		freq[item]++ // zero value of int is 0, so the first increment just works
	}
	return freq
}
```

That `freq[item]++` line is doing something elegant. The zero value of `int` is `0`, so the first time a key appears, Go reads `0`, adds `1`, and stores `1`. No `if _, ok := freq[item]; ok` ceremony. The zero value *is* the right starting point. This is idiomatic Go — design your types so the zero value works.

### Classic problem: anagram check

Two strings are anagrams if one is a rearrangement of the other. The frequency-map proof: build a freq map for one string, decrement for the other, then verify every count lands at zero.

**Complexity:** O(n) time, O(1) space (the alphabet is fixed at 26 or 128 chars — bounded).

```go
func isAnagram(s, t string) bool {
	if len(s) != len(t) {
		return false
	}
	var count [26]int // fixed-size array: O(1) space, no map overhead for ASCII
	for i := range len(s) {
		count[s[i]-'a']++
		count[t[i]-'a']--
	}
	for _, c := range count {
		if c != 0 {
			return false
		}
	}
	return true
}
```

### Classic problem: first unique character

Scan twice. First pass builds the frequency map. Second pass finds the first index where the count is exactly 1.

**Complexity:** O(n) time, O(1) space (bounded alphabet).

```go
func firstUniqChar(s string) int {
	var freq [26]int
	for _, ch := range s {
		freq[ch-'a']++
	}
	for i, ch := range s {
		if freq[ch-'a'] == 1 {
			return i
		}
	}
	return -1
}
```

### Classic problem: top-K frequent elements

Here's where it gets interesting. Count frequencies in one pass, then pull out the top K. The trick: after counting, you need a **min-heap of size K** — push each element in, and if the heap exceeds K, pop the smallest. That keeps the K largest without sorting everything.

Go's `container/heap` is clunky (it requires implementing an interface), but it's the tool the job calls for.

**Complexity:** O(n log k) time, O(n + k) space.

```go
package main

import (
	"container/heap"
	"fmt"
)

// An item holds a value and its frequency count.
type Item struct {
	val  int
	freq int
}

// MinHeap satisfies heap.Interface (min by frequency).
type MinHeap []Item

func (h MinHeap) Len() int           { return len(h) }
func (h MinHeap) Less(i, j int) bool { return h[i].freq < h[j].freq }
func (h MinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x any)        { *h = append(*h, x.(Item)) }
func (h *MinHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

func topKFrequent(nums []int, k int) []int {
	// Step 1: build frequency map.
	freq := make(map[int]int, len(nums))
	for _, n := range nums {
		freq[n]++
	}

	// Step 2: maintain a min-heap of size k.
	h := &MinHeap{}
	heap.Init(h)
	for val, cnt := range freq {
		heap.Push(h, Item{val, cnt})
		if h.Len() > k {
			heap.Pop(h) // evict the least-frequent
		}
	}

	// Step 3: drain the heap into a result slice.
	result := make([]int, k)
	for i := k - 1; i >= 0; i-- {
		result[i] = heap.Pop(h).(Item).val
	}
	return result
}

func main() {
	fmt.Println(topKFrequent([]int{1, 1, 1, 2, 2, 3}, 2)) // [1 2]
	fmt.Println(topKFrequent([]int{1}, 1))                  // [1]
}
```

### Classic problem: majority element

The element that appears more than n/2 times. You can do this in O(n) time and O(1) space with Boyer-Moore voting, but the frequency-map approach is clean and worth knowing — it's the pattern, not the trick.

```go
func majorityElement(nums []int) int {
	freq := make(map[int]int, len(nums))
	for _, n := range nums {
		freq[n]++
		if freq[n] > len(nums)/2 {
			return n
		}
	}
	panic("no majority element") // guaranteed by problem constraints
}
```

## Dedup & Sets

Your user-facing API returns a list of recommended product IDs. It calls three upstream services, stitches the results together, and — because two services can recommend the same product — produces duplicates. You need to deduplicate in one pass without sorting.

**The pattern:** `map[T]struct{}` as a set. The zero-size `struct{}` value costs zero bytes — you're using the map purely for its key-lookup. Insert a key to "add" it to the set; the comma-ok lookup to "test" membership.

<Define term={'map[T]struct{} as a set'}>
Go has no built-in set type. The idiom is `map[T]struct{}`: use the map's keys to represent set members, and `struct{}` (the zero-size type, 0 bytes) as the value — because you only care whether a key exists, not what it maps to. Adding an element: `s[k] = struct{}{}`. Membership test: `_, ok := s[k]`. **Why not `map[T]bool`?** `bool` wastes 1 byte per entry; at a million entries that's 1 MB of useless data. More importantly, `map[T]bool` lets you accidentally write `m[k] = false`, which looks like "not a member" but the key *is* present — the comma-ok form is the only safe membership test either way.
</Define>

```go
// seen is a set of strings.
seen := make(map[string]struct{})
seen["PROD-42"] = struct{}{}           // add
_, ok := seen["PROD-42"]               // test: ok == true
_, ok = seen["PROD-99"]                // test: ok == false
```

### Contains duplicate

Return `true` if any value appears more than once.

**Complexity:** O(n) time, O(n) space.

```go
func containsDuplicate(nums []int) bool {
	seen := make(map[int]struct{}, len(nums))
	for _, n := range nums {
		if _, ok := seen[n]; ok {
			return true // already saw this value
		}
		seen[n] = struct{}{}
	}
	return false
}
```

### Intersection of two slices

Return the elements that appear in both `a` and `b`. Build a set from the first slice, then scan the second, collecting elements that land in the set.

**Complexity:** O(n + m) time, O(min(n, m)) space.

```go
func intersection(a, b []int) []int {
	setA := make(map[int]struct{}, len(a))
	for _, v := range a {
		setA[v] = struct{}{}
	}
	var result []int
	for _, v := range b {
		if _, ok := setA[v]; ok {
			result = append(result, v)
			delete(setA, v) // avoid duplicates in output
		}
	}
	return result
}
```

```go
func union(a, b []int) []int {
	seen := make(map[int]struct{}, len(a)+len(b))
	for _, v := range a {
		seen[v] = struct{}{}
	}
	for _, v := range b {
		seen[v] = struct{}{}
	}
	result := make([]int, 0, len(seen))
	for v := range seen {
		result = append(result, v)
	}
	return result
}

func difference(a, b []int) []int {
	setB := make(map[int]struct{}, len(b))
	for _, v := range b {
		setB[v] = struct{}{}
	}
	var result []int
	for _, v := range a {
		if _, ok := setB[v]; !ok {
			result = append(result, v)
		}
	}
	return result
}

func main() {
	a := []int{1, 2, 3, 4}
	b := []int{3, 4, 5, 6}
	fmt.Println("intersection:", intersection(a, b)) // [3 4]
	fmt.Println("union:", union(a, b))               // [1 2 3 4 5 6] (order varies)
	fmt.Println("difference a-b:", difference(a, b)) // [1 2]
}
```

## Grouping

An analytics service processes transaction records from five regional data centers. Before running aggregations, it needs to bucket transactions by region, by day, and by merchant category. Three different groupings, all with the same pattern.

**The pattern:** `map[K][]V` — a key that categorizes, and a slice of everything that falls into that category. Build it in one pass; query any bucket in O(1).

<Define term="Grouping (map[K][]V)">
A **grouping map** associates each category key with a slice of all values in that category. The Go idiom `groups[k] = append(groups[k], item)` works even when `k` is new: `append` on a nil slice allocates a fresh slice, so you never need to pre-initialize the bucket. One pass builds every bucket simultaneously — O(n) time, O(n) space. **On the job:** bucketing transactions by region or merchant, grouping log lines by severity, partitioning tasks by worker — any "sort into buckets" problem without needing to sort.
</Define>

```go
// Group events by their type.
func groupBy[K comparable, V any](items []V, key func(V) K) map[K][]V {
	groups := make(map[K][]V)
	for _, item := range items {
		k := key(item)
		groups[k] = append(groups[k], item)
	}
	return groups
}
```

That generic version is Go 1.18+ and works for any key/value combination. The `append` to a nil slice works fine — `append(nil, v)` creates a new slice, so you need no initialization ceremony.

### Classic problem: group anagrams

Given a slice of strings, group them so anagrams end up together. The key insight: anagrams have the same sorted characters, so `sort(word)` is a canonical key.

**Complexity:** O(n · k log k) where k is max word length. For fixed alphabets, a character-count signature (an array of 26 ints) turns this into O(n · k).

```go
import "sort"

func groupAnagrams(strs []string) [][]string {
	groups := make(map[string][]string)
	for _, s := range strs {
		key := sortedKey(s)
		groups[key] = append(groups[key], s)
	}
	result := make([][]string, 0, len(groups))
	for _, g := range groups {
		result = append(result, g)
	}
	return result
}

func sortedKey(s string) string {
	b := []byte(s)
	sort.Slice(b, func(i, j int) bool { return b[i] < b[j] })
	return string(b)
}
```

## Two-Sum Family

Here is the canonical "trade space for time" trick — the move that separates people who think algorithmically from people who just write code.

**The scenario:** a payment reconciliation job needs to find every pair of transaction amounts that sum to a target. The naive approach is O(n²): for every transaction, scan every other transaction. With a million rows that's a trillion comparisons. We have a Monday morning deadline.

**The insight:** for every element `x`, its complement is `target - x`. If we've already seen `target - x`, we have our pair. A hash map lets us check "have I seen this value before?" in O(1). One pass: O(n) time, O(n) space — we *trade* memory for time.

<Define term="Two-sum complement trick">
For each element `x` you scan, compute `complement = target - x`. If `complement` is already in the map, you found your pair — return both indices immediately. If not, store `seen[x] = currentIndex` and move on. The map remembers everything seen so far, so the complement check is O(1) instead of a second linear scan. This single-pass pattern — **build the answer as you scan, check the map at each step** — generalises to subarray sums (prefix maps), four-sum (split into two passes), and any "find two things that relate" problem. **On the job:** reconciliation jobs matching debits to credits, finding duplicate transactions, pairing open orders with fills.
</Define>

```go
func twoSum(nums []int, target int) []int {
	seen := make(map[int]int, len(nums)) // value → index
	for i, n := range nums {
		complement := target - n
		if j, ok := seen[complement]; ok {
			return []int{j, i} // found: indices of the pair
		}
		seen[n] = i
	}
	return nil // no pair found
}
```

### Subarray sum equals K (prefix sum + map)

Find the number of contiguous subarrays that sum to `k`. This is the two-sum idea applied to **prefix sums**: if `prefix[j] - prefix[i] == k`, then the subarray `[i+1..j]` sums to `k`. Equivalently: at index `j`, if we've already seen the prefix sum `prefix[j] - k`, there's a valid subarray ending here.

**Complexity:** O(n) time, O(n) space.

```go
func subarraySum(nums []int, k int) int {
	// counts maps prefix-sum → how many times we've seen it
	counts := map[int]int{0: 1} // prefix sum of 0 occurs once (empty prefix)
	sum, result := 0, 0
	for _, n := range nums {
		sum += n
		result += counts[sum-k] // how many earlier prefixes give a valid subarray
		counts[sum]++
	}
	return result
}
```

<UnderTheHood title="How Go maps work: Swiss tables, hashing, and why O(1)">

Understanding the internals pays off when you reason about worst-case behavior in an interview.

**The group structure (as of Go 1.24).** A `map[K]V` is backed by a Swiss Table-style hash table. Go's runtime stores key-value pairs in groups of 8 slots plus a control word. The control bytes store occupancy state and hash bits, letting Go reject non-matching entries without touching the actual key memory.

**Lookup in O(1) average.** To look up key `k`: compute `hash(k)`, use hash bits to choose the table/group probe path, compare control bytes first, then compare full keys only for plausible matches. With a healthy load factor, most lookups examine a small number of groups — constant time on average.

**Why iteration order is unsafe to depend on.** The Go spec says map iteration order is not specified. The standard runtime deliberately varies iteration order to prevent programs from accidentally depending on it. If you rely on sorted key order, use `slices.Sorted(maps.Keys(m))` (Go 1.23+).

**Growth and load factor.** When the table becomes too full for efficient probing, Go grows or splits internal storage and spreads the work across subsequent operations. This is why the amortized cost is O(1) but occasional inserts can do extra work.

**Hash collision and worst-case O(n).** If an attacker can craft keys that all collide along the same probe paths, lookups can degrade to O(n). Go mitigates this with **hash randomization** — the hash seed is chosen randomly, making it infeasible to predict collisions from outside the process.

**The O(n²) → O(n) transformation.** Without a map: "does X appear in a collection?" requires a linear scan of the collection — O(n) per query, O(n²) total for n queries. With a map: build the map once in O(n), then each query is O(1). The hash map turns a nested-loop problem into a single-pass problem. This is the trade: O(n) extra space for O(n) total time instead of O(n²).

</UnderTheHood>

## Set Operations & Go Idioms

<ConceptGrid cols={3}>
  <ConceptCard label="Zero-value insert">`freq[k]++` works even when `k` is not yet in the map. The missing key returns the zero value (`0` for `int`, `false` for `bool`), so you never need to initialize before incrementing.</ConceptCard>
  <ConceptCard label="Comma-ok lookup">`v, ok := m[k]` gives you the value *and* whether the key exists. Use `ok` to distinguish "key absent" from "key present with zero value". This is the only way to tell those apart.</ConceptCard>
  <ConceptCard label="map[T]struct{} set">Zero-size value = zero wasted memory. For sets, you don't care about the value — you care about key existence. `struct{}` signals this intent explicitly. `map[T]bool` works but wastes 1 byte per entry.</ConceptCard>
  <ConceptCard label="Pre-size with make">`make(map[K]V, n)` hints the initial capacity. Prevents multiple rehash/grow cycles when you know roughly how many entries you'll insert. Not a hard limit — the map still grows if needed.</ConceptCard>
  <ConceptCard label="Iteration order">Map iteration order is unspecified and deliberately varied by the runtime. Never depend on order. To process keys in sorted order: collect keys into a slice, sort it, then iterate the slice.</ConceptCard>
  <Gotcha>Never use `map[T]bool` as a set and then write `if m[k]` to test membership — this silently returns `false` for both a missing key *and* a key explicitly mapped to `false`. Use the comma-ok form: `if _, ok := m[k]; ok`.</Gotcha>

### Building and iterating a set idiomatically

```go
// Build a set from a slice — O(n).
func sliceToSet[T comparable](items []T) map[T]struct{} {
	s := make(map[T]struct{}, len(items))
	for _, item := range items {
		s[item] = struct{}{}
	}
	return s
}

// Test membership — O(1).
func contains[T comparable](s map[T]struct{}, item T) bool {
	_, ok := s[item]
	return ok
}

// Collect back to a slice — order unspecified.
func setToSlice[T comparable](s map[T]struct{}) []T {
	result := make([]T, 0, len(s))
	for k := range s {
		result = append(result, k)
	}
	return result
}
```

```go
func isAnagram(s, t string) bool {
```

<Exercise n={2} title="Longest consecutive sequence" level="medium">

Given an unsorted slice of integers, return the length of the longest sequence of consecutive integers (e.g. `[1,2,3,4]` → 4). Do it in O(n) — sorting is O(n log n) and will fail the time constraint.

**Hint:** put all numbers into a set. For each number that has no left neighbor (i.e. `n-1` is not in the set), it's the start of a sequence — walk forward counting.

<Solution>

```go
package main

import "fmt"

func longestConsecutive(nums []int) int {
	set := make(map[int]struct{}, len(nums))
	for _, n := range nums {
		set[n] = struct{}{}
	}
	best := 0
	for n := range set {
		// Only start counting from the beginning of a sequence.
		if _, ok := set[n-1]; ok {
			continue
		}
		length := 1
		for {
			if _, ok := set[n+length]; !ok {
				break
			}
			length++
		}
		if length > best {
			best = length
		}
	}
	return best
}

func main() {
	fmt.Println(longestConsecutive([]int{100, 4, 200, 1, 3, 2})) // 4 → [1,2,3,4]
	fmt.Println(longestConsecutive([]int{0, 3, 7, 2, 5, 8, 4, 6, 0, 1})) // 9
}
```

The key insight: only start a walk from a sequence's leftmost element (no left neighbor in the set). Each element is visited at most twice across all walks — O(n) total.

</Solution>

</Exercise>

<Exercise n={3} title="Subarray sum equals K" level="medium">

Implement `subarraySum(nums []int, k int) int` that counts the number of contiguous subarrays whose elements sum to `k`. Use prefix sums and a frequency map. Handle negative numbers.

```go
package main

import "fmt"

func subarraySum(nums []int, k int) int {
	// prefix[j] - prefix[i] == k  →  prefix[j] - k == prefix[i]
	// Count how many prior prefixes equal current prefix minus k.
	prefixCounts := map[int]int{0: 1} // empty prefix has sum 0
	sum, count := 0, 0
	for _, n := range nums {
		sum += n
		count += prefixCounts[sum-k]
		prefixCounts[sum]++
	}
	return count
}

	fmt.Println(subarraySum([]int{-1, -1, 1}, 0)) // 1
}
```

The sentinel `{0: 1}` handles subarrays that start at index 0 — if `sum == k` at index `i`, then `sum - k == 0` and the sentinel says "yes, we saw prefix 0 once."

<Exercise n={4} title="Four-sum count" level="hard">

Given four integer slices `a`, `b`, `c`, `d` of length n, count the number of 4-tuples `(i, j, k, l)` such that `a[i] + b[j] + c[k] + d[l] == 0`. Brute force is O(n⁴). Use two frequency maps to reach O(n²).

**Hint:** build a frequency map of all pairwise sums `a[i]+b[j]`. Then for each pair `c[k]+d[l]`, look up how many times its negation appears.

<Solution>

```go
package main

import "fmt"

func fourSumCount(a, b, c, d []int) int {
	n := len(a)
	// Build a frequency map of all sums from a and b.
	abFreq := make(map[int]int, n*n)
	for _, x := range a {
		for _, y := range b {
			abFreq[x+y]++
		}
	}
	// For each (c,d) pair, count how many (a,b) sums are their negation.
	count := 0
	for _, x := range c {
		for _, y := range d {
			count += abFreq[-(x + y)]
		}
	}
	return count
}

func main() {
	a := []int{1, 2}
	b := []int{-2, -1}
	c := []int{-1, 2}
	d := []int{0, 2}
	fmt.Println(fourSumCount(a, b, c, d)) // 2
}
```

Split into two O(n²) passes instead of one O(n⁴) pass. The hash map converts the inner-two-loops lookup from O(n²) to O(1). This "split and meet in the middle" trick generalizes to many sum-counting problems.

</Solution>

</Exercise>

<Exercise n={5} title="Minimum window containing all characters" level="hard">

Given strings `s` and `t`, return the shortest substring of `s` that contains every character in `t` (with correct counts). Use a sliding window + two frequency maps. Return `""` if no such substring exists.

**Complexity target:** O(n + m) time.

<Solution>

```go
package main

import "fmt"

func minWindow(s, t string) string {
	if len(t) > len(s) {
		return ""
	}
	need := make(map[byte]int)
	for i := range len(t) {
		need[t[i]]++
	}
	have := make(map[byte]int)
	satisfied := 0      // how many distinct chars meet the requirement
	required := len(need)

	left, best, bestLen := 0, "", len(s)+1
	for right := range len(s) {
		ch := s[right]
		have[ch]++
		if need[ch] > 0 && have[ch] == need[ch] {
			satisfied++
		}
		// Shrink from the left while the window is valid.
		for satisfied == required {
			if right-left+1 < bestLen {
				bestLen = right - left + 1
				best = s[left : right+1]
			}
			lch := s[left]
			have[lch]--
			if need[lch] > 0 && have[lch] < need[lch] {
				satisfied--
			}
			left++
		}
	}
	return best
}

func main() {
	fmt.Println(minWindow("ADOBECODEBANC", "ABC")) // "BANC"
	fmt.Println(minWindow("a", "a"))               // "a"
	fmt.Println(minWindow("a", "aa"))              // ""
}
```

The `satisfied` counter lets us test "is the window valid?" in O(1) rather than re-scanning both maps. When `satisfied == required`, every character in `t` is covered — shrink greedily.

</Solution>

</Exercise>

<Recap>

- **Frequency maps** (`map[T]int`): count occurrences in one O(n) pass. The zero value of `int` means `freq[k]++` works for any key, seen or not. Use for: anagram checks, top-K, majority element.
- **Sets** (`map[T]struct{}`): O(1) membership test, zero extra memory per entry. The comma-ok form `_, ok := s[k]` is the only way to distinguish "absent" from "present with zero value." Use for: dedup, contains-duplicate, intersection/union/difference.
- **Grouping** (`map[K][]V`): bucket items by a computed key in one pass. `append` to a nil slice works — no initialization needed. Use for: group-anagrams, any "categorize by property" problem.
- **Two-sum family**: the canonical "trade space for time" move. Build a map of seen values, then check complements in O(1) instead of scanning. Applies to: two-sum, pair counting, four-sum count, subarray-sum-k (with prefix sums).
- **Go map internals**: Swiss Table-style groups of 8 slots, control bytes for fast rejection, amortized growth, unspecified map iteration order, hash-seed randomization against hash-flooding attacks.
- **Pattern recognizer**: when you see a problem asking "does X exist in what we've seen so far?", reach for a map. That question converts O(n) scan → O(1) lookup, turning O(n²) to O(n).
