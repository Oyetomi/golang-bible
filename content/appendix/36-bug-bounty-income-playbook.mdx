## The Honest Numbers

Start here, because the wrong expectation is what makes people quit at month two. The consensus across platform data and dozens of hunter retrospectives:

| Phase | Timeline | Realistic outcome |
|---|---|---|
| **Paid education** | Months 1-3 | **$0.** Learning tools, HTTP, reading disclosed reports. Normal. |
| **First finds** | Months 4-6 | $100-500 if consistent and picking the right targets |
| **Steady part-time** | Months 6-12 | $500-2,000/month for a dedicated part-timer |
| **First $1,000 total earned** | Month 6-10 | The proof the model works for *you specifically* |

Where $300/month sits: it's the **"regular part-time" band** — roughly the 15-20% of active hunters who earn $1k-$10k/year. It is genuinely achievable, and it is **lumpy**: you might land a medium-severity bug one month, two small ones the next, and nothing the month after (all duplicates). The *average* is what matters, and the average hides the zero month.

<Define term="What $300/month actually is">
Not a salary with a floor — a **rolling average** of a few accepted findings. Concretely: about **one medium-severity bug** (community range ≈$500-2,000 for things like a stored XSS or a sensitive-data IDOR) **or two-to-three low-severity finds** (≈$100-500 each: information disclosure, a low-impact IDOR, a misconfiguration) per month. The income arrives unevenly — the discipline is to keep submitting through the dry months so the average holds. The top 1% of hunters earn more than the bottom 90% combined; you are not aiming for that. You are aiming for a **steady, modest, repeatable** number, which is a far more attainable and saner target.
</Define>

Here's that lumpiness made concrete — a representative quarter that averages to exactly the target, with the zero month in plain sight:

```go

import "fmt"

// Severity -> typical low/medium bounty (community-reported ranges, USD).
type tier struct {
	name   string
	payout int
}

func main() {
	low := tier{"Low/Info (P4)", 150}
	med := tier{"Medium (P3)", 600}

	// A modest, realistic quarter for a consistent part-time hunter past the
	// first few months: income is LUMPY — some months a medium, some only a
	// low or two, some nothing (all duplicates).
	months := []int{
		low.payout + low.payout, // month 1: two lows
		0,                       // month 2: all duplicates — the dry month
		med.payout,              // month 3: one medium
	}
	total := 0
	for i, m := range months {
		fmt.Printf("month %d: $%d\n", i+1, m)
		total += m
	}
	fmt.Printf("quarter total: $%d  ->  average $%d/month\n", total, total/len(months))
	fmt.Println("the average hides the zero month — plan for lumpy income")
}
```

## Master One Class: IDOR

The single highest-return decision a beginner makes: **pick one bug class and hunt it exclusively for three to six months.** The unanimous recommendation across every honest 2026 source — and the right one for a developer — is **IDOR / broken access control.**

<Define term="Why IDOR is the beginner's money class">
**Insecure Direct Object Reference** is a broken-access-control bug: the app uses a user-supplied identifier to fetch a resource without checking that *this* user owns it. It is the best starting class for four reasons. **(1) It's the most-rewarded** — broken access control has held #1 on the OWASP Top 10 since 2021, and platform data consistently shows it as the top-paid category. **(2) The barrier is almost nothing** — you need two accounts and Burp Repeater, no exploit chains, no payload craft. **(3) The attack surface is enormous** — it exists anywhere a developer forgot an ownership check: every API endpoint, every file download, every admin panel, every multi-tenant query. **(4) It's about logic, not tricks** — exactly the authorization reasoning a developer already understands. The access-control check a developer forgot is as present in a $100M fintech as in a weekend project. That's the whole job: find the missing check, prove the impact, write it up.
</Define>

### The payout ladder — always climb it

The same endpoint can be worth $100 or $5,000 depending on *what you can do* with the IDOR. Always push from read toward write toward vertical escalation:

| Rung | What it is | Typical severity / range |
|---|---|---|
| **Read IDOR** | View another user's data (`GET /invoice/124`) | Low-Medium, ≈$100-500 |
| **Write IDOR** | *Change* another user's data — email, password, address, order (`PUT`/`POST`/`PATCH`/`DELETE`) | **P1, ≈$1,500-5,000** |
| **Vertical IDOR** | A regular user hits an admin-only endpoint (`/api/admin/*`) | **Critical** — the program's nightmare |
| **Blind IDOR** | The action fires but the response is generic (`200 OK`); verify out-of-band | Same impact as the action it performs |
| **UUID IDOR** | IDs are UUIDs (not guessable) — but they **leak** in other endpoints | Often overlooked = often unduplicated |

The two mindset shifts that move you up the ladder: **don't stop at read** — if you can read user B's data, test whether you can `PUT` to it (write IDORs turn Low into P1); and **UUIDs are not safe** — a `GET /api/team-members` that lists UUIDs hands you the keys to `GET /api/user/{uuid}/salary`. Always cross-reference IDs leaked in one response against object endpoints elsewhere.

### The detection mechanic, in Go

The Burp extensions **Autorize** and **Authz** automate IDOR hunting with one idea: **replay every request under a second, lower-privileged identity and diff the response against the owner's baseline.** Same status and same body under the attacker's session means the ownership check is missing — a mechanical green/red signal instead of eyeballing. Here's that core logic, runnable and verified:

<GoPlayground>

```go
package main

import "fmt"

// A captured response, seen under some identity.
type resp struct {
	status int
	body   string
}

// classify replays the SAME request under the attacker's identity and compares
// it to the owner's baseline — the core of the Autorize/Authz Burp extensions.
// This is how you turn "is there an IDOR?" into a mechanical green/red check.
func classify(owner, attacker resp) string {
	switch {
	case attacker.status == 401 || attacker.status == 403:
		return "ENFORCED — attacker denied"
	case attacker.status == 200 && attacker.body == owner.body:
		return "BYPASS — attacker sees the owner's data (IDOR)"
	case attacker.status == 404 && owner.status == 200:
		return "hidden from attacker — but probe the 403-vs-404 oracle"
	default:
		return "enforced — different content"
	}
}

func main() {
	// Owner (user 1001) views their own invoice.
	owner := resp{status: 200, body: `{"invoice":777,"owner":1001,"total":"$4,200"}`}

	// VULN endpoint: no ownership check — attacker (user 2002) requesting the
	// same /invoice/777 gets the owner's data back.
	attackerVuln := resp{status: 200, body: `{"invoice":777,"owner":1001,"total":"$4,200"}`}
	fmt.Println("vuln :", classify(owner, attackerVuln))

	// SAFE endpoint: ownership enforced — attacker is denied.
	attackerSafe := resp{status: 403, body: `{"error":"forbidden"}`}
	fmt.Println("safe :", classify(owner, attackerSafe))
}
```

## Recon Is The Job

The bugs that pay are almost never on `www`. They're on `api.`, `admin.`, `staging.`, a forgotten subdomain running two-year-old software nobody has touched. The best hunters spend **60-80% of their time on recon** — mapping the territory before they look for a single bug.

<Define term="The recon pipeline">
A repeatable chain that turns a root domain into a ranked list of live, interesting assets — **passive enumeration first** (no footprint), then active validation, then targeted scanning, then **diff for what's new**:

```text
subfinder / assetfinder / amass / crt.sh   → every subdomain
  → httpx                                   → only the LIVE hosts
  → katana / gau / waybackurls              → historical + crawled URLs
  → getJS / LinkFinder                      → JS files: hidden endpoints, hard-coded keys
  → nuclei -severity high,critical          → exposures/, cves/, misconfig/, takeover
  → anew                                    → emit only NET-NEW lines each run
```

The two highest-signal stages beginners skip: **JavaScript mining** (JS files are goldmines — they reference undocumented API endpoints and, embarrassingly often, hard-coded credentials) and **`anew` diffing** (re-run the whole pipeline daily; `anew` shows only what changed, so a freshly-deployed, never-tested subdomain surfaces the day it appears). The **recon-methodology** chapter builds this exact pipeline, with `anew` and the outlier-hunt verified in Go.
</Define>

While the deep bugs take time, sweep for **low-hanging fruit** on every target first — these stack into a steady baseline income:

<ConceptGrid cols={2}>
  <ConceptCard label="Information disclosure">Exposed `.env` (API keys), `.git` directories (source leak), `phpinfo()`, backup files. Found via dorking + your recon. Easy, ≈$50-500, very common.</ConceptCard>
  <ConceptCard label="Subdomain takeover">A dangling CNAME pointing at a deprovisioned service you can claim (`subzy` flags them). Low individual pay (≈$200-3k) but high volume and beginner-friendly. (See the takeover engine in **high-value-bug-classes**.)</ConceptCard>
  <ConceptCard label="JWT alg:none / confusion">A verifier that trusts the token's `alg` header. ≈$500-5k, usually P2-P3. You built the verified allowlist fix in the **OAuth/OIDC** chapter.</ConceptCard>
  <ConceptCard label="CORS misconfig">A reflected `Access-Control-Allow-Origin` with credentials enabled — cross-origin data theft. Drilled in the **CORS** chapter and its HackLab.</ConceptCard>
</ConceptGrid>

## Reports That Get Paid

Roughly 40% of people who submit a report **never earn** — and it's frequently the *report*, not the bug. A real, valid finding gets a $0 "not reproducible" because the write-up was unclear. The structure that gets paid:

<ConceptGrid cols={2}>
  <ConceptCard label="1. Title">The vulnerability *and* its impact in one line. `IDOR in /api/v2/user/{id}/orders allows reading any user's order history` — not `IDOR found`.</ConceptCard>
  <ConceptCard label="2. Severity">Use CVSS or the platform's scale, and **do not overrate**. Honest severity builds trust with the triage team; inflated severity gets you ignored.</ConceptCard>
  <ConceptCard label="3. Steps to reproduce">Numbered, exact, complete: precise URLs, parameter names, payload values. Imagine an analyst reading it six months later — they must reproduce it without asking you a question.</ConceptCard>
  <ConceptCard label="4. Proof of concept">Show the *actual* impact, not the claim. Not `XSS exists here` — the alert firing, the other user's data returned, the request/response pair from Burp.</ConceptCard>
  <ConceptCard label="5. Impact (business terms)">`An attacker can iterate invoice IDs and extract names, addresses, and partial payment details of all users` lands harder than `IDOR found`. Translate the bug into what it costs the company.</ConceptCard>
  <ConceptCard label="The N/A is education">Most early reports come back duplicate, out-of-scope, or informational. That's not failure — it's the feedback loop. Read every triage response; it tells you exactly what you misjudged. This loop separates the hunters who quit at month two from the ones at $300/month by month six.</ConceptCard>
</ConceptGrid>

## Is This Still Worth It? The 2026 AI Reckoning

The honest question, before you spend eight weeks on this: aren't bug bounties **cooked** by AI? Point a frontier model at a program, say *find bugs in this*, and it will — a huge chunk of submissions are now AI-found. So is there still a $300/month in it for a human?

**The answer is yes — but the game transformed, and you have to play the transformed game.** The useful analogy (from hakluke's *Are bug bounties cooked?*) is Swiss watchmaking and quartz: cheap quartz didn't kill watchmaking, it killed *one tier of it*. Seiko and Swatch adapted; mechanical watches became a **premium craft**. Same shape here.

<Define term="What AI actually changed (and didn't)">
What **collapsed** is the **floor**. Bugs that were genuinely hard to find five years ago are now findable by almost anyone — and by automation — so the *supply* of commodity findings exploded while *demand* stayed flat, and the value of a commodity bug plummeted. Running the same `nuclei` templates and parameter scanners as everyone else (and every AI) lands you in a sea of **duplicates and low-floor info-disclosure** — fine for learning, not a durable income. What **did not** change is the **ceiling**: the bugs that require *understanding the application's intent* — business-logic flaws, multi-step access-control, the IDOR you chain into account takeover, the canonicalization mismatch nobody else noticed — are exactly what AI still can't reason its way to, because they're about *meaning*, not pattern-matching. You were already competing against AI (from security teams, startups, and other hunters) before the platforms shipped their own; that's not the threat. The one real risk hakluke names is **cost**: frontier-AI tooling runs hundreds to thousands a month, which could price out newcomers and shrink the talent diversity that makes the whole model work. Budget accordingly, and lean on free tooling and your own depth while you build up.
</Define>

So the adaptation — which is *the same method this whole chapter teaches*, now with the stakes made explicit:

<ConceptGrid cols={2}>
  <ConceptCard label="Don't fish where the AI fishes">Spraying generic templates and auto-submitting is the race to zero — saturated, duplicate-heavy, and increasingly the **AI-slop** that gets accounts deprioritized or banned. Use commodity scanning to *learn* and to catch the occasional easy info-disclosure, not as your income strategy.</ConceptCard>
  <ConceptCard label="Depth is the moat">The durable money is in **business logic, chained access-control, and intent** — the IDOR→write→vertical→chain ladder, the *hunt one target two weeks deep* discipline. This is precisely what a model pointed at a program from cold can't reach, and exactly what this chapter pushed you toward from the start.</ConceptCard>
  <ConceptCard label="Use AI as leverage, not a firehose">Point it at *your* work, not at the program: accelerate recon, read JS faster, generate test hypotheses, triage and severity-check your own findings, draft the report you then verify. Use it in the ways other hunters aren't yet — that's the edge, not the volume.</ConceptCard>
  <ConceptCard label="Your developer brain is the differentiator">The thing AI commoditized is *throwing payloads*. The thing it didn't is *understanding the system* — which is the developer's native advantage this chapter opened with. The transformed game rewards exactly the hunter who thinks like an engineer debugging intent.</ConceptCard>
</ConceptGrid>

The reassuring conclusion: **a steady $300/month was never about out-spraying the bots.** It was always about the *method* — master one class, do the deep recon, find the missing check that requires understanding, write the honest high-signal report. That method is precisely what survives the AI transformation. The hunters who get cooked are the ones who were *only* doing what a script could do.

## The 8-Week Plan

The biggest beginner problem isn't a lack of resources — it's a lack of structure. Here's the consensus starter, mapped to the chapters that teach each piece:

| Weeks | Focus | Your chapter |
|---|---|---|
| **1-2** | HTTP + Burp fundamentals; create HackerOne/Intigriti accounts | **burp-suite** (ch33), **http-servers** |
| **3-4** | IDOR deep-dive; read **50 disclosed IDOR reports** on HackerOne Hacktivity | **broken-access-control** (ch13), **case bank** |
| **5-6** | Pick one VDP; run **full recon**, map everything — don't hunt yet | **recon-methodology** (ch25) |
| **7-8** | Hunt IDOR only; submit **≥1 report** even if unsure — report-writing is itself the skill | **owasp-bug-hunters-field-guide** |

<Define term="The compounding loop (what happens after week 8)">
When you land your **first accepted report**, stop and dissect it: *what program type was this? what feature had the bug? what did I do differently?* Write it down — then repeat that exact approach on **three more programs in the same category**. **One payout is luck; three from the same approach is a method.** That method is your edge: it makes you faster, wastes less time on dead ends, and turns hunting from random poking into a repeatable process. This is how a part-time hunter goes from $0 to a steady $300/month and keeps climbing — not by learning every vulnerability, but by industrializing the one or two they find reliably.
</Define>

<Recap>

- **The honest curve:** months 1-3 pay **$0** for almost everyone; a steady **$300/month is realistic around month 4-8** of consistent part-time work. Income is **lumpy** — the average hides the zero months. ≈40% of submitters never earn, usually from bad target selection or unreproducible reports.
- **Master one class — IDOR.** It's the most-rewarded category, needs only two accounts and Burp Repeater, and exists in nearly every endpoint. Climb the payout ladder: **read → write → vertical escalation** (write IDORs turn Low into P1), and remember **UUIDs leak**. The detection is mechanical — replay each request under a second identity and diff (the Autorize/Authz logic, ≈20 lines of Go).
- **Recon is 60-80% of the job.** The bugs are on forgotten subdomains, not `www`. Run `subfinder → httpx → JS-mining → nuclei → anew`, sweep low-hanging fruit (info disclosure, subdomain takeover, JWT `alg:none`, CORS), and `anew`-diff daily so new assets surface the day they deploy.
- **Pick programs that pay steadily:** climb the **VDP → public → private-invite** ladder (reputation is the currency), and select for **higher minimum bounty**, wide scope, fast triage — then hunt **one target two-plus weeks deep**.
- **Reports get paid on clarity:** title with impact, honest severity, exact numbered repro, real PoC, business-terms impact. The N/A responses are the feedback loop, not failure.
- **The loop that compounds:** dissect your first paid report and repeat its exact approach three more times. One payout is luck; three from the same method is a method — and a method is a steady income.
- **AI transformed the game, it didn't end it.** Commodity bugs are a duplicate-heavy race to zero (you compete against AI and everyone's scanners); the durable income is **depth** — intent-dependent logic and chained access-control AI can't reason to — with AI used as **leverage on your own workflow**, not a submission firehose. The method that earns $300/month is the one that survives the transformation.
