When you rely exclusively on user-space telemetry:
1. **You cannot see kernel queue delays**: If a packet waits 300ms in the socket receive buffer (`SO_RCVBUF`) before Go's runtime netpoll calls `read()`, your application timer only measures from the moment `read()` returns. You miss the entire 300ms queue stall.
2. **Context switch overhead destroys high packet rates**: A standard Linux system handling 1,000,000 packets per second spends over 60% of CPU cycles creating `sk_buff` structs, managing routing tables, and copying memory to user space.
3. **Application crashes kill your visibility**: If a microservice panics or deadlocks, its internal metrics server dies with it. Kernel-level probes continue running unaffected.

</Define>

## eBPF Architecture & The Verifier

The eBPF engine is not an interpreter; it is a full in-kernel computing subsystem. When your Go program loads eBPF bytecode, the Linux kernel subjects it to a draconian safety inspection before running it through a Just-In-Time (JIT) compiler.

```
┌─────────────────────────────────────────────────────────────┐
│                        USER SPACE                           │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                     Go Program                        │  │
│  │   - cilium/ebpf loader                                │  │
│  │   - ringbuf.Reader (consumes telemetry)               │  │
│  │   - BPF Map management (updating blocklists)          │  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             │ bpf() syscall                 │
├─────────────────────────────┼───────────────────────────────┤
│                        KERNEL SPACE                         │
│                             ▼                               │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                   BPF Subsystem                       │  │
│  │  1. In-Kernel Verifier (DAG static analysis)          │  │
│  │  2. JIT Compiler (BPF Bytecode ➔ x86_64/ARM64)        │  │
│  └───────────┬───────────────────────────────▲───────────┘  │
│              │ attaches                      │ reads/writes │
│              ▼                               ▼              │
│  ┌───────────────────────┐       ┌───────────────────────┐  │
│  │      Hook Points      │       │       BPF Maps        │  │
│  │  - XDP (NIC Driver)   │◄─────►│  - HASH / ARRAY       │  │
│  │  - kprobe / kretprobe │       │  - RINGBUF (mmap'd)   │  │
│  │  - tracepoints        │       │  - LRU_HASH           │  │
│  └───────────────────────┘       └───────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

<Define term="In-Kernel BPF Verifier">
The Linux kernel's static analysis engine that proves an eBPF program is 100% memory-safe and guaranteed to terminate before executing. It simulates every possible code path, verifying that pointers never access uninitialized memory or out-of-bounds array indices, unbounded loops are forbidden, and kernel state cannot be corrupted.
</Define>

The verifier enforces ruthless constraints:
- **No unbounded loops**: As of modern kernels (Linux 5.3+), bounded loops are permitted, but the verifier must mathematically prove they terminate within instruction limits (up to 1,000,000 verified complexity states).
- **Mandatory Bounds Checking**: Every packet memory access `data + offset` must be explicitly guarded with a conditional branch checking against `data_end`. If you omit a single check, the verifier rejects the program with `invalid access to packet`.
- **Restricted Stack Size**: An eBPF program has a strict 512-byte stack limit. Large structures must be stored in BPF maps or per-CPU scratch buffers.
- **Helper Functions Only**: eBPF code cannot call arbitrary C standard library functions or kernel functions; it can only invoke blessed in-kernel helper functions (`bpf_ktime_get_ns()`, `bpf_map_lookup_elem()`, `bpf_ringbuf_submit()`).

<UnderTheHood title="The BPF JIT, CO-RE & Go Runtime Synergy (Go 1.26 + Linux 6.x)">

How does Go interact with kernel eBPF without CGO?

Historically, developers used BCC (BPF Compiler Collection), which required dragging Python, LLVM, and a full C toolchain onto production servers.

The modern paradigm is **BPF CO-RE (Compile Once – Run Everywhere)** backed by **BTF (BPF Type Format)**. The C code is compiled once into an ELF binary containing compact debug types. The pure-Go library `github.com/cilium/ebpf` parses this ELF file directly in Go user space, relocates kernel struct field offsets on the fly to match the host's running kernel, and executes the `sys_bpf` syscall (`syscall.Syscall(unix.SYS_BPF, ...)`) to load the verified bytecode.

In Go 1.26, modern containerized microservices benefit from container-aware runtime integration. When Go processes trace kernel events via eBPF, memory-mapped BPF ring buffers provide non-blocking event consumption that avoids Go runtime scheduler thread thrashing.

</UnderTheHood>

## Compiling & bpf2go Generation

Instead of hand-writing raw bytecode or juggling complex Makefile scripts, the Go eBPF ecosystem uses `bpf2go`. `bpf2go` is a command-line tool shipped with `cilium/ebpf` that compiles C source code with `clang` and generates type-safe Go bindings.

Let's look at how the C program and Go bindings fit together.

### 1. The C eBPF Program (`probe.c`)

Here is an eBPF program that monitors settlement transactions by intercepting IPv4 TCP connections:

```c
//go:build ignore
#include <linux/bpf.h>
#include <linux/if_ether.h>
#include <linux/ip.h>
#include <linux/in.h>
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_endian.h>

// Event structure streamed to Go user space
struct wire_event_t {
    __u32 src_ip;
    __u32 dst_ip;
    __u16 dst_port;
    __u16 pkt_len;
    __u64 timestamp_ns;
};

// BPF Map: Ring buffer for streaming events
struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 1 << 24); // 16 MB ring buffer
} events SEC(".maps");

// BPF Map: Hash map for IP allowlist
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10000);
    __type(key, __u32);   // IPv4 address
    __type(value, __u8);  // 1 = allowed, 0 = blocked
} ip_filter SEC(".maps");

SEC("xdp")
int xdp_meridian_filter(struct xdp_md *ctx) {
    void *data = (void *)(long)ctx->data;
    void *data_end = (void *)(long)ctx->data_end;

    // 1. Boundary check for Ethernet header
    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > data_end) {
        return XDP_PASS;
    }

    if (eth->h_proto != bpf_htons(ETH_P_IP)) {
        return XDP_PASS;
    }

    // 2. Boundary check for IPv4 header
    struct iphdr *ip = (void *)(eth + 1);
    if ((void *)(ip + 1) > data_end) {
        return XDP_PASS;
    }

    // 3. Lookup in Go-managed BPF hash map
    __u32 src_ip = ip->saddr;
    __u8 *allowed = bpf_map_lookup_elem(&ip_filter, &src_ip);
    if (allowed && *allowed == 0) {
        // Drop blocked IP at wire speed
        return XDP_DROP;
    }

    // 4. Reserve space in Ring Buffer for telemetry
    struct wire_event_t *event = bpf_ringbuf_reserve(&events, sizeof(*event), 0);
    if (!event) {
        return XDP_PASS; // Ring buffer full, do not drop packet
    }

    event->src_ip = src_ip;
    event->dst_ip = ip->daddr;
    event->dst_port = 0;
    event->pkt_len = bpf_ntohs(ip->tot_len);
    event->timestamp_ns = bpf_ktime_get_ns();

    bpf_ringbuf_submit(event, 0);
    return XDP_PASS;
}

char _license[] SEC("license") = "GPL";
```

### 2. Generating Go Bindings

To compile this into Go, you place a `go:generate` directive inside your Go package:

```go
//go:generate go run github.com/cilium/ebpf/cmd/bpf2go -target bpf probe probe.c -- -I/usr/include/bpf -O2
```

Running `go generate ./...` creates two files:
- `probe_bpf.o`: The compiled ELF BPF bytecode.
- `probe_bpf.go`: Generated Go structs (`probeObjects`, `probePrograms`, `probeMaps`, `probeWireEventT`) containing embedded bytecode and type-safe map/program handles.

<Define term="bpf2go">
A code generation tool from the `cilium/ebpf` project that invokes `clang` to compile C eBPF source into bytecode, embeds the compiled ELF assets directly into `.go` source files, and creates type-safe Go structs matching BPF maps and program definitions.
</Define>

## XDP: Dropping Packets at the NIC

### XDP Return Actions

An XDP program inspects packet memory and terminates by returning one of five integer codes:

| Action | Code | Meaning |
| :--- | :--- | :--- |
| `XDP_DROP` | `1` | Discards the packet immediately at the driver level. Consumes &lt; 15 nanoseconds. |
| `XDP_PASS` | `2` | Passes the packet up into the normal Linux network stack (`sk_buff` allocation). |
| `XDP_TX` | `3` | Bounces the packet back out the same network interface it arrived on. |
| `XDP_REDIRECT` | `4` | Bypasses kernel stack and forwards packet to another NIC, CPU core, or AF_XDP socket. |
| `XDP_ABORTED` | `0` | Indicates an eBPF program error; drops packet and emits a tracepoint warning. |

Let's look at how we parse network packets safely in Go models.

```go
package main

import (
	"encoding/binary"
	"errors"
	"fmt"
	"net"
)

// EthernetHeader models struct ethhdr (14 bytes)
type EthernetHeader struct {
	DstMAC    net.HardwareAddr
	SrcMAC    net.HardwareAddr
	EtherType uint16
}

// IPv4Header models struct iphdr (minimum 20 bytes)
type IPv4Header struct {
	VersionIHL uint8
	TOS        uint8
	TotalLen   uint16
	ID         uint16
	FlagsFrag  uint16
	TTL        uint8
	Protocol   uint8
	Checksum   uint16
	SrcIP      net.IP
	DstIP      net.IP
}

// ParsePacketHeaders performs in-memory simulation of XDP verifier-safe parsing
func ParsePacketHeaders(pkt []byte) (*EthernetHeader, *IPv4Header, error) {
	// Verifier rule 1: Bounds check Ethernet header (14 bytes)
	if len(pkt) < 14 {
		return nil, nil, errors.New("packet smaller than Ethernet header")
	}

	eth := &EthernetHeader{
		DstMAC:    net.HardwareAddr(pkt[0:6]),
		SrcMAC:    net.HardwareAddr(pkt[6:12]),
		EtherType: binary.BigEndian.Uint16(pkt[12:14]),
	}

	// Only handle IPv4 (0x0800)
	if eth.EtherType != 0x0800 {
		return eth, nil, nil
	}

	// Verifier rule 2: Bounds check IPv4 header (14 + 20 = 34 bytes)
	if len(pkt) < 34 {
		return eth, nil, errors.New("truncated IPv4 packet")
	}

	ipBytes := pkt[14:]
	ihl := (ipBytes[0] & 0x0F) * 4 // Internet Header Length in bytes
	if ihl < 20 || len(ipBytes) < int(ihl) {
		return eth, nil, errors.New("invalid IHL size")
	}

	ip := &IPv4Header{
		VersionIHL: ipBytes[0],
		TOS:        ipBytes[1],
		TotalLen:   binary.BigEndian.Uint16(ipBytes[2:4]),
		ID:         binary.BigEndian.Uint16(ipBytes[4:6]),
		FlagsFrag:  binary.BigEndian.Uint16(ipBytes[6:8]),
		TTL:        ipBytes[8],
		Protocol:   ipBytes[9],
		Checksum:   binary.BigEndian.Uint16(ipBytes[10:12]),
		SrcIP:      net.IP(ipBytes[12:16]),
		DstIP:      net.IP(ipBytes[16:20]),
	}

	return eth, ip, nil
}

func main() {
	// Raw synthetic Ethernet + IPv4 frame targeting Meridian wire port (TCP)
	rawFrame := []byte{
		// Dst MAC: 52:54:00:12:34:56
		0x52, 0x54, 0x00, 0x12, 0x34, 0x56,
		// Src MAC: 00:1A:2B:3C:4D:5E
		0x00, 0x1A, 0x2B, 0x3C, 0x4D, 0x5E,
		// EtherType: IPv4 (0x0800)
		0x08, 0x00,
		// IPv4 Header: Version 4, IHL 5 (20 bytes)
		0x45, 0x00, 0x00, 0x3C,
		0x1C, 0x7B, 0x40, 0x00,
		0x40, 0x06, 0x00, 0x00, // TTL=64, Proto=TCP (6)
		0xC0, 0xA8, 0x01, 0x64, // Src: 192.168.1.100
		0x0A, 0x00, 0x00, 0x01, // Dst: 10.0.0.1
	}

	eth, ip, err := ParsePacketHeaders(rawFrame)
	if err != nil {
		fmt.Println("Parse error:", err)
		return
	}

	fmt.Println("EtherType:", fmt.Sprintf("0x%04X", eth.EtherType))
	fmt.Println("Source IP:", ip.SrcIP)
	fmt.Println("Destination IP:", ip.DstIP)
	fmt.Println("Protocol:", ip.Protocol)
```

## Kprobes & Uprobes: Latency Telemetry

When diagnosing latency anomalies, packet inspection is only half the battle. You need to know how long functions take to execute inside the kernel and inside your Go binaries.

<Define term="kprobe and kretprobe">
**kprobe** (kernel probe) attaches to the entry of virtually any Linux kernel function to capture input arguments. **kretprobe** (kernel return probe) attaches to the function return to measure elapsed execution time and inspect return values.
</Define>

<Define term="uprobe and uretprobe">
User-space probes that attach directly to symbol offsets inside compiled executable binaries (including Go application binaries) without recompiling or restarting the target service.
</Define>

### Tracing Kernel TCP Latency with Kprobes

Consider tracing `tcp_sendmsg` in the kernel to measure how long socket writes block:

```c
// C kprobe snippet
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10240);
    __type(key, __u64); // PID + TGID
    __type(value, __u64); // Timestamp (nanoseconds)
} start_times SEC(".maps");

SEC("kprobe/tcp_sendmsg")
int BPF_KPROBE(trace_tcp_sendmsg_enter) {
    __u64 pid_tgid = bpf_get_current_pid_tgid();
    __u64 ts = bpf_ktime_get_ns();
```

## BPF Ring Buffer: Streaming to Go

In legacy eBPF programs, streaming data to user space required `BPF_MAP_TYPE_PERF_EVENT_ARRAY`. That approach allocated per-CPU buffers, leading to memory fragmentation, wasted RAM on high-core servers, and out-of-order event delivery.

Modern eBPF (Linux 5.8+) introduces the **BPF Ring Buffer** (`BPF_MAP_TYPE_RINGBUF`).

<Define term="BPF Ring Buffer">
A lockless multi-producer single-consumer circular queue allocated in kernel memory and mapped directly into user space via `mmap()`. It provides strictly ordered event delivery, variable-length event records, and zero-copy reservations.
</Define>

### Consuming Ring Buffer Events in Go

Here is how the Go user-space program reads from the BPF ring buffer using `cilium/ebpf/ringbuf`:

```go
package main

import (
	"bytes"
	"context"
	"encoding/binary"
	"errors"
	"fmt"
	"log"
	"os"
	"os/signal"
	"syscall"
	"time"

	"github.com/cilium/ebpf/ringbuf"
)

type WireTransferTelemetry struct {
	TimestampNs uint64
	TransferID  uint64
	AmountCents uint64
	DurationNs  uint64
	PID         uint32
	Status      uint32
}

func StreamTelemetry(ctx context.Context, rd *ringbuf.Reader) error {
	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		record, err := rd.Read()
		if err != nil {
			if errors.Is(err, ringbuf.ErrClosed) {
				return nil
			}
			log.Printf("ringbuf read error: %v", err)
			continue
		}

		var event WireTransferTelemetry
		if err := binary.Read(bytes.NewReader(record.RawSample), binary.LittleEndian, &event); err != nil {
			log.Printf("failed to decode event: %v", err)
			continue
		}

		latency := time.Duration(event.DurationNs) * time.Nanosecond
		if latency > 10*time.Millisecond {
			log.Printf("ALERT: Slow Settlement #%d (Amount: %d cents) took %v (PID: %d)",
				event.TransferID, event.AmountCents, latency, event.PID)
		}
	}
}
```

## A Production Observability Engine

Let's assemble a complete, production-grade observability engine in Go. This architecture:
1. Manages kernel lifecycle with `cilium/ebpf`.
2. Attaches dynamic probes.
3. Updates BPF maps at runtime to block abusive IPs.
4. Streams and aggregates high-frequency telemetry events.
5. Handles clean teardown on `SIGINT`/`SIGTERM`.

```go
package main

import (
	"context"
	"encoding/binary"
	"fmt"
	"net"
	"os"
	"os/signal"
	"sync"
	"sync/atomic"
	"syscall"
	"time"
)

// In-memory simulation of complete BPF Map + Ring Buffer pipeline
type ObservabilityEngine struct {
	mu           sync.RWMutex
	blockedIPs   map[uint32]bool
	ringBuffer   chan []byte
	totalDrops   atomic.Uint64
	totalEvents  atomic.Uint64
	slowSettlers atomic.Uint64
}

func NewObservabilityEngine(bufferCapacity int) *ObservabilityEngine {
	return &ObservabilityEngine{
		blockedIPs: make(map[uint32]bool),
		ringBuffer: make(chan []byte, bufferCapacity),
	}
}

// BlockIP updates the BPF Map from Go user space
func (oe *ObservabilityEngine) BlockIP(ipStr string) error {
	ip := net.ParseIP(ipStr).To4()
	if ip == nil {
		return fmt.Errorf("invalid IPv4: %s", ipStr)
	}
	ipKey := binary.BigEndian.Uint32(ip)

	oe.mu.Lock()
	oe.blockedIPs[ipKey] = true
	oe.mu.Unlock()
	return nil
}

// SimulateInKernelXDP simulates the driver-level eBPF XDP hook
func (oe *ObservabilityEngine) SimulateInKernelXDP(srcIP net.IP, transferID uint64, amount uint64, durationNs uint64) bool {
	ipKey := binary.BigEndian.Uint32(srcIP.To4())

	oe.mu.RLock()
	isBlocked := oe.blockedIPs[ipKey]
	oe.mu.RUnlock()

	if isBlocked {
		oe.totalDrops.Add(1)
		return false // XDP_DROP
	}

	// XDP_PASS: Emit event to ring buffer
	eventBytes := make([]byte, 40)
	binary.LittleEndian.PutUint64(eventBytes[0:8], uint64(time.Now().UnixNano()))
	binary.LittleEndian.PutUint64(eventBytes[8:16], transferID)
	binary.LittleEndian.PutUint64(eventBytes[16:24], amount)
	binary.LittleEndian.PutUint64(eventBytes[24:32], durationNs)
	binary.BigEndian.PutUint32(eventBytes[32:36], ipKey)
	binary.LittleEndian.PutUint32(eventBytes[36:40], 1) // status = SUCCESS

	select {
	case oe.ringBuffer <- eventBytes:
		oe.totalEvents.Add(1)
	default:
		// Ring buffer backpressure
	}
	return true
}

// ConsumeTelemetry runs in Go user space
func (oe *ObservabilityEngine) ConsumeTelemetry(ctx context.Context) {
	for {
		select {
		case <-ctx.Done():
			return
		case raw := <-oe.ringBuffer:
			if len(raw) < 40 {
				continue
			}
			transferID := binary.LittleEndian.Uint64(raw[8:16])
			amount := binary.LittleEndian.Uint64(raw[16:24])
			durationNs := binary.LittleEndian.Uint64(raw[24:32])
			srcIPRaw := binary.BigEndian.Uint32(raw[32:36])

			ip := make(net.IP, 4)
			binary.BigEndian.PutUint32(ip, srcIPRaw)

			if durationNs > 10_000_000 { // > 10ms
				oe.slowSettlers.Add(1)
				fmt.Printf("[KERNEL TRACE] LATENCY SPIKE: Transfer #%d ($%.2f) from %s took %v\n",
					transferID, float64(amount)/100.0, ip.String(), time.Duration(durationNs))
			}
		}
	}
}
```

Implement a Go function `ValidateAndExtractTCPPayload(packet []byte) (srcIP net.IP, dstPort uint16, payload []byte, err error)` that replicates the verifier safety checks required before accessing TCP payload memory. Return errors if packet bounds are breached.

```go
package main

import (
	"encoding/binary"
	"errors"
	"fmt"
	"net"
)

func ValidateAndExtractTCPPayload(packet []byte) (net.IP, uint16, []byte, error) {
	// 1. Ethernet header check (14 bytes)
	if len(packet) < 14 {
		return nil, 0, nil, errors.New("packet smaller than Ethernet header")
	}
	etherType := binary.BigEndian.Uint16(packet[12:14])
	if etherType != 0x0800 {
		return nil, 0, nil, errors.New("non-IPv4 packet")
	}

	// 2. IPv4 header check (14 + 20 bytes min)
	if len(packet) < 34 {
		return nil, 0, nil, errors.New("truncated IPv4 header")
	}
	ipStart := 14
	ihl := int(packet[ipStart]&0x0F) * 4
	if ihl < 20 || len(packet) < ipStart+ihl {
		return nil, 0, nil, errors.New("invalid IHL")
	}

	protocol := packet[ipStart+9]
	if protocol != 6 { // TCP
		return nil, 0, nil, errors.New("non-TCP packet")
	}
	srcIP := net.IP(packet[ipStart+12 : ipStart+16])

	// 3. TCP header check (ipStart + ihl + 20 bytes min)
	tcpStart := ipStart + ihl
	if len(packet) < tcpStart+20 {
		return nil, 0, nil, errors.New("truncated TCP header")
	}

	dstPort := binary.BigEndian.Uint16(packet[tcpStart+2 : tcpStart+4])
	dataOffset := int((packet[tcpStart+12] >> 4) & 0x0F) * 4
	if dataOffset < 20 || len(packet) < tcpStart+dataOffset {
		return nil, 0, nil, errors.New("invalid TCP data offset")
	}

	payloadStart := tcpStart + dataOffset
	payload := packet[payloadStart:]
	return srcIP, dstPort, payload, nil
}

func main() {
	// Synthesize a valid Ethernet + IP + TCP packet with payload
	pkt := make([]byte, 58)
	binary.BigEndian.PutUint16(pkt[12:14], 0x0800) // EtherType IPv4
	pkt[14] = 0x45                                 // Version 4, IHL 5 (20 bytes)
	pkt[23] = 6                                    // Proto TCP
	copy(pkt[26:30], net.ParseIP("10.0.1.50").To4())
	copy(pkt[30:34], net.ParseIP("10.0.1.1").To4())
	binary.BigEndian.PutUint16(pkt[36:38], 8080)   // DstPort 8080
	pkt[46] = 0x50                                 // TCP Data Offset 5 (20 bytes)
	copy(pkt[54:], []byte("WIRE"))                 // 4-byte payload

	src, port, payload, err := ValidateAndExtractTCPPayload(pkt)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Source: %s, Port: %d, Payload: %s\n", src, port, string(payload))
}
```

Just like the Linux BPF verifier, every offset calculation (`ihl * 4` and `dataOffset * 4`) must be mathematically validated against total packet length before advancing pointers.

<Exercise n={4} title="Logarithmic Latency Histogram Aggregator" level="hard">

Simulate an in-kernel BPF logarithmic histogram accumulator in Go. Implement `RecordLatency(dur time.Duration)` and `PrintHistogram()` where latency values are bucketed exponentially by powers of two (2^k microseconds), matching the behavior of `bpftool` and `bcc` histogram maps.

<Solution>

```go
package main

import (
	"fmt"
	"math/bits"
	"sync/atomic"
	"time"
)

// Log2Histogram implements a lock-free power-of-two histogram accumulator
type Log2Histogram struct {
	// Buckets 0..63 representing [2^i, 2^(i+1)) microseconds
	buckets [64]atomic.Uint64
}

func (h *Log2Histogram) RecordLatency(dur time.Duration) {
	us := uint64(dur.Microseconds())
	if us == 0 {
		h.buckets[0].Add(1)
		return
	}
	// Calculate log2 floor using leading zeros count
	bucket := 64 - bits.LeadingZeros64(us)
	if bucket >= 64 {
		bucket = 63
	}
	h.buckets[bucket].Add(1)
}

func (h *Log2Histogram) PrintHistogram() {
	fmt.Printf("%-18s : %-10s %s\n", "Latency Range (µs)", "Count", "Distribution")
	for i := 0; i < 30; i++ {
		count := h.buckets[i].Load()
		if count == 0 {
			continue
		}
		var low, high uint64
		if i == 0 {
			low, high = 0, 1
		} else {
			low = 1 << (i - 1)
			high = (1 << i) - 1
		}
		stars := ""
		for s := uint64(0); s < count && s < 40; s++ {
			stars += "*"
		}
		fmt.Printf("[%8d -> %8d] : %-10d %s\n", low, high, count, stars)
	}
}

func main() {
	hist := &Log2Histogram{}
	// Simulate wire settlement latency events
	hist.RecordLatency(500 * time.Microsecond)
	hist.RecordLatency(800 * time.Microsecond)
	hist.RecordLatency(1200 * time.Microsecond)
	hist.RecordLatency(1500 * time.Microsecond)
	hist.RecordLatency(4500 * time.Microsecond)
	hist.RecordLatency(25000 * time.Microsecond) // 25ms spike

	hist.PrintHistogram()
}
```

In-kernel BPF maps like `BPF_MAP_TYPE_ARRAY` use `bpf_log2l()` to index histogram buckets in constant time O(1). In Go, `bits.LeadingZeros64` compiles directly to the single-cycle x86 `BSR` / `LZCNT` instruction.

## Recap

- **eBPF** executes sandboxed, JIT-compiled bytecode directly inside the Linux kernel in response to system events, avoiding user-space context switches.
- The **in-kernel verifier** guarantees safety by statically checking every branch, ensuring bounds checks on all packet pointers, and preventing unbounded loops.
- **`bpf2go`** and `cilium/ebpf` compile C source to BPF bytecode and generate type-safe pure-Go loaders without requiring CGO or external runtime tools.
- **XDP** hooks into the NIC driver receive ring to filter or drop hostile traffic at wire speed before the kernel allocates `sk_buff` structs.
- **Kprobes and Uprobes** intercept kernel and user-space function entry/return points to measure latency and trace production behavior non-invasively.
- The **BPF Ring Buffer** maps memory directly into user space for lockless, high-throughput, ordered event streaming into Go applications.

- **Kernel-Level Observability**: eBPF runs sandboxed, JIT-compiled bytecode directly inside the Linux kernel, giving microsecond-level telemetry and 100Gbps XDP packet processing with zero user-space context switch penalties.
- **The BPF Verifier**: Enforces strict invariants before loading: no unbounded loops, mandatory pointer boundary checks, bounded stack frames (512 bytes), and type safety.
- **Probes**: `kprobes`/`kretprobes` attach dynamically to kernel functions; `uprobes` attach to Go user-space function symbols; `tracepoints` attach to stable static kernel hooks.
- **Lockless Ring Buffer**: `BPF_MAP_TYPE_RINGBUF` maps memory via `mmap()`, delivering ordered, variable-length event records directly to Go user space without per-CPU memory fragmentation.
- **Pure Go Tooling**: `cilium/ebpf` and `bpf2go` compile, bundle, and load BPF programs into the kernel without runtime CGO dependencies.
