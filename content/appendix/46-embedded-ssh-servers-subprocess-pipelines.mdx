## Embedded SSH Server in Go (crypto/ssh)

Why embed an SSH server inside a Go application instead of relying on the host operating system's OpenSSH daemon (`sshd`)?

In traditional systems, supporting Git over SSH or an internal interactive admin CLI required:
1. Creating real UNIX user accounts in `/etc/passwd` or configuring complex PAM / LDAP modules.
2. Writing public keys into `~/.ssh/authorized_keys` files on the host filesystem, risking race conditions and file permission errors.
3. Granting the process root privileges so `sshd` can switch user IDs (`setuid`/`setgid`).
4. Relying on brittle `AuthorizedKeysCommand` scripts that shell out to verify tokens.

<Define term="Embedded SSH Server">
An **embedded SSH server** is a full SSH protocol implementation compiled directly into your Go binary using `golang.org/x/crypto/ssh`. It listens on a TCP port, negotiates transport encryption (Diffie-Hellman/Curve25519), authenticates users against internal memory, databases, or HashiCorp Vault, and routes requests to pure Go handlers or sandboxed child processes without needing root privileges or host OS accounts.
</Define>

<Define term="Public Key Authentication">
**Public key authentication** is an asymmetric cryptographic handshake where the client proves possession of a private key corresponding to a registered public key. In Go's `crypto/ssh`, the server provides a `PublicKeyCallback` function that receives the client's `ssh.PublicKey`, validates its signature, and attaches identity metadata (such as User ID, Organization, and Permissions) to the session context.
</Define>

### Anatomy of an Embedded SSH Server

Let's inspect how an embedded SSH server is wired up in production systems like Gitea:

```go title="ssh_server.go"
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/x509"
	"encoding/pem"
	"errors"
	"fmt"
	"io"
	"log/slog"
	"net"

	"golang.org/x/crypto/ssh"
)

// ServerConfig configures the embedded SSH bastion.
type BastionServer struct {
	config *ssh.ServerConfig
}

func NewBastionServer(hostPrivateKeyPEM []byte) (*BastionServer, error) {
	config := &ssh.ServerConfig{
		// PublicKeyCallback is invoked when a client presents an SSH key.
		PublicKeyCallback: func(conn ssh.ConnMetadata, key ssh.PublicKey) (*ssh.Permissions, error) {
			slog.Info("Authenticating SSH client",
				"user", conn.User(),
				"remote_addr", conn.RemoteAddr().String(),
				"key_type", key.Type(),
			)

			// In a real system, query PostgreSQL / Redis for this public key.
			// Return permissions or metadata to attach to the connection.
			return &ssh.Permissions{
				Extensions: map[string]string{
					"user-id": "usr_meridian_42",
					"role":    "developer",
				},
			}, nil
		},
		// Reject plain text passwords for maximum security.
		PasswordCallback: func(conn ssh.ConnMetadata, password []byte) (*ssh.Permissions, error) {
			return nil, errors.New("password authentication disabled: public key required")
		},
	}

	// Parse host private key (so clients can verify the server's identity)
	signer, err := ssh.ParsePrivateKey(hostPrivateKeyPEM)
	if err != nil {
		return nil, fmt.Errorf("failed to parse host private key: %w", err)
	}
	config.AddHostKey(signer)

	return &BastionServer{config: config}, nil
}
```

### Handling Channels and Requests

SSH is a **multiplexed protocol**. A single encrypted TCP connection carries multiple independent, bidirectional virtual **channels** (e.g., `"session"`, `"direct-tcpip"` for port forwarding).

Within a `"session"` channel, the client can issue distinct out-of-band **requests**:
- `"pty-req"`: Requests a pseudo-terminal (specifies terminal dimensions and terminal emulation mode like `xterm-256color`).
- `"window-change"`: Notifies the server that the user resized their terminal window (columns and rows).
- `"env"`: Passes environment variables (`LC_ALL`, `TERM`).
- `"exec"`: Requests one-shot command execution (e.g., `git-upload-pack 'repo.git'`).
- `"shell"`: Requests an interactive shell session.

<Define term="PTY (Pseudo-Terminal)">
A **pseudo-terminal (PTY)** is a bidirectional software interface provided by the operating system kernel that emulates a physical hardware terminal. It consists of a master descriptor (controlled by the server) and a slave descriptor (attached to the child process). The PTY kernel driver handles line discipline, echo control, terminal control characters (`Ctrl+C` sending `SIGINT`), and window resize signals (`SIGWINCH`).
</Define>

Here is how the SSH server accepts incoming connections and dispatches channels:

```go title="channel_dispatcher.go"
func (b *BastionServer) HandleConnection(nConn net.Conn) {
	defer nConn.Close()

	// Perform SSH handshake and key exchange
	sshConn, channels, requests, err := ssh.NewServerConn(nConn, b.config)
	if err != nil {
		slog.Error("SSH handshake failed", "err", err)
		return
	}
	defer sshConn.Close()

	// Discard global out-of-band requests (e.g. keepalives)
	go ssh.DiscardRequests(requests)

	// Iterate over channels initiated by the client
	for newChannel := range channels {
		// We only accept standard session channels
		if newChannel.ChannelType() != "session" {
			newChannel.Reject(ssh.UnknownChannelType, "unsupported channel type")
			continue
		}

		channel, requests, err := newChannel.Accept()
		if err != nil {
			slog.Error("Could not accept channel", "err", err)
			return
		}

		go b.handleSession(channel, requests, sshConn.Permissions)
	}
}

func (b *BastionServer) handleSession(ch ssh.Channel, reqs <-chan *ssh.Request, perms *ssh.Permissions) {
	defer ch.Close()

	for req := range reqs {
		switch req.Type {
		case "exec":
			// Payload is a 32-bit big-endian length followed by the command string
			if len(req.Payload) < 4 {
				req.Reply(false, nil)
				return
			}
			cmdLen := int(req.Payload[0])<<24 | int(req.Payload[1])<<16 | int(req.Payload[2])<<8 | int(req.Payload[3])
			if len(req.Payload) < 4+cmdLen {
				req.Reply(false, nil)
				return
			}
			cmdStr := string(req.Payload[4 : 4+cmdLen])
			req.Reply(true, nil) // Acknowledge command acceptance

			slog.Info("Executing SSH command", "cmd", cmdStr, "user", perms.Extensions["user-id"])
			// Run command pipeline and stream stdout/stderr back into ch
			return

		case "pty-req":
			// Terminal allocation requested
			req.Reply(true, nil)

		case "shell":
			req.Reply(true, nil)

		default:
			// Reject unknown requests
			req.Reply(false, nil)
		}
	}
}
```

## Subprocess Execution & Pipeline Streaming (os/exec)

When an authenticated client requests `git-upload-pack '/meridian/core.git'`, the Go SSH server must invoke the Git binary on the host machine and bridge its standard input, standard output, and standard error directly to the remote SSH channel.

In Go, subprocess execution is managed by the standard library's `os/exec` package.

<Define term="os/exec">
**`os/exec`** is Go's standard library package for launching external operating system processes. It wraps low-level operating system system calls (`fork`, `clone`, `execve` on POSIX systems, and `CreateProcess` on Windows) with Go's `io.Reader` and `io.Writer` stream abstractions.
</Define>

<Define term="Subprocess Deadlock">
A **subprocess deadlock** is a concurrency defect where a parent process and child subprocess freeze waiting on each other. It occurs when a child fills a kernel pipe buffer (e.g. 64KB on Linux) on standard error while the parent is blocking waiting to read standard output, or when the parent calls `cmd.Wait()` before completely draining stdout and stderr pipes.
</Define>

### The Catastrophic Subprocess Deadlock Footgun

Let's dissect the number one bug that brings down production Git bastions:

<BeforeAfter

cmd := exec.Command("git-upload-pack", repoPath)
stdout, _ := cmd.StdoutPipe()
stderr, _ := cmd.StderrPipe()

// If the child writes >64KB to stderr (e.g. progress logs),

  good={`// SAFE: Concurrent pipe draining with WaitGroup!

cmd.Start()

var wg sync.WaitGroup
wg.Go(func() { io.Copy(clientChannel, stdout) })
wg.Go(func() { io.Copy(clientChannel.Stderr(), stderr) })

// Wait for all pipe data to drain BEFORE calling cmd.Wait()
wg.Wait()
cmd.Wait()`}

  goodLabel="Deadlock-Free Concurrent Pipe Streaming"

Why does the bad version hang forever?
1. Under Linux, anonymous pipes created by `pipe2()` have a default buffer capacity of **64 KB** (16 pages of 4096 bytes).
2. When the child subprocess writes data faster than the parent consumes it, the pipe buffer fills up.
3. Subsequent `write()` syscalls by the child will **block indefinitely in the Linux kernel** until space becomes available.
4. If your Go code calls `io.ReadAll(stdout)` first, but the child process is busy writing diagnostic or progress logs to `stderr`, the child freezes in kernel space waiting for stderr buffer space.
5. Your Go program freezes waiting for stdout to close. **Both processes wait for each other. Deadlock.**

### Sandboxing and Environment Sanitization

When executing subprocesses on behalf of remote SSH clients, never inherit the parent process's environment variables (`os.Environ()`). Secrets, database passwords, and API keys stored in environment variables could be leaked if the child process errors out or dumps diagnostic information.

```go title="sandbox_exec.go"
func BuildSecureGitCommand(ctx context.Context, repoPath string, gitSubcommand string, clientArgs []string) (*exec.Cmd, error) {
	// Whitelist allowed subcommands strictly
	switch gitSubcommand {
	case "git-upload-pack", "git-receive-pack", "git-upload-archive":
		// Allowed
	default:
		return nil, fmt.Errorf("forbidden git subcommand: %q", gitSubcommand)
	}

	cmd := exec.CommandContext(ctx, gitSubcommand, repoPath)

	// Set working directory to the target repository
	cmd.Dir = repoPath

	// Sanitize environment: only provide minimal necessary variables
	cmd.Env = []string{
		"PATH=/usr/bin:/usr/local/bin:/bin",
		"GIT_DIR=" + repoPath,
		"GIT_HTTP_EXPORT_ALL=1",
		"LANG=C",
	}

	return cmd, nil
}
```

```go
package main

import (

	"fmt"
	"io"
	"os/exec"

// SafeCapture runs a subprocess and captures stdout and stderr concurrently without deadlock.
func SafeCapture(ctx context.Context, name string, args ...string) (stdout []byte, stderr []byte, exitCode int, err error) {
	cmd := exec.CommandContext(ctx, name, args...)

	stdoutPipe, err := cmd.StdoutPipe()
	if err != nil {
		return nil, nil, -1, err
	}
	stderrPipe, err := cmd.StderrPipe()
	if err != nil {
		return nil, nil, -1, err
	}

	if err := cmd.Start(); err != nil {
		return nil, nil, -1, err
	}

	var outBuf, errBuf bytes.Buffer
	var wg sync.WaitGroup

	// Concurrently drain both pipes
	wg.Add(2)
	go func() {
		defer wg.Done()
		io.Copy(&outBuf, stdoutPipe)
	}()
	go func() {
		defer wg.Done()
		io.Copy(&errBuf, stderrPipe)
	}()

	// Wait for pipe readers to reach EOF before calling Wait()
	wg.Wait()

	if waitErr := cmd.Wait(); waitErr != nil {
		if exitErr, ok := waitErr.(*exec.ExitError); ok {
			return outBuf.Bytes(), errBuf.Bytes(), exitErr.ExitCode(), waitErr
		}
		return outBuf.Bytes(), errBuf.Bytes(), -1, waitErr
	}

	return outBuf.Bytes(), errBuf.Bytes(), 0, nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()

	out, errOut, code, err := SafeCapture(ctx, "echo", "Meridian Bastion Subprocess Engine Active")
	if err != nil {
		fmt.Printf("Execution failed: %v\n", err)
		return
	}

	fmt.Printf("Exit Code: %d\n", code)
	fmt.Printf("Stdout: %s", string(out))
	fmt.Printf("Stderr: %s\n", string(errOut))
}
```

## Zero-Copy io.Pipe & Buffer Pools

In a high-throughput code forge handling thousands of concurrent developers cloning multi-gigabyte repositories, memory efficiency is paramount.

If you buffer data in memory using `bytes.Buffer` or `io.ReadAll`, a single `git clone` of a 2 GB repository allocates 2 GB on the heap. Ten concurrent clones will consume 20 GB of RAM, causing severe GC mark assist pauses and triggering the Linux Out-Of-Memory (OOM) killer.

<Define term="io.Pipe">
**`io.Pipe()`** is a synchronous in-memory pipe primitive provided by Go's standard library. It creates an interconnected `*io.PipeReader` and `*io.PipeWriter`. Writes to the `PipeWriter` block until an active read on the `PipeReader` consumes the exact bytes. It uses zero intermediate heap buffering.
</Define>

<ConceptGrid cols={3}>
  <ConceptCard label="Synchronous I/O">`io.Pipe` transfers bytes directly between goroutine call stacks without allocating internal queue buffers.</ConceptCard>
  <ConceptCard label="Backpressure Propagation">If the client network connection slows down, `PipeWriter.Write()` blocks, immediately pausing the child subprocess producer.</ConceptCard>
  <ConceptCard label="Zero Intermediate RAM">A 100 GB Git repository streams through the same 64 KB memory window without growing the heap.</ConceptCard>
  <Gotcha>Never read and write from an `io.Pipe` in the same goroutine! Because `Write()` blocks until `Read()` consumes the data, a single goroutine performing both operations will deadlock itself instantly.</Gotcha>
</ConceptGrid>

### Memory Recycling with sync.Pool and io.CopyBuffer

Instead of allowing `io.Copy` to allocate an un-recycled 32 KB buffer on every invocation, production systems maintain a `sync.Pool` of fixed-size 64 KB byte slices (`[]byte`):

```go title="stream_pool.go"
var bufferPool = sync.Pool{
	New: func() any {
		// Allocate aligned 64KB buffer
		buf := make([]byte, 64*1024)
		return &buf
	},
}

// StreamZeroCopy transfers data from src to dst using a pooled 64KB buffer.
func StreamZeroCopy(dst io.Writer, src io.Reader) (int64, error) {
	bufPtr := bufferPool.Get().(*[]byte)
	defer bufferPool.Put(bufPtr)

	// io.CopyBuffer uses our pooled slice instead of allocating on the heap
	return io.CopyBuffer(dst, src, *bufPtr)
}
```

### Auditing Streams with io.MultiWriter and Crypto Hashing

In enterprise bastion architectures, compliance regulations require generating an audit hash (e.g. SHA-256) of every Git push payload in real time as it traverses the network, without storing the payload on disk or buffering it in memory.

Go's `io.MultiWriter` duplicates a write stream to multiple destinations simultaneously:

```go title="audit_tee.go"
func StreamWithAudit(dstChildStdin io.Writer, clientChannel io.Reader) ([32]byte, int64, error) {
	hasher := sha256.New()

	// MultiWriter sends incoming bytes to both the child subprocess AND the SHA-256 hasher
	teeWriter := io.MultiWriter(dstChildStdin, hasher)

	bufPtr := bufferPool.Get().(*[]byte)
	defer bufferPool.Put(bufPtr)

	bytesCopied, err := io.CopyBuffer(teeWriter, clientChannel, *bufPtr)
	if err != nil {
		return [32]byte{}, bytesCopied, err
	}

	var sum [32]byte
	copy(sum[:], hasher.Sum(nil))
	return sum, bytesCopied, nil
}
```

## Git Wire Protocol & pkt-line Framing

When Git communicates over SSH or HTTP (the "Smart Transfer Protocol"), it does not exchange raw text lines or arbitrary JSON payloads. It speaks a binary-safe, length-prefixed framing protocol called **pkt-line** (Packet-Line).

<Define term="pkt-line Framing">
**`pkt-line` framing** is Git's universal network framing protocol (RFC Git Protocol v1 & v2). Every packet begins with a 4-byte hexadecimal length prefix indicating the total packet size (including the 4 prefix bytes). The maximum payload size is 65520 bytes (total length 65524 / `fff4`). Special 4-byte sentinel prefixes control stream state: `0000` (Flush), `0001` (Delimiter), and `0002` (Response End).
</Define>

<Define term="Smart Git Protocol">
The **Smart Git Protocol** is Git's network exchange mechanism implemented by `git-upload-pack` (fetch/clone) and `git-receive-pack` (push). It begins with an initial reference and capability advertisement framed in pkt-line packets, followed by a negotiation phase (want/have commands), and concludes with a multiplexed sideband packfile data stream.
</Define>

### Structure of pkt-line Packets

Let's examine how Git frames different data types:

```text
┌─────────────────┬────────────────────────────────────────────────────────┐
│ Hex Prefix (4B) │ Payload (0 to 65516 bytes)                             │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 000a            │ "hello\n" (total length: 4 prefix + 6 data = 10 / 0xa) │
│ 003f            │ "a1b2c3... HEAD\x00multi_ack thin-pack side-band-64k\n"  │
│ 0000            │ Flush packet (signals end of section / ref list)       │
│ 0001            │ Delimiter packet (used in Git Protocol v2)             │
│ 0002            │ Response End packet (used in Git Protocol v2)          │
└─────────────────┴────────────────────────────────────────────────────────┘
```

### Sideband Multiplexing (Band 1, Band 2, Band 3)

During `git clone` and `git push`, the server enables the `side-band` or `side-band-64k` capability. Instead of sending raw packfile bytes, the server sends pkt-lines where the first payload byte indicates the **channel/band**:

- **Band 1 (`0x01` - Primary Data)**: Raw Git packfile binary bytes.
- **Band 2 (`0x02` - Progress Messages)**: Informational text displayed on the developer's terminal (e.g., `"Compressing objects: 100% (42/42), done.\n"`).
- **Band 3 (`0x03` - Error Messages)**: Severe error or reject notice, causing the client to abort immediately.

```go title="sideband_writer.go"
type SidebandChannel byte

const (
	BandData     SidebandChannel = 1
	BandProgress SidebandChannel = 2
	BandError    SidebandChannel = 3
)

// WriteSideband writes a chunk to the specified sideband channel formatted as a pkt-line.
func WriteSideband(w io.Writer, band SidebandChannel, payload []byte) error {
	totalLen := len(payload) + 5 // 4 bytes hex + 1 byte band ID
	if totalLen > 65524 {
		return errors.New("sideband packet exceeds 65524 bytes")
	}

	header := fmt.Sprintf("%04x%c", totalLen, band)
	if _, err := io.WriteString(w, header); err != nil {
		return err
	}
	_, err := w.Write(payload)
	return err
}
```

### Deep Engineering: Under the Hood

<UnderTheHood title="SSH Handshake, Key Exchange, PTY Window Resizing & OS Syscall Pipes">

Let's pull back the curtain and inspect the mechanical reality operating at the Linux kernel and network socket boundaries.

#### 1. RFC 4253 SSH Transport Layer & Modern Key Exchange (Go 1.26)
When an SSH client connects to your Go server:
1. **Version Exchange:** Both sides exchange identification strings (e.g. `SSH-2.0-Go` and `SSH-2.0-OpenSSH_9.6`).
2. **KEXINIT:** Both peers exchange supported cryptographic primitives: Key Exchange algorithms (`curve25519-sha256`, `diffie-hellman-group14-sha256`, and modern Post-Quantum hybrid algorithms), Ciphers (`chacha20-poly1305@openssh.com`, `aes256-gcm@openssh.com`), and MACs.
3. **Diffie-Hellman / ECDH Exchange:** Ephemeral keys are generated; the shared secret $K$ is computed. The server signs the exchange hash $H$ using its host private key to prove identity.
4. **NEWKEYS:** Both sides switch symmetric ciphers. All subsequent frames are authenticated and encrypted.

#### 2. Unix Pseudo-Terminals (PTY), termios & TIOCSWINSZ
When an interactive terminal session is requested:
1. The server opens `/dev/ptmx` to acquire a master pseudo-terminal file descriptor.
2. It grants access and unlocks the corresponding slave descriptor (`/dev/pts/N`).
3. The child process's file descriptors `0`, `1`, and `2` are attached to the slave descriptor via `dup2()`.
4. When the remote client resizes their window, an SSH `"window-change"` message delivers the new row and column count. The Go server issues an `ioctl(masterFd, TIOCSWINSZ, &ws)` syscall. The Linux kernel immediately sends a `SIGWINCH` (Window Change) signal to the child process's foreground process group, prompting full-screen CLI programs (like `vim` or `htop`) to redraw their UI.

#### 3. Linux Kernel Pipe Internals (`pipe2`) & Buffer Capacity
When `cmd.StdoutPipe()` is invoked:
1. Go calls the `pipe2(fds, O_CLOEXEC)` system call.
2. The Linux kernel allocates a `struct pipe_inode_info` ring buffer containing 16 pages ($16 \times 4096 = 65,536$ bytes).
3. If the writer writes when the buffer is full, the kernel puts the writing task into the `TASK_INTERRUPTIBLE` sleep state.
4. If the reader closes its descriptor while the writer is writing, the kernel issues a `SIGPIPE` signal (which terminates naive C programs, but Go's runtime ignores `SIGPIPE` and converts it into `syscall.EPIPE`).

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    LINUX KERNEL PIPE RING BUFFER (64 KB)                    │
│                                                                             │
│   Child Subprocess (git) ──────► [ Page 0 ][ Page 1 ] ... [ Page 15 ] ─────► Go Runtime (io.Copy)
│     (write syscall)                  ▲                           │             (read syscall)
│                                      └────── 16 Pages Max ───────┘                          │
│                                                                                             ▼
│                                                                                   SSH Encrypted Stream
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 4. Modern Go 1.25 / 1.26 Concurrency Primitives
In modern Go (Go 1.25+ and Go 1.26), subprocess management and concurrency use:
- **`sync.WaitGroup.Go(func())`** (Go 1.25): Spawns goroutines directly bound to the wait group without manual `wg.Add(1)` and `defer wg.Done()`.
- **`errors.AsType[T](err)`** (Go 1.26): Type-safe generic error inspection for `*exec.ExitError`.
- **`Green Tea GC` (Go 1.26 default):** Delivers ultra-low allocation pause times when recycling network and subprocess buffers.

```go
	w io.Writer
}

func NewPktLineEncoder(w io.Writer) *PktLineEncoder {
	return &PktLineEncoder{w: w}
}

func (e *PktLineEncoder) WriteLine(payload []byte) error {
	totalLen := len(payload) + 4
	if totalLen > 65524 {
		return errors.New("packet exceeds maximum pkt-line length of 65524 bytes")
	}
	header := fmt.Sprintf("%04x", totalLen)
	if _, err := io.WriteString(e.w, header); err != nil {
		return err
	}
	_, err := e.w.Write(payload)
	return err

	_, err := io.WriteString(e.w, "0000")
	return err

	r io.Reader
}

func NewPktLineDecoder(r io.Reader) *PktLineDecoder {
	return &PktLineDecoder{r: r}
}

// ReadPacket returns (payload, isFlush, error).
func (d *PktLineDecoder) ReadPacket() ([]byte, bool, error) {
	var prefix [4]byte
	if _, err := io.ReadFull(d.r, prefix[:]); err != nil {
		return nil, false, err
	}

	prefixStr := string(prefix[:])
	if prefixStr == "0000" {
		return nil, true, nil // Flush packet
	}

	var length int
	if _, err := fmt.Sscanf(prefixStr, "%04x", &length); err != nil {
		return nil, false, fmt.Errorf("malformed hex length prefix %q: %w", prefixStr, err)
	}

	if length < 4 {
		return nil, false, fmt.Errorf("invalid length prefix %d < 4", length)
	}

	payloadLen := length - 4
	payload := make([]byte, payloadLen)
	if _, err := io.ReadFull(d.r, payload); err != nil {
		return nil, false, err
	}

	return payload, false, nil
}

	enc.WriteFlush()

	fmt.Printf("Raw Wire Output:\n%s\n", wire.String())

	// Decode from wire buffer
	dec := NewPktLineDecoder(&wire)
	for {
		payload, isFlush, err := dec.ReadPacket()

			break
		}
		if err != nil {
			panic(err)
		}

			fmt.Println("--- FLUSH PACKET RECEIVED (0000) ---")
			break
		}
```

<Exercise n={2} title="Subprocess Runner with Combined Streaming & Context" level="medium">

```go
package main

import (
	"bytes"
	"context"
	"errors"
	"fmt"
	"io"
	"os/exec"
	"sync"
	"time"
)

type ExecutionResult struct {
	Stdout   string
	Stderr   string
	ExitCode int
	TimedOut bool
}

func RunSubprocessWithTimeout(ctx context.Context, cmdName string, args ...string) (*ExecutionResult, error) {
	cmd := exec.CommandContext(ctx, cmdName, args...)

	stdoutPipe, err := cmd.StdoutPipe()
	if err != nil {
		return nil, err
	}
	stderrPipe, err := cmd.StderrPipe()
	if err != nil {
		return nil, err
	}

		return nil, err
	}

	var stdoutBuf, stderrBuf bytes.Buffer
	var wg sync.WaitGroup
	wg.Add(2)

	go func() {
		defer wg.Done()
		io.Copy(&stdoutBuf, stdoutPipe)
	}()
	go func() {
		defer wg.Done()
		io.Copy(&stderrBuf, stderrPipe)
	}()

	wg.Wait()
	waitErr := cmd.Wait()

		} else {
			exitCode = -1
		}
	}

	return &ExecutionResult{
		Stdout:   stdoutBuf.String(),
		Stderr:   stderrBuf.String(),
		ExitCode: exitCode,
		TimedOut: timedOut,
	}, nil
}
```

- **Embedded SSH Architecture (Gitea Pattern)**: Embedding `golang.org/x/crypto/ssh` turns your Go application into a secure, self-contained bastion. In-memory `PublicKeyCallback` eliminates host OS user accounts (`/etc/passwd`) and disk-based `authorized_keys` synchronization.

- **Deadlock-Free Subprocess Execution (`os/exec`)**: OS kernel pipes have a finite 64 KB capacity. You MUST drain `stdout` and `stderr` concurrently using goroutines. Never call `cmd.Wait()` before the pipe reading goroutines complete.
- **Zero-Copy Streaming with `io.Pipe` and `sync.Pool`**: Use `io.Pipe()` for synchronous, unbuffered data streaming with immediate backpressure. Recycle 64 KB buffers via `sync.Pool` with `io.CopyBuffer` to eliminate GC allocation spikes during gigabyte-scale Git clones.
- **Git Smart Wire Protocol (`pkt-line`)**: Git frames all wire messages with a 4-hex-digit length prefix (max length 65524). Special sentinel packets (`0000` Flush, `0001` Delim, `0002` End) control protocol negotiation and sideband multiplexing (Band 1 Data, Band 2 Progress, Band 3 Errors).
