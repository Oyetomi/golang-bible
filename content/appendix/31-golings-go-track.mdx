<HeroCard label="Appendix · Practice" title="Golings: The Fix-It Track">

Here's the thing, sport. You don't learn a language by reading about it — you learn it by *making broken code work* and feeling the compiler push back. That's the whole idea behind **rustlings**, the beloved Rust exercise series: a pile of tiny programs that *don't compile* (or compile but do the wrong thing), and your job is to fix each one until it passes. No projects, no setup, just **fix → run → green → next**.

This is that, for Go, **right here in the page**. Below is an ordered track of small broken programs — one concept each, from `variables` up through `channels`. You edit the code, hit **Run**, and it executes on the *real Go sandbox* — not a simulation. An exercise turns green only when your fix **compiles cleanly and prints the expected output**. Your progress is saved in the browser, so you can close the tab and pick up where you left off. Use the hint if you're stuck; read the one-line *why* when you pass. Do them in order — each is a reflex the rest of the Bible assumes you have. Now go make some red turn green, sport.

</HeroCard>

<Callout kind="pro" title="How to use this track">
Each exercise has a `// FIX:` comment telling you exactly what's wrong. Change the code to make it compile and print the target line, then press **Run** (the snippet runs real Go on Codapi). Green = solved and saved; the next one unlocks. Stuck for more than a minute? Hit **Show hint**. You can jump around with the numbered dots, but the intended path is top to bottom — the concepts build. Everything here was authored as a verified broken→fixed pair: the starter genuinely fails, and a correct fix genuinely passes.
</Callout>

<Callout kind="note" title="Where this fits">
This track is the **drill** companion to the language chapters. Every exercise maps to a concept taught in depth in Part 1 — slices and `append` (the **intermediate-go** and **data-semantics** chapters), pointer receivers (**data-semantics**), interfaces satisfied implicitly (**intermediate-go**), errors as values (**error-handling-at-scale**), closures (**functional-go**), `WaitGroup` and channels (the **concurrency** chapter). If an exercise stumps you even with the hint, that's a signal to revisit its chapter — then come back and turn it green. The exercises run on the same Go sandbox (Codapi) that powers every `<GoPlayground>` in the course, so what passes here behaves exactly the same everywhere else.
</Callout>
