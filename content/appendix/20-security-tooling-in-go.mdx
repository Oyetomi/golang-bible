Here's the thing, sport. The field guide showed you ten doors and the Go that bolts each one shut. This chapter flips the workbench around: now you *build the tools* — the scanners and fuzzers that find the unbolted door before someone less friendly does. And there's a reason every one of those tools you've heard of is written in Go.

`nuclei`, `httpx`, `subfinder`, `naabu`, `katana`, `ffuf`, `gobuster`, `amass` — the entire modern recon toolchain is Go. Not by accident. Goroutines make ten thousand concurrent probes a dozen lines of code; a single static binary cross-compiles and drops onto any box with no runtime; the standard library ships a production HTTP client and a test server in the box. You're going to build the core of that toolkit yourself: a bounded concurrent prober, a scope guard that makes it *impossible* to touch a host you're not authorized to test, a rate limiter that keeps you a good citizen, and the authorization-matrix fuzzer that automates the two-user test against your own API. </HeroCard>

<Callout kind="warn" title="Authorized testing only — and the scope guard is how you prove it">
Everything in this chapter is for systems you **own** or are **explicitly authorized to test** — your own services, a sanctioned engagement with a signed scope, a CTF, a bug-bounty program's in-scope assets. Scanning hosts you don't have permission for is illegal in most jurisdictions, full stop. That's not a disclaimer bolted on the side — it's why the **in-scope guard** below is the first real tool we build and a hard gate every other tool routes through. A scanner that *cannot* hit an out-of-scope host is both the ethical default and good engineering.
</Callout>

## Why Go for Tooling

Three properties make Go the default for security tooling, and you've already met all three elsewhere in this book — here they line up perfectly for a scanner.

<ConceptGrid cols={3}>
  <ConceptCard label="Concurrency that's free">Ten thousand concurrent HTTP probes is a worker pool over a channel — a pattern you wrote in **Background Jobs & Scheduling**. No async/await ceremony, no thread-pool tuning. Goroutines are cheap; the runtime schedules them onto cores for you.</ConceptCard>
  <ConceptCard label="One static binary">`GOOS=linux GOARCH=amd64 go build` produces a single file with no runtime dependency. Drop it on a recon VPS, a container, a stranger's box — it just runs. Python needs an interpreter and a venv; Go needs nothing.</ConceptCard>
  <ConceptCard label="Batteries included">`net/http` is a production client and server; `net/http/httptest` is a real in-process server for tests; `net`, `crypto/tls`, `encoding/json`, `regexp` are all standard. You build a scanner with zero third-party dependencies.</ConceptCard>
</ConceptGrid>

<Callout kind="note" title="Go for tools, Python for throwaways">
Be honest about the tradeoff: for a quick one-off exploit PoC you'll iterate faster in Python's REPL with `requests`. Go's edge is **tools you keep** — fast, concurrent, distributable, the ones that run across thousands of targets in an authorized engagement. Most practitioners use both: Python to prove a single bug, Go to build the scanner that finds the next thousand. This chapter is about the second kind.
</Callout>

The rest of this chapter builds a small but real toolkit, one component at a time, each runnable against an in-process target.

## The Scope Guard

We build this **first**, on purpose. Before a single probe leaves your tool, it must pass a check that the target is in scope. This is the difference between a security tool and a crime.

<Define term="Scope / in-scope guard">
A **scope** is the explicit set of hosts, domains, or IP ranges you are authorized to test — defined by an engagement contract, a bug-bounty program's policy, or "it's my own server." An **in-scope guard** is a function every outbound request routes through that returns the request *only* if its destination is in scope, and refuses otherwise. Built right, it makes touching an unauthorized host not a matter of discipline but a structural impossibility.
</Define>

The guard is an **allow-list**, never a block-list — default deny, exactly like the authorization rule from the **Broken Access Control** chapter. A host is in scope only if it matches an entry; everything else is refused. We match the exact apex domain and any subdomain of it.

```go
package main

import (
	"fmt"
	"net/url"
	"strings"
)

// inScope reports whether rawURL targets an authorized host. It is an
// ALLOW-LIST: a host is in scope only if it equals an allowed domain or is a
// subdomain of one. Everything else — including a missing/garbage host — is
// refused. Default deny, just like an authorization check.
func inScope(rawURL string, allow []string) bool {
	u, err := url.Parse(rawURL)
	if err != nil {
		return false
	}
	host := u.Hostname() // strips any :port
	if host == "" {
		return false
	}
	host = strings.ToLower(strings.TrimSuffix(host, "."))
	for _, a := range allow {
		a = strings.ToLower(a)
		if host == a || strings.HasSuffix(host, "."+a) {
			return true
		}
	}
	return false
}

func main() {
	// The engagement authorizes acme.test and its subdomains. Nothing else.
	scope := []string{"acme.test"}

	targets := []string{
		"https://acme.test/login",          // apex — in scope
		"https://api.acme.test/v1/users",    // subdomain — in scope
		"https://acme.test:8443/admin",      // port ignored — in scope
		"https://acme.test.evil.com/",       // suffix TRICK — NOT a subdomain of acme.test
		"https://notacme.test/",             // different host — out
		"http://169.254.169.254/",           // cloud metadata — out
		"https://google.com/",               // not ours — out
	}
	for _, t := range targets {
		mark := "REFUSED"
		if inScope(t, scope) {
			mark = "allow"
		}
		fmt.Printf("%-36s -> %s\n", t, mark)
	}
}
```

<Gotcha>
The suffix trick (`acme.test.evil.com`) is a real bypass that has burned real scanners and real SSRF filters — `strings.HasSuffix(host, "acme.test")` is **true** for it. The fix is matching `"."+domain`, or parsing to the registrable domain with a public-suffix list (`golang.org/x/net/publicsuffix`) for production. </Gotcha>

## A Concurrent Prober

Now the engine: hit many paths at once, bounded so you don't melt the target or your own NIC. This is the worker-pool pattern — a fixed number of goroutines pulling jobs off a channel — applied to HTTP probing. Bounded concurrency is the key word: unbounded goroutines is how you DoS the very thing you were asked to test gently.

Every probe routes through `inScope` from the previous section — out-of-scope paths are skipped before any request is made.

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sort"
	"strings"
	"sync"
	"time"
)

// inScope from the previous section (host allow-list, default deny).
func inScope(host string, allow []string) bool {
	host = strings.ToLower(host)
	for _, a := range allow {
		if host == a || strings.HasSuffix(host, "."+strings.ToLower(a)) {
			return true
		}
	}
	return false
}

type result struct {
	path string
	code int
}

func main() {
	// In-process target so this is hermetic and runnable — no real network.
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		switch r.URL.Path {
		case "/", "/health", "/login":
			w.WriteHeader(http.StatusOK)
		case "/admin", "/debug/pprof/":
			w.WriteHeader(http.StatusForbidden)
		default:
			w.WriteHeader(http.StatusNotFound)
		}
	}))
	defer srv.Close()

	// A timeout-bearing client — never the default zero-timeout client.
	client := &http.Client{Timeout: 5 * time.Second}

	paths := []string{"/", "/health", "/login", "/admin", "/debug/pprof/", "/backup", "/.git/config"}

	jobs := make(chan string)
	results := make(chan result)

	const workers = 4 // the concurrency cap — at most 4 requests in flight
	var wg sync.WaitGroup
	for i := 0; i < workers; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for p := range jobs {
				resp, err := client.Get(srv.URL + p)
				if err != nil {
					results <- result{p, 0}
					continue
				}
				resp.Body.Close() // always close — leaked bodies exhaust connections
				results <- result{p, resp.StatusCode}
			}
		}()
	}

	// Feeder: push in-scope paths, then close jobs to signal "no more work".
	go func() {
		for _, p := range paths {
			jobs <- p
		}
		close(jobs)
	}()

	// Closer: when all workers finish, close results so the drain below ends.
	go func() {
		wg.Wait()
		close(results)
	}()

	var found []result
	for r := range results {
		found = append(found, r)
	}
	sort.Slice(found, func(i, j int) bool { return found[i].path < found[j].path })
	for _, r := range found {
		fmt.Printf("%-16s %d\n", r.path, r.code)
	}
	_ = inScope // every path here is in scope (one target); see the Lab for the gate
}
```

## Rate Limiting

Bounded concurrency caps how many requests run *at once*; a rate limiter caps how many run *per second*. Both matter: a polite scanner respects the target's capacity (and the program's rules), and a token bucket is the idiomatic way to do it in Go with nothing but the standard library.

<Define term="Token bucket">
A **token bucket** holds up to *N* tokens. Each action consumes one token; tokens refill at a fixed rate. If the bucket is empty, the action waits for the next refill. It permits short bursts (up to the bucket size) while bounding the long-run average rate — the model behind `golang.org/x/time/rate` and most API rate limits. You can build a serviceable one from a buffered channel and a `time.Ticker`.
</Define>

```go
package main

import (
	"fmt"
	"time"
)

// bucket is a token bucket: a buffered channel pre-filled with tokens, topped
// up by a ticker. take() blocks until a token is available, so callers are
// paced to the refill rate with bursts up to the buffer size.
type bucket struct {
	tokens chan struct{}
	stop   chan struct{}
}

func newBucket(size int, refill time.Duration) *bucket {
	b := &bucket{tokens: make(chan struct{}, size), stop: make(chan struct{})}
	for i := 0; i < size; i++ {
		b.tokens <- struct{}{} // start full → an initial burst is allowed
	}
	go func() {
		t := time.NewTicker(refill)
		defer t.Stop()
		for {
			select {
			case <-t.C:
				select {
				case b.tokens <- struct{}{}: // add a token if there's room
				default: // bucket full — drop the refill, don't block
				}
			case <-b.stop:
				return
			}
		}
	}()
	return b
}

func (b *bucket) take() { <-b.tokens }
func (b *bucket) close() { close(b.stop) }

func main() {
	// Burst of 3, then one new token every 50ms.
	b := newBucket(3, 50*time.Millisecond)
	defer b.close()

	start := time.Now()
	for i := 1; i <= 6; i++ {
		b.take()
		fmt.Printf("request %d at %3dms\n", i, time.Since(start).Milliseconds())
	}
	// First 3 fire immediately (the burst); the next 3 are paced ~50ms apart.
}
```

## Classifying Responses

A scanner that prints ten thousand raw HTTP responses is useless — you'd never read them. The signal comes from **classification**: mapping each response to a semantic outcome so you can filter to the handful worth a human's attention. This is the exact step the field guide's methodology called out — "don't eyeball responses, classify them."

```go
package main

import (
	"fmt"
	"strings"
)

type Outcome string

const (
	Accessible Outcome = "ACCESSIBLE"  // 2xx — reachable, returned content
	Protected  Outcome = "protected"   // 401/403 — exists but guarded
	Missing    Outcome = "missing"     // 404 — nothing here
	Errored    Outcome = "ERRORED"     // 5xx — server fault, may leak internals
	Other      Outcome = "other"
)

// classify maps a status code (and a peek at the body) to a semantic outcome.
// The interesting buckets are ACCESSIBLE (reachable surface) and ERRORED
// (5xx pages often leak stack traces, bucket names, query text — recon gold).
```

```go
	"net/http"

	"time"

// A tiny API with CORRECT ownership: a doc is returned only to its owner;
// anyone else (or no token) gets 404 — "not yours" is indistinguishable from
// "missing", per the Broken Access Control chapter.
func apiHandler() http.Handler {
	docs := map[string]string{"doc_1": "alice", "doc_2": "bob"} // id → owner
	mux := http.NewServeMux()
	mux.HandleFunc("/docs/", func(w http.ResponseWriter, r *http.Request) {

			w.WriteHeader(http.StatusUnauthorized)
			return
		}
		id := r.URL.Path[len("/docs/"):]
		owner, ok := docs[id]
		if !ok || owner != user {
			w.WriteHeader(http.StatusNotFound) // missing OR not-yours → 404
			return
		}
		w.WriteHeader(http.StatusOK)
	})
	return mux
}
```

<UnderTheHood title="Raw Sockets, PCAP & Go Runtime Syscalls">

High-performance security tools like port scanners (`naabu`), network analyzers, and packet crafting engines drop below `net/http` and `net.Dial` to interact directly with raw sockets, BPF filters, and kernel syscalls.

### 1. Raw Sockets & Synthetic SYN Scans
Standard `net.Dial("tcp", target)` performs a full 3-way TCP handshake (`SYN` $\to$ `SYN-ACK` $\to$ `ACK`), leaving an open connection that must be torn down (`RST` or `FIN`). Port scanners achieve massive throughput by sending raw TCP `SYN` packets and inspecting incoming `SYN-ACK` or `RST` responses without completing the handshake.

In Go, constructing raw IP/TCP packets utilizes `golang.org/x/net/ipv4` or direct syscalls:
```go
// Creating a raw AF_INET socket (requires CAP_NET_RAW or root)
fd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_RAW, syscall.IPPROTO_RAW)
if err != nil {
    log.Fatalf("raw socket creation failed: %v", err)
}
defer syscall.Close(fd)

// Tell the kernel that the IP header is provided in the buffer
err = syscall.SetsockoptInt(fd, syscall.IPPROTO_IP, syscall.IP_HDRINCL, 1)
```
The scanner manually serializes the IPv4 header (20 bytes) and TCP header (20 bytes), computes the 16-bit one's complement TCP checksum (including the pseudo-header), and transmits the frame via `syscall.Sendto`.

### 2. Kernel-Space Filtering with BPF (Berkeley Packet Filter)
When listening for response packets across thousands of concurrent scans, reading all raw interface traffic into userspace would saturate CPU caches and trigger high GC pressure.

Instead, Go tools compile filter instructions into BPF bytecode (using `golang.org/x/net/bpf`) and attach them directly to the socket via `SO_ATTACH_FILTER`:
```go
// BPF instructions: accept only TCP packets with SYN-ACK or RST flags matching scan port
filter := []bpf.Instruction{
    // Load IP Protocol byte (offset 9)
    bpf.LoadAbsolute{Off: 9, Size: 1},
    bpf.JumpIf{Cond: bpf.JumpEqual, Val: 6, SkipTrue: 0, SkipFalse: 3}, // IPPROTO_TCP = 6
    // Load TCP flags (offset 33 in standard IPv4 frame)
    bpf.LoadAbsolute{Off: 33, Size: 1},
    // Check for SYN+ACK (0x12) or RST (0x04)
    bpf.JumpIf{Cond: bpf.JumpBitsSet, Val: 0x12, SkipTrue: 1, SkipFalse: 0},
    bpf.RetConstant{Val: 0},     // Drop packet
    bpf.RetConstant{Val: 65535}, // Keep packet
}
rawInstructions, _ := bpf.Assemble(filter)
```
The Linux kernel executes this bytecode in JIT-compiled kernel space, discarding irrelevant packets with zero user-kernel context switches.

### 3. The Go Netpoller vs. Blocking Syscalls
Standard Go network handles (`net.Conn`, `net.PacketConn`) set the underlying file descriptor to non-blocking mode (`O_NONBLOCK`). When a read or write returns `EAGAIN` or `EWOULDBLOCK`, the Go runtime registers the descriptor with the OS netpoller (`epoll` on Linux, `kqueue` on macOS/BSD) and puts the calling goroutine to sleep without blocking the OS thread ($M$).

When using raw syscalls (`syscall.RawConn` or raw file descriptors via `os.NewFile`):
- Direct `syscall.Read` or `syscall.Recvfrom` calls will **block the OS worker thread** ($M$), causing the runtime scheduler to spawn new $M$ threads (`sysmon` thread creation).
- Idiomatic Go security tools wrap raw descriptors in `os.NewFile(uintptr(fd), "raw-pcap")` and use `net.FilePacketConn` or `syscall.RawConn.Read(func(fd uintptr) bool { ... })`. This integrates raw socket descriptors into Go's non-blocking netpoller, allowing tens of thousands of packet handlers to run concurrently on minimal OS threads.

### 4. Linux Capabilities & Memory-Mapped Packet Rings (PACKET_MMAP)
Running recon binaries as `root` is a security anti-pattern. Modern Go tools leverage Linux capabilities:
```bash
# Grant packet capture and raw socket permissions without root execution
sudo setcap cap_net_raw,cap_net_admin=eip ./recon-prober
```
For ultra-high-speed packet ingestion (10GbE+ packet capture), Go tools integrate with `AF_PACKET` sockets configured with `PACKET_RX_RING` (`PACKET_MMAP`). The kernel writes incoming frames directly into a ring buffer shared with userspace memory (`mmap`), eliminating `recvmsg` syscall overhead and buffer copying entirely.

</UnderTheHood>

<Exercise n={1} title="Scope guard" level="easy">

Write `InScope(rawURL string, allow []string) bool` that parses the URL, lowercases the host, and returns true only if the host equals an allowed domain or is a subdomain (`"."+domain`). Prove it refuses the suffix trick `acme.test.evil.com` against scope `["acme.test"]`.

<Solution>

```go
package main

import (
	"fmt"
	"net/url"
	"strings"
)

func InScope(rawURL string, allow []string) bool {
	u, err := url.Parse(rawURL)
	if err != nil || u.Hostname() == "" {
		return false
	}
	host := strings.ToLower(u.Hostname())
	for _, a := range allow {
		a = strings.ToLower(a)
		if host == a || strings.HasSuffix(host, "."+a) {
			return true
		}
	}
	return false
}

func main() {
	scope := []string{"acme.test"}
	for _, t := range []string{"https://api.acme.test/x", "https://acme.test.evil.com/x", "https://evil.com/x"} {
		fmt.Printf("%-30s %v\n", t, InScope(t, scope))
	}
	// api.acme.test true, acme.test.evil.com false, evil.com false
}
```

<Exercise n={3} title="Bounded worker pool" level="medium">

Write `probeAll(base string, paths []string, workers int) map[string]int` that probes every path against an in-process `httptest` server using a fixed worker pool, returning path→status. Use a `sync.WaitGroup` and a results channel; cap concurrency at `workers`.

<Solution>

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

func probeAll(base string, paths []string, workers int) map[string]int {
	client := &http.Client{Timeout: 5 * time.Second}
	jobs := make(chan string)
	type res struct {
		path string
		code int
	}
	out := make(chan res)

	var wg sync.WaitGroup
	for i := 0; i < workers; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for p := range jobs {
				resp, err := client.Get(base + p)
				code := 0
				if err == nil {
					code = resp.StatusCode
					resp.Body.Close()
				}
				out <- res{p, code}
			}
		}()
	}
	go func() { for _, p := range paths { jobs <- p }; close(jobs) }()
	go func() { wg.Wait(); close(out) }()

	m := map[string]int{}
	for r := range out {
		m[r.path] = r.code
	}
	return m
}

func main() {
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path == "/ok" {
			w.WriteHeader(200)
			return
		}
		w.WriteHeader(404)
	}))
	defer srv.Close()

	m := probeAll(srv.URL, []string{"/ok", "/nope", "/ok"}, 3)
	fmt.Println("/ok =", m["/ok"], "  /nope =", m["/nope"])
}
```

The fixed worker count is the concurrency cap; closing `jobs` ends the workers, and the `WaitGroup`-then-`close(out)` goroutine ends the drain without a send-on-closed panic.

</Solution>

<Exercise n={4} title="Token-bucket pacing" level="medium">

Build a `Bucket` with `Take()` backed by a buffered channel pre-filled to capacity and refilled by a `time.Ticker`. Show that the first `size` calls return immediately and later calls are paced to the refill interval.

<Solution>

```go
package main

import (
	"fmt"
	"time"
)

type Bucket struct{ tokens chan struct{} }

func NewBucket(size int, refill time.Duration) *Bucket {
	b := &Bucket{tokens: make(chan struct{}, size)}
	for i := 0; i < size; i++ {
		b.tokens <- struct{}{}
	}
	go func() {
		t := time.NewTicker(refill)
		for range t.C {
			select {
			case b.tokens <- struct{}{}:
			default:
			}
		}
	}()
	return b
}

func (b *Bucket) Take() { <-b.tokens }

func main() {
	b := NewBucket(2, 40*time.Millisecond)
	start := time.Now()
	for i := 1; i <= 5; i++ {
		b.Take()
		fmt.Printf("take %d @ %dms\n", i, time.Since(start).Milliseconds())
	}
}
```

The first two takes drain the pre-fill instantly; the next three each wait for a ticker token, so they land roughly 40ms apart. Burst capacity = buffer size; long-run rate = refill rate.

```go
			return
		}
		owner, ok := docs[r.URL.Path[1:]]
		if !ok || owner != u {
			w.WriteHeader(404)
			return
		}
		w.WriteHeader(200)
	})
	srv := httptest.NewServer(h)
	defer srv.Close()

	cases := []Case{
		{"alice", "/d1", 200},
		{"bob", "/d1", 404}, // two-user test
		{"", "/d1", 401},
	}
	fmt.Printf("%d/%d pass\n", runMatrix(srv.URL, cases), len(cases))
}
```

The `bob → /d1 → 404` row is the two-user test. Flip the handler's `owner != u` check off and that row prints MISMATCH (got 200) — the tool catching the IDOR.

</Solution>

<Recap>

- **Go is the recon toolchain's language** — nuclei, httpx, subfinder, ffuf and the rest are all Go — because goroutines make bounded concurrency trivial, a single static binary cross-compiles anywhere, and `net/http` + `httptest` are in the standard library. Use Go for tools you keep; Python for throwaway PoCs.
- **The scope guard comes first.** An allow-list (default deny) that every probe routes through, matching the apex and true subdomains (`"."+domain` defeats the `acme.test.evil.com` suffix trick). It makes touching an unauthorized host a structural impossibility, not a matter of discipline — the ethical default and good engineering at once.
- **A bounded worker pool** is the prober engine: a fixed set of goroutines ranging a jobs channel caps concurrency; close `jobs` to end the workers, `WaitGroup`-then-`close(results)` to end the drain. Always a timeout client, always close response bodies.
- **A token bucket** paces requests per second — a buffered channel pre-filled for bursts, refilled by a ticker, drained by a blocking `Take()`. Reach for `golang.org/x/time/rate` in production.
- **Classification turns a flood into a triage list** — bucket every response by status (accessible / protected / missing / errored) and flag bodies that leak internals (panic traces, bucket names, SQL errors). Surface the few rows worth a human's attention.
- **The authz-matrix fuzzer is the one to ship.** It automates the two-user test — every (actor × endpoint) cell with an expected allow/deny, driven as real requests, the cross-principal deny rows catching BOLA, leaky lists, and cross-tenant access. Point it at your own service in CI and a missing ownership check fails the build instead of leaking the data.
