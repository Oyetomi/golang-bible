<Define term="Binary heap (min-heap / max-heap, array-backed)">
A **binary heap** is a complete binary tree stored as a plain flat array — no nodes, no pointers. Every element lives at an index; parent–child relationships are pure arithmetic (`parent = (i−1)/2`, `children = 2i+1` and `2i+2`). A **min-heap** puts the smallest value at index 0; a **max-heap** puts the largest. You choose which by flipping the `Less` comparison. If you get this wrong in production you dispatch the *lowest*-priority payment first — the opposite of what you want.
</Define>

<Define term="The heap property">
At every node `i`, the parent's value compares favorably to both children's values. In a min-heap: `parent ≤ left_child` AND `parent ≤ right_child`. This is a **local** guarantee at every edge — siblings and cousins are unordered. That locality is what makes inserts O(log n): you only walk one root-to-leaf path, not the whole structure.
</Define>

<Define term="Sift-up / sift-down">
The two repair operations that restore the heap property after mutation. **Sift-up** runs after an insert: the new element is appended at the end, then swapped with its parent repeatedly until it's no longer smaller (in a min-heap) than the parent, or it reaches the root — O(log n) swaps upward. **Sift-down** runs after extracting the root: the last element is moved to the root, then swapped with the *smaller* child repeatedly until both children are larger — O(log n) swaps downward. Every `heap.Push` and `heap.Pop` in Go's standard library is built from exactly these two operations.
</Define>

<Define term={"`container/heap` — the clunky interface"} since="this chapter">
Go's `container/heap` package provides heap logic but owns **no storage**. You hand it a slice that implements `heap.Interface` — five methods: `Len`, `Less`, `Swap` (from `sort.Interface`), plus `Push` (append to slice) and `Pop` (remove from slice tail). The package calls your methods and handles the sift-up/sift-down arithmetic. It predates generics (Go 1.0, 2011) and uses `any` for `Push`/`Pop` — hence the boilerplate. On the job: if you forget to nil out the last element in `Pop`, you leak memory in long-running services. The `old[n-1] = nil` line in struct heaps is not optional.
</Define>

<Define term="Priority queue">
A data structure that always gives you the element with the highest (or lowest) priority next, regardless of insertion order. A heap is the canonical O(log n) implementation: `Push` inserts in O(log n), `Pop` removes the top priority in O(log n), and *peeking* at the top is O(1). Meridian uses a priority queue whenever order of processing matters — settlement jobs before reconciliation jobs, fraud-flagged transfers ahead of routine ones. Without a priority queue you'd sort the entire job list on every new arrival: O(n log n) instead of O(log n).
</Define>

## The Heap Property & Array Representation

Here's the thing, sport: every heap tutorial shows you a picture of a tree. Then they show you an array. Then they tell you the tree *is* the array. And somehow, most people leave still uncertain why.

Let me fix that in three steps.

### Step 1: the heap property

A **binary heap** satisfies one invariant at every node: a parent's value compares favorably to both its children. There are two flavors:

- **Min-heap**: every parent ≤ both children. The *smallest* value sits at the root (index 0). `heap.Pop` always gives you the minimum.
- **Max-heap**: every parent ≥ both children. The *largest* value sits at the root. Flip the comparison in `Less` to turn a min-heap into a max-heap.

The invariant does *not* say anything about ordering between siblings or cousins. That's the key: it's a local guarantee enforced at every parent-child edge, not a global sort. This is precisely why heaps are fast — maintaining a global sort takes O(n log n); maintaining the heap property on one new element takes O(log n).

### Step 2: the array representation

A complete binary tree can be stored in a flat array with zero wasted space and zero pointers. For a node at index `i` (0-based):

```
parent(i)       = (i - 1) / 2
left_child(i)   = 2*i + 1
right_child(i)  = 2*i + 2
```

  <ConceptCard label="Root → index 0">The min (or max) of the entire heap. Peeking is O(1) — just read index 0. Extracting is O(log n).</ConceptCard>
  <ConceptCard label="Children at 2i+1, 2i+2">Given index i, left child lives at 2i+1 and right child at 2i+2. No pointers needed — pure arithmetic.</ConceptCard>
  <ConceptCard label="Parent at (i-1)/2">Integer division walks back up the tree. Sift-up uses this repeatedly to restore the property after an insert.</ConceptCard>
  <Gotcha>The array representation only works for a *complete* binary tree (all levels filled left-to-right). Heaps maintain completeness automatically because `Push` appends to the end and `Pop` swaps the root with the last element before shrinking.</Gotcha>
</ConceptGrid>

A seven-element min-heap in array form:

```
Array: [1, 3, 2, 7, 4, 5, 6]

Logical tree:
          1
        /   \
       3     2
      / \   / \
     7   4 5   6

parent(1=index 1) = (1-1)/2 = 0  → node 1
left_child(0)     = 2*0+1   = 1  → node 3
right_child(0)    = 2*0+2   = 2  → node 2
```

### Step 3: sift-up (after insert) and sift-down (after extract)

These two operations are the entire mechanism. Everything else — `Push`, `Pop`, `Fix` — is built from them.

**Sift-up** is used after inserting a new element at the end of the array. The new element may be smaller than its parent (in a min-heap), violating the heap property. We fix it by repeatedly swapping with the parent until the property is restored or we reach the root.

**Sift-down** is used after removing the root. The standard trick: move the *last* element to the root position (to keep the array compact), then sift it *down* — repeatedly swap with the smaller child until neither child is smaller.

<UnderTheHood title="Why O(log n) insert and O(1) peek?">

A complete binary tree with n nodes has height ⌊log₂ n⌋. Sift-up travels at most that many levels upward; sift-down travels at most that many levels downward. Each level is one comparison and one potential swap — constant work per level. Total: O(log n).

Peek (reading the minimum without removing it) is literally `h[0]` — O(1). The root is always the extreme element by the heap invariant.

**Heapify** (building a heap from an unordered array) runs in O(n) — not O(n log n) as you might expect. The trick: call sift-down from the last internal node down to the root. About half the nodes are leaves (needing zero sift-down work), a quarter need at most one swap, and so on. Summing the geometric series gives O(n). Go's `heap.Init` uses this exact approach — bottom-up sift-down — and has since `container/heap` shipped in Go 1.0.

The **Go runtime** representation (`container/heap`) owns no internal storage. You provide a slice that satisfies `heap.Interface`; the package's functions (`heap.Push`, `heap.Pop`, `heap.Fix`, `heap.Init`) mutate that slice in-place using the arithmetic index relationships above. There is no hidden tree node type. Your slice is the heap.

</UnderTheHood>

## container/heap in Practice

Go's `container/heap` is correct, efficient, and — I'll be direct — not pretty. You implement five methods. The package rewards correctness, not elegance. Let me show you exactly what it wants, then wrap it so you never have to look at the boilerplate again.

### The interface

```go
// container/heap requires your type to satisfy heap.Interface,
// which embeds sort.Interface.
type Interface interface {
    sort.Interface  // Len() int; Less(i, j int) bool; Swap(i, j int)
    Push(x any)     // append x to the underlying slice
    Pop() any       // remove and return the last element
}
```

There are five methods total: `Len`, `Less`, `Swap` (from `sort.Interface`), plus `Push` and `Pop`. The clunkiest part: `Push` and `Pop` operate on the *last* element of your slice, not the first. The package moves elements into position using `Swap` before calling `Pop`. You handle raw slice manipulation; the package handles the heap logic.

### A reusable min-heap of ints

```go
package main

import (
	"container/heap"
	"fmt"
)

// IntMinHeap is a min-heap of ints. Implements heap.Interface.
type IntMinHeap []int

func (h IntMinHeap) Len() int           { return len(h) }
func (h IntMinHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h IntMinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

// Push appends to the slice. Called by heap.Push after placing at end.
func (h *IntMinHeap) Push(x any) {
	*h = append(*h, x.(int))
}

// Pop removes and returns the last element. heap.Pop swaps
// root to last position before calling this.
func (h *IntMinHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

func main() {
	h := &IntMinHeap{5, 2, 8, 1, 9}
	heap.Init(h) // O(n) heapify — builds heap property in place

	heap.Push(h, 3)

	fmt.Println("min:", (*h)[0]) // O(1) peek at root

	for h.Len() > 0 {
		fmt.Printf("%d ", heap.Pop(h)) // extracts min each time
	}
	fmt.Println()
}
```

### A priority queue with custom priorities

Real interviews often demand a priority queue over structs. The pattern: embed the struct in a slice, implement `Less` based on the priority field.

```go
package main

import (
	"container/heap"
	"fmt"
)

// Item represents a task with a priority (higher = more urgent).
type Item struct {
	value    string
	priority int
}

// PriorityQueue is a max-heap ordered by priority.
type PriorityQueue []*Item

func (pq PriorityQueue) Len() int           { return len(pq) }
func (pq PriorityQueue) Less(i, j int) bool { return pq[i].priority > pq[j].priority }
func (pq PriorityQueue) Swap(i, j int)      { pq[i], pq[j] = pq[j], pq[i] }

func (pq *PriorityQueue) Push(x any) {
	*pq = append(*pq, x.(*Item))
}

func (pq *PriorityQueue) Pop() any {
	old := *pq
	n := len(old)
	item := old[n-1]
	old[n-1] = nil // avoid memory leak
	*pq = old[:n-1]
	return item
}

func main() {
	pq := &PriorityQueue{
		{value: "pay invoice", priority: 3},
		{value: "check balance", priority: 1},
		{value: "fraud alert", priority: 5},
		{value: "send report", priority: 2},
	}
	heap.Init(pq)

	heap.Push(pq, &Item{value: "reconcile accounts", priority: 4})

	for pq.Len() > 0 {
		item := heap.Pop(pq).(*Item)
		fmt.Printf("[p=%d] %s\n", item.priority, item.value)
	}
}
```

<UnderTheHood title="Why container/heap forces you to implement the interface">

`container/heap` predates Go generics (it was written in 2011 for Go 1.0 and has not changed structurally since). The `any` in `Push`/`Pop` is the pre-generics way of saying "I don't know what type you're storing." The package avoids generics to stay in stdlib without a major API break — changing it to `heap.Interface[T]` would break every existing implementation.

As of Go 1.24, the community idiom for a clean generic heap wrapper is to write a thin adapter yourself:

```go
// Generic min-heap adapter — wrap any ordered type.
type MinHeap[T any] struct {
    data []T
    less func(a, b T) bool
}

func (h *MinHeap[T]) Len() int           { return len(h.data) }
func (h *MinHeap[T]) Less(i, j int) bool { return h.less(h.data[i], h.data[j]) }
func (h *MinHeap[T]) Swap(i, j int)      { h.data[i], h.data[j] = h.data[j], h.data[i] }
func (h *MinHeap[T]) Push(x any)         { h.data = append(h.data, x.(T)) }
func (h *MinHeap[T]) Pop() any {
    old := h.data
    n := len(old)
    x := old[n-1]
    h.data = old[:n-1]
    return x
}
```

## Top-K Problems

The pattern: use a heap of size k. Stream elements through it. Maintain only what you need.

**Pattern name: Fixed-size heap (size k)**

- **K largest** from a stream of n: keep a *min-heap* of size k. When the heap exceeds k, pop the minimum. At the end, the heap contains the k largest. Complexity: O(n log k). Space: O(k).
- **K smallest** from a stream of n: keep a *max-heap* of size k. Pop the maximum when size > k. Same complexity.

Why a min-heap for k-largest? Because the *root* of the min-heap is the *smallest* of the k candidates. If a new element is larger than that minimum, it displaces it. You're always evicting the weakest competitor.

### K-largest elements

```go
package main

import (
	"container/heap"
	"fmt"
)

// IntMinHeap — same as Section 2.
type IntMinHeap []int

func (h IntMinHeap) Len() int           { return len(h) }
func (h IntMinHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h IntMinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *IntMinHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *IntMinHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// KLargest returns the k largest values in nums. O(n log k), O(k) space.
func KLargest(nums []int, k int) []int {
	h := &IntMinHeap{}
	heap.Init(h)

	for _, n := range nums {
		heap.Push(h, n)
		if h.Len() > k {
			heap.Pop(h) // evict the current smallest
		}
	}

	result := make([]int, h.Len())
	copy(result, *h)
	return result
}

func main() {
	nums := []int{3, 1, 5, 12, 2, 11, 7, 4, 8}
	fmt.Println("3 largest:", KLargest(nums, 3)) // [8 11 12] in heap order
}
```

### Top-K frequent elements

A classic: combine a frequency map with a heap of size k. This ties directly to the hashing chapter.

```go
package main

	"container/heap"
	"fmt"
)

	val   int
	freq  int
}

// FreqMinHeap: min-heap ordered by frequency (evict least frequent).
type FreqMinHeap []FreqItem

func (h FreqMinHeap) Len() int           { return len(h) }
func (h FreqMinHeap) Less(i, j int) bool { return h[i].freq < h[j].freq }
func (h FreqMinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// TopKFrequent returns the k most frequent elements. O(n log k).
func TopKFrequent(nums []int, k int) []int {
	freq := make(map[int]int)
	for _, n := range nums {
		freq[n]++
	}

	h := &FreqMinHeap{}
	heap.Init(h)

	for val, count := range freq {
		heap.Push(h, FreqItem{val, count})
		if h.Len() > k {
			heap.Pop(h) // evict least frequent
		}
	}

	result := make([]int, h.Len())
	for i := range result {
		result[i] = heap.Pop(h).(FreqItem).val
	}
	return result
}

func main() {
	nums := []int{1, 1, 1, 2, 2, 3}
	fmt.Println("top 2 frequent:", TopKFrequent(nums, 2)) // [1 2]
```

**Complexity summary for Top-K:**

| Approach | Time | Space | When to use |
|---|---|---|---|
| Sort then slice | O(n log n) | O(1) extra | n is small or k ≈ n |
| Min-heap of size k | O(n log k) | O(k) | Streaming / large n, small k |
| Quickselect | O(n) average | O(1) | k-th element only, not top-k list |

The heap approach shines when k ≪ n — for example, finding the top-100 stocks by volume out of 50,000 tickers.

**Common variations:**
- K-th largest element: same heap, just return `(*h)[0]` at the end (the root of the size-k min-heap)
- K closest points to origin: use a max-heap of size k, distance as priority
- Top-K frequent words: same as `TopKFrequent` but break ties lexicographically in `Less`

## Merge-K Sorted Lists

**Pattern name: K-way merge with a min-heap**

You have K sorted arrays (or linked lists). You want one sorted output. The naïve approach — flatten and sort — is O(N log N) where N is the total number of elements. The heap approach is O(N log K). When K ≪ N, that's a massive win.

**The insight**: maintain a min-heap containing exactly one element from each of the K lists — the *front* element. Each `Pop` gives you the globally smallest remaining element. Then push the *next* element from whichever list just donated the minimum.

### Merge-K sorted arrays

```go
package main

import (
	"container/heap"
	"fmt"
)

// Cursor points to one position in one of the K arrays.
type Cursor struct {
	val      int
	arrayIdx int // which array this cursor belongs to
	elemIdx  int // which element in that array
}

// CursorHeap is a min-heap of Cursors ordered by value.
type CursorHeap []Cursor

func (h CursorHeap) Len() int           { return len(h) }
func (h CursorHeap) Less(i, j int) bool { return h[i].val < h[j].val }
func (h CursorHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *CursorHeap) Push(x any)        { *h = append(*h, x.(Cursor)) }
func (h *CursorHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// MergeKSorted merges k sorted arrays into one sorted slice.
// Time: O(N log K) where N = total elements, K = number of arrays.
func MergeKSorted(arrays [][]int) []int {
	h := &CursorHeap{}
	heap.Init(h)

	// Seed with the first element of each array.
	for i, arr := range arrays {
		if len(arr) > 0 {
			heap.Push(h, Cursor{val: arr[0], arrayIdx: i, elemIdx: 0})
		}
	}

	var result []int
	for h.Len() > 0 {
		cur := heap.Pop(h).(Cursor)
		result = append(result, cur.val)

		// Advance the cursor into the same array.
		next := cur.elemIdx + 1
		if next < len(arrays[cur.arrayIdx]) {
			heap.Push(h, Cursor{
				val:      arrays[cur.arrayIdx][next],
				arrayIdx: cur.arrayIdx,
				elemIdx:  next,
			})
		}
	}
	return result
}

func main() {
	arrays := [][]int{
		{1, 4, 7},
		{2, 5, 8},
		{3, 6, 9},
	}
	fmt.Println(MergeKSorted(arrays)) // [1 2 3 4 5 6 7 8 9]
}
```

**The pattern in four sentences:**

1. Push the first element of every list into a min-heap along with a cursor (which list, which index).
2. Pop the global minimum. Append to output.
3. Advance that list's cursor by one. Push the next element from the same list into the heap (if it exists).
4. Repeat until the heap is empty.

The heap never holds more than K elements — one per list. Each of the N total elements does one push and one pop: O(N log K).

**Common variations:**
- Merge-K sorted *linked lists* (LeetCode 23): same algorithm; store `*ListNode` in the heap instead of a cursor struct
- Find the smallest range covering one element from each of K lists: add a max-tracker alongside the heap
- External sort (sorting a file larger than RAM): split into K sorted chunks on disk, merge-K them in streaming fashion

The heap is your answer every time. Once you see the pattern, you can't un-see it.

## Running Median

This is the interview problem that separates the "knows heaps" engineer from the "lives heaps" engineer. It is one of the most beautiful two-heap patterns ever devised.

**The problem**: numbers arrive one at a time in a stream. After each insertion, return the current median.

**Why it's hard**: a median is the middle value of a sorted sequence. Maintaining a fully sorted structure is O(log n) per insert but requires sorting, and you can't just binary-search an unsorted stream.

**The insight — two heaps as a balanced partition:**

Keep two heaps that partition all seen numbers at every moment:

- **`lo`**: a **max-heap** holding the smaller half of all numbers. Its root is the largest of the small numbers.
- **`hi`**: a **min-heap** holding the larger half. Its root is the smallest of the large numbers.

The invariant: `|lo.Len() - hi.Len()| ≤ 1`. When the sizes differ by at most 1, the median is:
- `lo.root` (if `lo` is larger)
- `hi.root` (if `hi` is larger)
- `(lo.root + hi.root) / 2` (if sizes are equal)

**Insertion algorithm:**

1. If the new number ≤ `lo.root`, push to `lo`. Otherwise push to `hi`.
2. Rebalance: if one heap exceeds the other by more than 1, pop from the larger and push to the smaller.

```go
package main

import (
	"container/heap"
	"fmt"
)

// MaxHeap for the lower half.
type MaxHeap []int

func (h MaxHeap) Len() int           { return len(h) }
func (h MaxHeap) Less(i, j int) bool { return h[i] > h[j] } // max at root
func (h MaxHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MaxHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *MaxHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// MinHeap for the upper half.
type MinHeap []int

func (h MinHeap) Len() int           { return len(h) }
func (h MinHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h MinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *MinHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// MedianFinder maintains a running median using two heaps.
type MedianFinder struct {
	lo *MaxHeap // lower half; max at root
	hi *MinHeap // upper half; min at root
}

func NewMedianFinder() *MedianFinder {
	lo, hi := &MaxHeap{}, &MinHeap{}
	heap.Init(lo)
	heap.Init(hi)
	return &MedianFinder{lo: lo, hi: hi}
}

func (mf *MedianFinder) AddNum(num int) {
	// Route to correct half.
	if mf.lo.Len() == 0 || num <= (*mf.lo)[0] {
		heap.Push(mf.lo, num)
	} else {
		heap.Push(mf.hi, num)
	}

	// Rebalance so sizes differ by at most 1.
	if mf.lo.Len() > mf.hi.Len()+1 {
		heap.Push(mf.hi, heap.Pop(mf.lo))
	} else if mf.hi.Len() > mf.lo.Len()+1 {
		heap.Push(mf.lo, heap.Pop(mf.hi))
	}
}

func (mf *MedianFinder) FindMedian() float64 {
	if mf.lo.Len() == mf.hi.Len() {
		return float64((*mf.lo)[0]+(*mf.hi)[0]) / 2.0
	}
	if mf.lo.Len() > mf.hi.Len() {
		return float64((*mf.lo)[0])
	}
	return float64((*mf.hi)[0])
}

func main() {
	mf := NewMedianFinder()
	for _, n := range []int{5, 15, 1, 3} {
		mf.AddNum(n)
		fmt.Printf("add %2d → median = %.1f\n", n, mf.FindMedian())
	}
}
```

<Exercise n={1} title="Kth Largest Element in a Stream" level="easy">

Design a class (struct in Go) that finds the k-th largest element in a stream. It is initialized with an integer `k` and an initial array of numbers. It has a method `Add(val int) int` that appends a number to the stream and returns the k-th largest element.

**Hint**: maintain a min-heap of size exactly k. The root is always the k-th largest.

<Solution>

```go
package main

import (
	"container/heap"
	"fmt"
)

type IntMinHeap []int

func (h IntMinHeap) Len() int           { return len(h) }
func (h IntMinHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h IntMinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *IntMinHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *IntMinHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

type KthLargest struct {
	k int
	h *IntMinHeap
}

func NewKthLargest(k int, nums []int) *KthLargest {
	h := &IntMinHeap{}
	heap.Init(h)
	kl := &KthLargest{k: k, h: h}
	for _, n := range nums {
		kl.Add(n)
	}
	return kl
}

func (kl *KthLargest) Add(val int) int {
	heap.Push(kl.h, val)
	for kl.h.Len() > kl.k {
		heap.Pop(kl.h)
	}
	return (*kl.h)[0]
}

func main() {
	kl := NewKthLargest(3, []int{4, 5, 8, 2})
	fmt.Println(kl.Add(3))  // 4
	fmt.Println(kl.Add(5))  // 5
	fmt.Println(kl.Add(10)) // 5
	fmt.Println(kl.Add(9))  // 8
	fmt.Println(kl.Add(4))  // 8
}
```

The min-heap always holds the k largest seen. Its root (minimum of those k) is the k-th largest overall. Every `Add` is O(log k).

</Solution>

</Exercise>

<Exercise n={2} title="Find K Closest Points to Origin" level="medium">

Given a list of points `[][2]int`, find the `k` closest to the origin `(0,0)`. Distance is Euclidean (but you can compare squared distances to avoid `math.Sqrt`).

**Pattern**: max-heap of size k, ordered by squared distance. Evict the farthest when size exceeds k.

<Solution>

```go
package main

import (
	"container/heap"
	"fmt"
)

type Point struct {
	x, y int
}

func (p Point) distSq() int { return p.x*p.x + p.y*p.y }

// MaxDistHeap: max-heap by squared distance (evict farthest).
type MaxDistHeap []Point

func (h MaxDistHeap) Len() int           { return len(h) }
func (h MaxDistHeap) Less(i, j int) bool { return h[i].distSq() > h[j].distSq() }
func (h MaxDistHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MaxDistHeap) Push(x any)        { *h = append(*h, x.(Point)) }
func (h *MaxDistHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

func KClosest(points [][2]int, k int) [][2]int {
	h := &MaxDistHeap{}
	heap.Init(h)
	for _, p := range points {
		heap.Push(h, Point{p[0], p[1]})
		if h.Len() > k {
			heap.Pop(h) // evict farthest
		}
	}
	result := make([][2]int, h.Len())
	for i, p := range *h {
		result[i] = [2]int{p.x, p.y}
	}
	return result
}

func main() {
	points := [][2]int{{1, 3}, {-2, 2}, {5, 8}, {0, 1}}
	fmt.Println(KClosest(points, 2)) // [[-2 2] [0 1]] (or any k=2 closest)
}
```

Squared distance avoids floating-point entirely. Time: O(n log k), space: O(k). Classic interview move.

</Solution>

</Exercise>

<Exercise n={3} title="Merge K Sorted Linked Lists" level="medium">

Given `k` sorted linked lists, merge them into one sorted list. Use the K-way merge pattern with a min-heap.

```go
// ListNode is a standard singly-linked list node.
type ListNode struct {
	Val  int
	Next *ListNode
}
```

<Solution>

```go
package main

import (
	"container/heap"
	"fmt"
)

type ListNode struct {
	Val  int
	Next *ListNode
}

type NodeHeap []*ListNode

func (h NodeHeap) Len() int           { return len(h) }
func (h NodeHeap) Less(i, j int) bool { return h[i].Val < h[j].Val }
func (h NodeHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *NodeHeap) Push(x any)        { *h = append(*h, x.(*ListNode)) }
func (h *NodeHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

func MergeKLists(lists []*ListNode) *ListNode {
	h := &NodeHeap{}
	heap.Init(h)
	for _, l := range lists {
		if l != nil {
			heap.Push(h, l)
		}
	}
	dummy := &ListNode{}
	cur := dummy
	for h.Len() > 0 {
		node := heap.Pop(h).(*ListNode)
		cur.Next = node
		cur = cur.Next
		if node.Next != nil {
			heap.Push(h, node.Next)
		}
	}
	return dummy.Next
}

func toSlice(head *ListNode) []int {
	var out []int
	for head != nil {
		out = append(out, head.Val)
		head = head.Next
	}
	return out
}

func makeList(vals []int) *ListNode {
	if len(vals) == 0 {
		return nil
	}
	head := &ListNode{Val: vals[0]}
	cur := head
	for _, v := range vals[1:] {
		cur.Next = &ListNode{Val: v}
		cur = cur.Next
	}
	return head
}

func main() {
	lists := []*ListNode{
		makeList([]int{1, 4, 5}),
		makeList([]int{1, 3, 4}),
		makeList([]int{2, 6}),
	}
	fmt.Println(toSlice(MergeKLists(lists))) // [1 1 2 3 4 4 5 6]
}
```

The heap stores actual `*ListNode` pointers. Advancing is `node.Next` — no index arithmetic needed. O(N log K) where N = total nodes.

</Solution>

</Exercise>

<Exercise n={4} title="Task Scheduler" level="hard">

You have a list of tasks (represented as characters, e.g. `["A","A","A","B","B","C"]`) and a cooldown `n`. Identical tasks must be separated by at least `n` intervals. Return the minimum number of intervals to finish all tasks (you may insert idle intervals).

**Hint**: a max-heap of frequencies drives the greedy choice — always execute the most frequent remaining task next.

<Solution>

```go
package main

import (
	"container/heap"
	"fmt"
)

type FreqMaxHeap []int

func (h FreqMaxHeap) Len() int           { return len(h) }
func (h FreqMaxHeap) Less(i, j int) bool { return h[i] > h[j] }
func (h FreqMaxHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *FreqMaxHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *FreqMaxHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

func LeastInterval(tasks []byte, n int) int {
	freq := make(map[byte]int)
	for _, t := range tasks {
		freq[t]++
	}

	h := &FreqMaxHeap{}
	for _, f := range freq {
		*h = append(*h, f)
	}
	heap.Init(h)

	time := 0
	for h.Len() > 0 {
		// Process up to n+1 tasks in one cycle.
		cycle := n + 1
		var temp []int
		for cycle > 0 && h.Len() > 0 {
			f := heap.Pop(h).(int)
			if f > 1 {
				temp = append(temp, f-1)
			}
			cycle--
			time++
		}
		for _, f := range temp {
			heap.Push(h, f)
		}
		// If heap is non-empty, we still had idle slots.
		if h.Len() > 0 {
			time += cycle // idle intervals
		}
	}
	return time
}

func main() {
	fmt.Println(LeastInterval([]byte("AAABBC"), 2))  // 8
	fmt.Println(LeastInterval([]byte("AAAABBBC"), 3)) // 10
}
```

Greedy + max-heap: each "cycle" of n+1 slots runs the most-frequent tasks first. Any leftover slots are idle. Time: O(N log U) where U = unique task types ≤ 26.

</Solution>

</Exercise>

<Exercise n={5} title="Sliding Window Median" level="hard">

Given an array of integers and window size `k`, return the median of each window as it slides from left to right. Use two heaps with lazy deletion.

**Pattern**: maintain `lo` (max-heap) and `hi` (min-heap) as in the running median, but also track elements that have been "logically deleted" (slid out of the window) in a `map[int]int`. On each rebalance step, skip over deleted elements at the tops of the heaps.

<Solution>

```go
package main

import (
	"container/heap"
	"fmt"
)

type MaxH []int
func (h MaxH) Len() int           { return len(h) }
func (h MaxH) Less(i, j int) bool { return h[i] > h[j] }
func (h MaxH) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MaxH) Push(x any)        { *h = append(*h, x.(int)) }
func (h *MaxH) Pop() any          { old := *h; n := len(old); x := old[n-1]; *h = old[:n-1]; return x }

type MinH []int
func (h MinH) Len() int           { return len(h) }
func (h MinH) Less(i, j int) bool { return h[i] < h[j] }
func (h MinH) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MinH) Push(x any)        { *h = append(*h, x.(int)) }
func (h *MinH) Pop() any          { old := *h; n := len(old); x := old[n-1]; *h = old[:n-1]; return x }

func medianSlidingWindow(nums []int, k int) []float64 {
	deleted := make(map[int]int)
	lo, hi := &MaxH{}, &MinH{}
	heap.Init(lo)
	heap.Init(hi)

	// Prune top of lo/hi that have been deleted.
	pruneMax := func() {
		for lo.Len() > 0 && deleted[(*lo)[0]] > 0 {
			deleted[(*lo)[0]]--
			heap.Pop(lo)
		}
	}
	pruneMin := func() {
		for hi.Len() > 0 && deleted[(*hi)[0]] > 0 {
			deleted[(*hi)[0]]--
			heap.Pop(hi)
		}
	}

	// Seed first window.
	for i := 0; i < k; i++ {
		heap.Push(lo, nums[i])
	}
	// Move top k/2 to hi.
	for i := 0; i < k/2; i++ {
		heap.Push(hi, heap.Pop(lo))
	}

	getMedian := func() float64 {
		if k%2 == 1 {
			return float64((*lo)[0])
		}
		return float64((*lo)[0]+(*hi)[0]) / 2.0
	}

	result := []float64{getMedian()}

	for i := k; i < len(nums); i++ {
		out := nums[i-k]
		in := nums[i]
		deleted[out]++

		if in <= (*lo)[0] {
			heap.Push(lo, in)
		} else {
			heap.Push(hi, in)
		}

		// Rebalance after lazy deletion changes effective sizes.
		loSz := lo.Len() - deleted[(*lo)[0]] // approximate; prune for exact
		hiSz := hi.Len()
		_ = loSz
		_ = hiSz

		// Simple rebalance via prune-then-transfer.
		pruneMax()
		pruneMin()
		for lo.Len() > hi.Len()+1 {
			heap.Push(hi, heap.Pop(lo))
			pruneMax()
		}
		for hi.Len() > lo.Len() {
			heap.Push(lo, heap.Pop(hi))
			pruneMin()
		}
		pruneMax()
		pruneMin()

		result = append(result, getMedian())
	}
	return result
}

func main() {
	fmt.Println(medianSlidingWindow([]int{1, 3, -1, -3, 5, 3, 6, 7}, 3))
	// [1 -1 -1 3 5 6]
}
```

Lazy deletion avoids O(n) linear scans to remove an element. The deleted map tracks what should be skipped; pruning cleans the heap tops before reading. Time: O(n log k).

</Solution>

</Exercise>

<Recap>

- A **binary heap** is a complete binary tree stored as a flat array. For node at index `i`: parent at `(i-1)/2`, children at `2i+1` and `2i+2`. No pointers — pure arithmetic.
- **Min-heap property**: every parent ≤ its children. Root = minimum. **Max-heap**: flip `Less` to `>`.
- **Sift-up** (after insert): compare new element to parent, swap upward until heap property holds. O(log n).
- **Sift-down** (after extract): move last element to root, swap downward with smaller child. O(log n). **Peek** is always O(1).
- **`container/heap`** owns no storage — you implement five methods (`Len/Less/Swap/Push/Pop`) on your slice type. `Push` appends; `Pop` cuts the last element (the package does the swapping). It's clunky, it's correct.
- **Top-K pattern**: min-heap of size k for k-largest; max-heap of size k for k-smallest. O(n log k) time, O(k) space. The root of the heap is always the k-th element.
- **Merge-K pattern**: min-heap of K cursors (one per list). Pop the global minimum, advance that list's cursor, push its next element. O(N log K).
- **Running median**: max-heap `lo` (lower half) + min-heap `hi` (upper half), kept within 1 of each other in size. Median readable from roots in O(1). Each insert is O(log n).

</Recap>
