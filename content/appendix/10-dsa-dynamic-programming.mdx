## The DP Mindset

Here is the truth about dynamic programming that nobody tells you upfront, because they're afraid it'll sound too simple: **DP is just recursion — but you refuse to recompute what you've already solved.**

That's it. The rest is engineering discipline around *how* you store the answers and *which order* you compute them in.

### Two conditions: know them cold

Before you write a single line of DP code, you must confirm two things about the problem:

<Define term="Overlapping subproblems">
The same subproblem — the same input to the same recursive call — is solved **more than once** in the naive recursion tree. For Fibonacci: `fib(3)` appears as a subtree under both `fib(5)` and `fib(4)`. That redundancy is what caching eliminates. If every subproblem is unique, divide-and-conquer (merge sort, binary search) is sufficient — DP adds no benefit.
</Define>

<Define term="Optimal substructure">
The **optimal solution to the whole problem can be constructed from optimal solutions to its subproblems**. For shortest path: the optimal route from A to C through B requires the optimal route from A to B. Without this property, a locally optimal sub-answer doesn't help you globally — DP gives the wrong answer or no speedup. Greedy algorithms also require optimal substructure, but without the overlap condition.
</Define>

Both must hold. Miss either one and DP gives you the wrong answer, or no speedup at all.

### Fibonacci: the gateway drug

The simplest example of both conditions is Fibonacci. You've seen it a hundred times. See it again — *this time, watch the computation tree.*

```go
func fib(n int) int {
	if n <= 1 {
		return n
	}
	return fib(n-1) + fib(n-2)
}
```

The two approaches to eliminating that waste are **memoization** (top-down: cache as you recurse) and **tabulation** (bottom-up: build the table iteratively). We'll cover both in depth. First, the repeatable method for *deriving* the recurrence — because that's the hardest part and nobody teaches it properly.

<Define term="Memoization (top-down DP)">
You write the **natural recursion** and add a cache — typically a `map` in Go. On each call, check the cache first; if there's a hit, return the stored answer. If not, compute it, store it, return it. The recursion tree still exists conceptually, but each unique subproblem is computed exactly once. Downside: function-call overhead, potential stack depth, and the cache lookup constant. Upside: you only compute the states you actually reach — useful when the state space is sparse.
</Define>

<Define term="Tabulation (bottom-up DP)">
You fill a **table iteratively**, starting from the base cases and working toward the answer. No recursion, no call stack. Each cell is filled exactly once, in an order that guarantees its dependencies are already filled. Faster constant factor than memoization in practice, no stack-overflow risk on large inputs, and easier to apply space optimizations (rolling array). The trade-off: you must figure out the correct fill order upfront, and you may compute states you never needed.
</Define>

<Define term="State, transition, and recurrence">
The **state** is what `dp[i]` (or `dp[i][j]`) *means* in English — "the minimum coins to make amount `i`," "the LCS length of `s[0..i-1]` and `t[0..j-1]`." The **transition** (also called the **recurrence relation**) expresses the current state as a function of strictly smaller states: `dp[i] = min(dp[i-c] + 1)`. The **base cases** are the cells filled before the loop — they don't depend on any other cell. Getting the state definition wrong makes the recurrence wrong; spend the majority of your thinking here before writing any code.
</Define>

### How to derive any recurrence (the repeatable method)

Every DP problem yields to the same four questions asked in order:

1. **Define the state.** What does `dp[i]` (or `dp[i][j]`) *mean*? Write it in English. "The minimum number of coins to make amount `i`." If you can't say it in one sentence, your state is wrong.
2. **Ask: what's the last decision?** For each state, think about the last choice made to reach it. For coin change: "the last coin added was denomination `c`."
3. **Write the transition.** Express the current state as a function of smaller states: `dp[i] = min(dp[i-c] + 1)` for all valid `c`.
4. **Identify base cases and the answer.** Where does the table start (base case)? Where is your final answer (often `dp[n]` or `dp[m][n]`)?

Apply these four questions to every problem in this chapter. By the fifth time, it'll be automatic.

## Memoization (Top-Down)

Memoization is the easier first step. You write the natural recursion — the one that falls straight out of the recurrence — and then add a cache. When the function is called with the same arguments again, you return the stored answer instead of recomputing.

### Fibonacci with memoization

```go
package main

import "fmt"

func fibMemo(n int, memo map[int]int) int {
	if n <= 1 {
		return n
	}
	if v, ok := memo[n]; ok {
		return v // cache hit — O(1) lookup, skip the subtree
	}
	memo[n] = fibMemo(n-1, memo) + fibMemo(n-2, memo)
	return memo[n]
}

func main() {
	memo := make(map[int]int)
	fmt.Println(fibMemo(10, memo))  // 55
	fmt.Println(fibMemo(40, memo))  // 102334155 — instant
	fmt.Println(fibMemo(80, memo))  // 23416728348161920 — still instant
}
```

### Climbing stairs

**Problem:** You can climb 1 or 2 steps at a time. How many distinct ways to reach step `n`?

**State:** `dp[i]` = number of ways to reach step `i`.
**Last decision:** the last step taken was 1 or 2.
**Transition:** `dp[i] = dp[i-1] + dp[i-2]` (came from one step below or two steps below).
**Base cases:** `dp[0] = 1` (one way to be at ground), `dp[1] = 1`.

```go
package main

import "fmt"

func climbStairs(n int) int {
	memo := make(map[int]int)
	var climb func(i int) int
	climb = func(i int) int {
		if i <= 1 {
			return 1
		}
		if v, ok := memo[i]; ok {
			return v
		}
		memo[i] = climb(i-1) + climb(i-2)
		return memo[i]
	}
	return climb(n)
}

func main() {
	fmt.Println(climbStairs(2))  // 2
	fmt.Println(climbStairs(5))  // 8
	fmt.Println(climbStairs(10)) // 89
}
```

### House robber

**Problem:** Houses in a row, each with a value. You can't rob two adjacent houses. Maximize loot.

**State:** `dp[i]` = max loot from houses `0..i`.
**Last decision:** rob house `i` or skip it.
**Transition:** `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`.
**Base cases:** `dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`.

```go
package main

import "fmt"

func rob(nums []int) int {
	n := len(nums)
	if n == 0 {
		return 0
	}
	memo := make(map[int]int)
	var dp func(i int) int
	dp = func(i int) int {
		if i < 0 {
			return 0
		}
		if i == 0 {
			return nums[0]
		}
		if v, ok := memo[i]; ok {
			return v
		}
		// rob house i: add nums[i], skip i-1
		// skip house i: best of houses 0..i-1
		take := dp(i-2) + nums[i]
		skip := dp(i - 1)
		if take > skip {
			memo[i] = take
		} else {
			memo[i] = skip
		}
		return memo[i]
	}
	return dp(n - 1)
}

func main() {
	fmt.Println(rob([]int{1, 2, 3, 1}))         // 4
	fmt.Println(rob([]int{2, 7, 9, 3, 1}))       // 12
	fmt.Println(rob([]int{2, 1, 1, 2}))          // 4
}
```

<UnderTheHood title="Why memoization turns O(2ⁿ) into O(n)">

The naive recursion for Fibonacci creates a *binary tree* of calls. At depth `k`, there are up to `2ᵏ` nodes — hence `O(2ⁿ)` total. The key insight is that the **number of distinct inputs is tiny**: for `fib(n)`, there are only `n+1` distinct arguments (0 through n). Each unique argument is computed exactly once and stored. Every subsequent call with the same argument is a `map` lookup: O(1).

So the total work is: (number of distinct states) × (work per state, excluding recursive calls) = `n × O(1)` = **O(n)**.

This generalizes: if a problem has `S` distinct states and each state takes `T` work to compute (assuming child states are already cached), memoization costs `O(S × T)`. For 2-D DP, `S = m × n` states each taking O(1) to fill → O(m × n) total.

In Go (as of 1.24), a `map[int]int` lookup is O(1) amortized with small constant. For a slice-backed table it's a direct index → faster constant, which is why tabulation is often preferred when the state space is dense and bounded. The scheduler is not involved here — this is purely single-goroutine compute. The memoized closure captures the `memo` map directly; no goroutine overhead, no sync primitives needed unless you parallelize subproblems.

</UnderTheHood>

## Tabulation (Bottom-Up)

Tabulation flips memoization on its head. Instead of recursing down and caching on the way back up, you fill a table **from the base cases upward**, ensuring that when you compute `dp[i]`, every smaller state it depends on is already in the table.

**Advantages over memoization:**
- No function call overhead or call stack — iterative loops are faster in practice.
- No risk of stack overflow on large inputs (goroutine stacks start small and grow, but deep recursion still consumes stack memory).
- Easier to spot and apply space optimizations (rolling array — covered in Section 6).

**The discipline:** every tabulation solution needs four labeled components. Say them aloud:
1. **State** — what does `dp[i]` mean?
2. **Transition** — how does `dp[i]` depend on smaller indices?
3. **Base case** — what cells are filled before the loop starts?
4. **Answer location** — which cell holds the final answer?

### Fibonacci via tabulation

```go
package main

import "fmt"

func fibTab(n int) int {
	if n <= 1 {
		return n
	}
	dp := make([]int, n+1)
	dp[0] = 0 // base case
	dp[1] = 1 // base case
	for i := 2; i <= n; i++ {
		dp[i] = dp[i-1] + dp[i-2] // transition
	}
	return dp[n] // answer at dp[n]
}

func main() {
	fmt.Println(fibTab(10)) // 55
	fmt.Println(fibTab(40)) // 102334155
}
```

## 1-D DP Classics

These four problems appear repeatedly in interviews. Each follows the same derivation ritual.

### Coin change — minimum coins

**Problem:** Given coin denominations and a target amount, find the minimum number of coins to make that amount. Infinite supply of each denomination.

**State:** `dp[i]` = minimum coins to make amount `i`.
**Last decision:** the last coin added had denomination `c`.
**Transition:** `dp[i] = min(dp[i-c] + 1)` for all `c` in coins where `c <= i`.
**Base case:** `dp[0] = 0` (zero coins make zero amount).
**Answer:** `dp[amount]` (or -1 if unreachable).

```go
package main

import "fmt"

func coinChange(coins []int, amount int) int {
	const inf = 1<<31 - 1
	dp := make([]int, amount+1)
	for i := range dp {
		dp[i] = inf // initialize to "impossible"
	}
	dp[0] = 0 // base case: 0 coins for amount 0

	for i := 1; i <= amount; i++ {
		for _, c := range coins {
			if c <= i && dp[i-c] != inf {
				if dp[i-c]+1 < dp[i] {
					dp[i] = dp[i-c] + 1
				}
			}
		}
	}
	if dp[amount] == inf {
		return -1
	}
	return dp[amount]
}

func main() {
	fmt.Println(coinChange([]int{1, 5, 6, 9}, 11))  // 2 (5+6)
	fmt.Println(coinChange([]int{2}, 3))             // -1 (impossible)
	fmt.Println(coinChange([]int{1, 2, 5}, 11))      // 3 (5+5+1)
}
```

### Longest increasing subsequence

**Problem:** Given `nums`, find the length of the longest strictly increasing subsequence (need not be contiguous).

**State:** `dp[i]` = length of LIS ending at index `i`.
**Last decision:** which previous element `j` did we extend from.
**Transition:** `dp[i] = max(dp[j] + 1)` for all `j < i` where `nums[j] < nums[i]`.
**Base case:** `dp[i] = 1` (every element is an LIS of length 1 by itself).
**Answer:** `max(dp[0..n-1])`.

```go
package main

import "fmt"

func lengthOfLIS(nums []int) int {
	n := len(nums)
	if n == 0 {
		return 0
	}
	dp := make([]int, n)
	for i := range dp {
		dp[i] = 1 // base case: every element is its own LIS
	}
	best := 1
	for i := 1; i < n; i++ {
		for j := 0; j < i; j++ {
			if nums[j] < nums[i] && dp[j]+1 > dp[i] {
				dp[i] = dp[j] + 1
			}
		}
		if dp[i] > best {
			best = dp[i]
		}
	}
	return best
}

func main() {
	fmt.Println(lengthOfLIS([]int{10, 9, 2, 5, 3, 7, 101, 18})) // 4 → [2,3,7,18]
	fmt.Println(lengthOfLIS([]int{0, 1, 0, 3, 2, 3}))           // 4
	fmt.Println(lengthOfLIS([]int{7, 7, 7, 7}))                 // 1
}
```

### Decode ways

**Problem:** A string of digits (`"12"` = 'AB', `"1"` = 'A', `"26"` = 'Z'). Count the number of ways to decode it.

**State:** `dp[i]` = number of ways to decode the first `i` characters.
**Transition:** `dp[i] += dp[i-1]` if `s[i-1]` is a valid single-digit decode ('1'-'9'); `dp[i] += dp[i-2]` if `s[i-2:i]` is a valid two-digit decode ('10'-'26').
**Base cases:** `dp[0] = 1` (empty string, one way), `dp[1] = 1` if `s[0] != '0'` else `0`.

```go
package main

import "fmt"

func numDecodings(s string) int {
	n := len(s)
	dp := make([]int, n+1)
	dp[0] = 1
	if s[0] != '0' {
		dp[1] = 1
	}
	for i := 2; i <= n; i++ {
		// single digit: s[i-1] in '1'..'9'
		if s[i-1] != '0' {
			dp[i] += dp[i-1]
		}
		// two digits: s[i-2..i-1] in 10..26
		two := (int(s[i-2]-'0'))*10 + int(s[i-1]-'0')
		if two >= 10 && two <= 26 {
			dp[i] += dp[i-2]
		}
	}
	return dp[n]
}

func main() {
	fmt.Println(numDecodings("12"))    // 2 → [1,2] or [12]
	fmt.Println(numDecodings("226"))   // 3 → [2,2,6],[22,6],[2,26]
	fmt.Println(numDecodings("06"))    // 0 → invalid leading zero
}
```

## 2-D DP Classics

Here's where interviews separate the people who memorized a few problems from the people who actually understand the technique. 2-D DP has the same four-question framework — the table just has two dimensions.

### Unique paths on a grid

**Problem:** Robot starts at top-left of an `m × n` grid, can only move right or down. How many paths to bottom-right?

**State:** `dp[r][c]` = number of paths from `(0,0)` to `(r,c)`.
**Transition:** `dp[r][c] = dp[r-1][c] + dp[r][c-1]` (arrived from above or from the left).
**Base cases:** entire top row and left column = 1 (only one way to reach any cell in those).
**Answer:** `dp[m-1][n-1]`.

```go
package main

import "fmt"

func uniquePaths(m, n int) int {
	dp := make([][]int, m)
	for i := range dp {
		dp[i] = make([]int, n)
	}
	// base cases: first row and first column are all 1
	for r := range m {
		dp[r][0] = 1
	}
	for c := range n {
		dp[0][c] = 1
	}
	for r := 1; r < m; r++ {
		for c := 1; c < n; c++ {
			dp[r][c] = dp[r-1][c] + dp[r][c-1]
		}
	}
	return dp[m-1][n-1]
}

func main() {
	fmt.Println(uniquePaths(3, 7)) // 28
	fmt.Println(uniquePaths(3, 2)) // 3
}
```

### Longest common subsequence (LCS)

**Problem:** Given strings `s` and `t`, find the length of their longest common subsequence (not necessarily contiguous).

**State:** `dp[i][j]` = LCS length of `s[0..i-1]` and `t[0..j-1]`.
**Transition:**
- If `s[i-1] == t[j-1]`: `dp[i][j] = dp[i-1][j-1] + 1` (last chars match, extend).
- Else: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])` (skip one char from either string).
**Base cases:** `dp[0][j] = 0` and `dp[i][0] = 0` (empty string has LCS 0 with anything).
**Answer:** `dp[m][n]`.

```go
package main

import "fmt"

func lcs(s, t string) int {
	m, n := len(s), len(t)
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}
	// base cases are zero — zero value is 0, already set
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if s[i-1] == t[j-1] {
				dp[i][j] = dp[i-1][j-1] + 1
			} else {
				dp[i][j] = max(dp[i-1][j], dp[i][j-1])
			}
		}
	}
	return dp[m][n]
}

func main() {
	fmt.Println(lcs("abcde", "ace"))     // 3 → "ace"
	fmt.Println(lcs("abc", "abc"))       // 3
	fmt.Println(lcs("abc", "def"))       // 0
	fmt.Println(lcs("AGGTAB", "GXTXAYB")) // 4 → "GTAB"
}
```

### Edit distance (Levenshtein)

**Problem:** Given words `s` and `t`, find the minimum number of operations (insert, delete, replace a single character) to transform `s` into `t`.

**State:** `dp[i][j]` = min operations to transform `s[0..i-1]` into `t[0..j-1]`.
**Transition:**
- If `s[i-1] == t[j-1]`: `dp[i][j] = dp[i-1][j-1]` (no operation needed).
- Else: `dp[i][j] = 1 + min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1])` (replace, delete from s, insert into s).
**Base cases:** `dp[i][0] = i` (delete all of `s`), `dp[0][j] = j` (insert all of `t`).
**Answer:** `dp[m][n]`.

```go
package main

import "fmt"

func editDistance(s, t string) int {
	m, n := len(s), len(t)
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}
	// base cases
	for i := range m + 1 {
		dp[i][0] = i
	}
	for j := range n + 1 {
		dp[0][j] = j
	}
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if s[i-1] == t[j-1] {
				dp[i][j] = dp[i-1][j-1]
			} else {
				dp[i][j] = 1 + min(dp[i-1][j-1], min(dp[i-1][j], dp[i][j-1]))
			}
		}
	}
	return dp[m][n]
}

func main() {
	fmt.Println(editDistance("horse", "ros"))     // 3
	fmt.Println(editDistance("intention", "execution")) // 5
	fmt.Println(editDistance("", "abc"))          // 3
	fmt.Println(editDistance("abc", "abc"))       // 0
}
```

### 0/1 Knapsack

**Problem:** Given `n` items, each with weight `w[i]` and value `v[i]`, and a knapsack capacity `W`. Pick items to maximize total value without exceeding capacity. Each item used at most once (0/1).

**State:** `dp[i][w]` = max value using items `0..i-1` with capacity `w`.
**Last decision:** include item `i-1` or exclude it.
**Transition:**
- Exclude: `dp[i][w] = dp[i-1][w]`.
- Include (if `weights[i-1] <= w`): `dp[i][w] = max(dp[i-1][w], dp[i-1][w-weights[i-1]] + values[i-1])`.
**Base cases:** `dp[0][w] = 0` (no items = zero value).
**Answer:** `dp[n][W]`.

```go
package main

import "fmt"

func knapsack(weights, values []int, capacity int) int {
	n := len(weights)
	// dp[i][w] = max value with first i items, capacity w
	dp := make([][]int, n+1)
	for i := range dp {
		dp[i] = make([]int, capacity+1)
	}
	for i := 1; i <= n; i++ {
		wi, vi := weights[i-1], values[i-1]
		for w := range capacity + 1 {
			dp[i][w] = dp[i-1][w] // exclude item i
			if wi <= w && dp[i-1][w-wi]+vi > dp[i][w] {
				dp[i][w] = dp[i-1][w-wi] + vi // include item i
			}
		}
	}
	return dp[n][capacity]
}

func main() {
	weights := []int{2, 3, 4, 5}
	values := []int{3, 4, 5, 6}
	fmt.Println(knapsack(weights, values, 8)) // 10 (items 0,1,2: 2+3+4=9 weight, 3+4+5=12? no)
	// Let's verify: items 0+3: weight=7, value=9. Items 1+2: weight=7, value=9. Items 0+1+nothing more=5w,7v. Items 0+2=6w,8v. Items 1+3=8w,10v ← best
	fmt.Println(knapsack([]int{1, 2, 3}, []int{6, 10, 12}, 5)) // 22 (items 1+2: w=5,v=22)
}
```

## Space Optimization

If you got through Section 5, you know DP. This section is what makes you *dangerous*: most 2-D DP tables can be reduced to a 1-D array, cutting space from O(m × n) to O(n). Interviewers love asking for this as a follow-up.

The key observation: for most 2-D DP problems, `dp[i][j]` depends only on the previous row (`dp[i-1][...]`) and/or the current row (`dp[i][j-1]`). You don't need to keep all `m` rows — just the current row and the previous row (or often just one row, overwritten carefully).

### Rolling array: unique paths (2-D → 1-D)

Original: `dp[r][c] = dp[r-1][c] + dp[r][c-1]`. Each cell depends on the row above and the cell immediately to the left. We need only the previous row.

```go
package main

import "fmt"

func uniquePathsOpt(m, n int) int {
	// 1-D rolling array: prev row → current row
	dp := make([]int, n)
	for i := range dp {
		dp[i] = 1 // base case: first row all 1s
	}
	for r := 1; r < m; r++ {
		// dp[0] stays 1 (left column always 1)
		for c := 1; c < n; c++ {
			// dp[c] currently holds dp[r-1][c] (from previous row)
			// dp[c-1] already updated in this row = dp[r][c-1]
			dp[c] = dp[c] + dp[c-1]
		}
	}
```

### Rolling array: LCS (2-D → 1-D)

LCS needs the diagonal element `dp[i-1][j-1]` as well. We preserve it using a temporary variable:

```go
package main

import "fmt"

func lcsOpt(s, t string) int {
	m, n := len(s), len(t)
	dp := make([]int, n+1) // represents dp[i][0..n]
	for i := 1; i <= m; i++ {
		prev := 0 // holds dp[i-1][j-1] before overwrite
		for j := 1; j <= n; j++ {
			tmp := dp[j] // save dp[i-1][j] before overwriting
			if s[i-1] == t[j-1] {
				dp[j] = prev + 1
			} else {
				dp[j] = max(dp[j], dp[j-1])
			}
			prev = tmp // prev is now dp[i-1][j] = dp[i][j-1]'s old diagonal
		}
	}
	return dp[n]
}

func main() {
	fmt.Println(lcsOpt("abcde", "ace"))   // 3
	fmt.Println(lcsOpt("AGGTAB", "GXTXAYB")) // 4
}
```

<UnderTheHood title="Why the inner loop direction matters: 0/1 vs. unbounded knapsack">

For 0/1 knapsack with a 1-D `dp` array of length `W+1`, the transition for item `i` is: `dp[w] = max(dp[w], dp[w-wi] + vi)`. The critical question is: after you update `dp[w]`, does `dp[w-wi]` still mean "without item `i`" or "possibly with item `i`"?

If you iterate `w` from `wi` to `W` (ascending), when you compute `dp[w]`, `dp[w-wi]` was already updated *in this same pass* — meaning it may already include item `i`. That gives the **unbounded knapsack** (each item can be used multiple times).

If you iterate `w` from `W` down to `wi` (descending), when you compute `dp[w]`, `dp[w-wi]` hasn't been updated yet in this pass — it still reflects the state without item `i`. That gives the **0/1 knapsack**.

This is a one-line difference that completely changes the semantics. The compiler gives you zero warning. The tests with small inputs often pass either way. This is exactly the kind of subtle correctness bug that kills you on a real coding interview or, worse, in a real scheduling or allocation system. Go 1.24's `range n` syntax makes the loop direction explicit — use it deliberately.

</UnderTheHood>

<Exercise n={1} title="Minimum path sum" level="easy">

Given an `m × n` grid of non-negative integers, find the path from top-left to bottom-right (moving only right or down) that minimizes the sum of all numbers along the path. Return that minimum sum.

**Example:** `grid = [[1,3,1],[1,5,1],[4,2,1]]` → 7 (path: 1→3→1→1→1).

Define the state and transition before you write any code.

<Solution>

**State:** `dp[r][c]` = minimum path sum to reach `(r,c)`.
**Transition:** `dp[r][c] = grid[r][c] + min(dp[r-1][c], dp[r][c-1])`.
**Base cases:** `dp[0][0] = grid[0][0]`, top row and left column fill by cumulative sum.

```go
package main

import "fmt"

func minPathSum(grid [][]int) int {
	m, n := len(grid), len(grid[0])
	dp := make([][]int, m)
	for i := range dp {
		dp[i] = make([]int, n)
	}
	dp[0][0] = grid[0][0]
	for c := 1; c < n; c++ {
		dp[0][c] = dp[0][c-1] + grid[0][c]
	}
	for r := 1; r < m; r++ {
		dp[r][0] = dp[r-1][0] + grid[r][0]
	}
	for r := 1; r < m; r++ {
		for c := 1; c < n; c++ {
			dp[r][c] = grid[r][c] + min(dp[r-1][c], dp[r][c-1])
		}
	}
	return dp[m-1][n-1]
}

func main() {
	grid := [][]int{{1, 3, 1}, {1, 5, 1}, {4, 2, 1}}
	fmt.Println(minPathSum(grid)) // 7
}
```

O(m × n) time, O(m × n) space. Optimize to O(n) with a rolling row if asked.

</Solution>

</Exercise>

<Exercise n={2} title="Coin change — count ways" level="medium">

Given coin denominations and a target `amount`, count the number of distinct combinations of coins that make exactly `amount`. Order does not matter (combinations, not permutations). Coins can be reused (unbounded). Return the count.

**Example:** `coins = [1,2,5], amount = 5` → 4 combinations: `[1,1,1,1,1]`, `[1,1,1,2]`, `[1,2,2]`, `[5]`.

<Solution>

**State:** `dp[i]` = number of combinations summing to `i`.
**Transition:** for each coin `c`, `dp[i] += dp[i-c]` (unbounded → iterate coins in outer loop, amounts in inner).
**Base case:** `dp[0] = 1`.

```go
package main

import "fmt"

func coinChangeWays(coins []int, amount int) int {
	dp := make([]int, amount+1)
	dp[0] = 1
	// outer loop on coins ensures combinations, not permutations
	for _, c := range coins {
		for i := c; i <= amount; i++ {
			dp[i] += dp[i-c]
		}
	}
	return dp[amount]
}

func main() {
	fmt.Println(coinChangeWays([]int{1, 2, 5}, 5)) // 4
	fmt.Println(coinChangeWays([]int{2}, 3))        // 0
}
```

The outer-coin, inner-amount order is the difference between combinations and permutations. Swap the loops and you get permutations (count ordered ways).

</Solution>

</Exercise>

<Exercise n={3} title="Edit distance — reconstruct the operations" level="medium">

Extend the edit distance solution to not just return the count, but also print the sequence of operations: `INSERT x`, `DELETE x`, `REPLACE x→y`, or `MATCH x`. Backtrack through the filled DP table.

<Solution>

Fill the table as before, then walk back from `dp[m][n]` to `dp[0][0]` following the arrows.

```go
package main

import "fmt"

func editOps(s, t string) {
	m, n := len(s), len(t)
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}
	for i := range m + 1 {
		dp[i][0] = i
	}
	for j := range n + 1 {
		dp[0][j] = j
	}
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if s[i-1] == t[j-1] {
				dp[i][j] = dp[i-1][j-1]
			} else {
				dp[i][j] = 1 + min(dp[i-1][j-1], min(dp[i-1][j], dp[i][j-1]))
			}
		}
	}

	// backtrack
	var ops []string
	i, j := m, n
	for i > 0 || j > 0 {
		if i > 0 && j > 0 && s[i-1] == t[j-1] {
			ops = append(ops, fmt.Sprintf("MATCH %c", s[i-1]))
			i--
			j--
		} else if i > 0 && j > 0 && dp[i][j] == dp[i-1][j-1]+1 {
			ops = append(ops, fmt.Sprintf("REPLACE %c→%c", s[i-1], t[j-1]))
			i--
			j--
		} else if i > 0 && dp[i][j] == dp[i-1][j]+1 {
			ops = append(ops, fmt.Sprintf("DELETE %c", s[i-1]))
			i--
		} else {
			ops = append(ops, fmt.Sprintf("INSERT %c", t[j-1]))
			j--
		}
	}
	// reverse ops (backtrack goes right-to-left)
	for k, l := 0, len(ops)-1; k < l; k, l = k+1, l-1 {
		ops[k], ops[l] = ops[l], ops[k]
	}
	for _, op := range ops {
		fmt.Println(op)
	}
}

func main() {
	editOps("horse", "ros")
}
```

</Solution>

</Exercise>

<Exercise n={4} title="Longest palindromic subsequence" level="hard">

Given a string `s`, return the length of the longest palindromic subsequence (subsequence that reads the same forwards and backwards).

**Hint:** The LPS of `s` is the LCS of `s` and its reverse.

**Example:** `s = "bbbab"` → 4 (`"bbbb"`).

<Solution>

```go
package main

import "fmt"

func longestPalindromeSubseq(s string) int {
	n := len(s)
	// Alternative: directly compute with dp[i][j] =
	// LPS of s[i..j]
	// dp[i][j] = dp[i+1][j-1] + 2 if s[i]==s[j]
	// dp[i][j] = max(dp[i+1][j], dp[i][j-1]) otherwise
	dp := make([][]int, n)
	for i := range dp {
		dp[i] = make([]int, n)
		dp[i][i] = 1 // single char is palindrome of length 1
	}
	// fill by increasing interval length
	for length := 2; length <= n; length++ {
		for i := 0; i <= n-length; i++ {
			j := i + length - 1
			if s[i] == s[j] {
				if length == 2 {
					dp[i][j] = 2
				} else {
					dp[i][j] = dp[i+1][j-1] + 2
				}
			} else {
				dp[i][j] = max(dp[i+1][j], dp[i][j-1])
			}
		}
	}
	return dp[0][n-1]
}

func main() {
	fmt.Println(longestPalindromeSubseq("bbbab")) // 4
	fmt.Println(longestPalindromeSubseq("cbbd"))  // 2
	fmt.Println(longestPalindromeSubseq("a"))     // 1
}
```

This is a 2-D DP on intervals. The state `dp[i][j]` covers the substring `s[i..j]`. Filling by interval length ensures smaller intervals are always ready when larger ones need them. O(n²) time and space.

</Solution>

</Exercise>

<Exercise n={5} title="Word break" level="hard">

Given a string `s` and a dictionary `wordDict`, determine if `s` can be segmented into a sequence of dictionary words (words may be reused).

**Example:** `s = "leetcode", wordDict = ["leet","code"]` → `true`.

<Solution>

**State:** `dp[i]` = true if `s[0..i-1]` can be segmented using words from the dictionary.
**Transition:** `dp[i] = true` if there exists `j < i` such that `dp[j] == true` and `s[j..i-1]` is in the dictionary.
**Base case:** `dp[0] = true` (empty string, trivially segmented).

```go
package main

import "fmt"

func wordBreak(s string, wordDict []string) bool {
	words := make(map[string]bool, len(wordDict))
	for _, w := range wordDict {
		words[w] = true
	}
	n := len(s)
	dp := make([]bool, n+1)
	dp[0] = true
	for i := 1; i <= n; i++ {
		for j := 0; j < i; j++ {
			if dp[j] && words[s[j:i]] {
				dp[i] = true
				break
			}
		}
	}
	return dp[n]
}

func main() {
	fmt.Println(wordBreak("leetcode", []string{"leet", "code"}))             // true
	fmt.Println(wordBreak("applepenapple", []string{"apple", "pen"}))        // true
	fmt.Println(wordBreak("catsandog", []string{"cats", "dog", "sand", "and", "cat"})) // false
}
```

O(n²) time, O(n) space. The `break` is an optimization: once we find a valid split at position `j`, no need to check further `j` values.

</Solution>

</Exercise>

<Recap>

- **DP = recursion + cache.** It applies when you have **overlapping subproblems** (same sub-input computed multiple times) and **optimal substructure** (optimal whole = built from optimal parts).
- **Derive the recurrence in four steps every time:** define the state (what does `dp[i]` mean?), ask what the last decision was, write the transition, identify base cases and answer location.
- **Memoization (top-down):** write the natural recursion, add a `map` cache. Each unique state computed once. Great first step.
- **Tabulation (bottom-up):** fill a table iteratively from base cases. No stack overhead, easier to space-optimize. Prefer it in production and in follow-up questions.
- **1-D DP classics:** coin change (min coins), LIS, house robber, decode ways. All follow the same recurrence discipline.
- **2-D DP classics:** unique paths (dependency: top + left), LCS (diagonal on match), edit distance (three neighbors for mismatch), 0/1 knapsack (previous row). Animate the table in your head before coding.
- **Space optimization:** if `dp[i][j]` depends only on the previous row, collapse to 1-D. For 0/1 knapsack, iterate capacity **backward**. For unbounded, iterate **forward**. The direction is not cosmetic — it changes correctness.
- **Go specifics:** `map[int]int` for memoization when the state space is sparse; `make([]int, n)` for tabulation when it's dense and bounded. `min`/`max` builtins (Go 1.21+) clean up transition code. Close over the memo map in a recursive closure; no need for a global.

</Recap>
