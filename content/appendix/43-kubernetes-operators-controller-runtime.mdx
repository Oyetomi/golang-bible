## Custom Resource Definitions & Kubebuilder

Kubernetes was designed from day one to be extensible. Rather than hardcoding every possible infrastructure abstraction into `k8s.io/api`, the API server allows you to register your own first-class endpoints using **Custom Resource Definitions (CRDs)**.

<Define term="Custom Resource Definition (CRD)">
A **Custom Resource Definition (CRD)** is an OpenAPI v3 schema registered with the Kubernetes API server under `apiextensions.k8s.io`. Once registered, the API server dynamically serves HTTP REST endpoints for your custom kind (e.g. `/apis/ledger.meridian.io/v1alpha1/namespaces/prod/ledgerdatabases/tx-store`), handling etcd persistence, client authentication, RBAC authorization, and schema validation.
</Define>

<Define term="Kubernetes Operator">
An **Operator** is a specialized controller pattern that pairs one or more Custom Resource Definitions with an automated Go control loop. The operator continuously tracks the custom resources, provisioning and managing complex stateful software (databases, queues, vaults) to match the declared specification.
</Define>

### Modeling Financial Infrastructure with Kubebuilder Markers

Writing raw OpenAPI v3 YAML specifications by hand is error-prone. In modern Go development, you define standard Go structs and annotate them with **Kubebuilder markers** (special `// +kubebuilder:...` comments). The `controller-gen` CLI tool then generates the exact YAML manifests, deep-copy functions (`zz_generated.deepcopy.go`), and validation rules.

Let's examine how Meridian defines the `LedgerDatabase` custom resource:

```go
package v1alpha1

import (
	metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"
)

// LedgerDatabaseSpec defines the desired state of LedgerDatabase.
type LedgerDatabaseSpec struct {
	// +kubebuilder:validation:Required
	// +kubebuilder:validation:Enum="15.4";"16.1";"16.2"
	// EngineVersion specifies the major.minor PostgreSQL release.
	EngineVersion string `json:"engineVersion"`

	// +kubebuilder:validation:Required
	// +kubebuilder:validation:Minimum=1
	// +kubebuilder:validation:Maximum=9
	// +kubebuilder:default=3
	// Replicas is the number of database pods in the replication quorum.
	Replicas int32 `json:"replicas"`

	// +kubebuilder:validation:Required
	// +kubebuilder:validation:Minimum=10
	// StorageGB is the persistent volume disk capacity per replica in gigabytes.
	StorageGB int32 `json:"storageGB"`

	// +kubebuilder:validation:Required
	// BackupSchedule is a cron expression for S3 WAL point-in-time archives.
	BackupSchedule string `json:"backupSchedule"`

	// +kubebuilder:validation:Required
	// VaultSecretRef is the name of the Kubernetes Secret containing HashiCorp Vault access tokens.
	VaultSecretRef string `json:"vaultSecretRef"`

	// +kubebuilder:default=true
	// HighAvailability enables synchronous multi-AZ replication.
	HighAvailability bool `json:"highAvailability"`
}

// LedgerDatabasePhase represents the operational lifecycle state of the database.
type LedgerDatabasePhase string

const (
	PhasePending      LedgerDatabasePhase = "Pending"
	PhaseProvisioning LedgerDatabasePhase = "Provisioning"
	PhaseReady        LedgerDatabasePhase = "Ready"
	PhaseDegraded     LedgerDatabasePhase = "Degraded"
	PhaseTerminating  LedgerDatabasePhase = "Terminating"
)

// LedgerDatabaseStatus defines the observed actual state of LedgerDatabase.
type LedgerDatabaseStatus struct {
	// ObservedGeneration reflects the metadata.generation of the spec most recently reconciled.
	ObservedGeneration int64 `json:"observedGeneration,omitempty"`

	// Phase summarizes the high-level health of the cluster.
	Phase LedgerDatabasePhase `json:"phase,omitempty"`

	// ActivePrimary is the pod DNS name of the current read-write primary node.
	ActivePrimary string `json:"activePrimary,omitempty"`

	// ReplicasReady is the number of active pods in sync with the primary WAL stream.
	ReplicasReady int32 `json:"replicasReady"`

	// Conditions represents detailed, standardized lifecycle assertions.
	// +patchMergeKey=type
	// +patchStrategy=merge
	// +listType=map
	// +listMapKey=type
	Conditions []metav1.Condition `json:"conditions,omitempty"`
}

// +kubebuilder:object:root=true
// +kubebuilder:subresource:status
// +kubebuilder:printcolumn:name="Version",type=string,JSONPath=`.spec.engineVersion`
// +kubebuilder:printcolumn:name="Replicas",type=integer,JSONPath=`.spec.replicas`
// +kubebuilder:printcolumn:name="Ready",type=integer,JSONPath=`.status.replicasReady`
// +kubebuilder:printcolumn:name="Phase",type=string,JSONPath=`.status.phase`
// +kubebuilder:printcolumn:name="Age",type=date,JSONPath=`.metadata.creationTimestamp`

// LedgerDatabase is the Schema for the ledgerdatabases API at Meridian.
type LedgerDatabase struct {
	metav1.TypeMeta   `json:",inline"`
	metav1.ObjectMeta `json:"metadata,omitempty"`

	Spec   LedgerDatabaseSpec   `json:"spec,omitempty"`
	Status LedgerDatabaseStatus `json:"status,omitempty"`
}

// +kubebuilder:object:root=true

// LedgerDatabaseList contains a list of LedgerDatabase.
type LedgerDatabaseList struct {
	metav1.TypeMeta `json:",inline"`
	metav1.ListMeta `json:"metadata,omitempty"`
	Items           []LedgerDatabase `json:"items"`
}
```

### The `/status` Subresource: Preventing Infinite Loops

Notice the marker `// +kubebuilder:subresource:status`. This is crucial.

In Kubernetes, enabling the `/status` subresource separates mutations to `spec` from mutations to `status`. When an end-user modifies `spec.replicas`, the API server increments `metadata.generation`. However, when your operator reconciles and updates `status.replicasReady` or `status.conditions`, the API server does **not** increment `metadata.generation`.

Without the `/status` subresource, every status update by the controller triggers a new reconciliation event on itself, generating a CPU-burning infinite reconciliation storm!

## The Reconciler Control Loop

The heart of every Kubernetes Operator is the **Reconciler**. A Reconciler does not respond to point-in-time RPC commands like `createPostgres()` or `scaleCluster()`. Instead, it implements a **level-triggered control loop**.

<Define term="Reconciler Control Loop">
A **Reconciler Control Loop** is a function with the signature `Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error)`. It is passed only a resource's `Namespace` and `Name`. It reads the desired state from the Custom Resource, queries the current state of the live cluster, calculates the delta, and executes minimal idempotent mutations to drive the cluster into alignment.
</Define>

<Define term="controller-runtime">
**`sigs.k8s.io/controller-runtime`** is the standard Go framework maintained by the Kubernetes SIGs for writing operators. It bundles client-go caching informers, workqueues, leader election, dynamic scheme registries, metrics exporters, and admission webhooks behind a unified Manager abstraction.
</Define>

<Define term="OwnerReference">
An **OwnerReference** is a metadata link on a child resource (e.g. a StatefulSet, Service, or ConfigMap) pointing to the parent Custom Resource. When the parent Custom Resource is deleted, the Kubernetes garbage collector automatically deletes all child resources containing its OwnerReference via cascading deletion.
</Define>

### Anatomy of `Reconcile(ctx, req)`

```go
package controller

import (
	"context"
	"fmt"
	"time"

	appsv1 "k8s.io/api/apps/v1"
	corev1 "k8s.io/api/core/v1"
	apierrors "k8s.io/apimachinery/pkg/api/errors"
	metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"
	"k8s.io/apimachinery/pkg/runtime"
	ctrl "sigs.k8s.io/controller-runtime"
	"sigs.k8s.io/controller-runtime/pkg/client"
	"sigs.k8s.io/controller-runtime/pkg/controller/controllerutil"
	"sigs.k8s.io/controller-runtime/pkg/log"

	ledgerv1alpha1 "github.com/meridian/ledger-operator/api/v1alpha1"
)

type LedgerDatabaseReconciler struct {
	client.Client
	Scheme *runtime.Scheme
}

func (r *LedgerDatabaseReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
	logger := log.FromContext(ctx)

	// 1. Fetch the custom resource from the local Informer cache
	var db ledgerv1alpha1.LedgerDatabase
	if err := r.Get(ctx, req.NamespacedName, &db); err != nil {
		if apierrors.IsNotFound(err) {
			// Object was deleted before reconcile executed. Return nil to drop from workqueue.
			logger.Info("LedgerDatabase resource not found. Ignoring since object must be deleted")
			return ctrl.Result{}, nil
		}
		// Transient cache or API server error. Requeue with exponential backoff.
		logger.Error(err, "Failed to get LedgerDatabase")
		return ctrl.Result{}, err
	}

	// 2. Handle Finalizers (discussed in next section)
	if !db.DeletionTimestamp.IsZero() {
		return r.handleDeletion(ctx, &db)
	}

	// 3. Reconcile Child ConfigMap (Database Configuration)
	if err := r.reconcileConfigMap(ctx, &db); err != nil {
		return ctrl.Result{}, err
	}

	// 4. Reconcile Child StatefulSet (Postgres Cluster)
	if err := r.reconcileStatefulSet(ctx, &db); err != nil {
		return ctrl.Result{}, err
	}

	// 5. Update Status Conditions & Phase
	if err := r.updateClusterStatus(ctx, &db); err != nil {
		return ctrl.Result{}, err
	}

	// 6. Return Result{}: Clean finish. Re-evaluate if watch fires or poll every 5m for drift.
	return ctrl.Result{RequeueAfter: 5 * time.Minute}, nil
}
```

### The 4 Return Signatures of `ctrl.Result`

When your `Reconcile` function completes, its return value tells `controller-runtime` exactly what to do next:

<ConceptGrid cols={3}>
  <ConceptCard label="1. ctrl.Result{}, nil">
    **Success & Idle.** The desired state matches actual state. Do not re-enqueue. Wait until the next Watch event occurs on the CRD or owned child resources.
  </ConceptCard>
  <ConceptCard label="2. ctrl.Result{}, err">
    **Error & Backoff.** A transient failure occurred (network glitch, 409 conflict, external API down). Controller-runtime places the key back in the workqueue with exponential backoff.
  </ConceptCard>
  <ConceptCard label="3. ctrl.Result{RequeueAfter: d}, nil">
    **Periodic Sync.** Success, but schedule a follow-up reconciliation in `d` duration (e.g. polling external AWS backup snapshots or verifying KMS key health).
  </ConceptCard>
</ConceptGrid>

Why doesn't a Kubernetes cluster running 50 operators melt the API server with millions of HTTP requests? The answer lies in the mechanical brilliance of **`client-go` Informers**:

```
                                                   ▼
 ┌──────────────┐   Thread-Safe Read Map    ┌─────────────┐

 └──────────────┘                           └─────────────┘
                                                   │ Event Handlers
                                                   ▼
                                            ┌─────────────┐
                                            │  Workqueue  │ (RateLimiting & Deduping)
                                            └──────┬──────┘
                                                   │
                                                   ▼
                                            ┌─────────────┐
                                            │ Reconcile() │ (Worker Goroutines)
                                            └─────────────┘
```

1. **The Reflector & ListAndWatch**: When your Operator starts, the Reflector issues a single HTTP `LIST` request to populate its memory baseline, followed by a persistent HTTP chunked streaming `WATCH` connection. Only delta change packets (`ADDED`, `MODIFIED`, `DELETED`) flow across the network.
2. **DeltaFIFO Queue**: The stream pushes change objects into a FIFO buffer called `DeltaFIFO`, which merges sequential events for the same object.
3. **Indexer / Local Cache**: The DeltaFIFO feeds an in-memory thread-safe cache (`Indexer`). When your controller calls `r.Get(ctx, req.NamespacedName, &db)`, **zero network I/O occurs**. It is an instant hash-map lookup from local RAM!
4. **Workqueue Deduplication**: If an object changes 100 times in 1 second, the Workqueue collapses all 100 change notifications into a **single key** (`prod/core-ledger-db`). Worker goroutines process the object once against its latest state.
5. **Optimistic Concurrency Control (OCC) & 409 Conflicts**: When writing back to the API server, Kubernetes compares `metadata.resourceVersion`. If another actor updated the object in etcd between your cache read and your write, the API server rejects the write with `HTTP 409 Conflict`. `controller-runtime` catches this, drops the stale state, re-enqueues the key, and retries cleanly.
6. **Go 1.25+ Container Limits**: As of Go 1.25, the Go runtime automatically detects cgroup CPU quotas in Kubernetes pods and sets `GOMAXPROCS` dynamically, eliminating thread thrashing in operator pods without third-party libraries.

</UnderTheHood>

## Finalizers & Resource Teardown

When an engineer runs `kubectl delete ledgerdatabase core-db`, Kubernetes default behavior is to immediately delete the object from etcd. If child pods are destroyed before external cloud dependencies are handled, **disaster strikes**:
1. Active PostgreSQL write transactions are killed abruptly without flushing WAL segments to AWS S3.
2. HashiCorp Vault encryption tokens and AWS IAM roles remain orphaned and active indefinitely.
3. High-availability DNS records point to dead IP addresses.

To prevent premature deletion and orchestrate clean teardown of external systems, Kubernetes provides **Finalizers**.

<Define term="Finalizer">
A **Finalizer** is a namespaced string key in `metadata.finalizers` (e.g. `ledger.meridian.io/finalizer`). When an object has at least one finalizer, the Kubernetes API server **refuses to delete the object from etcd**. Instead, it sets `metadata.deletionTimestamp` and allows controllers to perform asynchronous cleanup before stripping their finalizer key.
</Define>

### The Finalizer State Machine

```
               ┌──────────────────────────────┐
               │ Object Created (No Finalizer)│
               └──────────────┬───────────────┘
                              │ Reconcile adds finalizer
                              ▼
               ┌──────────────────────────────┐
               │ Finalizer Active in Metadata │ ◄── Normal Reconcile Operations
               └──────────────┬───────────────┘
                              │ User runs `kubectl delete`
                              ▼
               ┌──────────────────────────────┐
               │ DeletionTimestamp != nil     │
               └──────────────┬───────────────┘
                              │ Controller executes external teardown:
                              │ 1. Flush WAL logs to S3
                              │ 2. Revoke Vault KMS tokens
                              │ 3. Deregister Cloud DNS
                              ▼
               ┌──────────────────────────────┐
               │ Teardown Succeeded?          │
               └──────┬────────────────┬──────┘
                   No │                │ Yes
                      ▼                ▼
       ┌────────────────────────┐  ┌──────────────────────────────────────┐
       │ Return err & Requeue   │  │ Remove Finalizer string from metadata│
       │ (Object remains in k8s)│  └──────────────────┬───────────────────┘
       └────────────────────────┘                     │
                                                      ▼
                                   ┌──────────────────────────────────────┐
                                   │ etcd removes object permanently      │
                                   └──────────────────────────────────────┘
```

### Implementing Finalizers with `controllerutil`

```go
const ledgerFinalizer = "ledger.meridian.io/finalizer"

func (r *LedgerDatabaseReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
	var db ledgerv1alpha1.LedgerDatabase
	if err := r.Get(ctx, req.NamespacedName, &db); err != nil {
		return ctrl.Result{}, client.IgnoreNotFound(err)
	}

	// Examine DeletionTimestamp to determine if object is under deletion
	if db.ObjectMeta.DeletionTimestamp.IsZero() {
		// Object is NOT being deleted. Ensure our finalizer is registered.
		if !controllerutil.ContainsFinalizer(&db, ledgerFinalizer) {
			controllerutil.AddFinalizer(&db, ledgerFinalizer)
			if err := r.Update(ctx, &db); err != nil {
				return ctrl.Result{}, err
			}
		}
	} else {
		// Object IS being deleted!
		if controllerutil.ContainsFinalizer(&db, ledgerFinalizer) {
			// Execute external teardown logic
			if err := r.teardownExternalResources(ctx, &db); err != nil {
				// Teardown failed! Do NOT remove finalizer. Return err to retry.
				return ctrl.Result{}, fmt.Errorf("failed to finalize external resources: %w", err)
			}

			// Teardown succeeded. Remove finalizer so Kubernetes can delete object.
			controllerutil.RemoveFinalizer(&db, ledgerFinalizer)
			if err := r.Update(ctx, &db); err != nil {
				return ctrl.Result{}, err
			}
		}
		// Finalizer stripped or not present; stop reconciliation
		return ctrl.Result{}, nil
	}

	// Normal reconciliation continues...
	return r.reconcileActiveCluster(ctx, &db)
}
```

<Gotcha>
**The Fatal Teardown Trap:** Never remove the finalizer string if `teardownExternalResources()` returns an error! If you remove the finalizer on error, Kubernetes permanently removes the CR from etcd, leaving orphaned AWS S3 buckets, leaking KMS keys, and un-archived financial logs forever with no controller remaining to clean them up.
</Gotcha>

## Admission Webhooks & Event Recorders

Reconcilers operate *asynchronously* after an object has already been written to etcd. But what if a developer submits a manifest with a catastrophic flaw — such as trying to shrink a database volume from 500GB to 50GB (which PostgreSQL and EBS cannot do without data destruction) or disabling audit encryption?

To block invalid requests *before* they reach etcd, Kubernetes provides **Admission Webhooks**.

<Define term="Admission Webhook">
An **Admission Webhook** is an HTTP callback configured in Kubernetes (`admissionregistration.k8s.io`) that intercepts API server requests before persistence. **Mutating Webhooks** can modify objects (injecting defaults or sidecars), while **Validating Webhooks** can accept or reject requests with rich error messages.
</Define>

### Writing a Validating Webhook in Go

Using `controller-runtime`, you implement the `admission.CustomValidator` interface:

```go
package webhook

import (
	"context"
	"fmt"

	apierrors "k8s.io/apimachinery/pkg/api/errors"
	"k8s.io/apimachinery/pkg/runtime"
	"k8s.io/apimachinery/pkg/runtime/schema"
	"k8s.io/apimachinery/pkg/util/validation/field"
	ctrl "sigs.k8s.io/controller-runtime"
	"sigs.k8s.io/controller-runtime/pkg/webhook/admission"

	ledgerv1alpha1 "github.com/meridian/ledger-operator/api/v1alpha1"
)

type LedgerDatabaseCustomValidator struct{}

func (v *LedgerDatabaseCustomValidator) ValidateCreate(ctx context.Context, obj runtime.Object) (admission.Warnings, error) {
	db, ok := obj.(*ledgerv1alpha1.LedgerDatabase)
	if !ok {
		return nil, apierrors.NewBadRequest("expected LedgerDatabase object")
	}
	return nil, v.validate(db)
}

func (v *LedgerDatabaseCustomValidator) ValidateUpdate(ctx context.Context, oldObj, newObj runtime.Object) (admission.Warnings, error) {
	oldDB, ok1 := oldObj.(*ledgerv1alpha1.LedgerDatabase)
	newDB, ok2 := newObj.(*ledgerv1alpha1.LedgerDatabase)
	if !ok1 || !ok2 {
		return nil, apierrors.NewBadRequest("expected LedgerDatabase objects")
	}

	var allErrs field.ErrorList

	// Invariant 1: Storage can only grow, NEVER shrink
	if newDB.Spec.StorageGB < oldDB.Spec.StorageGB {
		allErrs = append(allErrs, field.Forbidden(
			field.NewPath("spec", "storageGB"),
			fmt.Sprintf("storage cannot be decreased from %dGB to %dGB (data loss hazard)",
				oldDB.Spec.StorageGB, newDB.Spec.StorageGB),
		))
	}

	// Invariant 2: Engine version cannot be downgraded
	if newDB.Spec.EngineVersion < oldDB.Spec.EngineVersion {
		allErrs = append(allErrs, field.Forbidden(
			field.NewPath("spec", "engineVersion"),
			"PostgreSQL major/minor version cannot be downgraded",
		))
	}

	if len(allErrs) > 0 {
		return nil, apierrors.NewInvalid(
			schema.GroupKind{Group: "ledger.meridian.io", Kind: "LedgerDatabase"},
			newDB.Name,
			allErrs,
		)
	}
	return nil, nil
}

func (v *LedgerDatabaseCustomValidator) ValidateDelete(ctx context.Context, obj runtime.Object) (admission.Warnings, error) {
	return nil, nil
}

func (v *LedgerDatabaseCustomValidator) validate(db *ledgerv1alpha1.LedgerDatabase) error {
	if db.Spec.HighAvailability && db.Spec.Replicas < 3 {
		return field.Invalid(
			field.NewPath("spec", "replicas"),
			db.Spec.Replicas,
			"HighAvailability mode requires at least 3 replicas for Raft/Sync quorum",
		)
	}
	return nil
}
```

```go
import (
	"fmt"
	"time"

type Spec struct {
	Replicas         int
	StorageGB        int
	HighAvailability bool

	Type               string
	Status             string
	Reason             string
	Message            string
	LastTransitionTime time.Time

	Conditions []Condition

func ValidateAndSetCondition(spec Spec, status *Status) error {

		setCond(status, "Validated", "False", "InsufficientStorage", "Storage must be >= 20GB")

			return fmt.Errorf("invalid HA replicas %d: must be odd number >= 3", spec.Replicas)

				Type:               cType,
				Status:             cStatus,
				Reason:             reason,
				Message:            msg,
				LastTransitionTime: time.Now().UTC(),
			}
			return
		}
	}
	status.Conditions = append(status.Conditions, Condition{
		Type:               cType,
		Status:             cStatus,
		Reason:             reason,
		Message:            msg,
		LastTransitionTime: time.Now().UTC(),
	})
}
```

```go
	updated.Spec.Env = make(map[string]string)
	for k, v := range current.Spec.Env {
		updated.Spec.Env[k] = v
	}

	// Compare replicas
	if current.Spec.Replicas != desired.Replicas {
		updated.Spec.Replicas = desired.Replicas
		needsUpdate = true
	}

	// Compare target image
	expectedImage := fmt.Sprintf("postgres:%s-alpine", desired.Version)
	if current.Spec.Image != expectedImage {
		updated.Spec.Image = expectedImage
		needsUpdate = true
	}

	// Compare Vault key env
	if current.Spec.Env["VAULT_SECRET_REF"] != desired.VaultKey {
		updated.Spec.Env["VAULT_SECRET_REF"] = desired.VaultKey
		needsUpdate = true
	}

}
```

Implement a complete finalizer teardown handler that cleans up an external S3 bucket and Vault lease.
```go
package main

import (
	"errors"
	"fmt"
	"slices"
	"time"
)

type CloudDriver interface {
	DeleteS3Bucket(bucket string) error
	RevokeVaultLease(leaseID string) error
}

type MockCloud struct {
	S3FailCount    int
	VaultFailCount int
}

func (m *MockCloud) DeleteS3Bucket(bucket string) error {
	if m.S3FailCount > 0 {
		m.S3FailCount--
		return errors.New("S3 503 Service Unavailable")
	}
	return nil
}

func (m *MockCloud) RevokeVaultLease(leaseID string) error {
	if m.VaultFailCount > 0 {
		m.VaultFailCount--
		return errors.New("Vault connection reset")
	}
	return nil
}

type Resource struct {
	Name       string
	Finalizers []string
	DeletedAt  *time.Time
	S3Bucket   string
	VaultLease string
}

func HandleTeardown(r *Resource, cloud CloudDriver, finalizer string) (requeue bool, err error) {
	if r.DeletedAt == nil {
		// Not being deleted
		return false, nil
	}

	if !slices.Contains(r.Finalizers, finalizer) {
		// Already finalized
		return false, nil
	}

	// 1. Teardown S3
	if err := cloud.DeleteS3Bucket(r.S3Bucket); err != nil {
		fmt.Printf("S3 deletion failed: %v -> Retaining finalizer and requeuing\n", err)
		return true, err
	}

	// 2. Teardown Vault
	if err := cloud.RevokeVaultLease(r.VaultLease); err != nil {
		fmt.Printf("Vault revocation failed: %v -> Retaining finalizer and requeuing\n", err)
		return true, err
	}

	// 3. Remove finalizer
	r.Finalizers = slices.DeleteFunc(r.Finalizers, func(f string) bool {
		return f == finalizer
	})
	fmt.Printf("Teardown complete for %s. Removed finalizer '%s'\n", r.Name, finalizer)
	return false, nil
}

func main() {
	cloud := &MockCloud{S3FailCount: 1, VaultFailCount: 1}
	now := time.Now().UTC()
	res := &Resource{
		Name:       "meridian-core-db",
		Finalizers: []string{"ledger.meridian.io/finalizer"},
		DeletedAt:  &now,
		S3Bucket:   "meridian-wal-tx-db",
		VaultLease: "lease-vault-881",
	}

	finalizer := "ledger.meridian.io/finalizer"

	fmt.Println("--- Pass 1: SRE deletes DB (S3 fails) ---")
	_, _ = HandleTeardown(res, cloud, finalizer)
	fmt.Printf("Finalizers remaining: %v\n", res.Finalizers)

	fmt.Println("\n--- Pass 2: Requeue attempt (S3 succeeds, Vault fails) ---")
	_, _ = HandleTeardown(res, cloud, finalizer)
	fmt.Printf("Finalizers remaining: %v\n", res.Finalizers)

	fmt.Println("\n--- Pass 3: Requeue attempt (All succeed) ---")
	_, _ = HandleTeardown(res, cloud, finalizer)
	fmt.Printf("Finalizers remaining: %v\n", res.Finalizers)
}
```

<Exercise n={4} title="Validating Webhook Admission Evaluator for Financial Invariants" level="hard">

Write a validating admission handler that decodes Old and New Custom Resource specs and enforces immutable financial rules:
1. `StorageGB` can only increase, never decrease.
2. `EngineVersion` major version cannot change (e.g. 15.x to 16.x requires a migration operator, cannot be done via in-place rolling update).
3. If `HighAvailability` was true in OldSpec, it cannot be disabled in NewSpec without explicit override header `"allow-ha-downgrade=true"`.

<Solution>

```go
package main

import (
	"fmt"
	"strings"
)

type DBSpec struct {
	EngineVersion    string
	StorageGB        int
	HighAvailability bool
}

type AdmissionRequest struct {
	Headers map[string]string
	OldSpec DBSpec
	NewSpec DBSpec
}

type ValidationResult struct {
	Allowed bool
	Errors  []string
}

func ValidateDBUpdate(req AdmissionRequest) ValidationResult {
	var errs []string

	// Rule 1: Storage cannot shrink
	if req.NewSpec.StorageGB < req.OldSpec.StorageGB {
		errs = append(errs, fmt.Sprintf("storageGB cannot shrink from %dGB to %dGB",
			req.OldSpec.StorageGB, req.NewSpec.StorageGB))
	}

	// Rule 2: Major version cannot change in-place
	oldMajor := strings.Split(req.OldSpec.EngineVersion, ".")[0]
	newMajor := strings.Split(req.NewSpec.EngineVersion, ".")[0]
	if oldMajor != newMajor {
		errs = append(errs, fmt.Sprintf("engineVersion major upgrade (%s -> %s) requires pg_upgrade migration operator",
			req.OldSpec.EngineVersion, req.NewSpec.EngineVersion))
	}

	// Rule 3: HA cannot be disabled without header override
	if req.OldSpec.HighAvailability && !req.NewSpec.HighAvailability {
		if req.Headers["allow-ha-downgrade"] != "true" {
			errs = append(errs, "disabling highAvailability is forbidden without allow-ha-downgrade header")
		}
	}

	if len(errs) > 0 {
		return ValidationResult{Allowed: false, Errors: errs}
	}
	return ValidationResult{Allowed: true}
}

func main() {
	req := AdmissionRequest{
		Headers: map[string]string{},
		OldSpec: DBSpec{EngineVersion: "15.4", StorageGB: 500, HighAvailability: true},
		NewSpec: DBSpec{EngineVersion: "16.1", StorageGB: 400, HighAvailability: false},
	}

	res := ValidateDBUpdate(req)
	fmt.Printf("Validation Result -> Allowed: %t\n", res.Allowed)
	for i, err := range res.Errors {
		fmt.Printf("  %d. %s\n", i+1, err)
	}
}
```

**Explanation**: Enforces strict Kubernetes admission gatekeeping, rejecting invalid API writes before they can reach etcd storage.
