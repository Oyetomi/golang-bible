## The lab bench

The cinema module from chapter 15 (a git repository, lint-clean, with its CI script), and two Redis servers: the usual one on port 6390, and a new one on 6391 that requires a username and password (stop 4). The service's flags are replaced by a `config` package; the service's behaviour doesn't change.

## The Silent Typo

*Stop 1 of 5.*

### Step 1: a value that parses and makes no sense

Until now, `main` read its settings with `flag.Duration`, `flag.String` and friends, and used them directly. `flag` checks that `-hold 0s` is a duration. It is. Nothing checks that it's a sensible *hold*:

```text
$ cinema -addr 127.0.0.1:18096 -hold 0s        # meant 90s
2026/09/27 08:21:06 cinema on http://127.0.0.1:18096, store=locked
$ curl -X POST -H 'X-User: alice' localhost:18096/movies/inception/seats/A7/hold
201
$ curl -X POST -H 'X-User: bob' localhost:18096/movies/inception/seats/A7/hold
201
$ curl -X POST -H 'X-User: carol' localhost:18096/movies/inception/seats/A7/hold
201
$ curl -s localhost:18096/movies/inception/seats | jq ".[6]"
{"id": "A7", "status": "free"}
```

**Three customers were told A7 was theirs**, and the seat map says nobody has it. The service started, logged its usual line, and answered every request with a success. This is the dangerous kind of misconfiguration: not a crash, but a service that works wrongly. Someone would notice at the door of the cinema, not in the logs.

### Step 2: the same service, three kinds of place

The fix isn't only validation. The service will run on a laptop (flags are convenient), in a container (environment variables are the norm: the **12-factor** convention is that config that changes between deploys lives in the environment), and in Kubernetes (settings in a ConfigMap, secrets in a mounted file). A service should accept each, in a known order, and say where each value came from. That's stop 2.

## Layers

*Stop 2 of 5.*

### Step 1: one registry, four layers

The `config` package registers every setting once, as a flag, and lets the other layers set it *by the same name*: a file key `"redis-addr"`, an environment variable `CINEMA_REDIS_ADDR`, a flag `-redis-addr`. Each is parsed by the flag's own parser (`time.ParseDuration` for durations, `strconv` for numbers), so `90s` means the same thing everywhere.

```go noverify
// Package config loads the cinema service's settings from four layers, each
// overriding the one before:
//
//	defaults < config file (JSON) < environment (CINEMA_*) < command-line flags
//
// Every setting is registered once, as a flag; the other layers set it by
// the same name, so they share one parser per type, and Sources records
// which layer each value came from.
package config

import (
	"bytes"
	"encoding/json"
	"errors"
	"flag"
	"fmt"
	"net"
	"os"
	"sort"
	"strings"
	"time"
)

type Config struct {
	Addr         string        `json:"addr"`
	Admin        string        `json:"admin"`
	Store        string        `json:"store"`
	Hold         time.Duration `json:"hold"`
	StoreTimeout time.Duration `json:"store_timeout"`
	Retries      int           `json:"retries"`
	Breaker      bool          `json:"breaker"`
	Stale        bool          `json:"stale"`
	Idempotent   bool          `json:"idempotent"`
	Rate         float64       `json:"rate"`
	RateRedis    bool          `json:"rate_redis"`
	Graceful     bool          `json:"graceful"`
	Redis        Redis         `json:"redis"`

	PrintConfig bool `json:"-"` // print the settings and their sources, then exit
}

type Redis struct {
	Addr         string `json:"addr"`
	Username     string `json:"username"`
	Password     Secret `json:"password"`
	PasswordFile string `json:"password_file"`
}

// Source says where a setting's value came from.
type Source string

const (
	FromDefault Source = "default"
	FromFile    Source = "file"
	FromEnv     Source = "env"
	FromFlag    Source = "flag"
)

// Load builds the configuration from args (os.Args[1:]) and environ
// (os.Environ()), and validates it. It returns every problem at once.
func Load(args, environ []string) (*Config, map[string]Source, error) {
	c := &Config{}
	fs := flag.NewFlagSet("cinema", flag.ContinueOnError)
	fs.StringVar(&c.Addr, "addr", "127.0.0.1:8091", "listen address")
	fs.StringVar(&c.Admin, "admin", "127.0.0.1:6060", "debug listener; never expose it publicly")
	fs.StringVar(&c.Store, "store", "locked", "locked | redis")
	fs.DurationVar(&c.Hold, "hold", 2*time.Minute, "how long a hold lasts")
	fs.DurationVar(&c.StoreTimeout, "store-timeout", 150*time.Millisecond, "per-attempt store timeout")
	fs.IntVar(&c.Retries, "retries", 0, "extra attempts after a failed store call")
	fs.BoolVar(&c.Breaker, "breaker", false, "wrap store calls in a circuit breaker")
	fs.BoolVar(&c.Stale, "stale", false, "serve the last good seat map when the store fails")
	fs.BoolVar(&c.Idempotent, "idempotent", false, "make Hold/Confirm safe to retry")
	fs.Float64Var(&c.Rate, "rate", 0, "requests per second allowed per customer (0 = no limit)")
	fs.BoolVar(&c.RateRedis, "rate-redis", false, "enforce -rate across replicas with a Redis counter")
	fs.BoolVar(&c.Graceful, "graceful", true, "drain in-flight requests on SIGTERM")
	fs.StringVar(&c.Redis.Addr, "redis-addr", "127.0.0.1:6390", "Redis address")
	fs.StringVar(&c.Redis.Username, "redis-username", "", "Redis ACL user")
	fs.Var((*secretFlag)(&c.Redis.Password), "redis-password", "Redis password (prefer -redis-password-file)")
	fs.StringVar(&c.Redis.PasswordFile, "redis-password-file", "", "file holding the Redis password, re-read on every new connection")
	configPath := fs.String("config", "", "JSON config file")
	fs.BoolVar(&c.PrintConfig, "print-config", false, "print every setting and where it came from, then exit")

	sources := map[string]Source{}
	fs.VisitAll(func(f *flag.Flag) { sources[f.Name] = FromDefault })
	var problems []error

	// Flags are parsed first only to find -config; they're applied again
	// last, so they still win.
	if err := fs.Parse(args); err != nil {
		return nil, nil, err
	}
	// Remember which flags were on the command line now: fs.Set, used by
	// the file and env layers below, marks flags as set too.
	onCommandLine := map[string]bool{}
	fs.Visit(func(f *flag.Flag) { onCommandLine[f.Name] = true })
	if *configPath == "" {
		*configPath = lookup(environ, "CINEMA_CONFIG")
	}
	if *configPath != "" {
		settings, err := readFile(*configPath)
		if err != nil {
			return nil, nil, err
		}
		for name, value := range settings {
			if fs.Lookup(name) == nil || name == "config" {
				problems = append(problems, fmt.Errorf("%s: unknown setting %q", *configPath, name))
				continue
			}
			if err := fs.Set(name, value); err != nil {
				problems = append(problems, fmt.Errorf("%s: %s=%q: %w", *configPath, name, value, err))
				continue
			}
			sources[name] = FromFile
		}
	}

	known := map[string]bool{"CINEMA_CONFIG": true}
	fs.VisitAll(func(f *flag.Flag) {
		env := EnvName(f.Name)
		known[env] = true
		if v, ok := lookupOK(environ, env); ok {
			if err := fs.Set(f.Name, v); err != nil {
				problems = append(problems, fmt.Errorf("%s=%q: %w", env, v, err))
				return
			}
			sources[f.Name] = FromEnv
		}
	})
	for _, kv := range environ { // a misspelled variable is silently ignored otherwise
		name, _, _ := strings.Cut(kv, "=")
		if strings.HasPrefix(name, "CINEMA_") && !known[name] {
			problems = append(problems, fmt.Errorf("%s: unknown environment variable", name))
		}
	}

	if err := fs.Parse(args); err != nil { // flags last: they win
		return nil, nil, err
	}
	for name := range onCommandLine {
		sources[name] = FromFlag
	}

	problems = append(problems, c.validate()...)
	if err := errors.Join(problems...); err != nil {
		return nil, nil, err
	}
	return c, sources, nil
}

// EnvName maps a flag name to its environment variable: redis-addr →
// CINEMA_REDIS_ADDR.
func EnvName(flagName string) string {
	return "CINEMA_" + strings.ToUpper(strings.ReplaceAll(flagName, "-", "_"))
}

func (c *Config) validate() []error {
	var errs []error
	bad := func(format string, a ...any) { errs = append(errs, fmt.Errorf(format, a...)) }
	for name, addr := range map[string]string{"addr": c.Addr, "admin": c.Admin, "redis-addr": c.Redis.Addr} {
		if _, _, err := net.SplitHostPort(addr); err != nil {
			bad("%s: %v", name, err)
		}
	}
	if c.Store != "locked" && c.Store != "redis" {
		bad("store: %q is not locked or redis", c.Store)
	}
	if c.Hold < 30*time.Second || c.Hold > 30*time.Minute {
		bad("hold: %v is outside 30s–30m (customers need time to pay, and seats can't stay locked all evening)", c.Hold)
	}
	if c.StoreTimeout <= 0 || c.StoreTimeout >= c.Hold {
		bad("store-timeout: %v must be positive and shorter than hold (%v)", c.StoreTimeout, c.Hold)
	}
	if c.Retries < 0 || c.Retries > 5 {
		bad("retries: %d is outside 0–5", c.Retries)
	}
	if c.Rate < 0 {
		bad("rate: %v is negative", c.Rate)
	}
	if c.RateRedis && c.Store != "redis" {
		bad("rate-redis: needs store=redis")
	}
	if !c.Redis.Password.IsZero() && c.Redis.PasswordFile != "" {
		bad("redis-password and redis-password-file are both set; use one")
	}
	if c.Redis.PasswordFile != "" {
		if info, err := os.Stat(c.Redis.PasswordFile); err != nil {
			bad("redis-password-file: %v", err)
		} else if perm := info.Mode().Perm(); perm&0o077 != 0 {
			bad("redis-password-file: %s is readable by others (mode %v); chmod 600 it", c.Redis.PasswordFile, perm)
		}
	}
	return errs
}

// Table prints every setting, its value and its source; secrets redacted.
func Table(c *Config, sources map[string]Source) string {
	names := make([]string, 0, len(sources))
	for n := range sources {
		if n != "config" && n != "print-config" {
			names = append(names, n)
		}
	}
	sort.Strings(names)
	values := map[string]any{
		"addr": c.Addr, "admin": c.Admin, "store": c.Store, "hold": c.Hold, "store-timeout": c.StoreTimeout,
		"retries": c.Retries, "breaker": c.Breaker, "stale": c.Stale, "idempotent": c.Idempotent,
		"rate": c.Rate, "rate-redis": c.RateRedis, "graceful": c.Graceful, "redis-addr": c.Redis.Addr,
		"redis-username": c.Redis.Username, "redis-password": c.Redis.Password, "redis-password-file": c.Redis.PasswordFile,
	}
	var b strings.Builder
	for _, n := range names {
		fmt.Fprintf(&b, "%-20s %-22v %s\n", n, values[n], sources[n])
	}
	return b.String()
}

// readFile reads a JSON object of setting names to values. Values may be
// strings, numbers or booleans; each is set through the flag's own parser.
func readFile(path string) (map[string]string, error) {
	raw, err := os.ReadFile(path) //nolint:gosec // the operator names the config file
	if err != nil {
		return nil, err
	}
	var m map[string]any
	dec := json.NewDecoder(bytes.NewReader(raw))
	dec.UseNumber()
	if err := dec.Decode(&m); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	out := make(map[string]string, len(m))
	for k, v := range m {
		out[k] = fmt.Sprint(v)
	}
	return out, nil
}

func lookup(environ []string, key string) string { v, _ := lookupOK(environ, key); return v }

func lookupOK(environ []string, key string) (string, bool) {
	for _, kv := range environ {
		if k, v, ok := strings.Cut(kv, "="); ok && k == key {
			return v, true
		}
	}
	return "", false
}

// secretFlag lets a Secret be set like any flag without printing it in -h.
type secretFlag Secret

func (s *secretFlag) Set(v string) error { *s = secretFlag(NewSecret(v)); return nil }
func (s *secretFlag) String() string     { return Secret(*s).String() }
```

The order is **defaults < file < environment < flags**: the more specific and the closer to this one run, the stronger. A file is shared by every instance; the environment is per deployment; a flag is what someone typed a moment ago.

### Step 2: which one won?

`-print-config` prints every setting, its value and where it came from:

```text
$ cat cinema.json
{
  "store": "redis",
  "hold": "90s",
  "retries": 1,
  "redis-addr": "127.0.0.1:6390"
}
$ CINEMA_CONFIG=cinema.json CINEMA_HOLD=3m ./cinema -retries 2 -print-config
addr                 127.0.0.1:8091         default
admin                127.0.0.1:6060         default
breaker              false                  default
graceful             true                   default
hold                 3m0s                   env
idempotent           false                  default
rate                 0                      default
rate-redis           false                  default
redis-addr           127.0.0.1:6390         file
redis-password                              default
redis-password-file                         default
redis-username                              default
retries              2                      flag
stale                false                  default
store                redis                  file
store-timeout        150ms                  default
```

`store` and `redis-addr` came from the file. `hold` is 3m: the file said 90s, the environment said 3m, and the environment wins. `retries` is 2: the file said 1, the flag said 2. When someone asks "why is the hold three minutes in production?", this table answers in one command.

The first version of the loader printed `flag` as the source of everything the file and the environment had set. `flag.FlagSet.Set` (which the file and environment layers call) records a flag as set, exactly like the command line does, so asking the FlagSet afterwards couldn't tell them apart. The loader now notes which flags were on the command line *before* any other layer runs. That's the kind of bug the `Sources` map exists to catch, and a test (`TestPrecedence`, below) now pins it.

### Step 3: testable by design

`Load(args, environ)` takes the command line and the environment as parameters instead of reading `os.Args` and `os.Getenv` itself, so tests can try any combination without touching the real process:

```go noverify
package config

import (
	"fmt"
	"os"
	"path/filepath"
	"strings"
	"testing"
	"time"
)

// Load takes args and environ as parameters, so every layer can be tested
// without touching the real process environment.
func TestPrecedence(t *testing.T) {
	file := filepath.Join(t.TempDir(), "cinema.json")
	if err := os.WriteFile(file, []byte(`{"hold": "90s", "retries": 1, "store": "redis"}`), 0o600); err != nil {
		t.Fatal(err)
	}
	cfg, src, err := Load([]string{"-retries", "2"}, []string{"CINEMA_CONFIG=" + file, "CINEMA_HOLD=3m"})
	if err != nil {
		t.Fatal(err)
	}
	for _, tc := range []struct {
		name string
		got  any
		want any
		from Source
	}{
		{"store", cfg.Store, "redis", FromFile},
		{"hold", cfg.Hold, 3 * time.Minute, FromEnv},
		{"retries", cfg.Retries, 2, FromFlag},
		{"addr", cfg.Addr, "127.0.0.1:8091", FromDefault},
	} {
		if tc.got != tc.want || src[tc.name] != tc.from {
			t.Errorf("%s = %v from %s, want %v from %s", tc.name, tc.got, src[tc.name], tc.want, tc.from)
		}
	}
}

func TestEveryProblemAtOnce(t *testing.T) {
	_, _, err := Load([]string{"-hold", "0s"}, []string{"CINEMA_RETRIES=ten", "CINEMA_HOLD_TIME=90s"})
	if err == nil {
		t.Fatal("want an error")
	}
	for _, want := range []string{"CINEMA_RETRIES", "CINEMA_HOLD_TIME: unknown", "hold: 0s"} {
		if !strings.Contains(err.Error(), want) {
			t.Errorf("error doesn't mention %q:\n%v", want, err)
		}
	}
}

func TestSecretNeverPrints(t *testing.T) {
	cfg, _, err := Load([]string{"-redis-password", "hunter2"}, nil)
	if err != nil {
		t.Fatal(err)
	}
	for _, format := range []string{"%v", "%+v", "%#v", "%s"} {
		if out := fmt.Sprintf(format, cfg); strings.Contains(out, "hunter2") {
			t.Errorf("%s printed the password: %s", format, out)
		}
	}
	if cfg.Redis.Password.Reveal() != "hunter2" {
		t.Error("Reveal lost the value")
	}
}
```

```text
$ go test -v ./config/
=== RUN   TestPrecedence
--- PASS: TestPrecedence (0.00s)
=== RUN   TestEveryProblemAtOnce
--- PASS: TestEveryProblemAtOnce (0.00s)
=== RUN   TestSecretNeverPrints
--- PASS: TestSecretNeverPrints (0.00s)
PASS
ok  	cinema/config	0.910s
```

Libraries do the same job with more features: **koanf** and **Viper** read YAML, TOML and remote sources and can watch files; **envconfig** maps environment variables onto struct tags. The shape is the same as here: layers in a fixed order, one parser per type, validation at the end. What matters is that the order is written down and the result can be printed.

## Validate at Startup

*Stop 3 of 5.*

### Step 1: every problem, at once

`validate` checks meaning, not just syntax: addresses must have a port, a hold must be 30 s to 30 min, the store timeout must be shorter than the hold, and so on. `Load` also rejects **unknown settings**: a key in the file that no flag has, and any `CINEMA_*` variable that isn't one of the service's. A misspelled name is otherwise silently ignored, and the default is used. Six mistakes at once:

```text
$ cat bad.json
{
  "store": "redis",
  "hold_time": "90s",
  "store-timeout": "5m",
  "redis-addr": "127.0.0.1"
}
$ CINEMA_CONFIG=bad.json CINEMA_RETRIES=ten CINEMA_RATE_LIMIT=5 ./cinema -hold 0s; echo "exit $?"
cinema: invalid configuration:
bad.json: unknown setting "hold_time"
CINEMA_RETRIES="ten": parse error
CINEMA_RATE_LIMIT: unknown environment variable
redis-addr: address 127.0.0.1: missing port in address
hold: 0s is outside 30s–30m (customers need time to pay, and seats can't stay locked all evening)
store-timeout: 5m0s must be positive and shorter than hold (0s)
exit 2
(14 ms, including process start)
```

The service **refused to start**, exit status 2, in 14 ms, and listed all six problems. `errors.Join` collects them, so whoever is fixing the deploy fixes everything in one pass instead of one per restart. Four of the six would have been silent without this: `hold_time` and `CINEMA_RATE_LIMIT` ignored (defaults used instead), `hold: 0s` accepted (stop 1), and a store timeout of 5 minutes, which would make every Redis hiccup a 5-minute wait.

### Step 2: fail at startup, not at the first request

Why not start anyway and report problems when they matter? Because an orchestrator knows what to do with a process that exits at startup: in a Kubernetes rolling update the new pods never become ready, the rollout stalls, and the old pods keep serving. A process that starts and serves wrong answers passes its health checks and takes all the traffic. Refusing to start is the safe failure.

What startup validation can't know: whether Redis will accept the password, or whether it's up. The service checks that too (`rdb.Ping` before listening), but a dependency can fail later, which is what readiness checks (chapter 12) are for.

## Where Secrets Leak

*Stop 4 of 5.*

### Step 1: a Redis user with a password

The production Redis requires authentication, with an **ACL user** for the cinema that can do only what the cinema does:

```text
user cinema on #<sha256 of the password> ~seat:* ~rate:* +@read +@write +@connection -@dangerous
```

Keys starting with `seat:` or `rate:` only; reading and writing, but none of the `@dangerous` commands (`FLUSHALL`, `CONFIG`, `KEYS`…). With the cinema's own password:

```text
$ redis-cli --user cinema --pass "$(cat redis-password)" FLUSHALL
NOPERM User cinema has no permissions to run the 'flushall' command

$ redis-cli --user cinema --pass "$(cat redis-password)" CONFIG GET requirepass
NOPERM User cinema has no permissions to run the 'config|get' command

$ redis-cli --user cinema --pass "$(cat redis-password)" SET users:admin x
NOPERM No permissions to access a key
```

If the cinema's password leaks, the attacker can mess with seats, not wipe the database, read the config or touch other applications' keys. **Least privilege** limits what a leak costs. Now: where does the password leak?

### Step 2: leak 1, the environment

The obvious way to pass a password to a container is an environment variable. The service accepts `CINEMA_REDIS_PASSWORD`, so:

```text
$ CINEMA_REDIS_PASSWORD=… ./cinema -store redis … &
$ ps eww -p $(pgrep cinema) | tr ' ' '\n' | grep CINEMA_
CINEMA_REDIS_PASSWORD=c1d7180bf9f2be8d1b202ea68ad4f23e
```

`ps eww` prints a process's environment (on Linux, so does `/proc/<pid>/environ`), readable by the same user, by root, and often by monitoring agents and crash reporters. Environment variables are also inherited by every child process the service starts, and they appear in `docker inspect` for containers started with `-e`.

### Step 3: leak 2, the lab bench's own command line

Building this chapter, the first ACL-protected Redis was started with its users on the command line (`redis-server --user cinema on '>password' …`):

```text
$ docker inspect cinema-redis-auth --format '{{json .Args}}'
["redis-server","--user","default","off","--user","admin","on",">760e0406b0352ad1758dbd7a32a70b13","~*","&*","+@all","--user","cinema","on",">c1d7180bf9f2be8d1b202ea68ad4f23e","~seat:*","~rate:*","+@read","+@write","+@connection","-@dangerous"]
```

Both passwords, the admin's included, in plain text, for anyone who can run `docker inspect` (or `ps` on the host). Those passwords were thrown away. The container now reads its users from a mounted **ACL file**, which holds only SHA-256 hashes of the passwords (`#…`), so the file itself reveals nothing usable:

```text
$ cat users.acl
user default off
user admin on #388e2975fa96… ~* &* +@all
user cinema on #4039baedfda0… ~seat:* ~rate:* +@read +@write +@connection -@dangerous
$ docker inspect cinema-redis-auth --format '{{json .Args}}'
["redis-server","--aclfile","/etc/redis/users.acl"]
```

The service gets its password the same way: `-redis-password-file`, a file readable only by the service's user (mode `0600`), outside the environment and the command line. That's also how orchestrators deliver secrets: Kubernetes mounts a Secret as files, Docker has `/run/secrets`, and Vault Agent writes secrets to files and rewrites them when they change. `validate` rejects a password file others can read:

```text
$ ls -l pw-loose
-rw-r--r--@ pw-loose
$ ./cinema -store redis -redis-addr 127.0.0.1:6391 -redis-username cinema -redis-password-file pw-loose
cinema: invalid configuration:
redis-password-file: pw-loose is readable by others (mode -rw-r--r--); chmod 600 it
exit 2
```

(Kubernetes mounts Secret files with mode `0644` unless the volume sets `defaultMode`; set it to `0400`, or this check stops the pod, which is the point.)

### Step 4: leak 3, printing the config

Even with the password in a file, the service holds it in memory, and services print their configuration: a startup log, a `%+v` while debugging, a JSON debug endpoint. With the password as a plain `string`, then as `config.Secret`, then as a `Secret` in an unexported field:


The plain string leaked in **every** format. `Secret`, whose `String`, `GoString`, `MarshalJSON` and `LogValue` all return `[redacted]`, closed all five. Then the third case: a `Secret` in an **unexported** field printed the password through every fmt verb and slog. `fmt` can only call methods on values it can reach through reflection's `Interface()`, and unexported fields aren't; for those it prints the fields raw, and `Secret`'s one field was the string itself.

The fix changes where the value lives: `Secret` holds a *pointer* to the string.

```go noverify
package config

import (
	"encoding/json"
	"log/slog"
)

// Secret holds a password or token. Every way Go prints a value (fmt's
// verbs, JSON, slog) shows "[redacted]"; only Reveal returns the value.
//
// The value sits behind a pointer: where fmt can't call String (a Secret
// in an unexported field), it prints the pointer's address, not the value.
type Secret struct{ v *string }

func NewSecret(v string) Secret { return Secret{&v} }

// Reveal returns the secret itself. Call it only where the value is used.
func (s Secret) Reveal() string {
	if s.v == nil {
		return ""
	}
	return *s.v
}

func (s Secret) IsZero() bool { return s.Reveal() == "" }

func (s Secret) String() string {
	if s.IsZero() {
		return ""
	}
	return "[redacted]"
}

func (s Secret) GoString() string             { return `config.Secret("` + s.String() + `")` }
func (s Secret) MarshalJSON() ([]byte, error) { return json.Marshal(s.String()) }
func (s Secret) LogValue() slog.Value         { return slog.StringValue(s.String()) }
```

```text
  %#v  main.plainRedis{Addr:"127.0.0.1:6391", Username:"cinema", Password:"4039baedfda0-example"}
```

## Rotation

*Stop 5 of 5.*

### Step 1: why rotate, and the order that works

Passwords get changed: on a schedule, when someone with access leaves, and in a hurry when one leaks. A rotation that needs a restart gets postponed, so the service should pick up a new password by itself. The safe order uses Redis's ability to give a user **two passwords at once**:

1. Add the new password to the user (`ACL SETUSER cinema #<new hash>`): both work.
2. Deliver the new password to the service (write the file).
3. Remove the old one (`ACL SETUSER cinema !<old hash>`).

Existing connections stay authenticated when a password is removed; only *new* connections use the new one. So `rotate.sh` then drops every cinema connection (`CLIENT KILL USER cinema`), as a Redis restart or failover would, to force the question: does the service reconnect with the right password?

### Step 2: the file, read on every new connection

The service doesn't cache the password. go-redis calls `CredentialsProviderContext` whenever it opens a connection, and the service's provider reads the file each time:

```go noverify
// main.go, lines 176–200
	var store booking.Store
	var rdb *redis.Client
	switch cfg.Store {
	case "locked":
		store = booking.NewMemoryStore()
	case "redis":
		opts := &redis.Options{Addr: cfg.Redis.Addr, ContextTimeoutEnabled: true}
		if cfg.Redis.PasswordFile != "" {
			// Read the file on every new connection, so a rotated password
			// is picked up without a restart.
			opts.CredentialsProviderContext = func(ctx context.Context) (string, string, error) {
				pw, err := os.ReadFile(cfg.Redis.PasswordFile) //nolint:gosec // the operator names the secret file
				return cfg.Redis.Username, strings.TrimSpace(string(pw)), err
			}
		} else {
			opts.Username, opts.Password = cfg.Redis.Username, cfg.Redis.Password.Reveal()
		}
		rdb = redis.NewClient(opts)
		if err := rdb.Ping(context.Background()).Err(); err != nil {
			log.Fatalf("redis %s: %v", cfg.Redis.Addr, err)
		}
		rs := booking.NewRedisStore(rdb)
		rs.Idempotent = cfg.Idempotent
		store = rs
	}
```

`rotate.sh file` runs the rotation under `hammer` (50 holds and 200 seat maps a second, for 8 seconds):

```text
t=2s  new password added in Redis and written to redis-password (both passwords valid)
t=3s  old password removed
t=4s  CLIENT KILL USER cinema: 3 connections dropped, as on a Redis restart or failover
--- load (8 s)
hold    400 requests  201:40 409:360               p50 1.2ms    p99 3.9ms    max 20ms
seats  1599 requests  200:1599                     p50 1.1ms    p99 3.7ms    max 18ms
--- the seat map, after the load: 200
```

**Zero errors** in 1,999 requests: 3 connections dropped at t=4s, reopened with the new password from the file, and customers saw nothing (the p99 barely moved).

### Step 3: the password read once, at startup

The same rotation, with the service given its password once, in `CINEMA_REDIS_PASSWORD`:


### Step 4: rotation without a password file

The same pattern works wherever the secret comes from. Kubernetes updates mounted Secret files in place (via an atomic symlink swap) when the Secret changes, after a delay of up to a minute or so; environment variables taken from a Secret never change until the pod restarts. Vault goes further with **dynamic secrets**: its database secrets engine (which supports Redis) creates a fresh user with a short lease for each instance and deletes it when the lease ends, so there's no long-lived password to leak or rotate at all. In every case the service's side is the same: read the current credentials when you connect, not once at startup.

<Exercise n={3} title="Find the fourth leak" level="medium">

The service now keeps the password out of the environment, the command line and printed output. Name two more places it could appear, and how to close each.

<Solution>

**Core dumps and heap profiles**: the password is in memory; a core dump (or a `/debug/pprof/heap` profile's retained strings) contains it. Disable core dumps in production (`ulimit -c 0`, the default in most containers) and keep pprof on the loopback admin listener, as the service does. **Error messages**: an error that wraps a connection URL (`redis://cinema:password@host`) prints the password; the service uses separate username and password fields, never a URL with credentials. Others: shell history (`export CINEMA_REDIS_PASSWORD=…` typed by hand), CI logs (`set -x` in a deploy script), and crash reporters that attach the environment.

</Solution>

</Exercise>

<Exercise n={4} title="Reload the log level" level="medium">

Make the log level changeable without a restart: on SIGHUP, re-run `config.Load` and apply only the settings that are safe to change live. Which of the service's settings are safe, and what must happen if the reloaded config is invalid?

<Solution>

Safe live: the log level, rate limits (swap the limiter behind an `atomic.Pointer`), the store timeout and retry count (read per call). Not safe: listen addresses, the store kind, the Redis address (they'd need new servers and clients; do those with a rolling restart). On SIGHUP, load and validate the *whole* new config; if it's invalid, log the errors and **keep the old config**. Half-applying a bad config is worse than ignoring it. </Solution>

<Exercise n={5} title="Dynamic credentials" level="hard">

Sketch how the cinema would use short-lived Redis users (a new user per instance with a 1-hour lease, as Vault's database engine issues them). What changes in the provider, and what happens to open connections when a user expires?

<Solution>

The provider returns the *current* lease's username and password, read from the file Vault Agent rewrites (or fetched from Vault's API with the lease renewed in the background). When a lease ends, Vault deletes the Redis user, and Redis **closes that user's connections** (deleting a user, unlike removing a password, disconnects it). Every in-flight command on those connections fails once. So: renew or re-issue well before expiry (Vault Agent handles this for the secrets it renders), make sure new connections pick up the new user (the provider does), and set go-redis's `ConnMaxLifetime` below the lease so connections turn over before their user disappears. Chapter 12's retries cover the rare command that still lands on a closing connection.

</Solution>

</Exercise>
