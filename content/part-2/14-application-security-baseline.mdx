<HeroCard label="Part 2 · Chapter 14" title="Application Security Baseline">

Every byte that arrives over the network is input from someone you don't control. Most of what goes wrong in a service's security is the same few mistakes: trusting a length, splicing a string into a query or a command or a path, letting the service fetch a URL it was handed, printing a value that was meant to stay private. None of them needs cleverness to fix. They need the fix to be the *default* in the code you write.

This chapter is the defensive floor. For each mistake there is a leaky version and a fixed one, both in one small Go module (`modules/part2-ch14-baseline`), each with a test that runs both against your own machine and prints the difference. The inputs are harmless (an `echo`, a wildcard, a file in a temp directory), nothing contacts another host, and the point is what the **fix** has to stop. Part 3 layers the fintech controls on top of this floor, and its [broken access control chapter](/part-3/broken-access-control) picks up where stop 2's SQL section leaves off.

Seven stops. If you get lost, come back here:

1. **Input is hostile.** Strict decoding, a size cap, and a length field that lies.
2. **The injection family.** SQL, shell commands and file paths: data that becomes code.
3. **SSRF.** A service that fetches a URL for a caller, and the guard at the connection.
4. **XSS and `html/template`.** Escaping by context, and the one type that switches it off.
5. **Transport and headers.** TLS as a floor and the headers every response carries.
6. **Secrets out of logs.** A type that cannot print itself.
7. **Supply-chain scanning.** `govulncheck`, and why it counts what your code calls.

</HeroCard>

## Input is Hostile

*Stop 1 of 7.*

### Step 1: decode strictly, and cap the size

Everything in a request is a claim by someone else: the JSON body, the headers, the lengths inside a binary frame. The first rule is to accept only what you expect and refuse the rest. For JSON that is two settings on the standard decoder, and a cap in front of it:

```go noverify
// input.go, lines 17–28
// DecodeStrict reads one JSON object from a body of at most max bytes and refuses fields it does not know.
func DecodeStrict(w http.ResponseWriter, r *http.Request, v any, max int64) error {
	dec := json.NewDecoder(http.MaxBytesReader(w, r.Body, max))
	dec.DisallowUnknownFields()
	if err := dec.Decode(v); err != nil {
		return err
	}
	if dec.More() { // trailing data after the object
		return errors.New("unexpected data after JSON object")
	}
	return nil
}
```

`http.MaxBytesReader` stops reading after `max` bytes and makes the request fail, so an enormous body can't be pushed into memory. `DisallowUnknownFields` turns a field you didn't define into an error rather than silently ignoring it. That matters because of **mass assignment**: a client that adds `"is_admin": true` to a body is testing whether your code copies every field it is given. `dec.More()` catches a second JSON value glued on after the first. Five bodies against a 1,024-byte cap:

```text
valid                            -> <nil>
unknown field (mass assignment)  -> json: unknown field "is_admin"
wrong type                       -> json: cannot unmarshal string into Go struct field CreatePayment.amount of type int64
trailing data                    -> unexpected data after JSON object
too big                          -> http: request body too large
```

Four of five refused, each with a specific reason. Notice what isn't in the list: no escaping, no "sanitizing". The rule is an **allow-list**: define exactly the shape you accept, and everything else fails.

### Step 2: a length field is a weapon

Binary and framed protocols put a length in front of the data. That number is chosen by whoever is sending. The naive reader trusts it:

```go noverify
// input.go, lines 32–41
// ReadFrameNaive trusts a 4-byte length prefix and allocates that much before reading anything.
func ReadFrameNaive(r io.Reader) ([]byte, error) {
	var n uint32
	if err := binary.Read(r, binary.BigEndian, &n); err != nil {
		return nil, err
	}
	buf := make([]byte, n) // the attacker chose n
	_, err := io.ReadFull(r, buf)
	return buf, err
}
```

`make([]byte, n)` allocates all `n` bytes at once. A four-byte message saying "the next 256 MB are coming" gets a 256 MB slice, and the reader then waits for data that never arrives, holding the memory. `TestAllocationBomb` measures both readers with a 4-byte frame claiming 256 MB:

```text
a 4-byte frame claiming 256 MB: naive reader allocated 256 MB; bounded reader allocated 64 bytes and returned frame too large
```

256 MB against 64 bytes. The fix is one comparison before the `make`:

```go noverify
// input.go, lines 43–56
// ReadFrame refuses lengths above max, and reads in a bounded way so a lie about the length
// costs only as much memory as bytes actually arrive.
func ReadFrame(r io.Reader, max uint32) ([]byte, error) {
	var n uint32
	if err := binary.Read(r, binary.BigEndian, &n); err != nil {
		return nil, err
	}
	if n > max {
		return nil, ErrTooLarge
	}
	buf := make([]byte, n)
	_, err := io.ReadFull(r, buf)
	return buf, err
}
```

Pick the limit from what your protocol genuinely needs, not from what the type can hold. A `uint32` can say 4 GB; your messages are probably under a megabyte. The same idea applies to every count and offset that arrives from outside: the number of items in an array, the size of an image, the depth of nested JSON. **Bound it before you allocate on its behalf.**

## The Injection Family

*Stop 2 of 7.*

The common shape: your code builds a string in a language that something else parses (SQL, a shell, a filesystem path), and part of that string came from the caller. The caller's data is then *interpreted* as part of the language. The fix is always the same in spirit: keep data and instructions in separate channels.

### Step 1: SQL

The table is 1,000 users in a real Postgres. Two versions of the same lookup:

```go noverify
// inject.go, lines 15–27
// FindNaive builds SQL by concatenation: the caller writes part of the query.
func (d *DB) FindNaive(ctx context.Context, name string) (int, error) {
	rows, err := d.Pool.Query(ctx, "SELECT id FROM users WHERE name = '"+name+"'")
	if err != nil {
		return 0, err
	}
	defer rows.Close()
	n := 0
	for rows.Next() {
		n++
	}
	return n, rows.Err()
}
```

```go noverify
// inject.go, lines 29–41
// Find binds the value as a parameter: it is data, never SQL.
func (d *DB) Find(ctx context.Context, name string) (int, error) {
	rows, err := d.Pool.Query(ctx, "SELECT id FROM users WHERE name = $1", name)
	if err != nil {
		return 0, err
	}
	defer rows.Close()
	n := 0
	for rows.Next() {
		n++
	}
	return n, rows.Err()
}
```

The naive one puts the caller's text inside the quotes of the query. Give it a string that closes the quote and adds a condition that is always true:

```text
name="user7"          concatenated:    1 rows (<nil>)   parameterized: 1 rows (<nil>)
name="' OR '1'='1"    concatenated: 1000 rows (<nil>)   parameterized: 0 rows (<nil>)
```

Concatenated, that input became `WHERE name = '' OR '1'='1'`, which is true for every row: 1,000 rows from a lookup that should return one. Parameterized, the same text went to Postgres as a *value* to compare with `name`, and no user has that name, so 0 rows. In a parameterized query the query text and the values travel separately; the database never reads the value as SQL.

A parameter can only stand for a *value*. A column name for `ORDER BY` can't be a parameter, and concatenating one brings the risk back. The answer is an allow-list that maps the caller's word to a known column:

```go noverify
// inject.go, lines 43–54
// A parameter can be a value but not a column name, so identifiers come from an allow-list.
var sortable = map[string]string{"name": "name", "email": "email", "created": "id"}

func (d *DB) FirstSorted(ctx context.Context, col string) (string, error) {
	c, ok := sortable[col]
	if !ok {
		return "", fmt.Errorf("cannot sort by %q", col)
	}
	var name string
	err := d.Pool.QueryRow(ctx, "SELECT name FROM users ORDER BY "+c+" LIMIT 1").Scan(&name)
	return name, err
}
```

```text
ORDER BY "email"                  -> "user1000", <nil>
ORDER BY "name; DROP TABLE users" -> "", cannot sort by "name; DROP TABLE users"
```

### Step 2: shell commands

`os/exec` doesn't use a shell unless you ask for one. `exec.Command("echo", "checking", host)` passes `host` as a single argument to the program. `sh -c "echo checking " + host` hands the whole string to a shell, which treats `;` as a command separator:

```go noverify
// inject.go, lines 56–60
// EchoNaive runs a shell with the host spliced into the command line.
func EchoNaive(host string) (string, error) {
	out, err := exec.Command("sh", "-c", "echo checking "+host).CombinedOutput()
	return strings.TrimSpace(string(out)), err
}
```

```go noverify
// inject.go, lines 64–71
// Echo passes the host as one argument: no shell parses it. It also validates the shape.
func Echo(host string) (string, error) {
	if !hostRe.MatchString(host) {
		return "", fmt.Errorf("invalid host %q", host)
	}
	out, err := exec.Command("echo", "checking", host).CombinedOutput()
	return strings.TrimSpace(string(out)), err
}
```

Using `echo`, a harmless command, so the point is visible without risk:

```text
host="example.com"                  shell: "checking example.com"   argv: "checking example.com" <nil>
host="example.com; echo INJECTED"   shell: "checking example.com\nINJECTED"   argv: "" invalid host "example.com; echo INJECTED"
```

The shell version ran the second command: `INJECTED` appeared on its own line. The fixed version needs two things. First, no shell: an argument list, so nothing parses metacharacters. Second, validate the shape anyway (`hostRe` accepts only letters, digits, dots and hyphens), because the program you launch can have its own options: a value that starts with `-` can be read as a flag. Validation is the second lock, and it also gives a clean error.

### Step 3: file paths

`filepath.Join(base, name)` cleans `..` but does not stop the result leaving `base`; `../secret.txt` joins to a path outside it. Since Go 1.24, `os.OpenRoot` gives a handle that *cannot* leave the directory:

```go noverify
// traversal.go, lines 9–12
// ReadUnsafe joins the base and the caller's name and reads the result.
func ReadUnsafe(base, name string) ([]byte, error) {
	return os.ReadFile(filepath.Join(base, name))
}
```

```go noverify
// traversal.go, lines 14–28
// ReadSafe opens the file through an os.Root: the kernel refuses any path, including one that
// goes through a symlink, that leaves the base directory.
func ReadSafe(base, name string) ([]byte, error) {
	root, err := os.OpenRoot(base)
	if err != nil {
		return nil, err
	}
	defer root.Close()
	f, err := root.Open(name)
	if err != nil {
		return nil, err
	}
	defer f.Close()
	return io.ReadAll(f)
}
```

The test puts a secret file next to the served directory, plus a symlink inside it that points at the secret:

```text
"ok.txt"         filepath.Join: "hello"              <nil> | os.Root: "hello" <nil>
"../secret.txt"  filepath.Join: "outside the base"   <nil> | os.Root: "" openat ../secret.txt: path escapes from parent
"link.txt"       filepath.Join: "outside the base"   <nil> | os.Root: "" openat link.txt: path escapes from parent
```

Both the plain `../` and the symlink read the secret through `filepath.Join`. `os.Root` refused both with "path escapes from parent". The symlink case is the one string checks can't catch: the *name* `link.txt` looks innocent, and only the filesystem knows it points elsewhere. Do the confinement where the file is opened, in the kernel's terms, not by inspecting the string.

## SSRF

*Stop 3 of 7.*

### Step 1: the service that fetches for a stranger

**Server-side request forgery** happens when your service makes an HTTP request to a URL a caller supplied: a webhook, an image preview, a link unfurler. The caller can point it at addresses only your server can reach: `localhost`, the private network, the cloud provider's metadata address (`169.254.169.254`). Your service becomes the caller's proxy into places they couldn't reach themselves. The default `http.Client` will happily connect to any of them.

The defence has to live at the connection, because that's the only place you know the *real* address. Checking the hostname string first is not enough: `localhost`, `127.1`, an IPv6 form of an IPv4 address, and a public name that resolves to a private address all reach the same place. So the check goes in the dialer's `Control` function, which runs after DNS has answered and before the connection is made:

```go noverify
// ssrf.go, lines 15–21
// public reports whether an address is one this service may connect to on a caller's behalf.
func public(a netip.Addr) bool {
	a = a.Unmap() // ::ffff:127.0.0.1 is 127.0.0.1
	return !(a.IsLoopback() || a.IsPrivate() || a.IsLinkLocalUnicast() || a.IsLinkLocalMulticast() ||
		a.IsMulticast() || a.IsUnspecified() || a.IsInterfaceLocalMulticast() ||
		netip.MustParsePrefix("100.64.0.0/10").Contains(a)) // carrier-grade NAT
}
```

```go noverify
// ssrf.go, lines 23–55
// SafeClient checks the address at connect time, after DNS has answered, so a hostname that
// resolves to an internal address (or is changed between a check and a use) is still refused.
// allow lists exact address:port pairs to permit anyway; tests use it to reach one local server.
func SafeClient(allow ...netip.AddrPort) *http.Client {
	d := &net.Dialer{
		Timeout: 3 * time.Second,
		Control: func(network, address string, c syscall.RawConn) error {
			ap, err := netip.ParseAddrPort(address)
			if err != nil {
				return err
			}
			for _, a := range allow {
				if a == ap {
					return nil
				}
			}
			if !public(ap.Addr()) {
				return fmt.Errorf("%w: %s", ErrBlocked, ap.Addr())
			}
			return nil
		},
	}
	return &http.Client{
		Timeout:   5 * time.Second,
		Transport: &http.Transport{DialContext: d.DialContext, Proxy: nil},
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			if len(via) >= 3 {
				return errors.New("too many redirects")
			}
			return nil // each redirect is dialled through the same guard
		},
	}
}
```

`public` refuses loopback, private (10/8, 172.16/12, 192.168/16), link-local (which includes the metadata address), multicast, the unspecified address, and the carrier-grade-NAT range. `a.Unmap()` first, so `::ffff:127.0.0.1` is seen as `127.0.0.1`. Every redirect is dialled through the same guard, which matters as much as the first request.

### Step 2: measured

A local server plays the internal service. Seven destinations through the guarded client, then the same through the default client:

```text
guarded GET http://127.0.0.1:62624                               -> blocked=true
guarded GET http://localhost:62624                               -> blocked=true
guarded GET http://169.254.169.254/latest/meta-data/             -> blocked=true
guarded GET http://10.0.0.5/                                     -> blocked=true
guarded GET http://[::ffff:127.0.0.1]:62624                      -> blocked=true
guarded GET http://0.0.0.0:80/                                   -> blocked=true
guarded GET http://100.64.0.1/                                   -> blocked=true
default client GET http://127.0.0.1:62624 -> connected (err=<nil>)
allowed host redirects to an internal one: blocked=true (true)
default client follows the same redirect: status 200, err=<nil>
```

All seven were refused *before any connection was attempted* (for `169.254.169.254` and `10.0.0.5` nothing left the machine at all). The default client connected to the internal server directly, and it followed a redirect from one server to another without a second thought. In the last pair, the guarded client is allowed to reach the first host (a test-only exception) and still refuses when that host redirects it to an internal one. That is the redirect case, and it is why the guard belongs on the dialer, not on the first URL.

## XSS and html/template

*Stop 4 of 7.*

### Step 1: escaping depends on where the value lands

**Cross-site scripting** is markup or script from an attacker ending up in a page and running in the victim's browser. The defence is to escape a value for the place it is inserted, and *the right escaping differs by place*: text between tags, inside an attribute, inside a URL, inside a script. Go's `html/template` knows which of those a `{{.Name}}` is in and applies the right escaping. `text/template` applies none. One template with the same value in three places, rendered both ways with `<script>alert(1)</script>"`:

```go noverify
// xss.go, lines 9–15
const page = `<p>Hello, {{.Name}}!</p><a href="/u?q={{.Name}}">profile</a><script>var n = {{.Name}};</script>`

func RenderHTML(name string) string {
	var b strings.Builder
	htmpl.Must(htmpl.New("p").Parse(page)).Execute(&b, map[string]string{"Name": name})
	return b.String()
}
```

```text
input: <script>alert(1)</script>"
html/template: <p>Hello, &lt;script&gt;alert(1)&lt;/script&gt;&#34;!</p><a href="/u?q=%3cscript%3ealert%281%29%3c%2fscript%3e%22">profile</a><script>var n = "<script>alert(1)</script>\"";</script>
text/template: <p>Hello, <script>alert(1)</script>"!</p><a href="/u?q=<script>alert(1)</script>"">profile</a><script>var n = <script>alert(1)</script>";</script>
```

Look at how `html/template` treated the same value three ways: as text (`&lt;script&gt;`), as a URL component (`%3cscript%3e…`), and as a JavaScript string (`"<script>…"`). That's the context tracking. `text/template` put the raw value everywhere, including a working `<script>` element in the text and a broken-out attribute in the link.

### Step 2: the switch that turns it off

`template.HTML` is a type that says "this string is already safe HTML", and `html/template` believes it:

```text
template.HTML: <p>Hello, <script>alert(1)</script>"!</p>
```

Same input, no escaping. So the rule: use `html/template` for every HTML response, never `text/template`; never convert user-controlled data to `template.HTML`, `template.JS` or `template.URL`; and treat a grep for those types as a review checklist.

## Transport and Headers

*Stop 5 of 7.*

### Step 1: TLS as a floor, headers as a default

Traffic in transit must be encrypted, and old protocol versions have known weaknesses. The server side of that is a minimum version in the TLS config. The response side is a small set of headers that tell browsers how to treat what they receive, applied to every response by one middleware:

```go noverify
// headers.go, lines 8–19
// Secure adds the headers every response should carry.
func Secure(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		h := w.Header()
		h.Set("Strict-Transport-Security", "max-age=63072000; includeSubDomains")
		h.Set("X-Content-Type-Options", "nosniff")
		h.Set("Content-Security-Policy", "default-src 'self'; frame-ancestors 'none'")
		h.Set("Referrer-Policy", "no-referrer")
		h.Set("Cache-Control", "no-store")
		next.ServeHTTP(w, r)
	})
}
```

```go noverify
// headers.go, lines 21–24
// TLSConfig is the server side of "enforce TLS": nothing older than TLS 1.2.
func TLSConfig() *tls.Config {
	return &tls.Config{MinVersion: tls.VersionTLS12}
}
```

`TestHeadersAndTLS` starts a real TLS server with that config and middleware, and calls it:

```text
Strict-Transport-Security: max-age=63072000; includeSubDomains
X-Content-Type-Options: nosniff
Content-Security-Policy: default-src 'self'; frame-ancestors 'none'
Referrer-Policy: no-referrer
Cache-Control: no-store
a TLS 1.1 client: true
negotiated with a normal client: TLS version 0x0304
```

- **`Strict-Transport-Security`** tells browsers to use HTTPS only for the next two years (63,072,000 seconds), so a downgrade to plain HTTP can't be forced.
- **`X-Content-Type-Options: nosniff`** stops the browser guessing a response is script when you said it was something else.
- **`Content-Security-Policy`** restricts where scripts, images and frames can come from; `default-src 'self'` means only from your own origin, and `frame-ancestors 'none'` stops other sites embedding the page.
- **`Referrer-Policy`** and **`Cache-Control: no-store`** keep URLs and sensitive responses from leaking into other sites and shared caches.
- **A TLS 1.1 client was refused** (`true` = its connection failed) because of `MinVersion: tls.VersionTLS12`, and a normal client negotiated `0x0304`, which is TLS 1.3.

Middleware is the right place: a header set per handler is a header somebody forgets on the next handler.

<Recap>

- `MinVersion: tls.VersionTLS12` refused a TLS 1.1 client; a normal client negotiated TLS 1.3.
- One middleware sets HSTS, nosniff, CSP, Referrer-Policy and Cache-Control on every response.

</Recap>

## Secrets out of Logs

*Stop 6 of 7.*

### Step 1: a type that cannot print itself

Secrets end up in logs by accident: a config struct printed at startup, an error that includes a connection string, a request dumped for debugging. The reliable defence isn't remembering to redact at each call site, it's a type whose every way of printing is redacted:

```go noverify
// redact.go, lines 5–16
// Secret never prints its value: not with %v, not through slog, not as JSON.
type Secret string

func (Secret) String() string               { return "[REDACTED]" }
func (Secret) GoString() string             { return "[REDACTED]" }
func (Secret) LogValue() slog.Value         { return slog.StringValue("[REDACTED]") }
func (Secret) MarshalText() ([]byte, error) { return []byte("[REDACTED]"), nil }

type Config struct {
	Host     string `json:"host"`
	Password Secret `json:"password"`
}
```

`Secret` overrides `String` (for `%v` and `%s`), `GoString` (for `%#v`), `LogValue` (for `log/slog`) and `MarshalText` (for JSON). A config struct holding a `Secret` then prints safely through each path:

```text
slog JSON: {"level":"INFO","msg":"starting","config":{"host":"db.internal","password":"[REDACTED]"},"password":"[REDACTED]"}
fmt %v:    {db.internal [REDACTED]}
fmt %+v:   {Host:db.internal Password:[REDACTED]}
json.Marshal: {"host":"db.internal","password":"[REDACTED]"}
the real value is still there for the code that needs it: "s3cr3t-pw"
```

Four ways to print the config, none leaked the password, and the last line shows the code that needs the real value can still get it with an explicit `string(c.Password)`. That explicit conversion is the point: getting the secret out is a visible, greppable act, and the accident is impossible.

<Gotcha>
Don't log a raw error from an operation that involved a secret (a failed login, a database dial with a password in the DSN): the error text can contain it. Log a stable message and an error *category*, and keep the detail out of the log line.
</Gotcha>

<Recap>

- A `Secret` type with `String`, `GoString`, `LogValue` and `MarshalText` redacted itself through `%v`, `%+v`, slog and JSON: 0 leaks in 4 paths.
- The real value needs an explicit conversion, so leaks become deliberate and searchable.

</Recap>

<Exercise n={1} title="Strict JSON decoder" level="easy">

Write an HTTP handler `BudgetHandler` that decodes a JSON body into a struct `BudgetRequest{AmountCents int, Category string}`. The handler must:
1. Cap the body at 512 KB with `http.MaxBytesReader`.
2. Reject unknown fields.
3. Return 400 if `AmountCents` is not positive.

<Solution>

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type BudgetRequest struct {
	AmountCents int    `json:"amount_cents"`
	Category    string `json:"category"`
}

func BudgetHandler(w http.ResponseWriter, r *http.Request) {
	r.Body = http.MaxBytesReader(w, r.Body, 512<<10)

	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()

	var req BudgetRequest
	if err := dec.Decode(&req); err != nil {
		http.Error(w, "bad request: "+err.Error(), http.StatusBadRequest)
		return
	}
	if req.AmountCents <= 0 {
		http.Error(w, "amount_cents must be positive", http.StatusBadRequest)
		return
	}
	fmt.Fprintf(w, "accepted: %d cents for %s", req.AmountCents, req.Category)
}

func main() {
	http.HandleFunc("/budget", BudgetHandler)
	fmt.Println("listening on :8080")
}
```

`DisallowUnknownFields` turns unknown JSON keys into a decode error rather than silently dropping them. `MaxBytesReader` prevents a large body from exhausting server memory.

</Solution>

</Exercise>

<Exercise n={2} title="Safe filepath containment" level="medium">

Write a function `SafeStatementPath(root, name string) (string, error)` that:
1. Joins `root` and `name` with `filepath.Join`.
2. Applies `filepath.Clean`.
3. Returns an error if the cleaned path is not strictly inside `root` (not just a prefix match — it must be a child, not a sibling).
4. Returns the clean path on success.

Test it with `"../../etc/shadow"`, `"2024/jan.pdf"`, and `"../statements-archive/old.pdf"`.

<Solution>

```go
package main

import (
	"errors"
	"fmt"
	"path/filepath"
	"strings"
)

func SafeStatementPath(root, name string) (string, error) {
	// Clean both so that a root without a trailing sep still works.
	clean := filepath.Clean(filepath.Join(root, name))
	// Use filepath.Separator to be platform-correct.
	if !strings.HasPrefix(clean, filepath.Clean(root)+string(filepath.Separator)) {
		return "", errors.New("path escapes root directory")
	}
	return clean, nil
}

func main() {
	root := "/data/statements"
	cases := []string{
		"../../etc/shadow",
		"2024/jan.pdf",
		"../statements-archive/old.pdf",
	}
	for _, c := range cases {
		path, err := SafeStatementPath(root, c)
		if err != nil {
			fmt.Printf("BLOCKED %q: %v\n", c, err)
		} else {
			fmt.Printf("ALLOWED: %s\n", path)
		}
	}
}
```

The key detail: `filepath.Clean(root)+string(filepath.Separator)` normalizes the root *and* appends the separator before the prefix check, so a sibling directory sharing a name prefix can't slip through.

</Solution>
