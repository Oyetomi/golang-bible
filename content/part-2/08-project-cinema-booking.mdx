## The problem & the design

*Stop 1 of 6.*

### Step 1: what we're building

A cinema shows *Inception* in a hall of 40 seats (rows A to E, seats 1 to 8) and *Dune* in one of 24. A customer's journey is three calls:

1. **Hold**: "reserve A7 for me while I pay." It fails if anyone else holds or has booked A7. A hold expires on its own after a couple of minutes, so a customer who closes the tab doesn't lock the seat forever.
2. **Confirm**: "I've paid, make A7 mine." It must succeed only if *this* customer still holds A7.
3. **Release**: "I changed my mind." It must free the seat only if *this* customer holds it.

The service is a Go module, `cinema`:

```text
cinema/
├── booking/            the domain: Store interface, MemoryStore, RedisStore
├── cmd/cinema/         the HTTP server and the seat-map page (index.html, embedded)
└── cmd/rush/           a load test: N customers, one seat, at the same instant
```

To run it you need Go and Docker (for Redis):

```text
$ docker run -d --name cinema-redis -p 127.0.0.1:6390:6379 redis:8-alpine
$ go run ./cmd/cinema -store redis
2026/09/27 01:05:25 cinema on http://127.0.0.1:8091, store=redis, holds last 2m0s
```

Open `http://127.0.0.1:8091`, click a green seat, and it turns amber with your outline; pay, and it goes grey. Open a second tab and you're a second customer, who sees your hold appear within a second.

### Step 2: the results, up front

Every row is the same `rush` load test: 1,000 customers, one seat, all released at the same instant.

| store | where it runs | customers told they got A7 |
|---|---|---|
| map, no lock | 1 process, via HTTP | 1 (three runs), but `-race` reports the race |
| map, no lock | 1,000 goroutines calling it directly | the process died: `fatal error: concurrent map writes` |
| map + mutex | 1 process | 1 |
| map + mutex | 3 replicas | **3** |
| Redis | 3 replicas | 1 |

And the bug that isn't about concurrent clicks at all: with holds lasting 1 second, a customer whose hold expired mid-payment and whose confirm then arrived late, **took the seat** from the customer who held it next, with the "store it in Redis" code most tutorials show. Both were charged. Stop 5 reproduces it and fixes it with two Redis commands.

## Domain & architecture

*Stop 2 of 6.*

### Step 1: the types and the Store interface

Everything the HTTP layer knows about storage is this file:

```go noverify
// Package booking holds seats for cinema customers while they pay, then
// books them. Every Store implementation must give each seat at most one
// holder at a time, however many requests arrive at once.
package booking

import (
	"context"
	"errors"
	"fmt"
	"time"
)

type Status string

const (
	Free   Status = "free"
	Held   Status = "held"   // reserved while the customer pays; expires
	Booked Status = "booked" // paid for; permanent
)

// Seat is one seat's state as the seat map shows it.
type Seat struct {
	ID     string `json:"id"`
	Status Status `json:"status"`
	User   string `json:"user,omitempty"`
}

var (
	ErrTaken     = errors.New("seat is held or booked by someone else")
	ErrNotHolder = errors.New("you don't hold this seat (or your hold expired)")
	ErrNoSeat    = errors.New("no such movie or seat")
)

// Store is what the HTTP handlers depend on. Implementations: MemoryStore
// (one process) and RedisStore (any number of processes).
type Store interface {
	Hold(ctx context.Context, movie, seat, user string, ttl time.Duration) error
	Confirm(ctx context.Context, movie, seat, user string) error
	Release(ctx context.Context, movie, seat, user string) error
	Seats(ctx context.Context, movie string) ([]Seat, error)
}

// Halls: rows × seats per row for each film we're showing.
var Halls = map[string]struct{ Rows, Cols int }{
	"inception": {Rows: 5, Cols: 8}, // A1 … E8
	"dune":      {Rows: 4, Cols: 6}, // A1 … D6
}

// SeatIDs lists a hall's seats in order: A1, A2, … B1, …
func SeatIDs(movie string) ([]string, error) {
	h, ok := Halls[movie]
	if !ok {
		return nil, ErrNoSeat
	}
	ids := make([]string, 0, h.Rows*h.Cols)
	for r := range h.Rows {
		for c := range h.Cols {
			ids = append(ids, fmt.Sprintf("%c%d", 'A'+r, c+1))
		}
	}
	return ids, nil
}

func validSeat(movie, seat string) bool {
	ids, err := SeatIDs(movie)
	if err != nil {
		return false
	}
	for _, id := range ids {
		if id == seat {
			return true
		}
	}
	return false
}
```

Three things to notice:

- **The errors are the API.** `ErrTaken` means "someone else got there first" and `ErrNotHolder` means "you're not (or no longer) the one holding it". The handlers turn both into HTTP 409, and anything else into 500. `errors.Is`, not string comparison.
- **`Store` is the whole contract.** Four methods, each taking the customer's identity, each atomic with respect to the others. The handlers depend on this interface; `main` decides which implementation to pass in. That's **dependency injection**: swapping the in-memory store for Redis is a flag, not a rewrite, and tests can pass whichever store they like.
- **The hall layout is fixed.** Seat IDs come from `Halls`, so `Seats` never has to search for keys (which matters in Redis, stop 5).

### Step 2: why the interface is shaped like this

A simpler design would be one method, `Book(seat)`. Real checkouts don't work like that: the time between "I want this seat" and "my card went through" is seconds to minutes, and during that time nobody else may take the seat, *and* the seat must come back if the customer disappears. That's why there are three operations and why each one names the user: `Confirm` and `Release` are only valid for the customer who holds the seat, and enforcing that is the store's job, not the handler's. The late-customer bug in stop 5 is exactly what happens when a store forgets it.

## Store v1: a map without a lock

*Stop 3 of 6.*

### Step 1: the store

The in-memory store keeps every seat in a map, keyed `"movie/seat"`. Each method does a **check** ("is this seat free?", "does this user hold it?") and then an **act** (write the map):

```go noverify
package booking

import (
	"context"
	"sync"
	"time"
)

// MemoryStore keeps seats in a map guarded by one mutex. It is correct
// inside one process, and only inside one process.
type MemoryStore struct {
	mu    sync.Mutex
	seats map[string]entry // "movie/seat" → state; guarded by mu
	now   func() time.Time

	// Unsafe skips the mutex. It exists only so the chapter can run this
	// exact code without its lock and show what goes wrong.
	Unsafe bool
}

type entry struct {
	status  Status
	user    string
	expires time.Time // for holds
}

func NewMemoryStore() *MemoryStore {
	return &MemoryStore{seats: map[string]entry{}, now: time.Now}
}

func (s *MemoryStore) lock() {
	if !s.Unsafe {
		s.mu.Lock()
	}
}

func (s *MemoryStore) unlock() {
	if !s.Unsafe {
		s.mu.Unlock()
	}
}

// current returns the seat's state, treating an expired hold as free.
// The caller holds the lock.
func (s *MemoryStore) current(key string) (entry, bool) {
	e, ok := s.seats[key]
	if ok && e.status == Held && !s.now().Before(e.expires) {
		return entry{}, false
	}
	return e, ok
}

func (s *MemoryStore) Hold(_ context.Context, movie, seat, user string, ttl time.Duration) error {
	if !validSeat(movie, seat) {
		return ErrNoSeat
	}
	key := movie + "/" + seat
	s.lock()
	defer s.unlock()
	if _, taken := s.current(key); taken { // check…
		return ErrTaken
	}
	s.seats[key] = entry{status: Held, user: user, expires: s.now().Add(ttl)} // …then act
	return nil
}

func (s *MemoryStore) Confirm(_ context.Context, movie, seat, user string) error {
	key := movie + "/" + seat
	s.lock()
	defer s.unlock()
	e, ok := s.current(key)
	if !ok || e.status != Held || e.user != user {
		return ErrNotHolder
	}
	s.seats[key] = entry{status: Booked, user: user}
	return nil
}

func (s *MemoryStore) Release(_ context.Context, movie, seat, user string) error {
	key := movie + "/" + seat
	s.lock()
	defer s.unlock()
	e, ok := s.current(key)
	if !ok || e.status != Held || e.user != user {
		return ErrNotHolder
	}
	delete(s.seats, key)
	return nil
}

func (s *MemoryStore) Seats(_ context.Context, movie string) ([]Seat, error) {
	ids, err := SeatIDs(movie)
	if err != nil {
		return nil, err
	}
	s.lock()
	defer s.unlock()
	out := make([]Seat, len(ids))
	for i, id := range ids {
		out[i] = Seat{ID: id, Status: Free}
		if e, ok := s.current(movie + "/" + id); ok {
			out[i] = Seat{ID: id, Status: e.status, User: e.user}
		}
	}
	return out, nil
}
```

The `Unsafe` flag makes `lock` and `unlock` do nothing. It exists only so this chapter can run the same code with and without its mutex; with `Unsafe` set, this is the store most people write first.

### Step 2: the load test passes

`rush` releases 1,000 customers at the same instant, each asking the server to hold A7:

```go noverify
// rush: -users customers all try to hold the same seat at the same moment,
// spread across one or more replicas of the cinema service.
package main

import (
	"encoding/json"
	"flag"
	"fmt"
	"net/http"
	"strings"
	"sync"
	"sync/atomic"
)

func main() {
	replicas := flag.String("urls", "http://127.0.0.1:8091", "comma-separated replicas")
	users := flag.Int("users", 1000, "customers")
	seat := flag.String("seat", "A7", "seat everyone wants")
	flag.Parse()
	urls := strings.Split(*replicas, ",")

	var won, taken, other atomic.Int64
	var winners sync.Map
	start := make(chan struct{})
	var wg sync.WaitGroup
	for i := range *users {
		wg.Go(func() {
			base := urls[i%len(urls)] // round-robin, like a load balancer
			user := fmt.Sprintf("user-%04d", i)
			req, _ := http.NewRequest("POST", base+"/movies/inception/seats/"+*seat+"/hold", nil)
			req.Header.Set("X-User", user)
			<-start // everyone clicks at once
			resp, err := http.DefaultClient.Do(req)
			if err != nil {
				other.Add(1)
				return
			}
			resp.Body.Close()
			switch resp.StatusCode {
			case http.StatusCreated:
				won.Add(1)
				winners.Store(user, base)
			case http.StatusConflict:
				taken.Add(1)
			default:
				other.Add(1)
			}
		})
	}
	close(start)
	wg.Wait()
	fmt.Printf("%d customers, %d replica(s): %d got the seat, %d were told it's taken, %d errors\n",
		*users, len(urls), won.Load(), taken.Load(), other.Load())

	for _, base := range urls {
		resp, err := http.Get(base + "/movies/inception/seats")
		if err != nil {
			fmt.Println(base, err)
			continue
		}
		var seats []struct{ ID, Status, User string }
		json.NewDecoder(resp.Body).Decode(&seats)
		resp.Body.Close()
		for _, s := range seats {
			if s.ID == *seat {
				fmt.Printf("  %s says %s is %s by %s\n", base, s.ID, s.Status, s.User)
			}
		}
	}
}
```

### Step 3: the test that calls the store directly

The race is in the store, so test the store: 1,000 goroutines released at once, calling `Hold` directly, with and without the lock.

```go noverify
package booking

import (
	"context"
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
	"time"
)

// rush makes n goroutines hold the same seat at the same moment and
// returns how many were told they got it.
func rush(s Store, n int) int64 {
	var won atomic.Int64
	start := make(chan struct{})
	var wg sync.WaitGroup
	for i := range n {
		wg.Go(func() {
			<-start
			if s.Hold(context.Background(), "inception", "A7", fmt.Sprint("user-", i), time.Minute) == nil {
				won.Add(1)
			}
		})
	}
	close(start)
	wg.Wait()
	return won.Load()
}

func TestOneWinner(t *testing.T) {
	for _, unsafe := range []bool{true, false} {
		t.Run(fmt.Sprintf("unsafe=%v", unsafe), func(t *testing.T) {
			for round := range 5 {
				s := NewMemoryStore()
				s.Unsafe = unsafe
				if won := rush(s, 1000); won != 1 {
					t.Errorf("round %d: %d customers were told they have seat A7", round, won)
				}
			}
		})
	}
}
```

```text
$ go test ./booking/
```

## Store v2: a mutex

*Stop 4 of 6.*

### Step 1: the same code, with its lock

Without `Unsafe`, every method takes `s.mu` before the check and releases it after the act, so no other request can run between them. That's the whole fix, and it's already in the file above: `lock()` at the top of each method, `defer unlock()` right after.

```text
$ go test -race -count=1 -run 'TestOneWinner/unsafe=false' ./booking/
ok  	cinema/booking	1.821s
$ go run ./cmd/cinema -store locked &
$ go run ./cmd/rush -users 1000
1000 customers, 1 replica(s): 1 got the seat, 999 were told it's taken, 0 errors
```

Five rounds of 1,000 goroutines, one winner each, no race reports.

<Callout kind="note" title="Mutex or RWMutex?">

`Seats` only reads, so it could take a read lock (`sync.RWMutex.RLock`) and let many seat-map refreshes run at once. With 40 seats and a lock held for microseconds, it made no measurable difference here, so the store uses a plain `sync.Mutex`: one kind of lock, nothing to get wrong. Switch when a profile shows readers queueing behind each other.

</Callout>

### Step 2: three replicas

## Store v3: Redis

*Stop 5 of 6.*

### Step 1: one key per seat, one command per decision

Move the seat state to a place every replica shares. **Redis** fits well: it keeps keys in memory, runs commands one at a time (so a single command can't be interleaved with another), and can expire a key by itself. Each seat is one key, `seat:inception:A7`, whose value says who holds or booked it: `held:alice` or `booked:alice`.

```go noverify
package booking

import (
	"context"
	"errors"
	"strings"
	"time"

	"github.com/redis/go-redis/v9"
)

// RedisStore keeps each seat as one Redis key, so every replica of the
// service sees the same seats. Values are "held:<user>" or "booked:<user>".
// It needs Redis 8.4 or later for SET … IFEQ and DELEX.
type RedisStore struct {
	rdb *redis.Client
}

func NewRedisStore(rdb *redis.Client) *RedisStore { return &RedisStore{rdb: rdb} }

func seatKey(movie, seat string) string { return "seat:" + movie + ":" + seat }

// Hold: SET key held:<user> NX PX <ttl>. NX makes it succeed only if the
// key doesn't exist; Redis runs commands one at a time, so of any number
// of concurrent holds exactly one gets OK.
func (s *RedisStore) Hold(ctx context.Context, movie, seat, user string, ttl time.Duration) error {
	if !validSeat(movie, seat) {
		return ErrNoSeat
	}
	err := s.rdb.SetArgs(ctx, seatKey(movie, seat), "held:"+user, redis.SetArgs{Mode: "NX", TTL: ttl}).Err()
	if errors.Is(err, redis.Nil) {
		return ErrTaken
	}
	return err
}

// Confirm: SET key booked:<user> IFEQ held:<user>. It succeeds only if this
// user's hold is still there, and because it has no expiry option it also
// removes the hold's TTL: one atomic command.
func (s *RedisStore) Confirm(ctx context.Context, movie, seat, user string) error {
	err := s.rdb.Do(ctx, "SET", seatKey(movie, seat), "booked:"+user, "IFEQ", "held:"+user).Err()
	if errors.Is(err, redis.Nil) {
		return ErrNotHolder
	}
	return err
}

// Release: DELEX key IFEQ held:<user>. Deletes the key only if it is still
// this user's hold.
func (s *RedisStore) Release(ctx context.Context, movie, seat, user string) error {
	n, err := s.rdb.Do(ctx, "DELEX", seatKey(movie, seat), "IFEQ", "held:"+user).Int()
	if err != nil {
		return err
	}
	if n == 0 {
		return ErrNotHolder
	}
	return nil
}

// Seats reads every seat of the hall with one MGET.
func (s *RedisStore) Seats(ctx context.Context, movie string) ([]Seat, error) {
	ids, err := SeatIDs(movie)
	if err != nil {
		return nil, err
	}
	keys := make([]string, len(ids))
	for i, id := range ids {
		keys[i] = seatKey(movie, id)
	}
	vals, err := s.rdb.MGet(ctx, keys...).Result()
	if err != nil {
		return nil, err
	}
	out := make([]Seat, len(ids))
	for i, id := range ids {
		out[i] = Seat{ID: id, Status: Free}
		if v, ok := vals[i].(string); ok {
			status, user, _ := strings.Cut(v, ":")
			out[i] = Seat{ID: id, Status: Status(status), User: user}
		}
	}
	return out, nil
}

// NaiveRedisStore is the version most tutorials show: confirm with a plain
// SET plus PERSIST, release with a plain DEL. Neither checks who holds the
// seat. It exists so the chapter can show what that costs.
type NaiveRedisStore struct{ *RedisStore }

func (s NaiveRedisStore) Confirm(ctx context.Context, movie, seat, user string) error {
	key := seatKey(movie, seat)
	if err := s.rdb.Set(ctx, key, "booked:"+user, 0).Err(); err != nil {
		return err
	}
	return s.rdb.Persist(ctx, key).Err()
}

func (s NaiveRedisStore) Release(ctx context.Context, movie, seat, user string) error {
	return s.rdb.Del(ctx, seatKey(movie, seat)).Err()
}
```

Each operation is **one** Redis command, so the check and the act can't be separated:

| operation | command | succeeds only if |
|---|---|---|
| Hold | `SET seat:… held:<user> NX PX 120000` | the key doesn't exist (**N**ot e**X**ists), and it expires in 2 minutes |
| Confirm | `SET seat:… booked:<user> IFEQ held:<user>` | the value is still this user's hold; no expiry option, so the TTL is removed |
| Release | `DELEX seat:… IFEQ held:<user>` | the value is still this user's hold |
| Seats | `MGET` of all 40 seat keys | (a read; one round trip) |

`SET … IFEQ` and `DELEX` were added in Redis 8.4 (`COMMAND DOCS DELEX` says "since 8.4.0"); on older versions, the same compare-and-act runs as a short Lua script, shown in exercise 5. Note what `Seats` doesn't use: `KEYS seat:inception:*`, which scans every key in Redis and blocks all other clients while it does. The hall layout gives us the key names, so one `MGET` reads them all.

### Step 2: holds that expire on their own

With `-hold 5s`, a hold's whole life fits in a terminal:

```text
$ curl -X POST -H "X-User: alice" .../A7/hold
201
$ curl -X POST -H "X-User: bob" .../A7/hold
{"error":"seat is held or booked by someone else"}
409
$ redis-cli GET seat:inception:A7
held:alice
$ redis-cli PTTL seat:inception:A7
4868
# 5.2 s later
$ redis-cli EXISTS seat:inception:A7
0
{"id":"A7","status":"free"}
$ curl -X POST -H "X-User: bob" .../A7/hold
201
```

Alice held A7, didn't pay, and 5 seconds later Redis deleted the key: A7 was free again and Bob got it. No cleanup job, no cron, nothing that can itself crash. That's the reason to use a TTL.

### Step 3: the customer who comes back late

The TTL has a consequence. Alice holds A7, and her bank's 3-D Secure page takes longer than the hold. Her hold expires; Bob holds A7; then Alice's payment succeeds and her browser calls confirm. What happens depends on whether `Confirm` checks who holds the seat.

`late.sh` runs exactly that against a real server with 1-second holds. First against `NaiveRedisStore`: the `Confirm` (plain `SET` + `PERSIST`) and `Release` (plain `DEL`) that most "seat booking with Redis" tutorials show, and that an earlier edition of this chapter used:

<UnderTheHood title="Why one Redis command is atomic, and what that doesn't cover">

Redis executes commands on one thread, one at a time. Since Redis 6 it can use extra threads to read requests from sockets and write replies, but command execution stays single-threaded, so `SET … NX`, `SET … IFEQ` and `DELEX … IFEQ` each run start to finish with no other command in between. That's why each store method is exactly one command: a `GET` followed by a `SET` from Go would be the check-then-act race again, just with a network hop in the middle.

It doesn't make Redis a perfect lock service. With a single primary, a crash can lose the last writes that weren't persisted (`appendonly yes` with `appendfsync everysec` loses up to a second). With replication, a failover can promote a replica that hadn't received the latest hold. For seat holds that's an acceptable, rare, recoverable problem, and the payment step is where money is protected (by idempotency keys, Part 1 chapter 24). If a double booking must be impossible even across failures, the booking belongs in a database transaction with a unique constraint on (show, seat).

</UnderTheHood>

## The web API & the seat map

*Stop 6 of 6.*

### Step 1: the server

```go noverify
// cinema serves the seat map and the hold → confirm → release API.
//
//	go run ./cmd/cinema -store redis -addr :8091
package main

import (
	"context"
	"embed"
	"encoding/json"
	"errors"
	"flag"
	"log"
	"net/http"
	"time"

	"cinema/booking"

	"github.com/redis/go-redis/v9"
)

//go:embed index.html
var static embed.FS

type api struct {
	store booking.Store
	hold  time.Duration
}

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(v)
}

// fail maps store errors to HTTP statuses: the customer's problem (409, 404)
// or ours (500).
func fail(w http.ResponseWriter, err error) {
	switch {
	case errors.Is(err, booking.ErrTaken), errors.Is(err, booking.ErrNotHolder):
		writeJSON(w, http.StatusConflict, map[string]string{"error": err.Error()})
	case errors.Is(err, booking.ErrNoSeat):
		writeJSON(w, http.StatusNotFound, map[string]string{"error": err.Error()})
	default:
		log.Printf("store error: %v", err)
		writeJSON(w, http.StatusInternalServerError, map[string]string{"error": "internal error"})
	}
}

// seatAction wraps a hold/confirm/release call: it reads the path and the
// X-User header and turns the result into a response.
func (a *api) seatAction(ok int, do func(ctx context.Context, movie, seat, user string) error) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		user := r.Header.Get("X-User")
		if user == "" {
			writeJSON(w, http.StatusBadRequest, map[string]string{"error": "X-User header required"})
			return
		}
		if err := do(r.Context(), r.PathValue("movie"), r.PathValue("seat"), user); err != nil {
			fail(w, err)
			return
		}
		w.WriteHeader(ok)
	}
}

// newMux wires the routes. Tests call it with any Store.
func newMux(a *api) *http.ServeMux {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /movies/{movie}/seats", func(w http.ResponseWriter, r *http.Request) {
		seats, err := a.store.Seats(r.Context(), r.PathValue("movie"))
		if err != nil {
			fail(w, err)
			return
		}
		writeJSON(w, http.StatusOK, seats)
	})
	mux.HandleFunc("POST /movies/{movie}/seats/{seat}/hold", a.seatAction(http.StatusCreated,
		func(ctx context.Context, movie, seat, user string) error {
			return a.store.Hold(ctx, movie, seat, user, a.hold)
		}))
	mux.HandleFunc("POST /movies/{movie}/seats/{seat}/confirm", a.seatAction(http.StatusOK, a.store.Confirm))
	mux.HandleFunc("DELETE /movies/{movie}/seats/{seat}/hold", a.seatAction(http.StatusNoContent, a.store.Release))
	mux.Handle("GET /", http.FileServerFS(static))
	return mux
}

func main() {
	addr := flag.String("addr", "127.0.0.1:8091", "listen address")
	kind := flag.String("store", "locked", "unsafe | locked | redis | redis-naive")
	redisAddr := flag.String("redis", "127.0.0.1:6390", "Redis address")
	hold := flag.Duration("hold", 2*time.Minute, "how long a hold lasts")
	flag.Parse()

	var store booking.Store
	switch *kind {
	case "unsafe":
		s := booking.NewMemoryStore()
		s.Unsafe = true
		store = s
	case "locked":
		store = booking.NewMemoryStore()
	case "redis", "redis-naive":
		rdb := redis.NewClient(&redis.Options{Addr: *redisAddr})
		if err := rdb.Ping(context.Background()).Err(); err != nil {
			log.Fatal(err)
		}
		store = booking.NewRedisStore(rdb)
		if *kind == "redis-naive" {
			store = booking.NaiveRedisStore{RedisStore: store.(*booking.RedisStore)}
		}
	default:
		log.Fatalf("unknown -store %q", *kind)
	}
	a := &api{store: store, hold: *hold}

	log.Printf("cinema on http://%s, store=%s, holds last %v", *addr, *kind, *hold)
	log.Fatal(http.ListenAndServe(*addr, newMux(a)))
}
```

The shape worth copying:

- **Routes use Go 1.22 patterns.** `"POST /movies/{movie}/seats/{seat}/hold"` matches the method and the path, and `r.PathValue("seat")` reads the wildcard: no router library.
- **One wrapper, three actions.** `seatAction` reads the path and the `X-User` header, calls the store method, and maps errors: `ErrTaken` and `ErrNotHolder` to 409, `ErrNoSeat` to 404, anything else to a logged 500. `a.store.Confirm` and `a.store.Release` are passed as **method values**: functions with their receiver already bound.
- **`newMux` is separate from `main`**, so a test can build the same routes around any store.
- **The page is embedded.** `//go:embed index.html` compiles the file into the binary, and `http.FileServerFS(static)` serves it: one file to deploy.

`X-User` stands in for authentication here; in a real service the user comes from a verified session or token (Part 1 chapter 16), never from a header the client chooses (Part 1 chapter 20, Auth & API Design).

```go noverify
import (

func TestSeatFlow(t *testing.T) {
	srv := httptest.NewServer(newMux(&api{store: booking.NewMemoryStore(), hold: time.Minute}))

	steps := []struct {

		{"alice holds A7", "POST", "/movies/inception/seats/A7/hold", "alice", http.StatusCreated},
		{"bob can't hold A7", "POST", "/movies/inception/seats/A7/hold", "bob", http.StatusConflict},
		{"bob can't confirm A7", "POST", "/movies/inception/seats/A7/confirm", "bob", http.StatusConflict},
		{"no user header", "POST", "/movies/inception/seats/A8/hold", "", http.StatusBadRequest},
		{"no such seat", "POST", "/movies/inception/seats/Z9/hold", "alice", http.StatusNotFound},
		{"no such movie", "GET", "/movies/barbie/seats", "", http.StatusNotFound},
		{"alice confirms A7", "POST", "/movies/inception/seats/A7/confirm", "alice", http.StatusOK},
		{"alice can't release a booked seat", "DELETE", "/movies/inception/seats/A7/hold", "alice", http.StatusConflict},
	}
	for _, st := range steps { // in order: each step depends on the ones before
		req, _ := http.NewRequest(st.method, srv.URL+st.path, nil)
		if st.user != "" {
			req.Header.Set("X-User", st.user)
		}
		resp, err := http.DefaultClient.Do(req)
		if err != nil {
			t.Fatalf("%s: %v", st.name, err)
		}
		resp.Body.Close()
		if resp.StatusCode != st.want {
			t.Errorf("%s: got %d, want %d", st.name, resp.StatusCode, st.want)
		}
	}
}
```

<Exercise n={1} title="Two tabs, one seat" level="easy">

Run `-store redis`, open the seat map in two tabs, and hold the same seat in both. Then do the same with `curl` and explain the status codes and the body.

<Solution>

<Exercise n={2} title="Limit holds per customer" level="medium">

```go
func TestHoldLimit(t *testing.T) {
	s := NewMemoryStore()
	var ok, limited atomic.Int64
	var wg sync.WaitGroup
	for i := range 20 { // one customer, 20 tabs, 20 different seats at once
		wg.Go(func() {
			err := s.Hold(context.Background(), "inception", fmt.Sprintf("B%d", i%8+1), "greedy", time.Minute)
			switch {
			case err == nil:
				ok.Add(1)
			case errors.Is(err, ErrTooManyHolds):

			}
		})
	}
```

<Exercise n={3} title="Watch a hold expire" level="easy">

Run the server with `-hold 5s`, hold a seat with `curl`, and use `redis-cli PTTL` to watch it count down. What does the seat map show after 5 seconds, and why is no Go code involved?

<Solution>

The chapter's transcript: `PTTL` returned 4868 ms right after the hold, `EXISTS` returned 0 at 5.2 s, and `GET /seats` showed A7 as free. Redis deletes the key itself when its TTL runs out (lazily when it's next accessed, and in a background sweep otherwise), so `MGET` simply finds nothing and `Seats` reports the seat free. There's no timer in the Go service, which is the point: a crashed or redeployed replica can't forget to release anything.

</Solution>

</Exercise>

<Exercise n={4} title="Make the late customer's experience right" level="medium">

With the correct store, Alice's late confirm gets 409. Her card was charged. Describe what the checkout should do, in order, and which part must be idempotent.

<Solution>

1. **Hold** the seat, then **authorize** the card (reserve the money, don't capture it).
2. **Confirm** the seat with `SET … IFEQ`.
3. If confirm succeeded, **capture** the payment. If it returned 409 (the hold expired and the seat may be someone else's), **void** the authorization and tell Alice her hold ran out, offering the next best seat.

Capture and void must be idempotent (keyed by the booking attempt) because the service can crash between steps and retry, which Part 1 chapter 24 measured going wrong without an idempotency key. Ordering it this way means money is only taken once the seat is certainly hers. Charging first and hoping confirm succeeds is how the naive store charged both customers.

</Solution>

</Exercise>

<Exercise n={5} title="Redis older than 8.4" level="hard">

`SET … IFEQ` and `DELEX` need Redis 8.4. Write `Release` and `Confirm` for older Redis with Lua scripts, and check them with `redis-cli EVAL`.

<Solution>

A Lua script runs atomically inside Redis, like a single command:

```text
$ L="if redis.call('GET', KEYS[1]) == ARGV[1] then return redis.call('DEL', KEYS[1]) else return 0 end"
$ redis-cli SET seat:inception:A7 held:bob PX 60000
OK
$ redis-cli EVAL "$L" 1 seat:inception:A7 held:alice     # alice's late release
0
$ redis-cli GET seat:inception:A7
held:bob
$ redis-cli EVAL "$L" 1 seat:inception:A7 held:bob       # bob's release
1

$ C="if redis.call('GET', KEYS[1]) == ARGV[1] then return redis.call('SET', KEYS[1], ARGV[2]) else return false end"
$ redis-cli SET seat:inception:A7 held:bob PX 60000
OK
$ redis-cli EVAL "$C" 1 seat:inception:A7 held:alice booked:alice

$ redis-cli EVAL "$C" 1 seat:inception:A7 held:bob booked:bob
OK
$ redis-cli PTTL seat:inception:A7
-1
```

In Go, `redis.NewScript(L)` and `script.Run(ctx, rdb, []string{key}, "held:"+user)` load the script once and call it by its SHA afterwards. The plain `SET` inside the confirm script has no expiry option, so it removes the TTL (`PTTL` −1), as `SET … IFEQ` does.

</Solution>

</Exercise>

import (
	"errors"
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

var (
	ErrTaken     = errors.New("seat is held or booked by someone else")
	ErrNotHolder = errors.New("you don't hold this seat (or your hold expired)")
)

type entry struct {
	status  string // "held" or "booked"
	user    string
	expires time.Time // for holds
}

// Store holds and books seats. now is the clock: time.Now in the service,
// a clock the checks move forward by hand here.
type Store struct {
	mu    sync.Mutex
	seats map[string]entry // guarded by mu
	now   func() time.Time
}

// current returns the seat's state, treating an expired hold as free.
// The caller holds s.mu.
func (s *Store) current(seat string) (entry, bool) {
	e, ok := s.seats[seat]
	if ok && e.status == "held" && !s.now().Before(e.expires) {
		return entry{}, false
	}
	return e, ok
}

// Hold is correct: check and act under one lock, expired holds count as free.
func (s *Store) Hold(seat, user string, ttl time.Duration) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	if _, taken := s.current(seat); taken {
		return ErrTaken
	}
	s.seats[seat] = entry{status: "held", user: user, expires: s.now().Add(ttl)}
	return nil
}

// Confirm and Release are the functions you edit.
//
// BUG 1: Confirm books the seat for user without checking that user still
// holds it. A customer whose hold expired takes the seat from whoever holds
// it now, and both get charged.
// BUG 2: Release deletes the seat without checking who holds it. A late
// "release" frees someone else's hold.
func (s *Store) Confirm(seat, user string) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.seats[seat] = entry{status: "booked", user: user}
	return nil
}

func (s *Store) Release(seat, user string) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	delete(s.seats, seat)
	return nil
}

// ── below this line: do not edit ──

func (s *Store) state(seat string) string {
	s.mu.Lock()
	defer s.mu.Unlock()
	if e, ok := s.current(seat); ok {
		return e.status + " by " + e.user
	}
	return "free"
}

func main() {
	clock := time.Date(2026, 9, 26, 20, 0, 0, 0, time.UTC)
	s := &Store{seats: map[string]entry{}, now: func() time.Time { return clock }}
	allOK := true
	check := func(name string, got, want any) {

			}

	check("alice holds B4", s.Hold("B4", "alice", 2*time.Minute), nil)

	check("bob holds B4 after alice's hold expired", s.Hold("B4", "bob", 2*time.Minute), nil)

<Recap>

- **Hold → confirm → release** is the real checkout shape: a hold must be exclusive and must expire; confirm and release are valid only for the current holder.
- **A map without a lock** passed a 1,000-customer HTTP load test and still wasn't correct: `-race` reported it, and calling `Hold` from 1,000 goroutines directly crashed the process with `fatal error: concurrent map writes`, every time.
- **A mutex** made the store correct in one process (1 winner, race-free) and three replicas sold A7 **three times**: locks protect a process's memory, not state shared between processes.
- **Redis** gave one winner across three replicas, each operation one atomic command: `SET NX PX` to hold, `SET … IFEQ` to confirm (and drop the TTL), `DELEX … IFEQ` to release, `MGET` to read the hall. Holds expired on their own (measured 5 s).
- **Expiry cuts both ways.** A naive confirm (`SET` + `PERSIST`) and release (`DEL`) let a late customer take or free someone else's seat: both customers charged, three customers for one seat. The ownership check fixed both.
- **Architecture:** handlers depend on a `Store` interface chosen in `main`; `newMux` is testable with `httptest` and a `MemoryStore`; the page is embedded with `go:embed`. `X-User` stands in for real authentication.

</Recap>
