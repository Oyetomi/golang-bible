## go vet

*Stop 1 of 7.*

### Step 1: a pull request that passes its tests

The branch `occupancy` adds the report to the store, an admin endpoint that serves it, and a test for each:

```go noverify
package booking

// Occupancy counts a hall's held and booked seats, for the box office.
func (s MemoryStore) Occupancy(movie string) (held, booked int) {
	s.lock()
	defer s.unlock()
	for _, id := range seatIDs[movie] {
		if e, ok := s.current(movie + "/" + id); ok {
			switch e.status {
			case Held:
				held++
			case Booked:
				booked++
			}
		}
	}
	return held, booked
}
```

```go noverify
package main

import (
	"context"
	"log"
	"net/http"
	"time"

	"cinema/booking"
)

// occupancy serves GET /admin/occupancy/{movie}: how full is the hall?
func (a *api) occupancy(w http.ResponseWriter, r *http.Request) {
	movie := r.PathValue("movie")
	ctx, _ := context.WithTimeout(r.Context(), time.Second)
	seats, err := a.store.Seats(ctx, movie)
	if err != nil {
		fail(w, err)
		return
	}
	var held, booked int
	for _, s := range seats {
		switch s.Status {
		case booking.Held:
			held++
		case booking.Booked:
			booked++
		}
	}
	log.Printf("occupancy %s: %d held, %d booked", movie, held)
	writeJSON(w, http.StatusOK, map[string]int{"held": held, "booked": booked, "seats": len(seats)})
}
```

The booking package's tests **pass**. The handler's package didn't even build its tests, and the message comes from vet: `go test` runs a small, high-confidence subset of vet's checks (`atomic`, `bools`, `buildtag`, `directive`, `errorsas`, `ifaceassert`, `nilfunc`, `printf`, `stdversion`, `stringintconv`, `tests`) before every test run. Two of the three bugs aren't in that subset.

### Step 2: the whole of vet

```text
$ go vet ./...
booking/occupancy.go:4:9: Occupancy passes lock by value: cinema/booking.MemoryStore contains sync.Mutex
cmd/cinema/occupancy.go:15:7: the cancel function returned by context.WithTimeout should be called, not discarded, to avoid a context leak
cmd/cinema/occupancy.go:30:37: log.Printf format %d reads arg #3, but call has 2 args
```

Three findings, and each is a real defect:

- **copylocks**: `Occupancy` has a value receiver, so every call copies `MemoryStore`, including its `sync.Mutex`.
- **printf**: the format has three verbs and two arguments; the log would say `%!d(MISSING)` booked.
- **lostcancel**: the timeout's cancel function is thrown away, so the context's timer lives until it fires, a second after every request.

vet works from the code's types and structure, not from running it. That's why it finds bugs that tests, which only see the timings and inputs they happen to produce, can miss.

### Step 3: what the copied lock does

Is copylocks pedantry? A test in which the box office asks for the occupancy while customers are holding seats:

```go noverify
package booking

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

// The box office polls Occupancy while customers hold seats.
func TestOccupancyWhileHolding(t *testing.T) {
	s := NewMemoryStore()
	var wg sync.WaitGroup
	wg.Go(func() {
		for i := range 40 {
			if err := s.Hold(context.Background(), "inception", fmt.Sprintf("%c%d", 'A'+i/8, 1+i%8), fmt.Sprint("user", i), time.Minute); err != nil {
				t.Error(err)
			}
		}
	})
	wg.Go(func() {
		for range 40 {
			s.Occupancy("inception")
		}
	})
	wg.Wait()
}
```

The race detector saw `Occupancy` reading the store (to copy it) while `Hold` was writing the mutex: the copy's lock is a *different* lock, so it protects nothing about the seat map both of them share. And the test hung: look at the copied receiver in the stack, `{{{}, {0x1, 0x0}}…`. The mutex's state word is **1, locked**. The copy was taken while `Hold` held the lock, so `Occupancy` got a locked mutex that nobody will ever unlock, and waited on it forever.

### Step 1: dozens of linters, one run

`golangci-lint` runs many analyzers (vet's among them) in one process, sharing the parsed and type-checked code. With no configuration, v2 runs the `standard` set: `errcheck`, `govet`, `ineffassign`, `staticcheck`, `unused`. On the cinema module:

Fourteen unchecked errors: four in the new tests, ten in code that has passed review since chapter 8. The job isn't to make the number zero, it's to decide about each one. Three answers:

**Fix it**, when ignoring the error is a bug:

- `cmd/idem`: if `os.WriteFile("told.json")` fails, `-verify` compares against the file from an *earlier* run and prints plausible, wrong results. It now stops with the error.
- `cmd/rush`: a seat map that fails to decode left `seats` empty, indistinguishable from "no seats". It now prints the error.
- The tests: a `Hold` that fails in setup should fail the test there, not three lines later with a confusing count.

**Say it on purpose**, when ignoring it is correct: `writeJSON`'s `Encode` fails only if the client has gone away mid-response, and there's no one left to tell. `_ = json.NewEncoder(w).Encode(v)`, with a comment, tells the next reader (and errcheck) that it was a decision.

**Configure it**, when a whole class is noise: `io.Copy(io.Discard, resp.Body)` and closing a response body are safe to ignore everywhere. That goes in `.golangci.yml`, once:

```text
version: "2"

run:
  build-tags: [integration] # or the linters never see those files

linters:
  default: standard # errcheck, govet, ineffassign, staticcheck, unused
  enable:
    - bodyclose  # an HTTP response body that's never closed leaks a connection
    - errorlint  # err == ErrX or err.(T) breaks on wrapped errors
    - noctx      # HTTP requests and DB calls without a context can't be cancelled
    - gosec      # security-sensitive patterns
    - misspell
  settings:
    errcheck:
      exclude-functions:
        - io.Copy               # draining a body into io.Discard
        - (io.ReadCloser).Close # closing a response body we've read
    govet:
      enable-all: true
      disable:
        - fieldalignment # memory layout advice, not bugs
        - shadow         # too noisy for err := … in nested blocks
    gosec:
      excludes:
        - G104 # unchecked errors: errcheck's job, with its exclusions above
  exclusions:
    rules:
      - path: _test\.go
        linters: [gosec, noctx]
      # Load generators and experiment tools: no cancellation needed, and
      # their randomness picks seats, not keys.
      - path: cmd/(browse|flood|hammer|idem|inflight|rush)/
        linters: [noctx]
      - path: cmd/(browse|flood|hammer|idem|inflight|rush)/
        text: G404

formatters:
  enable:
    - gofmt
    - goimports
```

## go generate

*Stop 3 of 7.*

### Step 1: a status that's a number

The seat status has been a string (`"held"`) since chapter 8, and each seat entry in `MemoryStore` carries one. As a `uint8` enum it's smaller, and it's a closed set: `ParseStatus` can reject `"hled"` coming back from Redis instead of passing it to the seat map.

```text
entry with string status: 56 bytes
entry with uint8 status:  48 bytes
```

The catch: an integer enum needs a `String` method, and writing one by hand means keeping two lists in step. **stringer** generates it from the constants. The directive sits next to the type:

```go noverify
// booking.go, lines 13–38
// Status is a seat's state. String, and the JSON and Redis spellings, are
// generated from the comments below by stringer (see status_string.go).
type Status uint8

//go:generate go tool stringer -type=Status -linecomment

const (
	Free   Status = iota // free
	Held                 // held
	Booked               // booked
)

const numStatus = Booked + 1 // keep last: ParseStatus loops up to it

// ParseStatus is the inverse of String, for values read back from Redis.
func ParseStatus(s string) (Status, error) {
	for st := range numStatus {
		if st.String() == s {
			return st, nil
		}
	}
	return 0, fmt.Errorf("unknown seat status %q", s)
}

// MarshalText makes the JSON seat map say "held", not 1.
func (s Status) MarshalText() ([]byte, error) { return []byte(s.String()), nil }
```

`go generate` doesn't run by itself. It scans the source for `//go:generate` lines and runs each command, and you commit what it writes (`status_string.go`), so a plain `go build` never needs the generator.

### Step 3: import paths, proxies and private code

**v2 and later** change the import path. go-redis is at `github.com/redis/go-redis/v9`: a new major version is, to the go command, a different module, so a program can even use v8 and v9 side by side during a migration.

**The proxy and checksum database.** By default `go get` downloads modules from `proxy.golang.org` (a cache that keeps versions available even if the repository disappears) and checks each against `sum.golang.org` (a public, append-only log of module hashes, so everyone gets the same bytes for the same version). `go.sum` records those hashes for your module. For code that isn't public, `GOPRIVATE=github.com/yourco/*` makes the go command fetch those modules directly from source control and skip the checksum database (which would otherwise learn your private module names). Authentication is then git's job: an SSH key or a token in `.netrc`.

## Exercises

These use the cinema module (a git repository) and the jobs module from this chapter.

<Exercise n={1} title="What else does vet know?" level="easy">

Run `go tool vet help` and pick three analyzers not mentioned in this chapter. For each, write a two-line program that triggers it and confirm with `go vet`.

<Solution>

Three that are easy to trigger: **unreachable** (`return 1` followed by any statement); **stringintconv** (`string(i)` for an `int i`, which gives a rune, not digits; it's also in go test's subset); **structtag** (`json:"id" xml:"id"` with a missing space or a malformed tag like `` `json:id` ``). Others worth knowing: **httpresponse** (using `resp` before checking `err`), **loopclosure** (mostly obsolete since Go 1.22's per-iteration loop variables), **unusedresult** (calling `fmt.Sprintf` and dropping the result).

</Solution>

</Exercise>

<Exercise n={2} title="Fix, annotate or configure?" level="easy">

For each finding, choose, and say why: (a) errcheck on `defer f.Close()` for a file opened for reading; (b) errcheck on `defer f.Close()` for a file you've written to; (c) gosec G404 (`math/rand`) in a function that generates password-reset tokens; (d) noctx in a test helper.

<Solution>

(a) **Configure** or annotate: closing a read-only file can't lose data. (b) **Fix**: for a written file, `Close` can be where a write error (disk full, NFS) finally appears. Check it and return it, or `Sync` first. (c) **Fix**, urgently: that's exactly the case the rule exists for. Use `crypto/rand` (`rand.Text()` since Go 1.24). (d) **Configure** by path: the config already excludes noctx in `_test.go`; tests use `t.Context()` where cancellation matters.

</Solution>

</Exercise>

<Exercise n={3} title="Break MVS on purpose" level="medium">

In a copy of the jobs module, run `go get github.com/hibiken/asynq@v0.24.1` (an older Asynq). What happens to go-redis, and why? Then run `go mod graph | grep go-redis` to confirm.

<Solution>

Nothing happens to go-redis: `go list -m` still says v9.22.0. The graph shows why: `jobs github.com/redis/go-redis/v9@v9.22.0` and `github.com/hibiken/asynq@v0.24.1 github.com/redis/go-redis/v9@v9.0.3`. jobs' own requirement is the highest minimum, so MVS keeps it. Downgrading one module only pulls another down when the thing you downgrade *required* the higher version of the other (as x/tools did with x/net). The same `go get` also printed `upgraded github.com/golang/protobuf v1.5.0 => v1.5.2`: the older Asynq happens to require a *newer* protobuf, and the highest minimum wins in that direction too.

</Solution>

</Exercise>

<Exercise n={4} title="Reproduce across machines" level="medium">

The chapter's two builds matched on one Mac. List what else must be the same for a build on a CI runner to produce the identical binary, and how you'd pin each.

<Solution>

The **Go toolchain** version (`go` and `toolchain` lines in go.mod; with `GOTOOLCHAIN` it's fetched to match), **GOOS/GOARCH** (and GOARM64 etc.), **CGO_ENABLED** (cgo pulls in the C compiler and system libraries, which differ between machines: use `CGO_ENABLED=0` for pure-Go services), **flags** (`-trimpath`, `-ldflags`, tags), the **source** (a clean checkout of the commit; `vcs.modified=false`), and **dependencies** (go.sum pins them by hash). The build info from `go version -m` lists all of these, which is how you compare two builds that differ.

</Solution>

</Exercise>

<Exercise n={5} title="A govulncheck policy" level="hard">

Your service has 3 modules and 40 dependencies. Write the rules for a CI job that runs govulncheck: what fails the build, what only warns, and what happens to a finding with no fixed version.

<Solution>

Fail on **called** vulnerabilities (govulncheck exits non-zero for those in its default mode). Report, but don't fail, on imported-but-not-called and required-but-not-imported ones: schedule upgrades, because the next change could make them reachable. For a called vulnerability **without a fix**: fail by default, and allow a recorded, expiring exception (issue link, owner, date) after someone has checked whether the vulnerable path is exploitable in your use. Run it on every pull request *and* on a schedule against main, since new vulnerabilities are published about code that hasn't changed. Scan the deployed binaries (`-mode binary`) too, to catch images built before a disclosure.

</Solution>

</Exercise>

<Lab
  title="Write the Check That Caught the Copied Lock"
  archetype="build-it"
  difficulty="guided"
  points={120}
  hintCost={15}
  verify="self-check"
  expect="ALL CHECKS PASS"
  objective="lockCopies parses one Go source file (go/parser) and must report every method with a value receiver, and every function with a value parameter, whose type holds a sync.Mutex or sync.RWMutex: directly, embedded, or inside another struct field from the same file. A pointer (to the lock or to the struct) copies no lock. This is the heart of vet's copylocks check."
  starter={`package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"slices"
	"strings"
)

// lockCopies parses one Go file and reports every function or method that
// receives, by value, a struct holding a lock: the bug vet's copylocks
// check caught in the cinema's Occupancy method. Report methods as
// "Type.Method" and functions by name, sorted.
//
// A struct holds a lock if it has a field (named or embedded) whose type is
// sync.Mutex or sync.RWMutex, or whose type is another struct in the same
// file that holds a lock. A pointer (*sync.Mutex, *MemoryStore) copies no
// lock. It is the only function you edit (you may add helpers above the line).
func lockCopies(src string) ([]string, error) {
	fset := token.NewFileSet()
	f, err := parser.ParseFile(fset, "src.go", src, 0)
	if err != nil {
		return nil, err
	}
	var found []string
	for _, decl := range f.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok {
			continue
		}
		_ = fn // look at fn.Recv and fn.Type.Params
	}
	return found, nil
}

// ── below this line: do not edit ──

func main() {
	allOK := true
	check := func(name, src string, want ...string) {
		got, err := lockCopies("package p\\n\\nimport \\"sync\\"\\n\\nvar _ sync.Mutex\\n\\n" + src)
		if err != nil {
			fmt.Printf("FAIL %s: %v\\n", name, err)
			allOK = false
			return
		}
		slices.Sort(got)
		if want == nil {
			want = []string{}
		}
		if got == nil {
			got = []string{}
		}
		if !slices.Equal(got, want) {
			fmt.Printf("FAIL %s: got [%s], want [%s]\\n", name, strings.Join(got, " "), strings.Join(want, " "))
			allOK = false
		}
	}

	store := \`
type MemoryStore struct {
	mu    sync.Mutex
	seats map[string]string
}
\`
	check("value receiver (the cinema's bug)", store+\`
func (s MemoryStore) Occupancy() int { return len(s.seats) }
func (s *MemoryStore) Hold(seat string) { s.seats[seat] = "held" }
\`, "MemoryStore.Occupancy")

	check("pointer receivers are fine", store+\`
func (s *MemoryStore) Occupancy() int { return len(s.seats) }
func (s *MemoryStore) Hold(seat string) { s.seats[seat] = "held" }
\`)

	check("embedded RWMutex", \`
type Cache struct {
	sync.RWMutex
	films []string
}
func (c Cache) Films() []string { return c.films }
func (c *Cache) Add(f string) { c.films = append(c.films, f) }
\`, "Cache.Films")

	check("a pointer to a mutex copies no lock", \`
type Counter struct {
	mu *sync.Mutex
	n  int
}
func (c Counter) Value() int { return c.n }
\`)

	check("a lock inside a struct field", store+\`
type Cinema struct {
	name  string
	store MemoryStore
}
func (c Cinema) Name() string { return c.name }
func (c *Cinema) Rename(n string) { c.name = n }
\`, "Cinema.Name")

	check("functions with a value parameter", store+\`
func report(s MemoryStore) int { return len(s.seats) }
func reportPtr(s *MemoryStore) int { return len(s.seats) }
func count(n int, s MemoryStore, m *MemoryStore) int { return n }
\`, "count", "report")

	check("structs without locks", \`
type Seat struct{ ID, Status string }
func (s Seat) Free() bool { return s.Status == "free" }
func show(s Seat) string { return s.ID }
\`)

	if allOK {
		fmt.Println("ALL CHECKS PASS")
	}
}`}

<Recap>

- **go vet** reads code, not runs: it caught a copied mutex, a missing Printf argument and a leaked cancel in a PR whose tests passed. The copied lock raced, and hung on a mutex copied in the locked state; without `-race` the test passed 10 of 10. `go test` runs only a vet subset (printf yes, copylocks no).
- **golangci-lint**: 14 findings on existing code, then 20 with more linters, triaged into fixes (two real bugs, a missing server timeout), explicit ignores, and path-scoped config. `--new-from-rev` lints only a PR's lines; `uniq-by-line` hid two vet findings behind gosec's.
- **go generate** with `go tool stringer` pins the generator in go.mod. Stringer's guard breaks the build when constants move; `go generate && git diff --exit-code` catches stale output that still compiles.
- **Build tags** keep integration tests (real Redis, one winner of 200) out of the fast path, and out of vet and lint unless they're told the tag: the untagged lint run missed a finding.
- **MVS** picks the highest minimum, never the latest (x/sys v0.37.0 with v0.48.0 available); adding a tool raised x/sys for the service. **go.work** links local modules for development and changes version selection; CI builds with `GOWORK=off`.
- **Reproducible builds**: two directories, two binaries; with `-trimpath`, identical. `go version -m` shows dependencies, flags and `vcs.revision`/`vcs.modified`.
- **govulncheck** reported 1 called vulnerability among 15 known, with the call path; `-mode binary` scans what you deploy. An SBOM lists it all for other tools. The CI pipeline runs every check in about 24 s, and stopped the buggy PR at vet in 0.6 s.

</Recap>
