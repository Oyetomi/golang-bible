Chapter 9 debugged the cinema service by stopping it, dumping it and profiling it. In production you rarely get to do that before customers notice. **Observability** is building the service so that, while it runs, you can answer questions you didn't think of in advance: is it working, for whom isn't it, and why.

2. **Metrics with Prometheus.** Counters and histograms labelled by route, scraped every 2 s, queried with PromQL.

4. **Acting on it.** An SLI, an SLO, an error budget, a burn-rate alert, and the incident: from alert to log line to trace to cause.

## The three signals

Before any code, the idea. A running service can tell you about itself in three ways, called **telemetry signals**. Each answers a different question, and one failing request shows up in all three.

<Define term="Log">
A line of text written when something happens: "this request, for this seat, failed with this error". Logs describe **individual events**, in full detail. A **structured** log is one where each line is data (here, a JSON object), so a tool can filter and group lines instead of searching text.
</Define>

<Define term="Metric">
A number kept up to date as things happen, like a tally. A **counter** only goes up ("hold requests so far: 48,211"); a **histogram** counts how many requests fell into each latency range ("under 1 ms: 40,000; 1–2.5 ms: 7,000…"). Metrics answer **how many and how fast, overall**, and cost the same whether you serve ten requests or ten million. A **label** splits one metric by a dimension, such as the route or the status code.
</Define>

<Define term="Trace and span">
A **trace** is the story of one request: every piece of work done for it, in order, with how long each took, even across several services. Each piece is a **span**. Spans nest: the request is a span, and the call to Redis inside it is a child span. Every span of one request carries the same **trace ID**.
</Define>

## Structured logging with slog

*Stop 1 of 4.*

### Step 1: one JSON line per request

`log/slog` (Go 1.21) writes **structured** logs: a message plus key-value pairs, which a JSON handler turns into one JSON object per line. The service sets it up once:

```go
slog.SetDefault(slog.New(slog.NewJSONHandler(os.Stdout, nil)))
```

The line itself is written by `observe`, a middleware that wraps every request. To log the status code, it first needs a way to learn it. A handler writes its status code to the `ResponseWriter`; nothing hands it back. `statusRecorder` wraps the writer to remember the code. It also passes `Flush` through, because wrapping a writer hides the interfaces the original had, and the seat stream needs to flush:

```go noverify title="cinema/cmd/cinema/obs.go · lines 46–61"
// statusRecorder remembers the status code a handler wrote.
type statusRecorder struct {
	http.ResponseWriter
	code int
}

func (s *statusRecorder) WriteHeader(code int) {
	s.code = code
	s.ResponseWriter.WriteHeader(code)
}

func (s *statusRecorder) Flush() {
	if f, ok := s.ResponseWriter.(http.Flusher); ok {
		f.Flush()
	}
}
```

`observe` is the middleware that produces a log line, a counter increment and a histogram observation for every request. The label is `r.Pattern`, the route as registered (`POST /movies/{movie}/seats/{seat}/hold`), never the raw path: with raw paths, every seat of every film would become its own time series. The log line carries the trace ID, which is what later links a log line to its trace:

```go noverify title="cinema/cmd/cinema/obs.go · lines 63–90"
// observe wraps the mux: one log line, one counter and one histogram
// observation per request, all labelled with the route pattern
// ("POST /movies/{movie}/seats/{seat}/hold"), never the raw path.
func observe(next *http.ServeMux) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, code: http.StatusOK}
		next.ServeHTTP(rec, r)
		took := time.Since(start)

		route := r.Pattern // set by ServeMux (Go 1.23); "" if nothing matched
		if route == "" {
			route = "unmatched"
		}
		requests.WithLabelValues(route, strconv.Itoa(rec.code)).Inc()
		latency.WithLabelValues(route).Observe(took.Seconds())

		level := slog.LevelInfo
		if rec.code >= 500 {
			level = slog.LevelError
		}
		slog.Log(r.Context(), level, "request",
			"route", route, "path", r.URL.Path, "status", rec.code,
			"ms", float64(took.Microseconds())/1000,
			"user", r.Header.Get("X-User"),
			"trace_id", trace.SpanContextFromContext(r.Context()).TraceID().String())
	})
}
```

So every request produces one line. Real lines from the running service:

```text
{"time":"2026-09-27T02:52:48.592895713Z","level":"INFO","msg":"cinema starting","addr":"0.0.0.0:8091","store":"redis","hold":"2m0s"}
{"time":"2026-09-27T02:53:14.035528711Z","level":"INFO","msg":"request","route":"POST /movies/{movie}/seats/{seat}/hold","path":"/movies/inception/seats/A7/hold","status":201,"ms":1.043,"user":"alice","trace_id":"4bf92f3577b34da6a3ce929d0e0e4736"}
```

A log pipeline (Loki, Elasticsearch, CloudWatch) can now filter on `status >= 500`, group by `route`, or find every line with one `trace_id`, without regular expressions. Two fields do the heavy lifting:

- **`route`** is the pattern the mux matched (`r.Pattern`, Go 1.23), identical for every seat. `path` is the concrete URL.
- **`trace_id`** comes from the span OpenTelemetry put in the request's context. It's the key that joins this line to the request's trace (stop 3).

### Step 2: levels, and a bug the switch to slog exposed

Requests that end in a 5xx are logged at `ERROR`. And the first time Redis went down, this line appeared:

```text
{"time":"2026-09-27T03:02:09.996938875Z","level":"INFO","msg":"store error: dial tcp: lookup cinema-redis on 127.0.0.11:53: no such host"}
```

`INFO`, for a failure. The old handler code still used `log.Printf("store error: %v", err)`; after `slog.SetDefault`, the standard `log` package writes through slog, at level INFO. Anyone alerting on `level=ERROR` would have missed it. The fix logs at the right level, with the error as a field and the trace ID:

```go noverify
// main.go, lines 46–59
// fail maps store errors to HTTP statuses: the customer's problem (409, 404)
// or ours (500).
func fail(w http.ResponseWriter, r *http.Request, err error) {
	switch {
	case errors.Is(err, booking.ErrTaken), errors.Is(err, booking.ErrNotHolder):
		writeJSON(w, http.StatusConflict, map[string]string{"error": err.Error()})
	case errors.Is(err, booking.ErrNoSeat):
		writeJSON(w, http.StatusNotFound, map[string]string{"error": err.Error()})
	default:
		slog.ErrorContext(r.Context(), "store error", "err", err,
			"trace_id", trace.SpanContextFromContext(r.Context()).TraceID().String())
		writeJSON(w, http.StatusInternalServerError, map[string]string{"error": "internal error"})
	}
}
```

```text
{"time":"2026-09-27T03:04:53.169624673Z","level":"ERROR","msg":"store error","err":"dial tcp: lookup cinema-redis on 127.0.0.11:53: no such host","trace_id":"dcb624cf5d50a3647f89b3b3f46a7197"}
{"time":"2026-09-27T03:04:53.16967309Z","level":"ERROR","msg":"request","route":"GET /movies/{movie}/seats","path":"/movies/inception/seats","status":500,"ms":91.98,"user":"","trace_id":"dcb624cf5d50a3647f89b3b3f46a7197"}
```

Two lines, one trace ID: the cause and its effect, joinable.

<Callout kind="warn" title="Never log secrets or personal data">

`user` here is a made-up guest name. Real services log a user *ID*, never passwords, tokens, card numbers or anything you'd have to delete on a privacy request. Log lines are copied to more places, and kept longer, than your database.

</Callout>

<UnderTheHood title="How slog stays cheap">

A `slog.Logger` checks the level before doing any work (`Enabled`), so a disabled `Debug` call costs a comparison. Key-value arguments are converted to `slog.Attr` values without allocating for common types (`slog.Value` stores small values inline), and the JSON handler appends directly into a pooled buffer. The `...Context` variants pass the context to the handler, which is how handlers that add the trace ID automatically work.

</UnderTheHood>

## Metrics with Prometheus

*Stop 2 of 4.*

### Step 1: counters and histograms, labelled by route

Logs describe events one at a time; **metrics** are numbers aggregated as they happen, cheap enough to keep for every request forever. The service has three (in `obs.go`):

- `cinema_http_requests_total{route, code}`: a **counter**, only ever increases.
- `cinema_http_request_duration_seconds{route}`: a **histogram**: counts of requests per latency bucket (0.5 ms, 1 ms, 2.5 ms … 1 s), from which Prometheus estimates percentiles.
- `cinema_holds_total{result}`: hold outcomes, `ok`, `taken` or `error`.

Labels are the dimensions you can slice by. Every distinct combination of label values is a separate time series stored forever, so labels must have few values: `route` is the pattern (a handful), never the path (one per seat, per movie, per user: unbounded). The lab is about exactly this.

Three metrics, registered once at package level (`promauto` registers them with the default registry, which is what `/metrics` serves). A **counter** only goes up; a **histogram** sorts each observation into buckets, which is what lets Prometheus compute percentiles later. The buckets are chosen around this service's real latencies, 0.5 ms to 1 s. Every label value creates a separate time series, so labels must come from a small, fixed set:

```go noverify title="cinema/cmd/cinema/obs.go · lines 26–44"
// ── metrics ─────────────────────────────────────────────────────────────

var (
	requests = promauto.NewCounterVec(prometheus.CounterOpts{
		Name: "cinema_http_requests_total",
		Help: "HTTP requests by route and status code.",
	}, []string{"route", "code"})

	latency = promauto.NewHistogramVec(prometheus.HistogramOpts{
		Name:    "cinema_http_request_duration_seconds",
		Help:    "HTTP request latency by route.",
		Buckets: []float64{.0005, .001, .0025, .005, .01, .025, .05, .1, .25, .5, 1},
	}, []string{"route"})

	holdsTotal = promauto.NewCounterVec(prometheus.CounterOpts{
		Name: "cinema_holds_total",
		Help: "Hold attempts by result: ok, taken, error.",
	}, []string{"result"})
)
```

### Step 2: asking questions with PromQL

<Define term="PromQL">
Prometheus's query language. A query picks time series by metric name and labels (`cinema_http_requests_total{code="500"}`) and does arithmetic over them. `rate(x[1m])` turns an ever-growing counter into "per second, averaged over the last minute"; `sum by (route)` adds series together, keeping only the `route` label.
</Define>

Reading them:

- **`rate(counter[1m])`** turns an ever-growing counter into a per-second rate over the last minute: about 2,775 seat maps a second, 23 hold attempts a second.
- **`histogram_quantile(0.99, …)`**: 99% of seat maps took under 0.97 ms, and 99% of holds under 6.3 ms. The `le` label ("less than or equal") is the bucket boundary; percentiles are interpolated within buckets, so they're only as precise as the buckets you chose.
- **Most holds are 409, and that's fine.** Every seat ends up held, so most attempts are "taken". A 409 is the service working correctly; only 5xx counts as failure. Deciding what "failure" means is the first step of an SLO.

These four questions are the **RED** method for any request-driven service: **R**ate, **E**rrors, **D**uration. For resources (CPU, connection pools, queues) the equivalent is **USE**: Utilization, Saturation, Errors.

## Distributed Tracing with OpenTelemetry

*Stop 3 of 4.*

### Step 1: a span per request, a span per store call

A **trace** is the tree of work done for one request, possibly across many services. Each unit of work is a **span**: a name, a start and end time, attributes, a status, and the ID of its parent. All spans of one request share a **trace ID**.

`otelhttp.NewHandler` starts a server span per request, named after the route pattern. `tracedStore` starts a child span around each store call, with the movie and seat as attributes, and records errors. Spans are batched and sent over OTLP to Jaeger, which stores them and has a query API.

Tracing needs one setup call: an exporter that sends spans to Jaeger over OTLP/HTTP, a provider that batches them, the service name, and the W3C `traceparent` header as the way trace IDs travel between services:

```go noverify title="cinema/cmd/cinema/obs.go · lines 92–108"
// ── tracing ─────────────────────────────────────────────────────────────

// setupTracing sends spans to an OTLP/HTTP endpoint (Jaeger, a collector).
// It returns a function that flushes and stops the exporter.
func setupTracing(ctx context.Context, endpoint string) (func(context.Context) error, error) {
	exp, err := otlptracehttp.New(ctx, otlptracehttp.WithEndpoint(endpoint), otlptracehttp.WithInsecure())
	if err != nil {
		return nil, err
	}
	tp := sdktrace.NewTracerProvider(
		sdktrace.WithBatcher(exp),
		sdktrace.WithResource(resource.NewSchemaless(semconv.ServiceName("cinema"))),
	)
	otel.SetTracerProvider(tp)
	otel.SetTextMapPropagator(propagation.TraceContext{}) // W3C traceparent header
	return tp.Shutdown, nil
}
```

`otelhttp` wraps the whole server: every request gets a span, or continues the caller's trace if a `traceparent` header arrived. Naming spans after the route pattern keeps their names few:

```go noverify title="cinema/cmd/cinema/obs.go · lines 110–121"
// traced wraps the whole server: otelhttp starts a span per request (or
// continues the caller's trace from its traceparent header), named after
// the route pattern.
func traced(h http.Handler) http.Handler {
	return otelhttp.NewHandler(h, "cinema",
		otelhttp.WithSpanNameFormatter(func(_ string, r *http.Request) string {
			if r.Pattern != "" {
				return r.Pattern
			}
			return r.Method + " " + r.URL.Path
		}))
}
```

The store is wrapped too, by embedding: `tracedStore` embeds `booking.Store`, so it satisfies the interface automatically, and overrides the methods worth tracing. Each gets a child span with the film and seat as attributes, and `end` records any error on the span:

```go noverify title="cinema/cmd/cinema/obs.go · lines 123–140"
var tracer = otel.Tracer("cinema/booking")

// tracedStore adds a child span around every store call, with the seat
// and the outcome, and counts hold results.
type tracedStore struct{ booking.Store }

func (s tracedStore) span(ctx context.Context, name, movie, seat string) (context.Context, trace.Span) {
	return tracer.Start(ctx, name, trace.WithAttributes(
		attribute.String("cinema.movie", movie), attribute.String("cinema.seat", seat)))
}

func end(sp trace.Span, err error) {
	if err != nil {
		sp.RecordError(err)
		sp.SetStatus(codes.Error, err.Error())
	}
	sp.End()
}
```

`Hold` also counts results, split into `ok`, `taken` and `error`, because "a seat was taken" is normal traffic and "the store failed" is an incident, and an alert must be able to tell them apart:

```go noverify title="cinema/cmd/cinema/obs.go · lines 142–169"
func (s tracedStore) Hold(ctx context.Context, movie, seat, user string, ttl time.Duration) error {
	ctx, sp := s.span(ctx, "store.Hold", movie, seat)
	err := s.Store.Hold(ctx, movie, seat, user, ttl)
	end(sp, err)
	switch {
	case err == nil:
		holdsTotal.WithLabelValues("ok").Inc()
	case err == booking.ErrTaken:
		holdsTotal.WithLabelValues("taken").Inc()
	default:
		holdsTotal.WithLabelValues("error").Inc()
	}
	return err
}

func (s tracedStore) Confirm(ctx context.Context, movie, seat, user string) error {
	ctx, sp := s.span(ctx, "store.Confirm", movie, seat)
	err := s.Store.Confirm(ctx, movie, seat, user)
	end(sp, err)
	return err
}

func (s tracedStore) Seats(ctx context.Context, movie string) ([]booking.Seat, error) {
	ctx, sp := s.span(ctx, "store.Seats", movie, "")
	seats, err := s.Store.Seats(ctx, movie)
	end(sp, err)
	return seats, err
}
```

### Step 2: continuing the caller's trace

If the caller (another service, or a browser with tracing) is already in a trace, it sends a W3C **`traceparent`** header: version, trace ID, its own span ID, flags. The service continues that trace instead of starting a new one:

```text
$ curl -X POST -H 'X-User: alice' -H 'traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01' localhost:8091/movies/inception/seats/A7/hold
201
```

The log line for it:

```text
{"time":"2026-09-27T02:53:14.035528711Z","level":"INFO","msg":"request","route":"POST /movies/{movie}/seats/{seat}/hold","path":"/movies/inception/seats/A7/hold","status":201,"ms":1.043,"user":"alice","trace_id":"4bf92f3577b34da6a3ce929d0e0e4736"}
```

And the trace, fetched from Jaeger's API (`/api/traces/4bf92f35…`) and printed as a tree:

```text
POST /movies/{movie}/seats/{seat}/hold  1.230 ms  span=a2c58b5d3f51d983 parent=00f067aa0ba902b7  {'http.request.method': 'POST'}
  store.Hold  0.991 ms  span=acfbb792dee7222d parent=a2c58b5d3f51d983  {'cinema.movie': 'inception', 'cinema.seat': 'A7'}
```

The server span's parent is `00f067aa0ba902b7`, the span ID from our header: the service joined our trace. Of the 1.23 ms request, 0.99 ms was the Redis call. The same trace ID appears in the log line, so from any log line you can open its trace, and from a slow span you can find its logs.

<ELI5
  concept="Trace, span, trace ID"
  analogy="A parcel's tracking number, and every scan it gets on the way."
  role="reader"
>

A **trace ID** is the tracking number stuck on one request when it enters the system. Every service that handles it passes the number along (the `traceparent` header between services, the context inside one).

Each **span** is one scan: "arrived at the cinema service at 14.035, handed to the store, store took 0.991 ms, done." Spans point at the span that caused them, so together they form the parcel's whole route.

When a customer says "my booking failed at 3:02", you find the log line, read its tracking number, and see every step of that one request, including the one that broke.

</ELI5>

<UnderTheHood title="What traceparent carries">

`traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01` is four fields: version `00`, a 16-byte trace ID, the 8-byte ID of the caller's span, and flags (`01` = sampled: record this trace). `propagation.TraceContext` reads it on the way in (otelhttp does that) and writes it on outgoing requests made with an instrumented client (`otelhttp.NewTransport`), so the next service continues the same trace. Sampling decisions travel with it: if the first service decides not to record a trace, the others follow.

</UnderTheHood>

## The Consumption Side

*Stop 4 of 4.*

Telemetry is only worth something if it leads to action. This stop turns the metrics into a promise, an alert on that promise, and follows the alert through a real incident.

### Step 1: SLI, SLO, error budget

- **SLI** (indicator): a measurement of what users experience. For holds: the fraction of hold requests that fail with a 5xx.
- **SLO** (objective): the target for it. Here: **99.9% of holds succeed**, measured over 30 days.
- **Error budget**: what the SLO allows to fail: 0.1%. Over 30 days, that's 43.2 minutes' worth of total failure. Spend it on deploys and experiments; when it's gone, slow down.

The SLI as a Prometheus recording rule, and the alert, in `rules.yml`:

```yaml
groups:
  - name: cinema-slo
    rules:
      # SLI: the share of hold requests that failed with a 5xx. With no 5xx at
      # all, the numerator has no series, not a zero: "or vector(0)" fixes that.
      - record: cinema:hold_error_ratio:rate1m
        expr: |
          (sum(rate(cinema_http_requests_total{route="POST /movies/{movie}/seats/{seat}/hold", code=~"5.."}[1m])) or vector(0))
          /
          sum(rate(cinema_http_requests_total{route="POST /movies/{movie}/seats/{seat}/hold"}[1m]))

      # SLO: 99.9% of holds succeed. Error budget: 0.1%.
      # Fast burn: spending the budget 14.4x faster than allowed would use
      # 2% of a 30-day budget in one hour: page someone.
      - alert: HoldErrorBudgetFastBurn
        expr: cinema:hold_error_ratio:rate1m > 14.4 * 0.001
        for: 10s
        labels: {severity: page}
        annotations:
          summary: "Seat holds failing: {{ $value | humanizePercentage }} errors"
```

Note the `or vector(0)`. The first version of this rule didn't have it, and it returned **no data** the whole time the service was healthy:

```text
$ sum(rate(…{route="POST …/hold", code=~"5.."}[1m])) / sum(rate(…{route="POST …/hold"}[1m]))
  (no data)
$ cinema:hold_error_ratio:rate1m          # with or vector(0)
  {} => 0
```

No 5xx responses means no 5xx series; `sum` of nothing is an empty result, not 0; and dividing empty by anything is empty. A dashboard would show a gap, and an alert comparing it to a threshold would never evaluate. `or vector(0)` substitutes a real zero.

### Step 2: burn rate, and the incident

A **burn rate** is how fast you're spending the error budget relative to plan: burn rate 1 spends it exactly over 30 days; 14.4 spends 2% of a month's budget in an hour, which is worth waking someone for. The alert fires when the error ratio exceeds 14.4 × 0.1%, i.e. 1.44%, for 10 seconds.

With traffic running, Redis is stopped:

```text

t=5s   ratio=0                    alerts: no alerts
t=10s  ratio=0.908705654374032    alerts: HoldErrorBudgetFastBurn pending value=0.909
t=15s  ratio=0.9365496009334348   alerts: HoldErrorBudgetFastBurn pending value=0.937
t=21s  ratio=0.9555182597329754   alerts: HoldErrorBudgetFastBurn firing value=0.956
t=26s  ratio=0.9633874479725139   alerts: HoldErrorBudgetFastBurn firing value=0.963
…
t=51s  ratio=0.9825474584308594   alerts: HoldErrorBudgetFastBurn firing value=0.983
```

**Pending at 10 s** (the condition is true, waiting out `for: 10s`), **firing at 21 s**. The service never went down; its `/seats` endpoint went on answering from its own process. Only a signal defined as "can customers hold seats" noticed.

### Step 3: from alert to cause

The alert says *what* (holds failing). The logs say *which* requests; pick one:

```text
{"time":"2026-09-27T03:02:01.117174135Z","level":"ERROR","msg":"request","route":"POST /movies/{movie}/seats/{seat}/hold","path":"/movies/inception/seats/E8/hold","status":500,"ms":120.66,"user":"user-0004","trace_id":"be1bc3dbb241d05a5947739a8de279bc"}
```

Its trace says *why*:

```text
$ python3 tr.py be1bc3dbb241d05a5947739a8de279bc
POST /movies/{movie}/seats/{seat}/hold  120.842 ms  {'otel.status_code': 'ERROR', 'error': True}
  store.Hold  120.590 ms  {'cinema.movie': 'inception', 'cinema.seat': 'E8', 'otel.status_code': 'ERROR', 'otel.status_description': 'dial tcp: lookup cinema-redis on 127.0.0.11:53: no such host', 'error': True}

```

Of the 120.8 ms request, 120.6 ms went into `store.Hold`, which failed looking up `cinema-redis`: the Redis host is gone. Alert → log line → trace ID → span → cause, in three hops, without logging into a server.

### Step 4: recovery, and why the alert lagged

```text
t=0s   docker start cinema-redis
t=6s   ratio=0.9594594594594594   alerts: HoldErrorBudgetFastBurn firing value=0.959
t=11s  ratio=0.8181818181818182   alerts: HoldErrorBudgetFastBurn firing value=0.818
t=21s  ratio=0.6071428571428571   alerts: HoldErrorBudgetFastBurn firing value=0.607
t=31s  ratio=0.4222222222222222   alerts: HoldErrorBudgetFastBurn firing value=0.422
t=42s  ratio=0.2604166666666667   alerts: HoldErrorBudgetFastBurn firing value=0.260
t=52s  ratio=0.09615384615384615  alerts: HoldErrorBudgetFastBurn firing value=0.096
t=57s  ratio=0.04806346243583762  alerts: HoldErrorBudgetFastBurn firing value=0.048
t=62s  ratio=0                    alerts: no alerts
```

Holds worked again from the moment Redis was back, but the alert fired for another minute: `rate(…[1m])` averages over the last minute, and that minute still contained failures. The window is a trade-off: short windows react fast but flap on a few errors; long windows are stable but slow to fire and slow to clear. Production burn-rate alerts use **two windows at once** (for example, 1 hour *and* 5 minutes both above the threshold): the long window proves it's significant, the short one proves it's still happening, so the alert also clears quickly.

What did the incident cost? Roughly 70 seconds at about 95% of holds failing: about 66 seconds of the 43.2-minute monthly budget, **2.5%** of it.

// metrics counts requests per (route, status code), like the Prometheus

type metrics struct {

	counts map[string]int // key: route + " " + code
}

func (m *metrics) inc(route string, code int) {
	m.mu.Lock()
	defer m.mu.Unlock()

func observe(m *metrics, next *http.ServeMux) http.Handler {

		next.ServeHTTP(w, r)

		if !strings.HasPrefix(key, route+" ") {
			continue
		}
		total += n
		if strings.HasSuffix(key, " 500") || strings.HasSuffix(key, " 503") {
			failed += n
		}
	}
	return float64(failed) / float64(total)
