<HeroCard label="Part 2 · Chapter 22" title="Storage Engines: LSM-Trees vs B-Trees">

Chapters 20 and 21 moved the cinema's data across machines. This chapter goes inside one: when Postgres, Redis, etcd or CockroachDB is told "seat A7 is booked", what does it write, where, and how does it find it again? Almost every database answers with one of two designs. A **B-tree** keeps the data sorted in fixed-size pages and updates them in place. A **log-structured merge tree** (LSM) never updates in place: it appends, sorts in memory, writes sorted files, and merges them later.

The designs make opposite trade-offs, and the only way to feel them is to run them. So this chapter builds the simplest possible database first, then runs the same day of box-office traffic (a million seats, three million changes) through **Pebble**, the LSM engine inside CockroachDB, and **bbolt**, the B+tree engine inside etcd, and measures throughput, bytes written, bytes read and disk used. Then it looks at the other axis, rows versus columns, for the reports the box office runs at night.

Six stops. If you get lost, come back here:

1. **The simplest database.** Append to a file; the problem is finding things.
2. **LSM trees.** Memtables, sorted runs, levels and compaction, in Pebble.
3. **Bloom filters.** Skipping files that can't have the key, and when that backfires.
4. **B-trees.** Pages, splits and copy-on-write, in bbolt.
5. **LSM versus B-tree.** The same workload, side by side.
6. **Rows versus columns.** Why the nightly reports want a different layout.

## The lab bench

One Go module, `engines`, with four programs: `logdb` (a database in 100 lines), `lsm` (Pebble v2.1.7), `btree` (bbolt 1.5.0) and `columns` (parquet-go 0.32.0). The workload is the same for Pebble and bbolt: 25,000 showings of 40 seats, a million seat keys like `inception/show-12345/C6`, and three million changes of about 100 bytes each in random order, committed a thousand at a time. Everything runs on an Apple M1 with its SSD; absolute numbers will differ on your machine, the ratios much less.

## The Simplest Database

*Stop 1 of 6.*

### Step 1: append, and scan

The simplest way to store seat states: append a line `key<TAB>value` for every change, and to read a key, the **last** line for it wins. Writing is as fast as a disk can go, because nothing is ever overwritten or reorganised.

```go noverify
// logdb is the simplest database there is: every change to a seat is
// appended to a file, and the latest line for a key is its value. It
// measures lookups by scanning, lookups through an in-memory hash index,
// and what compaction does to the file.
package main

import (
	"bufio"
	"fmt"
	"io"
	"log"
	"math/rand/v2"
	"os"
	"strings"
	"time"
)

// showings × seats: 200 showings of 40 seats = 8,000 seats.
func seatKey(showing, seat int) string {
	return fmt.Sprintf("inception/show-%03d/%c%d", showing, 'A'+seat/8, 1+seat%8)
}

type DB struct {
	f     *os.File
	index map[string]int64 // key → offset of its latest line (nil: no index)
}

func (db *DB) Set(key, value string) error {
	off, err := db.f.Seek(0, io.SeekEnd)
	if err != nil {
		return err
	}
	if _, err := fmt.Fprintf(db.f, "%s\t%s\n", key, value); err != nil {
		return err
	}
	if db.index != nil {
		db.index[key] = off
	}
	return nil
}

// GetScan reads the whole file; the last line for key wins.
func (db *DB) GetScan(key string) (string, bool) {
	if _, err := db.f.Seek(0, io.SeekStart); err != nil {
		log.Fatal(err)
	}
	sc := bufio.NewScanner(db.f)
	var val string
	found := false
	for sc.Scan() {
		k, v, _ := strings.Cut(sc.Text(), "\t")
		if k == key {
			val, found = v, true
		}
	}
	return val, found
}

// GetIndexed seeks straight to the key's latest line.
func (db *DB) GetIndexed(key string) (string, bool) {
	off, ok := db.index[key]
	if !ok {
		return "", false
	}
	line, err := bufio.NewReader(io.NewSectionReader(db.f, off, 1<<16)).ReadString('\n')
	if err != nil {
		log.Fatal(err)
	}
	_, v, _ := strings.Cut(strings.TrimSuffix(line, "\n"), "\t")
	return v, true
}

func size(f *os.File) int64 {
	st, err := f.Stat()
	if err != nil {
		log.Fatal(err)
	}
	return st.Size()
}

func main() {
	dir, err := os.MkdirTemp("", "logdb")
	if err != nil {
		log.Fatal(err)
	}
	defer os.RemoveAll(dir)
	f, err := os.Create(dir + "/seats.log")
	if err != nil {
		log.Fatal(err)
	}
	db := &DB{f: f, index: map[string]int64{}}

	// A day of the box office: 200,000 changes to 8,000 seats (holds,
	// releases, bookings), so each seat changes about 25 times.
	r := rand.New(rand.NewPCG(1, 2))
	states := []string{"held:%d", "free", "booked:%d"}
	t0 := time.Now()
	for range 200_000 {
		st := states[r.IntN(3)]
		if strings.Contains(st, "%d") {
			st = fmt.Sprintf(st, r.IntN(100_000))
		}
		if err := db.Set(seatKey(r.IntN(200), r.IntN(40)), st); err != nil {
			log.Fatal(err)
		}
	}
	fmt.Printf("200,000 appends in %v; the log is %.1f MB for %d live seats\n",
		time.Since(t0).Round(time.Millisecond), float64(size(f))/1e6, len(db.index))

	key := seatKey(137, 21)
	t0 = time.Now()
	v, _ := db.GetScan(key)
	fmt.Printf("get %s by scanning the log:     %-8v → %s\n", key, time.Since(t0).Round(time.Microsecond), v)
	t0 = time.Now()
	for range 10_000 {
		v, _ = db.GetIndexed(key)
	}
	fmt.Printf("get %s through the hash index: %-8v → %s  (average of 10,000)\n", key, (time.Since(t0) / 10_000).Round(100*time.Nanosecond), v)
	fmt.Printf("the index: %d keys in memory, one offset each\n", len(db.index))

	// Compaction: rewrite the log with only each key's latest line.
	t0 = time.Now()
	nf, err := os.Create(dir + "/seats.compacted")
	if err != nil {
		log.Fatal(err)
	}
	ndb := &DB{f: nf, index: map[string]int64{}}
	for k := range db.index {
		v, _ := db.GetIndexed(k)
		if err := ndb.Set(k, v); err != nil {
			log.Fatal(err)
		}
	}
	fmt.Printf("compaction: %.1f MB → %.2f MB in %v\n", float64(size(f))/1e6, float64(size(nf))/1e6, time.Since(t0).Round(time.Millisecond))
}
```

```text
200,000 appends in 538ms; the log is 6.3 MB for 8000 live seats
get inception/show-137/C6 by scanning the log:     8.82ms   → free
get inception/show-137/C6 through the hash index: 1.1µs    → free  (average of 10,000)
the index: 8000 keys in memory, one offset each
compaction: 6.3 MB → 0.25 MB in 30ms
```

200,000 changes appended in 538 ms. Reading one seat by scanning the log: **8.8 ms**, and it grows with every write the log has ever received.

### Step 2: an index, and compaction

The fix for reads is an **index**: a hash map from each key to the byte offset of its latest line. Then a read is one seek: **1.1 µs**, 8,000 times faster. Two new problems appear. The index lives in memory, so every key must fit in RAM. And the log keeps every old version: 6.3 MB for 8,000 live seats. **Compaction** rewrites it with only the latest value of each key: **0.25 MB**.

That's a real design, not a toy: Bitcask (Riak's storage engine) is exactly this, with the log split into segments so compaction can run on old segments while new writes go to the current one. Its limits are the two above: all keys in memory, and no way to read a *range* ("all the seats of showing 137") without scanning, because a hash index has no order.

## LSM Trees

*Stop 2 of 6.*

### Step 1: keep the log, but sorted

An LSM tree keeps the append-only log's fast writes and adds order:

1. Every write is appended to a **write-ahead log** (for crash safety) and inserted into the **memtable**, a sorted structure in memory.
2. When the memtable fills (4 MB here), it's **flushed**: written out as an immutable **sorted table** (an SSTable), with an index of its blocks. That write is sequential and whole.
3. Tables pile up in **level 0**. **Compaction** merges tables into larger sorted runs in lower levels (L1…L6), keeping only the newest version of each key and dropping deleted ones.
4. A read looks in the memtable, then the tables from newest to oldest, and stops at the first hit.

### Step 2: Pebble with the day's traffic

```go noverify
// lsm writes a day of the cinema's seat changes into Pebble (the LSM-tree
// engine inside CockroachDB) and reports what the engine did with them:
// memtable flushes, sorted table files per level, compactions, bytes
// written per byte of data, and what a read costs with and without Bloom
// filters.
package main

import (
	"flag"
	"fmt"
	"log"
	"math/rand/v2"
	"os"
	"time"

	"github.com/cockroachdb/pebble/v2"
	"github.com/cockroachdb/pebble/v2/bloom"
)

func key(showing, seat int) []byte {
	return fmt.Appendf(nil, "inception/show-%05d/%c%d", showing, 'A'+seat/8, 1+seat%8)
}

func levels(db *pebble.DB) {
	m := db.Metrics()
	fmt.Printf("  memtable: %.1f MB\n", float64(m.MemTable.Size)/1e6)
	for i, l := range m.Levels {
		if l.TablesCount > 0 {
			fmt.Printf("  L%d: %3d sorted tables, %6.1f MB\n", i, l.TablesCount, float64(l.TablesSize)/1e6)
		}
	}
}

func main() {
	useBloom := flag.Bool("bloom", true, "Bloom filters on every level")
	cacheMB := flag.Int64("cache", 12, "block cache size in MB")
	l6 := flag.Bool("l6filters", false, "consult Bloom filters in L6 too (Pebble skips them there by default)")
	flag.Parse()
	dir, err := os.MkdirTemp("", "lsm")
	if err != nil {
		log.Fatal(err)
	}
	defer os.RemoveAll(dir)
	cache := pebble.NewCache(*cacheMB << 20) // smaller than the data (about 20 MB compressed)
	defer cache.Unref()
	opts := &pebble.Options{
		MemTableSize: 4 << 20, // 4 MB memtables, to see flushes at this size
		Cache:        cache,
	}
	for i := range opts.Levels {
		if *useBloom {
			opts.Levels[i].FilterPolicy = bloom.FilterPolicy(10) // 10 bits per key
		}
	}
	db, err := pebble.Open(dir, opts)
	if err != nil {
		log.Fatal(err)
	}

	// 3,000,000 changes to 1,000,000 seats (25,000 showings × 40), in
	// batches of 1,000, like a busy box office would commit them.
	r := rand.New(rand.NewPCG(1, 2))
	var userBytes int
	t0 := time.Now()
	for batch := range 3000 {
		if batch == 1500 {
			fmt.Println("halfway through the writes, the tree looks like this:")
			levels(db)
		}
		b := db.NewBatch()
		for range 1000 {
			k := key(r.IntN(25000), r.IntN(40))
			v := fmt.Appendf(nil, `{"status":"booked","customer":"customer-%06d","paid":"2026-09-27T19:%02d:00Z"}`, r.IntN(1_000_000), r.IntN(60))
			userBytes += len(k) + len(v)
			if err := b.Set(k, v, nil); err != nil {
				log.Fatal(err)
			}
		}
		if err := b.Commit(pebble.NoSync); err != nil {
			log.Fatal(err)
		}
	}
	if err := db.Flush(); err != nil {
		log.Fatal(err)
	}
	took := time.Since(t0)
	time.Sleep(2 * time.Second) // let background compactions settle
	m := db.Metrics()
	tot := m.Total()
	fmt.Printf("3,000,000 writes (%.0f MB of keys and values) in %v: %.0f writes/s\n", float64(userBytes)/1e6, took.Round(time.Millisecond), 3e6/took.Seconds())
	fmt.Printf("memtable flushes: %d   compactions: %d\n", m.Flush.Count, m.Compact.Count)
	fmt.Println("after the writes and the compactions they triggered:")
	levels(db)
	written := m.WAL.BytesWritten + tot.TableBytesFlushed + tot.TableBytesCompacted
	fmt.Printf("bytes written to disk: WAL %.0f MB + flushes %.0f MB + compactions %.0f MB = %.0f MB (%.1f× the data)\n",
		float64(m.WAL.BytesWritten)/1e6, float64(tot.TableBytesFlushed)/1e6, float64(tot.TableBytesCompacted)/1e6,
		float64(written)/1e6, float64(written)/float64(userBytes))
	fmt.Printf("on disk now: %.1f MB (1,000,000 live seats; old versions compacted away)\n", float64(m.DiskSpaceUsage())/1e6)

	// A point lookup is a prefix seek; the iterator's statistics say how
	// many bytes of blocks it had to read, and how many came from the cache.
	read := func(label string, mk func() []byte) {
		t0 := time.Now()
		found := 0
		var blockBytes, fromDisk uint64
		for range 100_000 {
			it, err := db.NewIter(&pebble.IterOptions{UseL6Filters: *l6})
			if err != nil {
				log.Fatal(err)
			}
			if it.SeekPrefixGE(mk()) {
				found++
			}
			st := it.Stats().InternalStats
			blockBytes += st.BlockBytes
			fromDisk += st.BlockBytes - st.BlockBytesInCache
			if err := it.Close(); err != nil {
				log.Fatal(err)
			}
		}
		fmt.Printf("%-30s %7v per lookup, %6d found, blocks read: %4.0f MB (%4.0f MB not in cache)\n", label,
			(time.Since(t0) / 100_000).Round(10*time.Nanosecond), found, float64(blockBytes)/1e6, float64(fromDisk)/1e6)
	}
	read("100,000 lookups, seats that exist", func() []byte { return key(r.IntN(25000), r.IntN(40)) })
	read("100,000 lookups, seats that don't", func() []byte { return key(r.IntN(25000), 40+r.IntN(8)) }) // row F: no such seats
	if err := db.Close(); err != nil {
		log.Fatal(err)
	}
}
```

The first run (without filters) shows the whole life of the data:

- **397,000 writes per second**: each write is an append to the WAL and an insert into memory.

- **Write amplification 3.2x**: 312 MB of WAL, 392 MB of flushed tables and 261 MB of compaction output, for 303 MB of data. Every byte is written about three times, but always sequentially and in large pieces.

## Bloom Filters

*Stop 3 of 6.*

### Step 1: "definitely not here"

A read for a key that isn't in a table still has to check it: find the block the key would be in, read it, and look. For a key that exists in *none* of the tables, like row F in a hall that ends at E, that's a wasted block read per table. A **Bloom filter** is a small bit array per table that answers "is this key possibly here?" with no false negatives and a tunable rate of false positives (about 1% at 10 bits per key). If it says no, the table is skipped.

### Step 2: measured, three ways

The lookup lines of the three runs of `lsm` (the first, without filters, from stop 2's output):

```text

100,000 lookups, seats that don't   1.3µs per lookup,      0 found, blocks read: 24568 MB (   1 MB not in cache)
```

With a 12 MB block cache, filters made lookups for **seats that don't exist 4x faster** (5.53 µs to 1.3 µs), and only 1 MB of blocks had to come from disk instead of 83 MB: the filter said "no" and the data block was never read. (The "blocks read" column counts the filter blocks too, about 245 KB per lookup, but from the cache.) Seats that exist got slightly slower: the filter says "maybe", and the data block is read anyway.

With a **4 MB** cache, the same filters made everything **10x slower** (55 µs per absent lookup) and read **24.5 GB** from disk. Each table's filter block is about 250 KB, and Pebble's cache is split into 4 x NumCPU shards (32 here, so 128 KB each): a filter block can't be cached, so every lookup reads it from disk. A filter only helps if it's cheaper to consult than the data it saves you from reading.

### Step 3: why Pebble had them off

The first attempt at this measurement turned filters on and saw **no difference at all**. Pebble's source says why: by default it doesn't consult Bloom filters in **L6**, the bottom level, where (as here) almost all the data ends up. A key absent from the upper levels usually has to be looked for in L6 anyway, and L6's filters are the biggest, so Pebble spends the memory elsewhere; `IterOptions.UseL6Filters` turns them on for workloads, like "does this seat exist", where most lookups miss.

## B-Trees

*Stop 4 of 6.*

### Step 1: sorted pages, updated where they are

A B-tree keeps the keys sorted in fixed-size **pages** (4 KB here), arranged as a tree: **branch pages** hold keys and pointers to child pages, **leaf pages** hold the data. A lookup walks from the root to one leaf, a few pages for millions of keys, and a range scan walks leaves in order. A write finds its leaf and changes it. When a leaf fills up, it **splits** in two and the parent gets a new pointer. bbolt is a B+tree with **copy-on-write**: instead of overwriting a page (which could leave a torn page after a crash), a transaction writes changed pages to new locations, and the root pointer switches over at commit.

```go noverify
// btree writes the same seat changes into bbolt, a B+tree database (the
// engine inside etcd): the data lives in 4 KB pages, updated in place by
// copy-on-write, and a key's page is found by walking down from the root.
package main

import (
	"fmt"
	"log"
	"math/rand/v2"
	"os"
	"time"

	bolt "go.etcd.io/bbolt"
)

func key(showing, seat int) []byte {
	return fmt.Appendf(nil, "inception/show-%05d/%c%d", showing, 'A'+seat/8, 1+seat%8)
}

func open(noSync bool) (*bolt.DB, string) {
	dir, err := os.MkdirTemp("", "btree")
	if err != nil {
		log.Fatal(err)
	}
	db, err := bolt.Open(dir+"/seats.db", 0o600, &bolt.Options{NoSync: noSync})
	if err != nil {
		log.Fatal(err)
	}
	if err := db.Update(func(tx *bolt.Tx) error { _, err := tx.CreateBucket([]byte("seats")); return err }); err != nil {
		log.Fatal(err)
	}
	return db, dir
}

func fileMB(dir string) float64 {
	st, err := os.Stat(dir + "/seats.db")
	if err != nil {
		log.Fatal(err)
	}
	return float64(st.Size()) / 1e6
}

func main() {
	// The LSM run's workload: 3,000,000 changes to 1,000,000 seats in
	// random order, 1,000 per transaction, without fsync (as the LSM ran).
	db, dir := open(true)
	r := rand.New(rand.NewPCG(1, 2))
	var userBytes int
	t0 := time.Now()
	for range 3000 {
		err := db.Update(func(tx *bolt.Tx) error {
			b := tx.Bucket([]byte("seats"))
			for range 1000 {
				k := key(r.IntN(25000), r.IntN(40))
				v := fmt.Appendf(nil, `{"status":"booked","customer":"customer-%06d","paid":"2026-09-27T19:%02d:00Z"}`, r.IntN(1_000_000), r.IntN(60))
				userBytes += len(k) + len(v)
				if err := b.Put(k, v); err != nil {
					return err
				}
			}
			return nil
		})
		if err != nil {
			log.Fatal(err)
		}
	}
	took := time.Since(t0)
	st := db.Stats().TxStats
	fmt.Printf("3,000,000 writes (%.0f MB) in random order: %v, %.0f writes/s\n", float64(userBytes)/1e6, took.Round(time.Millisecond), 3e6/took.Seconds())
	fmt.Printf("  page splits: %d; pages written: %.0f MB (%.1f× the data); file: %.1f MB\n",
		st.GetSplit(), float64(st.GetPageAlloc())/1e6, float64(st.GetPageAlloc())/float64(userBytes), fileMB(dir))

	lookup := func(label string, mk func() []byte) {
		t0 := time.Now()
		found := 0
		err := db.View(func(tx *bolt.Tx) error {
			b := tx.Bucket([]byte("seats"))
			for range 100_000 {
				if b.Get(mk()) != nil {
					found++
				}
			}
			return nil
		})
		if err != nil {
			log.Fatal(err)
		}
		fmt.Printf("  100,000 lookups, %-15s %6v per lookup, %d found\n", label, (time.Since(t0) / 100_000).Round(10*time.Nanosecond), found)
	}
	lookup("seats that exist", func() []byte { return key(r.IntN(25000), r.IntN(40)) })
	lookup("seats that don't", func() []byte { return key(r.IntN(25000), 40+r.IntN(8)) })
	db.Close()
	os.RemoveAll(dir)

	// The same 1,000,000 seats written once each, in key order.
	db, dir = open(true)
	t0 = time.Now()
	for batch := range 1000 {
		err := db.Update(func(tx *bolt.Tx) error {
			b := tx.Bucket([]byte("seats"))
			b.FillPercent = 1.0 // appending in order: fill pages completely
			for i := range 1000 {
				n := batch*1000 + i
				if err := b.Put(key(n/40, n%40), []byte(`{"status":"booked","customer":"customer-000000","paid":"2026-09-27T19:00:00Z"}`)); err != nil {
					return err
				}
			}
			return nil
		})
		if err != nil {
			log.Fatal(err)
		}
	}
	st = db.Stats().TxStats
	fmt.Printf("1,000,000 writes in key order: %v; page splits: %d; file: %.1f MB\n", time.Since(t0).Round(time.Millisecond), st.GetSplit(), fileMB(dir))
	db.Close()
	os.RemoveAll(dir)

	// What fsync costs: 200 single-booking transactions, with and without it.
	for _, noSync := range []bool{true, false} {
		db, dir = open(noSync)
		t0 = time.Now()
		for i := range 200 {
			if err := db.Update(func(tx *bolt.Tx) error { return tx.Bucket([]byte("seats")).Put(key(i, 0), []byte("booked")) }); err != nil {
				log.Fatal(err)
			}
		}
		fmt.Printf("200 one-booking transactions, fsync=%-5v %v per commit\n", !noSync, (time.Since(t0) / 200).Round(time.Microsecond))
		db.Close()
		os.RemoveAll(dir)
	}
}
```

### Step 2: reading the numbers

- **Lookups: about 1 µs**, for seats that exist or don't. bbolt memory-maps its file, and the whole 186 MB tree was in the operating system's page cache; a lookup is a walk down three or four pages in memory.
- **Random writes: 96,000 a second, 151x write amplification.** 1,000 random keys per transaction touch about 1,000 different leaf pages; copy-on-write rewrites each (and the branch pages above them) to change about 100 bytes: **45.7 GB of pages written** for 303 MB of data. Turning off bbolt's freelist sync changed it by nothing (150.8x): it's the page writes.
- **Sequential writes: 717 ms** for a million keys in key order, with `FillPercent = 1.0`: appends always go to the last leaf, which fills completely before splitting, and the file is 135 MB instead of 186 (random inserts leave pages half full after splits).
- **fsync: 8 ms per commit** against 44 µs without it. Durability means waiting for the disk to confirm; on macOS, Go's `File.Sync` uses `F_FULLFSYNC`, which flushes the drive's own cache, so this is the honest price of "committed". It's why databases group many transactions into one sync (Postgres's group commit, Pebble's batches).

## LSM versus B-Tree

*Stop 5 of 6.*

### Step 1: the same workload, side by side

Three million random updates to a million seats, a thousand per batch, without fsync, on the same machine:

| | Pebble (LSM) | bbolt (B+tree) |
|---|---|---|
| random writes | **397,000/s** | 96,000/s |
| bytes written per byte of data | **3.2x** (WAL, flushes, compactions) | 151x (page rewrites) |
| size on disk for 1M live seats | **30 MB** (compressed tables) | 186 MB (half-full pages) |
| point lookup, key exists | 5.3 µs (12 MB cache) | **1.0 µs** (file in page cache) |
| point lookup, key absent | 5.5 µs, 1.3 µs with L6 filters | **0.9 µs** |

### Step 2: what decides it

- **Write-heavy, random keys** (event logs, time series, metrics, a busy box office's seat states): the LSM tree turns random writes into sequential ones and compresses well. That's why Cassandra, RocksDB-based systems, CockroachDB (Pebble) and ScyllaDB are LSM trees.
- **Read-heavy, point lookups and ranges, predictable latency**: the B-tree's read path is short and has no background compaction competing for the disk. That's why Postgres, MySQL's InnoDB, SQLite and etcd (bbolt) are B-trees.
- **Hidden costs**: an LSM tree's compaction runs in the background and can fall behind (reads slow down, writes get throttled); a B-tree's amplification is paid in the foreground, on every commit, and grows with randomness.

Postgres, for all its B-trees, also appends every change to its WAL first (chapter 20): real engines borrow from both sides.

## Rows versus Columns

*Stop 6 of 6.*

### Step 1: a different question

Every engine so far stores a record's fields together: the right layout for "show me booking 42". The box office's nightly report asks something else: "revenue per film, this year", which needs two fields (film, price) from **every** booking. Stored by row, the report reads all seven fields of every row to use two. **Columnar** storage (Parquet, the format data warehouses read) stores each field of many rows together:

```go noverify
// columns stores a year of the cinema's bookings two ways, one row per
// line (CSV) and one column at a time (Parquet), and answers the box
// office's question "revenue per film" from each.
package main

import (
	"bufio"
	"encoding/csv"
	"fmt"
	"io"
	"log"
	"math/rand/v2"
	"os"
	"sort"
	"strconv"
	"time"

	"github.com/parquet-go/parquet-go"
)

type Booking struct {
	ID         int64  `parquet:"id"`
	Film       string `parquet:"film,dict"`
	Showing    string `parquet:"showing"`
	Seat       string `parquet:"seat"`
	Customer   string `parquet:"customer"`
	PriceCents int64  `parquet:"price_cents"`
	PaidAt     string `parquet:"paid_at"`
}

var films = []string{"inception", "dune", "arrival", "interstellar", "tenet", "oppenheimer", "blade-runner", "heat"}

func main() {
	dir, err := os.MkdirTemp("", "columns")
	if err != nil {
		log.Fatal(err)
	}
	defer os.RemoveAll(dir)
	r := rand.New(rand.NewPCG(1, 2))
	rows := make([]Booking, 1_000_000)
	for i := range rows {
		rows[i] = Booking{
			ID:         int64(i),
			Film:       films[r.IntN(len(films))],
			Showing:    fmt.Sprintf("2026-%02d-%02dT%02d:00", 1+r.IntN(12), 1+r.IntN(28), 12+r.IntN(10)),
			Seat:       fmt.Sprintf("%c%d", 'A'+r.IntN(5), 1+r.IntN(8)),
			Customer:   fmt.Sprintf("customer-%06d", r.IntN(200_000)),
			PriceCents: int64(900 + 100*r.IntN(8)),
			PaidAt:     fmt.Sprintf("2026-%02d-%02dT%02d:%02d:%02dZ", 1+r.IntN(12), 1+r.IntN(28), r.IntN(24), r.IntN(60), r.IntN(60)),
		}
	}

	// Rows: CSV.
	f, err := os.Create(dir + "/bookings.csv")
	if err != nil {
		log.Fatal(err)
	}
	w := csv.NewWriter(bufio.NewWriter(f))
	for _, b := range rows {
		w.Write([]string{strconv.FormatInt(b.ID, 10), b.Film, b.Showing, b.Seat, b.Customer, strconv.FormatInt(b.PriceCents, 10), b.PaidAt})
	}
	w.Flush()
	f.Close()
	// Columns: Parquet, zstd-compressed.
	if err := parquet.WriteFile(dir+"/bookings.parquet", rows, parquet.Compression(&parquet.Zstd)); err != nil {
		log.Fatal(err)
	}
	for _, name := range []string{"bookings.csv", "bookings.parquet"} {
		st, _ := os.Stat(dir + "/" + name)
		fmt.Printf("%-17s %6.1f MB\n", name, float64(st.Size())/1e6)
	}

	// Revenue per film from the CSV: every byte of every row is read.
	t0 := time.Now()
	revenue := map[string]int64{}
	f, err = os.Open(dir + "/bookings.csv")
	if err != nil {
		log.Fatal(err)
	}
	cr := csv.NewReader(bufio.NewReader(f))
	cr.ReuseRecord = true
	for {
		rec, err := cr.Read()
		if err == io.EOF {
			break
		}
		if err != nil {
			log.Fatal(err)
		}
		p, _ := strconv.ParseInt(rec[5], 10, 64)
		revenue[rec[1]] += p
	}
	st, _ := f.Stat()
	f.Close()
	fmt.Printf("revenue per film from rows:    %v, read %.1f MB\n", time.Since(t0).Round(time.Millisecond), float64(st.Size())/1e6)
	csvRevenue := revenue

	// From Parquet: open the file, read only the film and price columns.
	t0 = time.Now()
	f, err = os.Open(dir + "/bookings.parquet")
	if err != nil {
		log.Fatal(err)
	}
	st, _ = f.Stat()
	pf, err := parquet.OpenFile(f, st.Size())
	if err != nil {
		log.Fatal(err)
	}
	filmCol, priceCol := -1, -1
	for i, c := range pf.Schema().Fields() {
		switch c.Name() {
		case "film":
			filmCol = i
		case "price_cents":
			priceCol = i
		}
	}
	revenue = map[string]int64{}
	var bytesRead int64
	for _, rg := range pf.RowGroups() {
		chunks := rg.ColumnChunks()
		filmVals := readColumn(chunks[filmCol])
		priceVals := readColumn(chunks[priceCol])
		for i := range filmVals {
			revenue[filmVals[i].String()] += priceVals[i].Int64()
		}
	}
	for _, rg := range pf.Metadata().RowGroups {
		bytesRead += rg.Columns[filmCol].MetaData.TotalCompressedSize + rg.Columns[priceCol].MetaData.TotalCompressedSize
	}
	f.Close()
	fmt.Printf("revenue per film from columns: %v, read %.2f MB (2 of 7 columns)\n", time.Since(t0).Round(time.Millisecond), float64(bytesRead)/1e6)

	names := make([]string, 0, len(revenue))
	for n := range revenue {
		names = append(names, n)
	}
	sort.Strings(names)
	same := true
	for _, n := range names {
		same = same && revenue[n] == csvRevenue[n]
	}
	fmt.Printf("same answer from both: %v (inception: $%d)\n", same, revenue["inception"]/100)
}

func readColumn(cc parquet.ColumnChunk) []parquet.Value {
	var out []parquet.Value
	pages := cc.Pages()
	defer pages.Close()
	for {
		p, err := pages.ReadPage()
		if err == io.EOF {
			return out
		}
		if err != nil {
			log.Fatal(err)
		}
		vals := make([]parquet.Value, p.NumValues())
		n, err := p.Values().ReadValues(vals)
		if err != nil && err != io.EOF {
			log.Fatal(err)
		}
		out = append(out, vals[:n]...)
		parquet.Release(p)
	}
}
```

```text
$ columns

bookings.parquet    15.6 MB
revenue per film from rows:    251ms, read 77.8 MB
revenue per film from columns: 120ms, read 1.35 MB (2 of 7 columns)
same answer from both: true (inception: $1563096)
```

### Step 2: two wins at once

- **Read only what you need**: the report read **1.35 MB** (the film and price columns) instead of the whole 77.8 MB CSV, and finished in half the time even though Parquet decoding costs more per value than splitting a CSV line.
- **Compress what's alike**: the whole Parquet file is **15.6 MB against 77.8 MB**. A column of eight film names, dictionary-encoded (`parquet:"film,dict"`), is a column of tiny integers; a column of prices from a few values compresses to almost nothing. Rows mix types and repeat nothing.

The cost is the other way round: writing one booking touches seven columns, and reading one whole booking reads from seven places. So the cinema keeps its live data in row stores (Redis, Postgres) and exports bookings into a columnar format (or a column store like ClickHouse or DuckDB) for reporting.

<Exercise n={1} title="Batch the fsyncs" level="easy">

bbolt took 8 ms per commit with fsync. Using bbolt's `db.Batch`, commit 200 bookings from 200 goroutines and measure the time per booking. Why is it faster, and what does each caller give up?

<Solution>

`Batch` groups concurrent calls into one transaction and one fsync, so 200 bookings cost a handful of syncs instead of 200: per-booking time drops towards 8 ms divided by the batch size. Each caller waits until the batch commits (a few milliseconds more latency for the first ones), and if any function in the batch fails, bbolt reruns the others without it, so the functions must be idempotent. It's group commit, the same idea Postgres uses for its WAL.

</Solution>

</Exercise>

<Exercise n={2} title="Tune the memtable" level="medium">

Rerun `lsm -bloom=false` with `MemTableSize` of 1 MB and 64 MB. How do the flush count, the L0 shape halfway through and the write amplification change?

<Solution>

A 1 MB memtable flushes about four times as often, making more, smaller L0 tables and more compaction work: write amplification rises. A 64 MB memtable flushes rarely and absorbs repeated writes to the same seats in memory (each flush writes only the latest version of each key), so both flushes and compactions write less: amplification falls. The costs: more memory, and a longer WAL to replay after a crash.

</Solution>

</Exercise>

<Exercise n={3} title="A range query in both engines" level="medium">

Add a scan of every seat of 1,000 random showings (40 keys each) to `lsm` and `btree`: a Pebble iterator with bounds, and a bbolt cursor with `Seek`. Compare the time per showing.

<Solution>

Both engines keep keys sorted, so a showing is one seek and 39 steps. bbolt walks one or two leaf pages from its memory-mapped file, typically a few microseconds. Pebble merges iterators over the memtable and each overlapping table, then reads the table blocks, so it costs somewhat more per seek, and the steps are cheap. Neither needs to read the other 999,960 seats, which is what the hash index of stop 1 couldn't avoid.

</Solution>

</Exercise>

<Exercise n={4} title="Deletes in an LSM tree" level="medium">

Delete 500,000 of the million seats in `lsm` and measure the disk usage before and after a manual compaction (`db.Compact` over the whole key range). Where did the space go before the compaction?

<Solution>

A delete in an LSM tree is a write: a **tombstone** that hides older versions. Before compaction, disk usage *grows* (the tombstones are added, the old values stay). Compaction merges each tombstone with the value it hides and drops both once no older table can hold the key, and usage falls to about half. Until then, reads for deleted keys have to find the tombstone, and range scans step over them, which is why workloads that delete a lot (queues) are known to be hard for LSM trees.

</Solution>

</Exercise>

<Exercise n={5} title="An index for the report" level="hard">

The nightly report also needs "seats sold per showing of inception". Design it three ways (a secondary index in Pebble, a bbolt bucket keyed by film then showing, and a Parquet file sorted by film) and say what each costs at write time and at report time.

<Solution>

**Pebble secondary index**: write a second key `idx/film/showing/seat` with every booking, in the same batch, so it's atomic: twice the writes (amplified 3.2x each), and the report is one range scan over `idx/inception/`. **bbolt bucket by film/showing**: the same idea, but each booking now touches two random leaf pages instead of one, roughly doubling bbolt's already large write amplification. **Parquet sorted by film**: nothing at booking time (it's written by a nightly export), and the report reads only inception's row groups (Parquet records min/max per row group, so readers skip the others) and one or two columns. Live queries want the index; reports want the export.

</Solution>

</Exercise>

// A small LSM tree for seat states. Writes go to the memtable; Flush turns

// Flush writes the memtable out as a new sorted run with a Bloom filter.
func (l *LSM) Flush() {
	if len(l.mem) == 0 {
		return
	}
	r := &run{filter: NewBloom(len(l.mem), 10)}
	for _, e := range l.mem {
		r.entries = append(r.entries, e)
		r.filter.Add(e.key)
	}
	slices.SortFunc(r.entries, func(a, b entry) int {
		switch {
		case a.key < b.key:
			return -1
		case a.key > b.key:
			return 1
		}
		return 0
	})
	l.runs = append(l.runs, r)
	l.mem = map[string]entry{}
}

// FIX 2: Get must return the newest value: memtable first, then runs from
// newest to oldest; a tombstone means "not found"; use the filter to skip
// runs; binary-search inside a run.
func (l *LSM) Get(key string) (string, bool) {
	if e, ok := l.mem[key]; ok {
		return e.value, true
	}
	for _, r := range l.runs {
		l.RunsSearched++
		for _, e := range r.entries {
			if e.key == key {
				return e.value, true
			}
		}
	}
	return "", false
}

// Bloom is a Bloom filter: m bits, k hash functions.
type Bloom struct {
	bits []uint64
	m, k uint64
}

func NewBloom(n, bitsPerKey int) *Bloom {
	m := uint64(max(64, n*bitsPerKey))
	return &Bloom{bits: make([]uint64, (m+63)/64), m: m, k: 7}
}

// false for a key that was added.
func (b *Bloom) Add(key string)             {}

func hashes(key string) (uint64, uint64) {
	h := fnv.New64a()
	h.Write([]byte(key))
	h1 := h.Sum64()
	h.Write([]byte{0xff})
	return h1, h.Sum64() | 1
}

<Recap>

- **An append-only log** writes as fast as the disk allows; a hash index makes lookups 1.1 µs instead of an 8.8 ms scan; compaction shrank 6.3 MB of history to 0.25 MB of current state. It can't do ranges.
- **LSM trees** (Pebble): WAL plus a sorted memtable, flushed to immutable sorted tables, merged by compaction. 397,000 random writes/s at **3.2x** write amplification, a million seats in 18.8 MB of L6.
- **Bloom filters** skip tables that can't hold a key: absent-key lookups went from 5.5 µs to 1.3 µs with filters that fit in cache, and to 55 µs (24.5 GB read) with filters that didn't. Pebble skips L6 filters by default for that reason.
- **B-trees** (bbolt): sorted 4 KB pages, copy-on-write. 1 µs lookups, but random updates at **151x** amplification and 96,000/s; ordered inserts filled pages in 717 ms. An fsync'd commit cost 8 ms.
- **Choose by workload**: random-write-heavy favours LSM (throughput, compression); read-heavy and latency-sensitive favours B-trees.
- **Columns** for analytics: Parquet answered revenue-per-film reading 1.35 MB of a 15.6 MB file where CSV needed all 77.8 MB.
