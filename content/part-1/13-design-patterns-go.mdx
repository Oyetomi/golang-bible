## Functional Options

<Define term="Functional Options" since="Design Patterns, the Go Way (Part 1, Chapter 13 — this chapter)">
A **functional option** is a function with the signature `func(*Config)` that mutates a private configuration struct. Instead of a constructor that takes fifteen arguments, you define one constructor plus a set of `With*` functions — each returning an option closure. Callers compose exactly what they need; the rest stays at safe, production-ready defaults. **Why it matters:** telescoping constructors (`NewClientWithTimeoutAndRetries`) explode combinatorially and cannot be composed dynamically. Functional options scale to any number of knobs with zero breaking changes to existing call sites.
</Define>

Building an HTTP client for the Meridian payment gateway requires configurable timeouts, retry limits, custom network transports, rate limiters, metrics sinks, and base URLs. The naive approach is a constructor taking ten arguments. The worse approach is ten separate `NewClientWith*` constructors.

### The telescoping constructor problem

### 1. Standard Functional Options

Here is the production-grade implementation of standard functional options for the Meridian Payment Gateway Client:

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

// config holds all tunable knobs. It is unexported so callers cannot mutate it after creation.
type config struct {
	timeout    time.Duration
	retries    int
	httpClient *http.Client
	rateLimit  int
}

// Option is a function type that mutates a private config struct.
type Option func(*config)

// WithTimeout sets the request timeout for gateway interactions.
func WithTimeout(d time.Duration) Option {
	return func(c *config) {
		if d > 0 {
			c.timeout = d
		}
	}
}

// WithRetries configures the maximum number of retry attempts for idempotent operations.
func WithRetries(n int) Option {
	return func(c *config) {
		if n < 0 {
			n = 0
		}
		c.retries = n
	}
}

// WithHTTPClient allows callers (like test suites) to inject custom transports.
func WithHTTPClient(hc *http.Client) Option {
	return func(c *config) {
		if hc != nil {
			c.httpClient = hc
		}
	}
}

// WithRateLimit caps the maximum requests per second.
func WithRateLimit(rps int) Option {
	return func(c *config) {
		if rps > 0 {
			c.rateLimit = rps
		}
	}
}

// PaymentClient represents a configured Meridian gateway client.
type PaymentClient struct {
	baseURL string
	cfg     *config
}

// NewPaymentClient constructs a client with sensible production defaults.
func NewPaymentClient(baseURL string, opts ...Option) *PaymentClient {
	cfg := &config{
		timeout:   10 * time.Second,
		retries:   3,
		rateLimit: 100,
	}
	for _, opt := range opts {
		if opt != nil {
			opt(cfg)
		}
	}
	if cfg.httpClient == nil {
		cfg.httpClient = &http.Client{Timeout: cfg.timeout}
	}
	return &PaymentClient{
		baseURL: baseURL,
		cfg:     cfg,
	}
}

func main() {
	// Production client with overrides
	prod := NewPaymentClient(
		"https://api.meridian.bank",
		WithTimeout(25*time.Second),
		WithRetries(5),
		WithRateLimit(500),
	)
	fmt.Printf("Prod client: timeout=%v retries=%d rateLimit=%d rps\n",
		prod.cfg.timeout, prod.cfg.retries, prod.cfg.rateLimit)

	// Test client using zero retries and default timeouts
	testClient := NewPaymentClient("http://localhost:8080", WithRetries(0))
	fmt.Printf("Test client: timeout=%v retries=%d rateLimit=%d rps\n",
		testClient.cfg.timeout, testClient.cfg.retries, testClient.cfg.rateLimit)
}
```

<UnderTheHood title="How closures capture state and heap escape">

Each `WithTimeout(d)` invocation allocates a lightweight function value — a **closure**. The closure captures the variable `d` (`time.Duration`) by value or reference in its function frame. When the constructor ranges over `opts` and invokes `opt(cfg)`, the closure reads `d` and stores it in `cfg.timeout`.

During compilation, Go's **escape analysis** determines whether the captured variables and closures remain on the stack or escape to the heap. Because options are passed into a constructor and executed before the constructor returns, if the options slice does not outlive the constructor, the compiler can often keep allocations minimal. Even when closures escape, the cost is a single 16-to-32 byte heap allocation at startup — an infinitesimal trade-off for rock-solid API stability.

</UnderTheHood>

### 2. Self-Referential Options: Set and Restore

Rob Pike's original formulation of functional options had a powerful twist: **the option function returns an option that restores the previous state**. This enables temporary configuration overrides — such as increasing audit verbosity or lowering rate limits for a single batch — that automatically roll back when finished:

<GoPlayground>

```go
package main

import "fmt"

type MeridianServer struct {
	logLevel   string
	maxWorkers int
}

// ServerOption mutates the server and returns an option that undoes the change.
type ServerOption func(*MeridianServer) ServerOption

func WithLogLevel(level string) ServerOption {
	return func(s *MeridianServer) ServerOption {
		prev := s.logLevel
		s.logLevel = level
		return WithLogLevel(prev) // returns the undo option
	}
}

func WithMaxWorkers(n int) ServerOption {
	return func(s *MeridianServer) ServerOption {
		prev := s.maxWorkers
		s.maxWorkers = n
		return WithMaxWorkers(prev)
	}
}

// Apply applies options and returns a compound restore function.
func (s *MeridianServer) Apply(opts ...ServerOption) (restore func()) {
	var undos []ServerOption
	for _, opt := range opts {
		if opt != nil {
			undos = append(undos, opt(s))
		}
	}
	return func() {
		// Undo in reverse order
		for i := len(undos) - 1; i >= 0; i-- {
			undos[i](s)
		}
	}
}

func main() {
	srv := &MeridianServer{logLevel: "INFO", maxWorkers: 16}
	fmt.Printf("Baseline: level=%s workers=%d\n", srv.logLevel, srv.maxWorkers)

	// Temporary override for emergency ledger reconciliation
	restore := srv.Apply(WithLogLevel("DEBUG"), WithMaxWorkers(64))
	fmt.Printf("During incident triage: level=%s workers=%d\n", srv.logLevel, srv.maxWorkers)

	// Revert to baseline
	restore()
	fmt.Printf("After triage restored: level=%s workers=%d\n", srv.logLevel, srv.maxWorkers)
}
```

### 3. Interface-Based Options: Named, Inspectable & Documented

When options must appear as first-class named types in `godoc`, carry `String()` methods for structured auditing, or support serialization, we define an `Option` interface:

<GoPlayground>

```go
package main

import (
	"fmt"
	"time"
)

type ledgerConfig struct {
	retentionDays int
	syncMode      bool
	flushInterval time.Duration
}

// Option is a formal interface instead of a bare function pointer.
type Option interface {
	apply(*ledgerConfig)
	fmt.Stringer
}

type retentionOpt int

func (r retentionOpt) apply(c *ledgerConfig) { c.retentionDays = int(r) }
func (r retentionOpt) String() string        { return fmt.Sprintf("RetentionDays(%d)", int(r)) }

func WithRetention(days int) Option { return retentionOpt(days) }

type syncModeOpt bool

func (s syncModeOpt) apply(c *ledgerConfig) { c.syncMode = bool(s) }
func (s syncModeOpt) String() string        { return fmt.Sprintf("SyncMode(%t)", bool(s)) }

func WithSyncMode(enabled bool) Option { return syncModeOpt(enabled) }

type LedgerEngine struct {
	cfg ledgerConfig
}

func NewLedgerEngine(opts ...Option) *LedgerEngine {
	cfg := ledgerConfig{retentionDays: 365, syncMode: false, flushInterval: time.Second}
	for _, opt := range opts {
		if opt != nil {
			fmt.Printf("[AUDIT] Applying config: %s\n", opt.String())
			opt.apply(&cfg)
		}
	}
	return &LedgerEngine{cfg: cfg}
}

func main() {
	engine := NewLedgerEngine(
		WithRetention(730),
		WithSyncMode(true),
	)
	fmt.Printf("Engine configured: retention=%d days, sync=%v\n",
		engine.cfg.retentionDays, engine.cfg.syncMode)
}
```

## Creational Patterns

Creational patterns abstract the instantiation process, making systems independent of how their constituent objects are created, composed, and represented. In Go, these patterns dispense with heavy class hierarchies and focus on value semantics, constructors, and goroutine safety.

### 1. Factory & Constructor Functions (`New*`, `NewWith*`)

In Go, constructors are functions. By convention:
- `NewType(...)` is the primary constructor.
- `NewTypeWithParams(...)` or `NewTypeFromConfig(...)` provide specialized entry points.
- A **Factory Registry** map enables dynamic polymorphism based on configuration keys (e.g., payment rail selection).

<GoPlayground>

```go
package main

import (
	"context"
	"fmt"
)

type PaymentRail interface {
	Settle(ctx context.Context, txnID string, amountCents int64) error
	Name() string
}

type ACHRail struct{}
func (a *ACHRail) Name() string { return "ACH_BATCH" }
func (a *ACHRail) Settle(_ context.Context, txnID string, amt int64) error {
	fmt.Printf("Queued %d cents for overnight ACH batch: %s\n", amt, txnID)
	return nil
}

type FedNowRail struct{}
func (f *FedNowRail) Name() string { return "FED_NOW_INSTANT" }
func (f *FedNowRail) Settle(_ context.Context, txnID string, amt int64) error {
	fmt.Printf("Settled %d cents instantly via FedNow: %s\n", amt, txnID)
	return nil
}

type SEPARail struct{}
func (s *SEPARail) Name() string { return "SEPA_EURO" }
func (s *SEPARail) Settle(_ context.Context, txnID string, amt int64) error {
	fmt.Printf("Settled €%d.%02d via SEPA Instant: %s\n", amt/100, amt%100, txnID)
	return nil
}

// RailFactoryRegistry maps string identifiers to constructor functions.
var railRegistry = map[string]func() PaymentRail{
	"ach":    func() PaymentRail { return &ACHRail{} },
	"fednow": func() PaymentRail { return &FedNowRail{} },
	"sepa":   func() PaymentRail { return &SEPARail{} },
}

// NewPaymentRail is our factory function.
func NewPaymentRail(railName string) (PaymentRail, error) {
	constructor, exists := railRegistry[railName]
	if !exists {
		return nil, fmt.Errorf("unsupported payment rail: %q", railName)
	}
	return constructor(), nil
}

func main() {
	ctx := context.Background()
	for _, name := range []string{"fednow", "ach", "sepa", "crypto"} {
		rail, err := NewPaymentRail(name)
		if err != nil {
			fmt.Printf("Factory error: %v\n", err)
			continue
		}
		fmt.Printf("Initialized rail [%s]\n", rail.Name())
		_ = rail.Settle(ctx, "TXN-9021", 45000)
	}
}
```

</GoPlayground>

### 2. Builder & Fluent APIs

When building complex entities where construction is **staged**, **conditional**, or **accumulative**, a Builder pattern with a fluent interface (`return b`) provides clarity. Errors are deferred to the final `Build()` step to avoid clunky error handling on every method call:

<GoPlayground>

```go
package main

import (
	"errors"
	"fmt"
	"strings"
	"time"
)

type TransactionPayload struct {
	ID             string
	SourceAccount  string
	DestAccount    string
	AmountCents    int64
	Currency       string
	IdempotencyKey string
	Tags           map[string]string
	CreatedAt      time.Time
}

// TransactionBuilder accumulates fields and validates at the end.
type TransactionBuilder struct {
	txn TransactionPayload
	err error
}

func NewTransactionBuilder(id string) *TransactionBuilder {
	b := &TransactionBuilder{
		txn: TransactionPayload{
			ID:        id,
			Currency:  "USD",
			Tags:      make(map[string]string),
			CreatedAt: time.Now(),
		},
	}
	if strings.TrimSpace(id) == "" {
		b.err = errors.New("transaction ID is required")
	}
	return b
}

func (b *TransactionBuilder) From(accountID string) *TransactionBuilder {
	if b.err != nil {
		return b
	}
	if strings.TrimSpace(accountID) == "" {
		b.err = errors.New("source account is required")
	}
	b.txn.SourceAccount = accountID
	return b
}

func (b *TransactionBuilder) To(accountID string) *TransactionBuilder {
	if b.err != nil {
		return b
	}
	if strings.TrimSpace(accountID) == "" {
		b.err = errors.New("destination account is required")
	}
	b.txn.DestAccount = accountID
	return b
}

func (b *TransactionBuilder) Amount(cents int64, currency string) *TransactionBuilder {
	if b.err != nil {
		return b
	}
	if cents <= 0 {
		b.err = errors.New("amount must be positive")
	}
	b.txn.AmountCents = cents
	if currency != "" {
		b.txn.Currency = currency
	}
	return b
}

func (b *TransactionBuilder) WithIdempotencyKey(key string) *TransactionBuilder {
	if b.err != nil {
		return b
	}
	b.txn.IdempotencyKey = key
	return b
}

func (b *TransactionBuilder) Tag(k, v string) *TransactionBuilder {
	if b.err != nil {
		return b
	}
	b.txn.Tags[k] = v
	return b
}

func (b *TransactionBuilder) Build() (*TransactionPayload, error) {
	if b.err != nil {
		return nil, b.err
	}
	if b.txn.SourceAccount == b.txn.DestAccount {
		return nil, errors.New("source and destination accounts must be distinct")
	}
	if b.txn.AmountCents == 0 {
		return nil, errors.New("transaction amount cannot be zero")
	}
	return &b.txn, nil
}

func main() {
	// Happy path builder
	txn, err := NewTransactionBuilder("TXN-1001").
		From("ACCT-ALICE-USD").
		To("ACCT-BOB-USD").
		Amount(125000, "USD").
		WithIdempotencyKey("IDEM-8821").
		Tag("channel", "mobile_api").
		Tag("risk_tier", "low").
		Build()

	if err != nil {
		fmt.Printf("Build error: %v\n", err)
		return
	}
	fmt.Printf("Built Transaction: %s -> %s for %d %s (idempotency=%s)\n",
		txn.SourceAccount, txn.DestAccount, txn.AmountCents, txn.Currency, txn.IdempotencyKey)

	// Validation failure path
	_, err = NewTransactionBuilder("TXN-1002").
		From("ACCT-ALICE-USD").
		To("ACCT-ALICE-USD"). // illegal self-transfer
		Amount(5000, "USD").
		Build()
	fmt.Printf("Invalid build caught: %v\n", err)
}
```

</GoPlayground>

### 3. Singleton (`sync.Once`, `sync.OnceValue`, `sync.OnceValues`)

In Go, eager initialization via package variables (`var Default = ...`) handles straightforward singletons. When initialization is expensive or requires runtime parameters, lazy initialization is performed with `sync.Once` or Go 1.21's type-safe helpers: `sync.OnceValue` and `sync.OnceValues`.

<GoPlayground>

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type DatabasePool struct {
	DSN       string
	CreatedAt time.Time
}

// Go 1.21+ sync.OnceValue wraps a func() T and returns a thread-safe memoized getter.
var GetDatabasePool = sync.OnceValue(func() *DatabasePool {
	fmt.Println("[INIT] Opening connection pool to Meridian Ledger DB (executes exactly once)...")
	return &DatabasePool{
		DSN:       "postgres://meridian_app:secret@db.internal:5432/ledger?sslmode=verify-full",
		CreatedAt: time.Now(),
	}
})

// sync.OnceValues handles a func() (T, error) pair.
var LoadGlobalExchangeRates = sync.OnceValues(func() (map[string]float64, error) {
	fmt.Println("[INIT] Fetching authoritative central bank FX tables (executes once)...")
	return map[string]float64{
		"EUR_USD": 1.085,
		"GBP_USD": 1.272,
		"USD_NGN": 1450.0,
	}, nil
})

func main() {
	var wg sync.WaitGroup
	// 5 concurrent goroutines calling GetDatabasePool simultaneously
	for i := 0; i < 5; i++ {
		wg.Add(1)
		go func(workerID int) {
			defer wg.Done()
			db := GetDatabasePool()
			fmt.Printf("Worker %d got pool instance at %p\n", workerID, db)
		}(i + 1)

	wg.Wait()

	rates, err := LoadGlobalExchangeRates()
	fmt.Printf("Authoritative FX USD/NGN: %.2f (err=%v)\n", rates["USD_NGN"], err)
```

### 4. Object Pool (`sync.Pool` Lifecycle & Buffer Reuse)

In high-throughput fintech systems handling 100,000 requests per second, allocating temporary byte buffers for JSON marshalling or cryptographic packet framing burns GC cycles. `sync.Pool` provides reusable object caches that reduce heap allocations to near zero.

<GoPlayground>

```go
package main

import (
	"bytes"
	"fmt"
	"sync"
)

// bufferPool manages reusable bytes.Buffer pointers.
var bufferPool = sync.Pool{
	New: func() any {
		// Allocate initial buffer capacity to prevent early growth
		return bytes.NewBuffer(make([]byte, 0, 1024))
	},
}

// FormatAuditLog formats a high-frequency ledger audit entry with ZERO allocations.
func FormatAuditLog(accountID, op string, cents int64) []byte {
	buf := bufferPool.Get().(*bytes.Buffer)
	buf.Reset() // CRITICAL: reset length to 0 while keeping underlying slice capacity
	defer bufferPool.Put(buf)

	fmt.Fprintf(buf, "AUDIT|ts=now|acct=%s|op=%s|cents=%d", accountID, op, cents)
	
	// Create defensive copy if slice needs to escape beyond defer Put()
	out := make([]byte, buf.Len())
	copy(out, buf.Bytes())
	return out
}

func main() {
	for i := 1; i <= 3; i++ {
		logEntry := FormatAuditLog(fmt.Sprintf("ACCT-%04d", i), "TRANSFER_OUT", int64(i*5000))
		fmt.Println(string(logEntry))
	}
}
```

</GoPlayground>

<UnderTheHood title="sync.Pool internals: P-local caches and GC flushing">

`sync.Pool` uses per-Processor (`P`) local storage (`poolLocal`) with lock-free ring buffers (`poolChain`). When a goroutine calls `Get()`, it attempts to retrieve an object from its current processor's private slot. If empty, it steals from other processors before falling back to `New()`.

**The GC Catch:** Objects in `sync.Pool` are subject to clearing during garbage collection. In Go's runtime, pools are drained across two GC cycles (via `poolCleanup` moving items from `local` to `victim`). Never store stateful connections or pointers requiring deterministic closing in `sync.Pool`. Always call `Reset()` before returning an object.

</UnderTheHood>

### 5. Prototype / Clone Pattern

When creating complex structures that differ only slightly from an existing archetype, the Prototype pattern clones the prototype and modifies the clone. In Go, structs without pointers clone by value copy (`clone := original`). Structs with slices, maps, or pointers require an explicit `Clone()` method to guarantee deep copying:

<GoPlayground>

```go
package main

import "fmt"

type FeeSchedule struct {
	BaseFeeCents int64
	Tiers        map[string]float64 // pointer/reference type!
}

type AccountArchetype struct {
	TierName    string
	MaxDailyTxn int
	Fees        FeeSchedule
}

// Clone performs a deep copy to prevent shared memory corruption.
func (a *AccountArchetype) Clone() *AccountArchetype {
	clone := &AccountArchetype{
		TierName:    a.TierName,
		MaxDailyTxn: a.MaxDailyTxn,
		Fees: FeeSchedule{
			BaseFeeCents: a.Fees.BaseFeeCents,
			Tiers:        make(map[string]float64, len(a.Fees.Tiers)),
		},
	}
	for k, v := range a.Fees.Tiers {
		clone.Fees.Tiers[k] = v
	}
	return clone
}

func main() {
	// Standard enterprise template prototype
	enterprisePrototype := &AccountArchetype{
		TierName:    "ENTERPRISE_BASE",
		MaxDailyTxn: 10000,
		Fees: FeeSchedule{
			BaseFeeCents: 50,
			Tiers:        map[string]float64{"card": 0.015, "wire": 0.005},
		},
	}

	// Clone prototype for custom VIP client
	vipClient := enterprisePrototype.Clone()
	vipClient.TierName = "VIP_ACME_CORP"
	vipClient.Fees.Tiers["wire"] = 0.001 // Mutating clone does NOT corrupt prototype!

	fmt.Printf("Prototype wire fee: %.3f\n", enterprisePrototype.Fees.Tiers["wire"])
	fmt.Printf("VIP Client wire fee: %.3f\n", vipClient.Fees.Tiers["wire"])
}
```

## Accept Interfaces Return Structs

<Define term="Accept Interfaces, Return Structs" since="Structs, Methods, Interfaces & Errors (Part 1, Chapter 2)">
**Accept interfaces** in function arguments — ask for the narrowest behavior your function requires (`io.Reader`, `PaymentStore`). **Return structs** (concrete types) from constructors and producers — giving callers full visibility and method access without artificial restrictions. **Why it matters:** returning an interface boxes the caller in and forces type assertions. Accepting a concrete struct couples your code to one implementation and makes testing impossible.
</Define>

This is the cornerstone of Go software architecture. Let's see it in practice:

<GoPlayground>

```go
package main

import (
	"context"
	"fmt"
)

type Account struct {
	ID          string
	BalancePennies int64
}

// AccountReader is the narrow, consumer-defined interface.
type AccountReader interface {
	GetAccount(ctx context.Context, id string) (*Account, error)
}

// AccountAuditor accepts the interface, decoupled from any specific DB driver.
type AccountAuditor struct {
	reader AccountReader
}

// NewAccountAuditor returns the concrete struct *AccountAuditor.
func NewAccountAuditor(r AccountReader) *AccountAuditor {
	return &AccountAuditor{reader: r}
}

func (a *AccountAuditor) AuditSolvency(ctx context.Context, id string) (bool, error) {
	acct, err := a.reader.GetAccount(ctx, id)
	if err != nil {
		return false, err
	}
	return acct.BalancePennies >= 0, nil
}

// In tests or in-memory runs:
type memoryAccountStore struct {
	data map[string]*Account
}

func (m *memoryAccountStore) GetAccount(_ context.Context, id string) (*Account, error) {
	acct, ok := m.data[id]
	if !ok {
		return nil, fmt.Errorf("account %s not found", id)
	}
	return acct, nil
}

func main() {
	store := &memoryAccountStore{
		data: map[string]*Account{
			"ACCT-01": {ID: "ACCT-01", BalancePennies: 50000},
			"ACCT-02": {ID: "ACCT-02", BalancePennies: -2500},
		},

	ctx := context.Background()

	fmt.Printf("ACCT-02 Solvent? %t\n", s2)
```

</GoPlayground>

<UnderTheHood title="The two-word interface value and the typed-nil trap">

In the Go runtime, an interface value is represented as a two-machine-word header:
1. `tab` (*itab): points to type metadata and the method lookup table (itab).
2. `data` (unsafe.Pointer): points to the concrete heap instance.

An interface is only equal to `nil` if **both** `tab` and `data` are zero. If a function returns a concrete nil pointer (`var f *fakeStore = nil`) assigned to an interface return type (`AccountReader`), the interface header receives a valid type descriptor for `*fakeStore` in `tab`, while `data` is nil. Testing `if r != nil` evaluates to **true** — triggering a panic when a method is called. Always return concrete nil values directly, or return explicit untyped `nil` when returning interface types.

</UnderTheHood>

## Structural Patterns

Structural patterns explain how to assemble structs and interfaces into larger, flexible architectures without sacrificing performance.

### 1. Adapter (Wrapping Interfaces & Function Adapters)

Adapters translate one interface into another that a client expects. Go supports both **struct adapters** (wrapping incompatible foreign SDKs) and **function adapters** (like `http.HandlerFunc`):

<GoPlayground>

```go
package main

import (
	"context"
	"fmt"
)

// Target interface expected by Meridian's core payment system
type ModernPaymentGateway interface {
	Charge(ctx context.Context, token string, amountCents int64) (string, error)
}

// Foreign / Legacy Banking SDK (Incompatible third-party interface)
type LegacySWIFTLibrary struct{}

func (l *LegacySWIFTLibrary) ExecuteWireTransfer(wireRef string, amountUnits float64) bool {
	fmt.Printf("[LEGACY SWIFT] Wire %s for $%.2f succeeded\n", wireRef, amountUnits)
	return true
}

// Struct Adapter
type SWIFTAdapter struct {
	sdk *LegacySWIFTLibrary
}

func NewSWIFTAdapter(sdk *LegacySWIFTLibrary) *SWIFTAdapter {
	return &SWIFTAdapter{sdk: sdk}
}

func (a *SWIFTAdapter) Charge(ctx context.Context, token string, cents int64) (string, error) {

		return "", fmt.Errorf("swift wire transfer failed")
	}

// Function Adapter idiom (like http.HandlerFunc)
type PaymentHandler interface {
	Process(cents int64) error
}

func (f PaymentHandlerFunc) Process(cents int64) error {
	return f(cents)

		fmt.Printf("Function adapter executed payment of %d cents\n", c)
		return nil
	})
	_ = h.Process(2500)
}
```

### 2. Decorator / Interceptor (HTTP Middleware & Generic Decorators)

Decorators dynamically attach responsibilities to objects. In Go, closures wrap functions with identical signatures, powering HTTP middleware, gRPC interceptors, and generic decorators (`Memoize`, `Retry`):

<GoPlayground>

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type FeeCalculator func(ctx context.Context, accountID string, amountCents int64) (int64, error)

// Generic Decorator: adds caching around any pure calculation
func WithMemoization(next FeeCalculator) FeeCalculator {
	var mu sync.Mutex
	cache := make(map[string]int64)

	return func(ctx context.Context, accountID string, amountCents int64) (int64, error) {
		key := fmt.Sprintf("%s:%d", accountID, amountCents)
		mu.Lock()
		if val, exists := cache[key]; exists {
			mu.Unlock()
			return val, nil
		}
		mu.Unlock()

		fee, err := next(ctx, accountID, amountCents)
		if err != nil {
			return 0, err
		}

		mu.Lock()
		cache[key] = fee
		mu.Unlock()
		return fee, nil
	}
}

// Generic Decorator: adds execution timing telemetry
func WithTiming(name string, next FeeCalculator) FeeCalculator {
	return func(ctx context.Context, accountID string, amountCents int64) (int64, error) {
		start := time.Now()
		fee, err := next(ctx, accountID, amountCents)
		fmt.Printf("[METRICS] %s took %v (fee=%d cents)\n", name, time.Since(start), fee)
		return fee, err
	}
}

func main() {
	var baseCalculator FeeCalculator = func(ctx context.Context, acct string, amt int64) (int64, error) {
		time.Sleep(10 * time.Millisecond) // simulate expensive dynamic lookup
		return amt / 100, nil             // 1% base fee
	}

	// Compose decorators
	pipeline := WithTiming("CalculateFee", WithMemoization(baseCalculator))

	ctx := context.Background()
	f1, _ := pipeline(ctx, "ACCT-100", 50000)
	f2, _ := pipeline(ctx, "ACCT-100", 50000) // cache hit!
	fmt.Printf("Results: f1=%d, f2=%d\n", f1, f2)
}
```

### 5. Proxy (Virtual, Protection & Caching Proxies)

A Proxy controls access to an underlying object. Go provides:
- **Virtual Proxy**: Lazy-loads expensive encryption keys or ML models on first request.
- **Protection Proxy**: Enforces RBAC permissions before delegating.
- **Caching Proxy**: Intercepts requests to return cached results.

<GoPlayground>

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
)

type VaultService interface {
	GetMasterKey(ctx context.Context, callerRole string) (string, error)
}

type RealHSMVault struct{}

func (r *RealHSMVault) GetMasterKey(_ context.Context, _ string) (string, error) {
	fmt.Println("  [HSM Hardware] Hardware security module unwrapped master key.")
	return "0xDEADBEEFCAFE9900", nil
}

// ProtectionAndCachingProxy combines authorization and lazy caching
type VaultProxy struct {
	vault     *RealHSMVault
	mu        sync.Mutex
	cachedKey string
}

func NewVaultProxy() *VaultProxy {
	return &VaultProxy{vault: &RealHSMVault{}}
}

func (p *VaultProxy) GetMasterKey(ctx context.Context, callerRole string) (string, error) {
	// Protection check
	if callerRole != "SECURITY_ADMIN" {
		return "", errors.New("access denied: unauthorized role")
	}

	p.mu.Lock()
	defer p.mu.Unlock()

	// Virtual/Caching proxy behavior
	if p.cachedKey != "" {
		fmt.Println("  [Proxy Cache] Returning cached master key.")
		return p.cachedKey, nil
	}

	key, err := p.vault.GetMasterKey(ctx, callerRole)
	if err != nil {
		return "", err
	}
	p.cachedKey = key
	return key, nil
}

func main() {
	proxy := NewVaultProxy()
	ctx := context.Background()

	// Unauthorized attempt
	_, err := proxy.GetMasterKey(ctx, "TELLER")
	fmt.Printf("Teller access: %v\n", err)

	// Authorized call 1 (hits real vault)
	k1, _ := proxy.GetMasterKey(ctx, "SECURITY_ADMIN")
	fmt.Printf("Admin key (call 1): %s\n", k1)

	// Authorized call 2 (hits proxy cache)
	k2, _ := proxy.GetMasterKey(ctx, "SECURITY_ADMIN")
	fmt.Printf("Admin key (call 2): %s\n", k2)
}
```

### 7. Flyweight (String Interning & Symbol Tables)

The Flyweight pattern reduces memory usage by sharing immutable common state among many entities. In Meridian, sharing interned pointers for currency codes, country metadata, and transaction states across millions of in-memory accounts prevents hundreds of megabytes of redundant heap allocations:

## Behavioral Patterns: Strategy, State & Observer

Behavioral patterns characterize the ways in which classes or objects interact and distribute responsibility.

### 1. Strategy (Interface- & Function-Based Strategies)

The Strategy pattern defines a family of interchangeable algorithms. In Go, one-method interfaces or function types *are* the Strategy pattern:

<GoPlayground>

```go
package main

func FlatFeeStrategy(amountCents int64) int64 {
	return 30 // $0.30 flat fee

func TieredPercentageStrategy(amountCents int64) int64 {

	return amountCents * 15 / 1000 // 1.5%

type PricingEngine struct {

	return amountCents + fee
}

	fmt.Printf("Flat fee on $100: %d cents\n", engine.CalculateTotal(10000))

	fmt.Printf("Tiered fee on $20,000: %d cents\n", engine.CalculateTotal(2_000_000))
}
```

### 2. State (State Machine via Interface Dispatch)

The State pattern allows an object to alter its behavior when its internal state changes. In Go, this is modeled by an interface representing states, where each concrete state struct handles allowed transitions and rejects invalid ones:

<GoPlayground>

```go
package main

import (
	"errors"
	"fmt"

type PaymentState interface {
	Authorize(p *PaymentContext) error
	Settle(p *PaymentContext) error
	Refund(p *PaymentContext) error
	Name() string
}

type PaymentContext struct {
	TxnID string
	State PaymentState
}

// 1. Pending State
type PendingState struct{}
func (s *PendingState) Name() string { return "PENDING" }
func (s *PendingState) Authorize(p *PaymentContext) error {
	fmt.Println("  -> Payment authorized successfully.")
	p.State = &AuthorizedState{}
```

### 3. Observer / PubSub (Channel-Based Event Buses)

In Go, Observer maps to channels. A generic `EventBroker` provides multi-subscriber fan-out with non-blocking sends so slow consumers cannot stall the publisher:

<GoPlayground>

```go
package main

import (
	"fmt"
	"sync"
)

type Event struct {
	Topic   string
	Payload string
}

type EventBroker struct {
	mu   sync.RWMutex
	subs map[string][]chan Event
}

func NewEventBroker() *EventBroker {
	return &EventBroker{subs: make(map[string][]chan Event)}
}

func (b *EventBroker) Subscribe(topic string) <-chan Event {
	b.mu.Lock()
	defer b.mu.Unlock()
	ch := make(chan Event, 16)
	b.subs[topic] = append(b.subs[topic], ch)
	return ch
}

func (b *EventBroker) Publish(topic, payload string) {
	b.mu.RLock()
	defer b.mu.RUnlock()
	evt := Event{Topic: topic, Payload: payload}
	for _, ch := range b.subs[topic] {
		select {
		case ch <- evt:
		default:
			// Non-blocking drop for overflowing subscriber channels
			fmt.Printf("[DROP] Subscriber buffer full on topic %s\n", topic)
		}
	}
}

func main() {
	broker := NewEventBroker()
	fraudSub := broker.Subscribe("payments.captured")
	auditSub := broker.Subscribe("payments.captured")

	var wg sync.WaitGroup
	wg.Add(2)

	go func() {
		defer wg.Done()
		e := <-fraudSub
		fmt.Printf("Fraud Engine received: %s\n", e.Payload)
	}()

	go func() {
		defer wg.Done()
		e := <-auditSub
		fmt.Printf("Audit Engine received: %s\n", e.Payload)
	}()

	broker.Publish("payments.captured", "TXN-7721 amount=5000")
	wg.Wait()
}
```

### 4. Command (Action Encapsulation, Undo Stacks & Outbox)

The Command pattern encapsulates a request as an object. In Go, a closure `func() error` or a struct with `Execute()` and `Undo()` provides reversible transaction sagas:

<GoPlayground>

```go
package main

import (
	"fmt"
)

type Command interface {
	Execute() error
	Undo() error
}

type TransferFundsCommand struct {
	from   string
	to     string
	amount int64
	done   bool
}

func (c *TransferFundsCommand) Execute() error {
	fmt.Printf("EXECUTING: Transfer %d cents from %s -> %s\n", c.amount, c.from, c.to)
	c.done = true
	return nil
}

func (c *TransferFundsCommand) Undo() error {
	if !c.done {
		return nil
	}
	fmt.Printf("COMPENSATING (UNDO): Reversing %d cents from %s back to %s\n", c.amount, c.to, c.from)
	c.done = false
	return nil
}

type CommandExecutor struct {
	history []Command
}

func (e *CommandExecutor) Run(cmd Command) error {
	if err := cmd.Execute(); err != nil {
		return err
	}
	e.history = append(e.history, cmd)
	return nil
}

func (e *CommandExecutor) RollbackAll() {
	for i := len(e.history) - 1; i >= 0; i-- {
		_ = e.history[i].Undo()
	}
	e.history = nil
}

func main() {
	executor := &CommandExecutor{}
	c1 := &TransferFundsCommand{from: "A", to: "B", amount: 5000}
	c2 := &TransferFundsCommand{from: "B", to: "C", amount: 3000}

	_ = executor.Run(c1)
	_ = executor.Run(c2)

	fmt.Println("\n--- Transaction Pipeline Failed downstream: Initiating Saga Compensations ---")
	executor.RollbackAll()
}
```

## Behavioral Patterns: Iterators, Rules & Mediators

### 1. Iterator (Go 1.23+ `iter.Seq`, `iter.Seq2` and `iter.Pull`)

Go 1.23 standardizes iterators into the `iter` package using range-over-func.
- `iter.Seq[V]`: Single value sequence `func(yield func(V) bool)`.
- `iter.Seq2[K, V]`: Key-value sequence `func(yield func(K, V) bool)`.
- `iter.Pull`: Converts a push iterator into a pull iterator that can be stepped manually to merge or zip sequences.

<GoPlayground>

```go
package main

import (
	"fmt"
	"iter"
)

type LedgerEntry struct {
	ID     string
	Amount int64
}

type LedgerDatabase struct {
	entries []LedgerEntry
}

// All returns a push iterator (iter.Seq2) over all entries.
func (db *LedgerDatabase) All() iter.Seq2[int, LedgerEntry] {
	return func(yield func(int, LedgerEntry) bool) {
		for i, entry := range db.entries {
			if !yield(i, entry) {
				return // CRITICAL: Stop immediately when consumer breaks
			}
		}
	}
}

func main() {
	db := &LedgerDatabase{
		entries: []LedgerEntry{
			{"TX-1", 5000},
			{"TX-2", 12000},
			{"TX-3", 8000},
			{"TX-4", 25000},
		},
	}

	// 1. Range-over-func in Go 1.23+
	fmt.Println("--- Range over iterator ---")
	for idx, item := range db.All() {
		fmt.Printf("[%d] %s: %d cents\n", idx, item.ID, item.Amount)
		if item.Amount > 10000 {
			fmt.Println("Breaking early on high-value item!")
			break
		}
	}

	// 2. iter.Pull for manual stepping
	fmt.Println("\n--- iter.Pull manual stepping ---")
	next, stop := iter.Pull2(db.All())
	defer stop()

	for {
		idx, item, ok := next()
		if !ok {
			break
		}
		fmt.Printf("Pulled index %d: %s\n", idx, item.ID)
	}
}
```

### 3. Chain of Responsibility (Validation & Compliance Pipelines)

In a Chain of Responsibility, a request travels down a pipeline of handlers. Each handler processes the payload and decides whether to halt or pass to the next stage:

```go
package main

import (
	"context"
	"errors"
	"fmt"

type ComplianceRequest struct {
	AccountID string
	Amount    int64
	Country   string
}

type ComplianceHandler interface {
	Check(ctx context.Context, req ComplianceRequest) error
	SetNext(handler ComplianceHandler) ComplianceHandler

type BaseComplianceHandler struct {
	next ComplianceHandler
}

func (b *BaseComplianceHandler) SetNext(h ComplianceHandler) ComplianceHandler {
	b.next = h
	return h
}

	if b.next != nil {
		return b.next.Check(ctx, req)
	}
	return nil
}

	}
	fmt.Println("  [VelocityCheck] Passed")
	return v.PassNext(ctx, req)
}
```

### 5. Visitor (AST Traversal & Type Switch Dispatch)

The Visitor pattern decouples an operation from the heterogeneous object structures it runs over. In Go, an idiomatic type switch over a sealed AST interface is far cleaner than double-dispatch:

```go
package main

import "fmt"

type RuleNode interface {
	isRule()
}

type MinBalanceRule struct{ Cents int64 }
type BlacklistRule struct{ BlockedAccount string }
type CurrencyWhitelistRule struct{ AllowedCurrencies []string }

func (MinBalanceRule) isRule()        {}
func (BlacklistRule) isRule()         {}
func (CurrencyWhitelistRule) isRule() {}

// EvaluateRule uses a type switch (idiomatic Go Visitor)
func EvaluateRule(node RuleNode, acct string, balance int64, curr string) bool {
	switch r := node.(type) {
	case MinBalanceRule:
		return balance >= r.Cents
	case BlacklistRule:
		return acct != r.BlockedAccount
	case CurrencyWhitelistRule:
		for _, c := range r.AllowedCurrencies {
			if c == curr {
				return true
			}
		}
		return false
	default:
		panic(fmt.Sprintf("unknown rule type: %T", node))
	}
}

	rules := []RuleNode{
		MinBalanceRule{Cents: 1000},
		BlacklistRule{BlockedAccount: "FRAUD-ACCT-99"},
		CurrencyWhitelistRule{AllowedCurrencies: []string{"USD", "EUR"}},

		ok := EvaluateRule(rule, "GOOD-ACCT", 5000, "USD")
		fmt.Printf("Evaluated %T: passed=%t\n", rule, ok)
```

## Concurrency Patterns: Worker Pools & Pipelines

### 1. Bounded Worker Pool

A worker pool uses a fixed set of goroutines reading from a shared channel, bounding memory and CPU regardless of job volume:

<GoPlayground>

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type ReconcileJob struct {
	TxnID       string
	AmountCents int64
}

type ReconcileResult struct {
	TxnID string
	Err   error
}

func RunWorkerPool(ctx context.Context, jobs []ReconcileJob, numWorkers int) []ReconcileResult {
	jobCh := make(chan ReconcileJob, len(jobs))
	resultCh := make(chan ReconcileResult, len(jobs))
	var wg sync.WaitGroup

	for range numWorkers {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for job := range jobCh {
				select {
				case <-ctx.Done():
					resultCh <- ReconcileResult{TxnID: job.TxnID, Err: ctx.Err()}
					continue
				default:
				}
				time.Sleep(5 * time.Millisecond) // Simulate DB reconciliation work
				resultCh <- ReconcileResult{TxnID: job.TxnID}
			}
		}()
	}

	for _, j := range jobs {
		jobCh <- j
	}
	close(jobCh) // Signal workers to exit when drained

	go func() {
		wg.Wait()
		close(resultCh)
	}()

	var results []ReconcileResult
	for r := range resultCh {
		results = append(results, r)
	}
	return results
}

func main() {
	jobs := make([]ReconcileJob, 8)
	for i := range jobs {
		jobs[i] = ReconcileJob{TxnID: fmt.Sprintf("TXN-%02d", i+1), AmountCents: int64((i + 1) * 1000)}
	}

	results := RunWorkerPool(context.Background(), jobs, 3)
	fmt.Printf("Worker pool processed %d jobs successfully.\n", len(results))
}
```

### 2. Fan-In and Fan-Out

Fan-out distributes work across parallel goroutines; Fan-in multiplexes their results back into a single output channel:

<GoPlayground>

```go
package main

import (
	"fmt"
	"sync"
)

type PaymentEvent struct {
	TxnID  string
	Amount int64
}

type Verdict struct {
	TxnID   string
	Checker string
	Flagged bool
}

func checker(name string, in <-chan PaymentEvent) <-chan Verdict {
	out := make(chan Verdict, 4)
	go func() {
		defer close(out)
		for e := range in {
			out <- Verdict{TxnID: e.TxnID, Checker: name, Flagged: e.Amount > 50000}
		}
	}()
	return out
}

func fanIn(channels ...<-chan Verdict) <-chan Verdict {
	merged := make(chan Verdict, 8)
	var wg sync.WaitGroup
	for _, ch := range channels {
		wg.Add(1)
		go func(c <-chan Verdict) {
			defer wg.Done()
			for v := range c {
				merged <- v
			}
		}(ch)
	}
	go func() {
		wg.Wait()
		close(merged)
	}()
	return merged
}

func main() {
	source := make(chan PaymentEvent, 3)
	source <- PaymentEvent{TxnID: "TX-1", Amount: 2000}
	source <- PaymentEvent{TxnID: "TX-2", Amount: 75000}
	source <- PaymentEvent{TxnID: "TX-3", Amount: 10000}
	close(source)

	// Fan out across two analysis engines
	lane1 := checker("Velocity", source)
	lane2 := checker("Sanctions", source)

	for v := range fanIn(lane1, lane2) {
		if v.Flagged {
			fmt.Printf("FLAGGED by %s: %s\n", v.Checker, v.TxnID)
		}
	}
}
```

### 1. Repository & Unit of Work

### 2. Actor Pattern (Goroutine State Ownership)

In the Actor pattern, a dedicated goroutine exclusively owns mutable state and communicates solely through an inbox channel, eliminating mutexes and data races:

<GoPlayground>

```go
package main

import (
	"fmt"
	"sync"
)

type AccountMessage struct {
	Op       string // "DEPOSIT" or "BALANCE"
	Amount   int64
	ReplyCh  chan int64
}

// AccountActor exclusively owns account balance
func AccountActor(inbox <-chan AccountMessage) {

	for msg := range inbox {

		case "DEPOSIT":
			balance += msg.Amount
			msg.ReplyCh <- balance
		case "BALANCE":
			msg.ReplyCh <- balance
		}
	}
}

func main() {

			<-reply
		}(1000)

	reply := make(chan int64)
	inbox <- AccountMessage{Op: "BALANCE", ReplyCh: reply}
```

### 3. Singleflight & Circuit Breaker

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

// Singleflight implementation
type Call struct {
	val any
	err error
	wg  sync.WaitGroup
}

type Group struct {
	mu sync.Mutex
	m  map[string]*Call
}

func (g *Group) Do(key string, fn func() (any, error)) (any, error) {
	g.mu.Lock()
	if g.m == nil {
		g.m = make(map[string]*Call)
	}
	if c, ok := g.m[key]; ok {
		g.mu.Unlock()
		c.wg.Wait()
		return c.val, c.err
	}
	c := new(Call)
	c.wg.Add(1)
	g.m[key] = c
	g.mu.Unlock()

	c.val, c.err = fn()
	c.wg.Done()

	g.mu.Lock()
	delete(g.m, key)
	g.mu.Unlock()

	return c.val, c.err
}

func main() {
	var g Group
	var executions int
	var mu sync.Mutex

	expensiveLookup := func() (any, error) {
		mu.Lock()
		executions++
		mu.Unlock()
		time.Sleep(20 * time.Millisecond) // Simulate slow backend gateway call
		return "EXCHANGE_RATE_1.085", nil
	}

	var wg sync.WaitGroup
	for i := 0; i < 5; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			v, _ := g.Do("fx:EUR_USD", expensiveLookup)
			fmt.Printf("Caller %d got result: %s\n", id, v)
		}(i + 1)
	}
	wg.Wait()

	fmt.Printf("Total backend executions: %d (Singleflight collapsed 5 callers into 1)\n", executions)
}
```

Build a three-layer HTTP middleware chain: `RecoveryMiddleware` (recovers panics -> 500), `LoggingMiddleware` (logs method + duration), and `AuthMiddleware` (checks `X-API-Key`). Demonstrate normal, unauthorized, and panicking requests with `httptest`.

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"net/http/httptest"
	"time"
)

func RecoveryMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("[PANIC RECOVERED] %v", rec)
				http.Error(w, "internal error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func LoggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		next.ServeHTTP(w, r)
		log.Printf("[LOG] %s %s took %v", r.Method, r.URL.Path, time.Since(start))
	})
}

func AuthMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("X-API-Key") != "meridian-secret" {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		next.ServeHTTP(w, r)
	})
}

func Chain(h http.Handler, mws ...func(http.Handler) http.Handler) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}

func Handler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "OK")
}

func main() {
	chain := Chain(http.HandlerFunc(Handler), RecoveryMiddleware, LoggingMiddleware, AuthMiddleware)
```

<Exercise n={4} title="Bounded worker pool with context deadline" level="medium">

Extend a worker pool to accept a `context.Context` with a deadline. Workers must abort remaining jobs once `ctx.Done()` fires, returning partial results and recording skipped jobs.

<Solution>

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type Job struct{ ID int }
type Result struct {
	ID      int
	Skipped bool
}

func RunPool(ctx context.Context, jobs []Job, workers int) ([]Result, int) {
	jobCh := make(chan Job, len(jobs))
	resultCh := make(chan Result, len(jobs))
	var wg sync.WaitGroup

	for range workers {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for job := range jobCh {
				select {
				case <-ctx.Done():
					resultCh <- Result{ID: job.ID, Skipped: true}
					continue
				default:
				}
				time.Sleep(15 * time.Millisecond)
				resultCh <- Result{ID: job.ID, Skipped: false}
			}
		}()
	}

	for _, j := range jobs { jobCh <- j }
	close(jobCh)

	go func() {
		wg.Wait()
		close(resultCh)
	}()

	var results []Result
	skipped := 0
	for r := range resultCh {
		results = append(results, r)
		if r.Skipped { skipped++ }
	}
	return results, skipped
}

func main() {
	jobs := make([]Job, 10)
	for i := range jobs { jobs[i] = Job{ID: i + 1} }

	ctx, cancel := context.WithTimeout(context.Background(), 35*time.Millisecond)
	defer cancel()

	res, skipped := RunPool(ctx, jobs, 2)
	fmt.Printf("Total: %d, Skipped: %d, Processed: %d\n", len(res), skipped, len(res)-skipped)
}
```

<Exercise n={7} title="Generic memoizing decorator" level="medium">

```go
package main

import (
	"fmt"
	"sync"
)

func Memoize[K comparable, V any](fn func(K) V) func(K) V {
	var mu sync.Mutex
	cache := make(map[K]V)

	return func(k K) V {
		mu.Lock()
		defer mu.Unlock()
		if val, exists := cache[k]; exists {
			return val
		}
		res := fn(k)
		cache[k] = res
		return res
	}
}

func main() {

		calls++
		return 500
	}

	_ = memo("ACCT-1")
	_ = memo("ACCT-1")
	_ = memo("ACCT-2")
```
