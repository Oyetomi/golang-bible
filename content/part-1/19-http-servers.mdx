## Handlers, Routing & Middleware

*Stop 1 of 6.*

### Step 1: one interface runs the whole server

<Define term="handler / http.Handler">
A **handler** is anything that can answer an HTTP request. In Go that's any type with the method `ServeHTTP(http.ResponseWriter, *http.Request)`. The router is a handler, a middleware chain is a handler, and your endpoint function becomes one too.
</Define>

```go
// From net/http: the one interface everything speaks.
type Handler interface {
	ServeHTTP(ResponseWriter, *Request)
}
```

The two arguments are the two halves of the conversation. `*http.Request` is what the client sent: method, URL, headers, body. `http.ResponseWriter` is where your answer goes: you set headers, optionally a status code, then write the body.

Writing a struct for every endpoint would be tedious, so `net/http` includes an adapter:

```go
// From net/http: a function type that IS a Handler.
type HandlerFunc func(ResponseWriter, *Request)

func (f HandlerFunc) ServeHTTP(w ResponseWriter, r *Request) { f(w, r) }
```

Read it slowly. `HandlerFunc` is a *type* whose values are functions. It has a method, `ServeHTTP`, which just calls the function. So `http.HandlerFunc(myFunc)` is a conversion that turns any function with the right signature into a `Handler`. No new code runs; the function gains a method.

### Step 2: routing with `ServeMux`

<Define term="ServeMux (router)">
A **ServeMux** maps request patterns to handlers. Since Go 1.22 a pattern can include the HTTP method and named wildcards: `"GET /api/accounts/{id}"` matches only GETs, and the handler reads the captured part with `r.PathValue("id")`. When several patterns match, the most specific one wins.
</Define>

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /api/accounts/{id}", getAccount) // {id} matches one path segment
mux.HandleFunc("POST /api/transfers", createTransfer)
mux.HandleFunc("GET /files/{path...}", serveFile)    // {path...} matches the rest of the path
```

Two version notes. Before Go 1.22, `ServeMux` had no methods or wildcards, which is why so many older projects use `chi` or `gorilla/mux`. And since **Go 1.26**, when you register a subtree like `/assets/` and a client asks for `/assets`, the automatic redirect is a **307** (which keeps the method and body) instead of a 301.

Always create your own mux. The package-level `http.DefaultServeMux` is shared by every library you import, and some register debug handlers on it just by being imported.

### Step 3: middleware is a corridor

<Define term="middleware">
**Middleware** is a function with the signature `func(http.Handler) http.Handler`: it takes a handler and returns a new one that does something before and/or after calling it. Cross-cutting concerns (logging, authentication, panic recovery, request IDs) live in middleware instead of being repeated in every endpoint.
</Define>

Here are those three pieces in code. `statusRecorder` is the trick that lets logging see the status: it wraps the real `ResponseWriter` and remembers what `WriteHeader` was called with. Because it **embeds** `http.ResponseWriter`, it gets all the other methods (`Header`, `Write`) for free and only overrides one.

<GoPlayground>

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

// statusRecorder remembers the status code the inner handler writes.
type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (s *statusRecorder) WriteHeader(code int) {
	s.status = code
	s.ResponseWriter.WriteHeader(code)
}

func logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("  → logging: in")
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(rec, r)
		fmt.Println("  ← logging: out, status", rec.status)
	})
}

func requireAuth(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("    → auth: in")
		if r.Header.Get("Authorization") == "" {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			fmt.Println("    ← auth: rejected, handler never runs")
			return
		}
		next.ServeHTTP(w, r)
		fmt.Println("    ← auth: out")
	})
}

func getAccount(w http.ResponseWriter, r *http.Request) {
	fmt.Println("      handler: account", r.PathValue("id"))
	fmt.Fprintln(w, "ok")
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /api/accounts/{id}", getAccount)
	h := logging(requireAuth(mux)) // logging is outermost

	fmt.Println("request with a token:")
	r1 := httptest.NewRequest("GET", "/api/accounts/ACC-42", nil)
	r1.Header.Set("Authorization", "Bearer t0k3n")
	h.ServeHTTP(httptest.NewRecorder(), r1)

	fmt.Println("request without one:")
	h.ServeHTTP(httptest.NewRecorder(), httptest.NewRequest("GET", "/api/accounts/ACC-42", nil))
}
```

</GoPlayground>

```text
request with a token:
  → logging: in
    → auth: in
      handler: account ACC-42
    ← auth: out
  ← logging: out, status 200
request without one:
  → logging: in
    → auth: in
    ← auth: rejected, handler never runs
  ← logging: out, status 401
```

`httptest.NewRequest` and `httptest.NewRecorder` let you call any handler directly, with no network. The recorder captures the status, headers and body, which is how you unit-test handlers.

With several middlewares, a small helper keeps the nesting readable:

```go
// chain(h, a, b, c) returns a(b(c(h))): the first one listed is outermost.
func chain(h http.Handler, mw ...func(http.Handler) http.Handler) http.Handler {
	for i := len(mw) - 1; i >= 0; i-- {
		h = mw[i](h)
	}
	return h
}
```

### Step 4: one goroutine per connection

When a connection arrives, `net/http` starts one goroutine for it. That goroutine reads requests off the connection and calls your handler for each one, synchronously. With HTTP/2, each stream (request) gets its own goroutine. Either way: **your handler runs concurrently with every other request**, so any state handlers share (a map, a counter) needs a mutex or an atomic, exactly as in the concurrency chapter.

Two rules about `ResponseWriter` that follow from how it's built:

- **Headers first.** The first `Write` (or `WriteHeader`) sends the status line and headers. Changing `w.Header()` after that does nothing.
- **The status is sent once.** A second `WriteHeader` is ignored, and the server logs `http: superfluous response.WriteHeader call`. If you never call it, the first `Write` sends 200.

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /api/accounts/{id}", getAccount)
	mux.HandleFunc("POST /api/transfers", createTransfer)
	mux.HandleFunc("GET /api/transfers/{txID}", getTransfer)
	srv := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       10 * time.Second,
		WriteTimeout:      30 * time.Second,
		IdleTimeout:       120 * time.Second,
	}

	// ctx is cancelled on Ctrl-C (SIGINT) or SIGTERM.
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	go func() {
		slog.Info("listening", "addr", srv.Addr)
		if err := srv.ListenAndServe(); !errors.Is(err, http.ErrServerClosed) {
			slog.Error("server failed", "err", err)
			os.Exit(1)
		}
	}()

	<-ctx.Done() // wait for a signal
	slog.Info("shutting down")

	shutdownCtx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
	defer cancel()
	if err := srv.Shutdown(shutdownCtx); err != nil {
		slog.Error("shutdown did not finish in time", "err", err)
	}
	slog.Info("server stopped cleanly")
}

func getAccount(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintf(w, "account: %s\n", r.PathValue("id"))
}

func createTransfer(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusAccepted) // the real version is in Stop 2
}

func getTransfer(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintf(w, "transfer: %s\n", r.PathValue("txID"))
}
```

```go
package main

import (
	"context"
	"fmt"
	"io"
	"net"
	"net/http"
	"time"
)

func main() {
	ln, _ := net.Listen("tcp", "127.0.0.1:0")
	url := "http://" + ln.Addr().String()

	mux := http.NewServeMux()
	mux.HandleFunc("GET /transfer", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(500 * time.Millisecond) // a slow, in-flight request
		fmt.Fprint(w, "transfer done")
	})
	srv := &http.Server{Handler: mux, ReadHeaderTimeout: 5 * time.Second}
	go srv.Serve(ln)

	start := time.Now()
	since := func() time.Duration { return time.Since(start).Round(100 * time.Millisecond) }

	done := make(chan struct{})
	go func() { // request A starts before the shutdown
		resp, err := http.Get(url + "/transfer")
		if err != nil {
			fmt.Println(since(), "A failed:", err)
		} else {
			body, _ := io.ReadAll(resp.Body)
			resp.Body.Close()
			fmt.Println(since(), "A finished:", resp.Status, string(body))
		}
		close(done)
	}()

	time.Sleep(100 * time.Millisecond)
	fmt.Println(since(), "SIGTERM arrives: calling Shutdown")
	go func() {
		time.Sleep(100 * time.Millisecond)
		_, err := http.Get(url + "/transfer") // request B arrives during shutdown
		fmt.Println(since(), "B (new connection) got:", err != nil)
	}()

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	err := srv.Shutdown(ctx) // blocks until A is done
	fmt.Println(since(), "Shutdown returned:", err)
	<-done
}
```

</GoPlayground>

```text
100ms SIGTERM arrives: calling Shutdown
200ms B (new connection) got: true
500ms A finished: 200 OK transfer done
600ms Shutdown returned: <nil>
```

B was refused (`got: true` means it got an error), A completed normally, and Shutdown returned once A was done. The extra 100 ms is Shutdown's polling interval.

One gap to know: `Shutdown` **does not wait for hijacked connections**, which means WebSockets (Stop 5). Use `srv.RegisterOnShutdown` to tell those handlers to close.

### Step 1: controlling how a type is encoded

A type controls its own JSON by implementing two methods: `MarshalJSON() ([]byte, error)` and `UnmarshalJSON([]byte) error`. `encoding/json` calls them whenever it meets that type, anywhere in a struct.

Meridian stores money as whole cents in an `int64`, but wants it on the wire as a string like `"12.34"`, so no client ever parses it into a floating-point number. The first version of this chapter's `Money` type looked fine and was wrong in four ways. Running it:

```text
Money(-50) marshals to "0.50"             ← the minus sign vanished
unmarshal "12.3"   -> 1203                ← 12.03, not 12.30
unmarshal "12.345" -> 1234                ← the extra digit silently dropped
unmarshal "1.5x"   -> 105                 ← garbage accepted
```

The marshal bug: it split `-50` into dollars (`-50 / 100 = 0`) and cents (`-50 % 100 = -50`), then made the cents positive, so the sign was lost whenever the amount was under one unit. The parse bugs came from `fmt.Sscanf("%d.%02d")`, which reads *up to* two digits and ignores whatever follows. For a payments API, each of those is an incident. The fixed version is strict about the format and handles the sign before splitting:

<GoPlayground>

```go
package main

import (
	"encoding/json"
	"fmt"
	"math"
	"strconv"
	"strings"
)

// Money is a whole number of cents. On the wire it's a string like "-12.34",
// so clients never parse it into a float.
type Money int64

func (m Money) MarshalJSON() ([]byte, error) {
	sign, v := "", int64(m)
	if v < 0 {
		sign, v = "-", -v // take the sign off FIRST, then split
	}
	return json.Marshal(fmt.Sprintf("%s%d.%02d", sign, v/100, v%100))
}

func (m *Money) UnmarshalJSON(data []byte) error {
	var s string
	if err := json.Unmarshal(data, &s); err != nil {
		return fmt.Errorf("money: want a string like \"12.34\": %w", err)
	}
	neg := strings.HasPrefix(s, "-")
	whole, frac, ok := strings.Cut(strings.TrimPrefix(s, "-"), ".")
	if !ok || !digits(whole) || len(frac) != 2 || !digits(frac) {
		return fmt.Errorf("money: want digits, a dot, then exactly 2 digits; got %q", s)
	}
	w, err := strconv.ParseInt(whole, 10, 64)
	if err != nil || w > math.MaxInt64/100-1 {
		return fmt.Errorf("money: amount out of range: %q", s)
	}
	c, _ := strconv.ParseInt(frac, 10, 64)
	v := w*100 + c
	if neg {
		v = -v
	}
	*m = Money(v)
	return nil
}

// digits reports whether s is one or more ASCII digits and nothing else.
func digits(s string) bool {
	return s != "" && strings.Trim(s, "0123456789") == ""
}

func main() {
	for _, m := range []Money{1234, -1234, -50, 5, 0} {
		b, _ := json.Marshal(m)
		var back Money
		json.Unmarshal(b, &back)
		fmt.Printf("%6d -> %-9s -> %6d\n", m, b, back)
	}
	for _, in := range []string{`"12.3"`, `"12.345"`, `"1.5x"`, `"+1.00"`, `"-0.50"`, `12.34`} {
		var m Money
		err := json.Unmarshal([]byte(in), &m)
		fmt.Printf("%-9s -> %d, %v\n", in, m, err)
	}
}
```

```text
"1.5x"    -> 0, money: want digits, a dot, then exactly 2 digits; got "1.5x"
"+1.00"   -> 0, money: want digits, a dot, then exactly 2 digits; got "+1.00"
"-0.50"   -> -50, <nil>
12.34     -> 0, money: want a string like "12.34": json: cannot unmarshal number into Go value of type string
```

Why is `MarshalJSON` on the value `(m Money)` but `UnmarshalJSON` on the pointer `(m *Money)`? Marshalling only reads, so a copy is fine. Unmarshalling must write the result into *your* variable, which needs its address: `*m = Money(v)` stores through the pointer. The rule of thumb: the round trip is the test. Always check that every value survives `Marshal` then `Unmarshal` unchanged, including negatives, zero, and the smallest unit.

### Step 2: payloads whose shape depends on a field

Sometimes one field tells you the shape of another. An event feed sends `{"type":"deposit","payload":{…}}` or `{"type":"withdrawal","payload":{…}}` with different payloads. `json.RawMessage` holds the raw bytes of a field without decoding them, so you can read `type` first and decode `payload` second:

<GoPlayground>

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Event struct {
	Type    string          `json:"type"`
	Payload json.RawMessage `json:"payload"` // raw bytes, decoded once we know the type
}

type Deposit struct {
	AccountID   string `json:"account_id"`
	AmountCents int64  `json:"amount_cents"`
}

type Withdrawal struct {
	AccountID   string `json:"account_id"`
	AmountCents int64  `json:"amount_cents"`
	ATM         string `json:"atm_id"`
}

func handleEvent(data []byte) error {
	var ev Event
	if err := json.Unmarshal(data, &ev); err != nil {
		return err
	}
	switch ev.Type {
	case "deposit":
		var d Deposit
		if err := json.Unmarshal(ev.Payload, &d); err != nil {
			return err
		}
		fmt.Printf("deposit:    %s +%d cents\n", d.AccountID, d.AmountCents)
	case "withdrawal":
		var w Withdrawal
		if err := json.Unmarshal(ev.Payload, &w); err != nil {
			return err
		}
		fmt.Printf("withdrawal: %s -%d cents at %s\n", w.AccountID, w.AmountCents, w.ATM)
	default:
		return fmt.Errorf("unknown event type %q", ev.Type)
	}
	return nil
}

func main() {
	for _, in := range []string{
		`{"type":"deposit","payload":{"account_id":"ACC-1","amount_cents":5000}}`,
		`{"type":"withdrawal","payload":{"account_id":"ACC-1","amount_cents":1000,"atm_id":"ATM-99"}}`,
		`{"type":"refund","payload":{}}`,
	} {
		if err := handleEvent([]byte(in)); err != nil {
			fmt.Println("error:     ", err)
		}
	}
}
```

### Step 3: `omitempty` and `omitzero`

`omitempty` leaves a field out of the output when it's "empty": `false`, `0`, `""`, a nil pointer, or an empty slice or map. Two surprises:

- A **struct** is never "empty" to `omitempty`, so a zero `time.Time` still prints as `"0001-01-01T00:00:00Z"`.
- A zero **number** is empty, so `"balance_cents":0` disappears, which a client may read as "unknown" rather than "zero".

**Go 1.24** added `omitzero`, which omits a field when it equals its type's zero value, and calls the type's `IsZero() bool` method if it has one. `time.Time` has one, so this works:

```go
type Transfer struct {
	ID        string    `json:"id"`
	SettledAt time.Time `json:"settled_at,omitzero"` // omitted until it's set
	Note      *string   `json:"note,omitempty"`      // nil pointer: omitted; pointer to "": kept
}
```

Use a pointer when you need to tell "absent" from "zero": `nil` means absent, a pointer to `0` means zero.

### Step 4: decoding input you don't trust

Every request body is written by a stranger. Four rules for decoding one:

1. **Cap the size** with `http.MaxBytesReader`, or one client can make you allocate gigabytes.
2. **Reject unknown fields** with `DisallowUnknownFields`, or a typo like `"amout_cents"` is silently ignored and the amount stays zero.
3. **Decode into a typed struct** with exactly the fields you accept, never `map[string]any`.
4. **Answer the right status:** 413 when the body was too big, 400 for everything else wrong with it.

Watch lines 8–10: that's how rule 4 tells the two errors apart.

```go
// decodeJSON reads one JSON value from r.Body into v, or writes an error response.
func decodeJSON(w http.ResponseWriter, r *http.Request, v any) bool {
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // 1 MiB
	d := json.NewDecoder(r.Body)
	d.DisallowUnknownFields()
	if err := d.Decode(v); err != nil {
		var tooBig *http.MaxBytesError
		if errors.As(err, &tooBig) {
			http.Error(w, "request body too large", http.StatusRequestEntityTooLarge)
			return false
		}
		http.Error(w, "bad request: "+err.Error(), http.StatusBadRequest)
		return false
	}
	if d.More() {
		http.Error(w, "bad request: body must be a single JSON object", http.StatusBadRequest)
		return false
	}
	return true
}

func createTransfer(w http.ResponseWriter, r *http.Request) {
	var req struct {
		FromAccount string `json:"from_account"`
		ToAccount   string `json:"to_account"`
		AmountCents int64  `json:"amount_cents"`
	}
	if !decodeJSON(w, r, &req) {
		return // the error response is already written
	}
	if req.AmountCents <= 0 || req.FromAccount == "" || req.ToAccount == "" {
		http.Error(w, "from_account, to_account and a positive amount_cents are required", http.StatusUnprocessableEntity)
		return
	}
	w.WriteHeader(http.StatusAccepted)
}
```

<Callout kind="note" title="Go 1.25: CrossOriginProtection">

`http.CrossOriginProtection` is middleware against cross-site request forgery. It rejects **non-safe** requests (anything but GET, HEAD and OPTIONS) that a browser marks as cross-origin, using the `Sec-Fetch-Site` header, or by comparing `Origin` with `Host` in older browsers. Requests without either header (curl, server-to-server calls) pass, because they aren't coming from a victim's browser.

```go
cop := http.NewCrossOriginProtection()
handler := cop.Handler(mux) // protect every state-changing route
```

It's separate from CORS headers, which you still need for legitimate cross-origin callers. Auth & API Design (Part 1, Chapter 20) covers the full picture.

</Callout>

<UnderTheHood title="encoding/json and json/v2 (Go 1.27)">

`json.Decoder` keeps its own read buffer and reads from the body as it parses, so it never needs the whole body in memory first; that's what lets `MaxBytesReader` stop an oversized body part-way. Struct field lookups use reflection, cached per type after first use.

Go 1.25 added a redesigned `encoding/json/v2` behind `GOEXPERIMENT=jsonv2`, with stricter defaults (for example, duplicate keys rejected) and faster decoding. In Go 1.27 it's still an experiment: without the flag, `encoding/json/v2` isn't available, and `encoding/json` is what you ship.

</UnderTheHood>

### Step 1: why not just `json.Marshal` the list

<ELI5
  concept="Streaming a response"
  analogy="Serving dishes as they leave the kitchen, not wheeling out the whole banquet."
  role="reader"
>

The ordinary way to return 100,000 transfers is to load them all, marshal one big JSON array, and write it. Your server holds all 100,000 in memory at once, and the client sees nothing until the last one is ready.

Streaming sends each record as it comes: one JSON object per line, flushed immediately. The client can show row one while you're still reading row 90,000, and your memory holds only the row in hand.

The catch: the `200 OK` goes out with the first row. If row 40,000 fails, you can't change the status any more, so a streaming endpoint needs a way to report a late failure in the body.

</ELI5>

<Define term="streaming response / NDJSON" since="Batch & Large-File Processing (Part 3)">
A **streaming response** is written incrementally instead of built in memory first. **NDJSON** (newline-delimited JSON) is the usual format for streaming records: one complete JSON object per line, no enclosing array, so a client can parse each line as it arrives. Its media type is `application/x-ndjson`.
</Define>

### Step 2: the handler

`json.NewEncoder(w).Encode(v)` writes `v` as JSON followed by a newline, which is exactly one NDJSON line. `http.NewResponseController(w).Flush()` (Go 1.20) pushes what's buffered to the client now:

```go
func streamStatement(db *sql.DB) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		rows, err := db.QueryContext(r.Context(),
			`SELECT id, amount_cents, reference FROM transactions
			 WHERE from_account = $1 OR to_account = $1
			 ORDER BY created_at`,
			r.PathValue("accountID"))
		if err != nil {
			http.Error(w, "query failed", http.StatusInternalServerError) // still possible: nothing sent yet
			return
		}
		defer rows.Close()

		w.Header().Set("Content-Type", "application/x-ndjson")
		rc := http.NewResponseController(w)
		enc := json.NewEncoder(w)
		for rows.Next() {
			var t Transfer
			if err := rows.Scan(&t.ID, &t.AmountCents, &t.Reference); err != nil {
				enc.Encode(map[string]string{"error": "scan failed"}) // too late for a status code
				return
			}
			if err := enc.Encode(t); err != nil {
				return // the client went away
			}
			rc.Flush()
		}
		if err := rows.Err(); err != nil {
			enc.Encode(map[string]string{"error": "stream interrupted"})
		}
	}
}
```

Notice the order. Everything that can fail *before* the first row (the query) is checked while you can still send a 500. Once rows are flowing, failures are reported as a final `{"error": …}` line, and the client must check for it.

`ResponseController` is preferred over the older `w.(http.Flusher)` type assertion because it sees through wrappers: after `logging` wraps `w` in a `statusRecorder`, the assertion fails, but `ResponseController` finds the flusher underneath (as long as the wrapper has an `Unwrap() http.ResponseWriter` method).

Reading NDJSON back is just as simple, because `json.Decoder` handles a sequence of values:

```go
		var t Transfer
		if err := dec.Decode(&t); err != nil {
			fmt.Println("decode:", err)
			return
		}
```

<UnderTheHood title="Where the bytes wait">

A `ResponseWriter` buffers writes (about 4 KB for HTTP/1.1) and sends them when the buffer fills, when you flush, or when the handler returns. Without `Flush`, a slow stream of small rows sits in that buffer, and the client sees nothing for a long time. For HTTP/1.1 responses with no `Content-Length`, the server uses chunked transfer encoding, so each flush becomes a chunk on the wire.

</UnderTheHood>

**Recap.** Stream large results as NDJSON: encode a row, flush, repeat. Check everything you can before the first byte; after that, report errors in the body.

### Step 1: a live feed over plain HTTP

<Define term="server-sent events (SSE)">
**Server-sent events** let a server push a stream of events to a browser over one long-lived HTTP response with `Content-Type: text/event-stream`. Each event is a few `field: value` lines ended by a blank line. The browser's `EventSource` reconnects automatically after a drop, sending the last event's `id` in a `Last-Event-ID` header so the server can resume.
</Define>

The wire format is plain text:

```text
id: 7
event: transfer
data: {"id":"TXN-7","status":"settled"}

```

`id` lets a reconnecting client resume, `event` names the type (the browser dispatches it to matching listeners), `data` is the payload, and the empty line ends the event. `retry: 3000` would tell the browser how long to wait before reconnecting.

### Step 2: a handler, and a client, both runnable

The handler honours `Last-Event-ID` and stops when the client disconnects. The client here imitates `EventSource`: it reads two events, "drops", then reconnects with the last id it saw.

<GoPlayground>

```go
package main

import (
	"bufio"
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strconv"
	"strings"
	"time"
)

// events is the stream every client sees, oldest first.
var events = []string{"TXN-1 settled", "TXN-2 settled", "TXN-3 failed", "TXN-4 settled", "TXN-5 settled"}

func sseHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	rc := http.NewResponseController(w)

	// A reconnecting browser sends the last id it saw; resume after it.
	next := 0
	if last, err := strconv.Atoi(r.Header.Get("Last-Event-ID")); err == nil {
		next = last + 1
	}
	for id := next; id < len(events); id++ {
		select {
		case <-r.Context().Done():
			return // client went away
		case <-time.After(50 * time.Millisecond): // pretend we waited for the next event
		}
		fmt.Fprintf(w, "id: %d\nevent: transfer\ndata: %s\n\n", id, events[id])
		rc.Flush()
	}
}

// read prints events until it has seen stopAfter of them, then disconnects.
// It returns the last id it saw, like a browser's EventSource would.
func read(url, lastID string, stopAfter int) string {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
	if lastID != "" {
		req.Header.Set("Last-Event-ID", lastID)
	}
	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		fmt.Println("error:", err)
		return lastID
	}
	defer resp.Body.Close()
	sc := bufio.NewScanner(resp.Body)
	seen := 0
	for sc.Scan() {
		line := sc.Text()
		if id, ok := strings.CutPrefix(line, "id: "); ok {
			lastID = id
		}
		if data, ok := strings.CutPrefix(line, "data: "); ok {
			fmt.Printf("  event %s: %s\n", lastID, data)
			if seen++; seen == stopAfter {
				return lastID // simulate the network dropping
			}
		}
	}
	return lastID
}

func main() {
	srv := httptest.NewServer(http.HandlerFunc(sseHandler))
	defer srv.Close()

	fmt.Println("connect:")
	last := read(srv.URL, "", 2)
	fmt.Println("connection dropped; reconnect with Last-Event-ID:", last)
	read(srv.URL, last, 0)
}
```

### Step 1: from HTTP to a two-way pipe

<Define term="WebSocket">
A **WebSocket** is a long-lived, two-way connection. It starts as an HTTP request asking to "upgrade"; after the server agrees, both sides can send messages (frames) at any time, independently, over the same TCP connection.
</Define>

<Define term="the HTTP upgrade handshake">

</Define>

### Step 2: a handler with `coder/websocket`

The standard library has no WebSocket server, so you use a library. `github.com/coder/websocket` (formerly `nhooyr.io/websocket`, same code under a new path) is context-aware; `gorilla/websocket` is the older, widely used alternative.

The standard shape is **one goroutine reading, one loop writing**, because a WebSocket read blocks until the other side sends something:

```go noverify
func wsHandler(ticks <-chan MarketTick) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		c, err := websocket.Accept(w, r, &websocket.AcceptOptions{
			OriginPatterns: []string{"trading.meridian.example"}, // reject other sites' pages
		})
		if err != nil {
			return // Accept has already written an error response
		}
		defer c.CloseNow()

		ctx, cancel := context.WithCancel(r.Context())
		defer cancel()

		// Reader: filter updates from the dealer. Reading also processes
		// pings and close frames, so something must always be reading.
		filters := make(chan ClientFilter, 1)
		go func() {
			defer cancel() // client closed or errored: stop the writer too
			for {
				var f ClientFilter
				if err := wsjson.Read(ctx, c, &f); err != nil {
					return
				}
				select {
				case filters <- f:
				default: // drop if the writer hasn't taken the previous one
				}
			}
		}()

		var filter ClientFilter
		for {
			select {
			case <-ctx.Done():
				c.Close(websocket.StatusNormalClosure, "bye")
				return
			case filter = <-filters:
			case tick := <-ticks:
				if !filter.Matches(tick) {
					continue
				}
				// A deadline on every write: a stalled client must not hold this goroutine.
				wctx, wcancel := context.WithTimeout(ctx, 5*time.Second)
				err := wsjson.Write(wctx, c, tick)
				wcancel()
				if err != nil {
					return
				}
			}
		}
	}
}
```

Three things this code gets right that are easy to miss:

- **`OriginPatterns`.** Browsers don't apply CORS to WebSockets, so any website could open a socket to your server using the victim's cookies. `Accept` rejects origins that aren't listed.
- **Someone is always reading.** `coder/websocket` answers the other side's pings and handles close frames only while a read is in progress. If you only write, send pings yourself with `c.Ping(ctx)` from a ticker, and call `c.CloseRead(ctx)` so incoming control frames are still processed.
- **A deadline on each write.** After the upgrade, `net/http` no longer manages this connection, so `Server.WriteTimeout` doesn't apply. The per-write context is the only thing stopping a stalled client from blocking this goroutine forever.

Exercise 5 has a complete echo server and client you can run locally, tested with `httptest.NewServer`.

<UnderTheHood title="Hijacking: net/http lets go of the connection">

`websocket.Accept` calls `Hijack` on the `ResponseWriter` (through `http.ResponseController` or the `http.Hijacker` interface), which returns the raw `net.Conn`. From then on, `net/http` forgets the connection: no buffering, no HTTP framing, no `ReadTimeout` or `WriteTimeout`, and `Server.Shutdown` won't wait for it. The library reads and writes RFC 6455 frames on the socket directly.

Hijacking only exists for HTTP/1.1. WebSockets over HTTP/2 need "extended CONNECT" (RFC 8441), which Go's HTTP/2 server doesn't enable, so browsers make their WebSocket upgrade over HTTP/1.1.

</UnderTheHood>

### Step 3: which one should you use?

<ConceptGrid cols={3}>
  <ConceptCard label="Polling">The client asks every few seconds. Works everywhere, trivially cacheable. Fine when updates are infrequent and a few seconds' delay is OK.</ConceptCard>
  <ConceptCard label="SSE">Server pushes; the client only listens. Plain HTTP, automatic reconnect and resume. Dashboards, notifications, progress bars, live feeds.</ConceptCard>
  <ConceptCard label="WebSockets">Both sides send constantly and independently. Chat, collaborative editing, trading, games. You handle reconnection, pings and backpressure yourself.</ConceptCard>
  <Gotcha>Most "real-time" features are one-way. Reach for SSE first; move to WebSockets only when the client genuinely streams data back.</Gotcha>
</ConceptGrid>

### Step 2: the four timeouts

| Field | Covers | Starting value |
|---|---|---|
| `ReadHeaderTimeout` | Receiving the request headers | 5 s. Always set it. |
| `ReadTimeout` | Headers **and** body | 10–30 s, or leave 0 and cap per handler for big uploads |
| `WriteTimeout` | From the end of the headers to the end of the response | 30–60 s for normal APIs |
| `IdleTimeout` | A keep-alive connection waiting for its next request | 60–120 s |

Why is `ReadHeaderTimeout` the one to set first, when `ReadTimeout` also covers headers? Because `ReadTimeout` also covers the **body**, so it's a single budget for a small JSON post and a 2 GB upload alike. `ReadHeaderTimeout` guards the phase attackers abuse without constraining legitimate large bodies. (If you leave `ReadHeaderTimeout` at 0, Go uses `ReadTimeout` for headers.)

### Step 3: streaming handlers and `WriteTimeout`

`WriteTimeout` is a deadline for the whole response, so it will cut off an SSE stream or a long NDJSON export. Measured with `WriteTimeout: 250ms` and a handler sending an event every 100 ms, the client received **3 of 6** events. The fix isn't a second server: a streaming handler can change its own deadline with `http.ResponseController` (Go 1.20):

```go
func sseHandler(w http.ResponseWriter, r *http.Request) {
	rc := http.NewResponseController(w)
	rc.SetWriteDeadline(time.Time{}) // zero time: no deadline for THIS response
	// … stream events, and stop when r.Context() is done …
}
```

With that one line, the same test received **6 of 6**. Better still, keep a deadline but push it forward before each write (`rc.SetWriteDeadline(time.Now().Add(10 * time.Second))`), so a client that stops reading is still dropped.

### Step 4: cap every body

Timeouts limit *time*; a fast attacker can still send a huge body within them. Wrap request bodies in `http.MaxBytesReader` (as `decodeJSON` does in Stop 2), with a limit that fits the endpoint: 1 MiB for JSON APIs, much more for an upload route.

For file uploads, don't read the whole multipart body into memory:

```go
// Up to 32 MiB of the form stays in memory; larger file parts go to temp files.
r.Body = http.MaxBytesReader(w, r.Body, 100<<20) // hard cap: 100 MiB total
if err := r.ParseMultipartForm(32 << 20); err != nil {
	http.Error(w, "bad upload", http.StatusBadRequest)
	return
}
file, header, err := r.FormFile("upload")
if err != nil {
	http.Error(w, "missing file", http.StatusBadRequest)
	return
}
defer file.Close()
_ = header.Size // the part's size as sent; the MaxBytesReader is what actually enforces a cap
```

### Step 5: security headers in one middleware

Timeouts and caps protect the server. Response headers protect the **browser** that renders your responses, by switching off permissive defaults.

<Define term="secure response headers">
**Secure response headers** tell the browser to enforce a policy on your content: which scripts may run (`Content-Security-Policy`), not to guess content types (`X-Content-Type-Options`), how much of the URL to leak to other sites (`Referrer-Policy`), and who may embed your pages (`X-Frame-Options`, CSP `frame-ancestors`).
</Define>

<ConceptGrid cols={2}>
  <ConceptCard label="X-Content-Type-Options: nosniff">Stops the browser "sniffing" a response's bytes to guess its type. Without it, a JSON endpoint that reflects user input can be coaxed into running as HTML or script.</ConceptCard>
  <ConceptCard label="Content-Security-Policy">An allow-list of where scripts, styles, images and frames may load from. `default-src 'none'` on a pure JSON API means even a reflected `<script>` won't execute.</ConceptCard>
  <ConceptCard label="Referrer-Policy">Limits the `Referer` header on outbound links. URLs can carry account IDs or one-time tokens; `no-referrer` keeps them from leaking.</ConceptCard>
  <ConceptCard label="X-Frame-Options / frame-ancestors">Stops clickjacking: an attacker's page loading yours in an invisible frame and tricking a logged-in user into clicking "Send".</ConceptCard>
</ConceptGrid>

<UnderTheHood title="How the timeouts are enforced">

Each timeout becomes a deadline on the underlying `net.Conn` (`SetReadDeadline`, `SetWriteDeadline`). A blocked `Read` or `Write` past its deadline returns a timeout error, so it fires even while your handler is in the middle of `json.Encode`. The server sets the read deadline before reading headers and the write deadline before calling your handler; `ResponseController.SetWriteDeadline` just moves that deadline for the current response. After a hijack, none of this applies: the WebSocket library sets its own deadlines from your contexts.

</UnderTheHood>

**Recap.** Always set `ReadHeaderTimeout`, plus read, write and idle timeouts; let streaming handlers adjust their own write deadline. Cap every body. Put security headers in one outer middleware.

```go
package main

import (
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"runtime/debug"

func recoverer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				if v == http.ErrAbortHandler {
					panic(v) // net/http's own "abort this response" signal: let it through
				}
				slog.Error("handler panicked", "panic", v, "path", r.URL.Path, "stack", string(debug.Stack()))
				http.Error(w, "internal server error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	h := recoverer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		var m map[string]int
		m["boom"]++ // writing to a nil map panics
	}))
	w := httptest.NewRecorder()
	h.ServeHTTP(w, httptest.NewRequest("GET", "/transfers", nil))
	fmt.Println("status:", w.Code)
}
```

```go
	"fmt"

	"net/http/httptest"

func decode[T any](w http.ResponseWriter, r *http.Request) (T, bool) {
	var v T
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20)
	d := json.NewDecoder(r.Body)

			http.Error(w, "request body too large", http.StatusRequestEntityTooLarge)
		} else {
			http.Error(w, "bad request: "+err.Error(), http.StatusBadRequest)
		}
		return v, false
	}
	if d.More() {
		http.Error(w, "bad request: one JSON object only", http.StatusBadRequest)
		return v, false
	}
	return v, true
}

type CreateAccount struct {
	Owner    string `json:"owner"`
	Currency string `json:"currency"`
}

func handler(w http.ResponseWriter, r *http.Request) {
	req, ok := decode[CreateAccount](w, r)
	if !ok {
		return
	}
	fmt.Fprintf(w, "created for %s in %s", req.Owner, req.Currency)
}

func main() {
	for _, body := range []string{
		`{"owner":"Ada","currency":"NGN"}`,
		`{"owner":"Ada","currency":"NGN","admin":true}`,
		`{"owner":"Ada"}{"owner":"Eve"}`,
	} {
		w := httptest.NewRecorder()
		handler(w, httptest.NewRequest("POST", "/api/accounts", strings.NewReader(body)))
		fmt.Printf("%d %s\n", w.Code, strings.TrimSpace(w.Body.String()))
	}
}
```

The type parameter lets one helper return a fully typed value for any request shape. Callers write `req, ok := decode[CreateAccount](w, r)`.

</Solution>

</Exercise>

<Exercise n={3} title="Money in whole units" level="medium">

Extend Stop 2's `Money` so `UnmarshalJSON` also accepts a whole-unit string with no decimal part (`"12"` means 1200 cents) while still rejecting `"12.3"`, `"12.345"` and anything non-numeric. Test the round trip for `0`, `-50`, `1234` and `-1234`, plus the new input.

<Solution>

```go
package main

import (
	"encoding/json"
	"fmt"
	"math"
	"strconv"
	"strings"
)

type Money int64

func (m Money) MarshalJSON() ([]byte, error) {
	sign, v := "", int64(m)
	if v < 0 {
		sign, v = "-", -v
	}
	return json.Marshal(fmt.Sprintf("%s%d.%02d", sign, v/100, v%100))
}

func (m *Money) UnmarshalJSON(data []byte) error {
	var s string
	if err := json.Unmarshal(data, &s); err != nil {
		return fmt.Errorf("money: want a string: %w", err)
	}
	neg := strings.HasPrefix(s, "-")
	whole, frac, hasDot := strings.Cut(strings.TrimPrefix(s, "-"), ".")
	if !hasDot {
		frac = "00" // "12" means 12.00
	}
	if !digits(whole) || len(frac) != 2 || !digits(frac) {
		return fmt.Errorf("money: invalid amount %q", s)
	}
	w, err := strconv.ParseInt(whole, 10, 64)
	if err != nil || w > math.MaxInt64/100-1 {
		return fmt.Errorf("money: amount out of range: %q", s)
	}
	c, _ := strconv.ParseInt(frac, 10, 64)
	v := w*100 + c
	if neg {
		v = -v
	}
	*m = Money(v)
	return nil
}

func digits(s string) bool { return s != "" && strings.Trim(s, "0123456789") == "" }

func main() {
	for _, m := range []Money{0, -50, 1234, -1234} {
		b, _ := json.Marshal(m)
		var back Money
		err := json.Unmarshal(b, &back)
		fmt.Printf("%6d -> %-9s -> %6d ok=%v\n", m, b, back, err == nil && back == m)
	}
	for _, in := range []string{`"12"`, `"-7"`, `"12.3"`, `"12.345"`, `"abc"`} {
		var m Money
		err := json.Unmarshal([]byte(in), &m)
		fmt.Printf("%-8s -> %d %v\n", in, m, err)
	}
}
```

The only change is treating "no dot" as ".00" before the same strict checks. Everything else still has to be exactly two digits after the dot.

<Exercise n={4} title="A streaming export, tested" level="medium">

Write an NDJSON export handler for a slice of transfers, with a flush after each row. Test it against a real `httptest.NewServer` and decode each line on the client side.

<Solution>

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type Transfer struct {
	ID          string `json:"id"`
	AmountCents int64  `json:"amount_cents"`
}

func exportHandler(txs []Transfer) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/x-ndjson")
		rc := http.NewResponseController(w)
		enc := json.NewEncoder(w)
		for _, t := range txs {
			if err := enc.Encode(t); err != nil {
				return
			}
			rc.Flush()
		}
	}
}

func main() {
	txs := []Transfer{{"TXN-001", 1000}, {"TXN-002", -500}, {"TXN-003", 25000}}
	srv := httptest.NewServer(exportHandler(txs))
	defer srv.Close()

	resp, err := http.Get(srv.URL)
	if err != nil {
		fmt.Println(err)
		return
	}
	defer resp.Body.Close()

	dec := json.NewDecoder(resp.Body)
	n := 0
	for dec.More() {
		var t Transfer
		if err := dec.Decode(&t); err != nil {
			fmt.Println("decode:", err)
			return
		}
		n++
		fmt.Printf("  %s: %d cents\n", t.ID, t.AmountCents)
	}
	fmt.Println("received", n, "transfers, content-type", resp.Header.Get("Content-Type"))
}
```

Using a real server (rather than `httptest.NewRecorder`) exercises the actual flushing and chunked encoding.

</Solution>

</Exercise>

<Exercise n={5} title="WebSocket echo, tested" level="hard">

With `github.com/coder/websocket`, write an echo handler that reads a JSON message, appends `" (echoed)"` to its `text` field, and writes it back. Test it with `httptest.NewServer` (a WebSocket needs a real connection to hijack; a recorder won't do).

<Solution>

```go
// Run locally: go get github.com/coder/websocket
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"net/http/httptest"

	"github.com/coder/websocket"
	"github.com/coder/websocket/wsjson"
)

type Msg struct {
	Text string `json:"text"`
}

func echoHandler(w http.ResponseWriter, r *http.Request) {
	c, err := websocket.Accept(w, r, nil)
	if err != nil {
		return
	}
	defer c.CloseNow()
	ctx := r.Context()

	var m Msg
	if err := wsjson.Read(ctx, c, &m); err != nil {
		return
	}
	m.Text += " (echoed)"
	wsjson.Write(ctx, c, m)
	c.Close(websocket.StatusNormalClosure, "")
}

func main() {
	srv := httptest.NewServer(http.HandlerFunc(echoHandler))
	defer srv.Close()

	// Convert http:// to ws://
	wsURL := "ws" + srv.URL[len("http"):]

	ctx := context.Background()
	c, _, err := websocket.Dial(ctx, wsURL, nil)
	if err != nil {
		log.Fatal(err)
	}
	defer c.CloseNow()

	if err := wsjson.Write(ctx, c, Msg{Text: "hello"}); err != nil {
		log.Fatal(err)
	}

	var reply Msg
	if err := wsjson.Read(ctx, c, &reply); err != nil {
		log.Fatal(err)
	}
	fmt.Println(reply.Text) // hello (echoed)
	c.Close(websocket.StatusNormalClosure, "")
}
```

Run with `coder/websocket` v1.8.15 it prints `hello (echoed)`. With `nil` options, `Accept` only allows same-origin browser requests, which is the safe default; the test client sends no `Origin` header, so it's allowed. For TLS, use `httptest.NewTLSServer` and `wss://`.

</Solution>

<Recap>

- **Everything is an `http.Handler`.** `HandlerFunc` adapts plain functions. Use your own `ServeMux` with Go 1.22 patterns (`"GET /accounts/{id}"`, `r.PathValue`); since Go 1.26 subtree redirects are 307.
- **Middleware** is `func(http.Handler) http.Handler`. Outermost runs first in and last out; recovery goes outside everything.
- **Shut down gracefully**: `signal.NotifyContext` for SIGINT and SIGTERM, then `srv.Shutdown(ctx)`, which finishes in-flight requests but doesn't wait for hijacked connections.
- **JSON**: test custom marshalers with a round trip (negative amounts under one unit broke the original `Money`); `json.RawMessage` for type-dependent payloads; `omitzero` (Go 1.24) for times and structs.
- **Untrusted bodies**: `MaxBytesReader` (413 on `*http.MaxBytesError`), `DisallowUnknownFields`, a strict struct, `d.More()` for trailing data, then separate validation (422).
- **Streaming**: NDJSON with `json.Encoder` + `ResponseController.Flush`; check failures before the first byte, report later ones in the body.
- **SSE**: `text/event-stream`, `id`/`event`/`data` lines, stop on `r.Context().Done()`, resume from `Last-Event-ID`.
- **WebSockets**: upgrade then hijack; check `Origin`, keep a reader running, deadline every write.
- **Hardening**: always `ReadHeaderTimeout`, plus read, write and idle timeouts; streaming handlers adjust their own write deadline with `ResponseController`; cap bodies; security headers in one middleware.

</Recap>
