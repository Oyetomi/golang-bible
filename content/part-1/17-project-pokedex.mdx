### Step 2: a command is a value

Each command is a small struct. The interesting field is `callback`: its type is a *function type*, so the struct holds the function itself.

```go
type cliCommand struct {
	name        string
	description string
	callback    func(cfg *config, args ...string) error
}
```

Read `func(cfg *config, args ...string) error` as "any function that takes a pointer to the shared config and zero or more strings, and returns an error". The `...string` makes the function **variadic**: inside it, `args` is a `[]string`. At the call site, `words[1:]...` spreads a slice into those arguments.

The registry is a map from the name you type to its command:

```go
func getCommands() map[string]cliCommand {
	return map[string]cliCommand{
		"help": {"help", "Display a help message", commandHelp},
		"exit": {"exit", "Exit the Pokedex", commandExit},
		// map, mapb and explore arrive in Stop 3
	}
}
```

Each `{"help", "Display a help message", commandHelp}` fills the struct's fields in declaration order: name, description, callback. `commandHelp` has no parentheses, so it isn't called here. The function itself is stored, to be called later.

### Step 3: why a function, not a package-level variable

It's tempting to write `var commands = map[string]cliCommand{...}` once at package level. Try it, and the compiler refuses:

```text
./main.go:13:5: initialization cycle for commands
	./main.go:13:5: commands refers to help
	./main.go:15:6: help refers to commands
```

The map's value mentions `commandHelp`, and `commandHelp` reads the map to list the commands. Go initialises package variables before `main` runs, and it can't finish `commands` without first knowing everything `commandHelp` refers to, which includes `commands`. That's a cycle, and it's a compile error rather than a runtime surprise. Wrapping the map in a function breaks the cycle: nothing is built until `getCommands()` is actually called, long after initialisation.

package main

import (
	"bufio"
	"fmt"
	"io"
	"strings"
)

type cliCommand struct {
	name        string
	description string
	callback    func(args ...string) error
}

func getCommands() map[string]cliCommand {
	return map[string]cliCommand{
		"help": {"help", "Display a help message", func(args ...string) error {
			fmt.Println("  (help would list the commands)")
			return nil
		}},
		"explore": {"explore", "List the Pokemon in an area", func(args ...string) error {
			fmt.Printf("  exploring %v\n", args)
			return nil
		}},
	}
}

func cleanInput(text string) []string {
	return strings.Fields(strings.ToLower(text))
}

func startREPL(in io.Reader) {
	commands := getCommands()
	scanner := bufio.NewScanner(in)
	for {
		fmt.Print("Pokedex > ")
		if !scanner.Scan() {
			fmt.Println("(end of input)")
			return
		}
		line := scanner.Text()
		fmt.Println(line) // echo, since there's no real keyboard here
		words := cleanInput(line)
		if len(words) == 0 {
			continue
		}
		cmd, ok := commands[words[0]]
		if !ok {
			fmt.Println("  Unknown command. Type 'help' for options.")
			continue
		}
		if err := cmd.callback(words[1:]...); err != nil {
			fmt.Println("  Error:", err)
		}
	}
}

func main() {
	// Pretend the user typed these four lines.
	typed := "HELP\n   explore   Canalave-City-Area  \n\nfly\n"
	startREPL(strings.NewReader(typed))
}

### Step 5: the real `main.go`

The full file adds one thing the demo didn't have: `config`, the state every command shares. It holds the API client and (from Stop 3) where the next and previous pages are.

```go noverify
// main.go
package main

import (
	"bufio"
	"fmt"
	"io"
	"os"
	"strings"
	"time"
)

// cliCommand is one entry in the registry: a name, a line of help,
// and the function to run.
type cliCommand struct {
	name        string
	description string
	callback    func(cfg *config, args ...string) error
}

// config is the state every command shares. It is passed in, never global,
// so a test can build one with a fake client.
type config struct {
	client  *PokeClient
	nextURL string // where "map" goes next ("" means the first page)
	prevURL string // where "mapb" goes ("" means there is no previous page)
	caught  map[string]PokemonResp // filled by the catch command (Exercise 1)
}

func getCommands() map[string]cliCommand {
	return map[string]cliCommand{
		"help":    {"help", "Display a help message", commandHelp},
		"exit":    {"exit", "Exit the Pokedex", commandExit},
		"map":     {"map", "Show the next 20 location areas", commandMap},
		"mapb":    {"mapb", "Show the previous 20 location areas", commandMapb},
		"explore": {"explore", "List the Pokemon in a location area", commandExplore},
	}
}

// cleanInput lowercases the line and splits it into words.
func cleanInput(text string) []string {
	return strings.Fields(strings.ToLower(text))
}

// startREPL reads commands from in until it runs out of input.
func startREPL(cfg *config, in io.Reader) {
	commands := getCommands()
	scanner := bufio.NewScanner(in)
	for {
		fmt.Print("Pokedex > ")
		if !scanner.Scan() {
			return // Ctrl-D (end of input)
		}
		words := cleanInput(scanner.Text())
		if len(words) == 0 {
			continue
		}
		cmd, ok := commands[words[0]]
		if !ok {
			fmt.Println("Unknown command. Type 'help' for options.")
			continue
		}
		if err := cmd.callback(cfg, words[1:]...); err != nil {
			fmt.Println("Error:", err)
		}
	}
}

func main() {
	cfg := &config{
		client: NewPokeClient("https://pokeapi.co/api/v2", 5*time.Minute),
		caught: make(map[string]PokemonResp),
	}
	startREPL(cfg, os.Stdin)
}
```

`cfg := &config{...}` builds one `config` and keeps a pointer to it. Every callback receives that same pointer, so when `map` updates `cfg.nextURL`, the next command sees the change.

The first two commands are short. `help` has one wrinkle: Go randomises map iteration order on purpose, so the names are collected and sorted before printing.

```go
func commandHelp(cfg *config, args ...string) error {
	commands := getCommands()
	names := make([]string, 0, len(commands))
	for name := range commands {
		names = append(names, name)
	}
	slices.Sort(names) // map order is random; sort for a stable listing
	fmt.Println("Usage:")
	for _, name := range names {
		fmt.Printf("  %-8s %s\n", name, commands[name].description)
	}
	return nil
}

func commandExit(cfg *config, args ...string) error {
	fmt.Println("Closing the Pokedex... Goodbye!")
	os.Exit(0)
	return nil
}
```

### Step 1: shape Go structs like the JSON

PokeAPI answers `GET https://pokeapi.co/api/v2/location-area` with a page like this (trimmed to 2 of its 20 results):

```json
{
  "count": 1539,
  "next": "https://pokeapi.co/api/v2/location-area?offset=20&limit=20",
  "previous": null,
  "results": [
    { "name": "canalave-city-area", "url": "https://pokeapi.co/api/v2/location-area/1/" },
    { "name": "eterna-city-area", "url": "https://pokeapi.co/api/v2/location-area/2/" }
  ]
}
```

You describe that shape with a struct. Each field's **struct tag**, the back-quoted `json:"..."`, names the JSON key it maps to:

```go
// types.go
package main

// LocationAreaPage is one page of GET /location-area.
type LocationAreaPage struct {
	Count    int     `json:"count"`
	Next     *string `json:"next"`     // null on the last page
	Previous *string `json:"previous"` // null on the first page
	Results  []struct {
		Name string `json:"name"`
		URL  string `json:"url"`
	} `json:"results"`
}

// LocationArea is GET /location-area/{name}, trimmed to what we use.
type LocationArea struct {
	PokemonEncounters []struct {
		Pokemon struct {
			Name string `json:"name"`
		} `json:"pokemon"`
	} `json:"pokemon_encounters"`
}

// PokemonResp is GET /pokemon/{name}, trimmed to what we use.
type PokemonResp struct {
	Name           string `json:"name"`
	BaseExperience int    `json:"base_experience"`
	Height         int    `json:"height"`
	Weight         int    `json:"weight"`
}
```

Two things to notice. You only declare the fields you use: the decoder skips any JSON key without a matching field. And `Results` is a slice of an **anonymous struct** (a struct type written inline without a name), which is handy when the shape is used in exactly one place.

### Step 2: why `Next` is a `*string`

`next` is either a URL or `null`. A plain `string` can't tell those apart: `null` would decode to `""`, the same as an empty string. A `*string` (a pointer to a string) has an extra state: `nil`, meaning "there is no string at all". The decoder sets it to `nil` for `null` and points it at the text otherwise.

<GoPlayground>

```go
package main

import (
	"encoding/json"
	"fmt"
)

type LocationAreaPage struct {
	Count    int     `json:"count"`
	Next     *string `json:"next"`
	Previous *string `json:"previous"`
	Results  []struct {
		Name string `json:"name"`
		URL  string `json:"url"`
	} `json:"results"`
}

func main() {
	// Trimmed from a real response for page 1 (the first 2 of 20 results).
	body := []byte(`{
		"count": 1539,
		"next": "https://pokeapi.co/api/v2/location-area?offset=20&limit=20",
		"previous": null,
		"results": [
			{"name": "canalave-city-area", "url": "https://pokeapi.co/api/v2/location-area/1/"},
			{"name": "eterna-city-area", "url": "https://pokeapi.co/api/v2/location-area/2/"}
		]
	}`)

	var page LocationAreaPage
	if err := json.Unmarshal(body, &page); err != nil {
		fmt.Println("decode:", err)
		return
	}
	fmt.Println("count:", page.Count)
	fmt.Println("previous is nil:", page.Previous == nil) // JSON null -> nil pointer
	if page.Next != nil {
		fmt.Println("next:", *page.Next) // *page.Next: follow the pointer to the string
	}
	for _, r := range page.Results {
		fmt.Println(" -", r.Name)
	}
}
```

</GoPlayground>

```text
count: 1539
previous is nil: true
next: https://pokeapi.co/api/v2/location-area?offset=20&limit=20
 - canalave-city-area
 - eterna-city-area
```

`json.Unmarshal(body, &page)` gets `&page`, the address of `page`, because it has to write into your variable. Given a copy, it would fill the copy and you'd see nothing. And `*page.Next` reads "the string that `page.Next` points to"; always check for `nil` first, because dereferencing a nil pointer panics.

### Step 3: one generic function for every endpoint

We need three downloads: a page of areas, one area, one Pokemon. Each would repeat the same steps: check the cache, build the request, send it, check the status, read the body, decode it. Only the result type differs.

That's exactly what generics (ch5) are for. `fetchJSON[T any]` (a method on the client, from Step 4) takes a **type parameter** `T`, the struct the caller wants back:

```go
page, err := c.fetchJSON[LocationAreaPage](ctx, url) // T is LocationAreaPage
mon, err := c.fetchJSON[PokemonResp](ctx, url)       // T is PokemonResp
```

Run a tiny version first. The cache here is a bare map; Stop 4 replaces it with a safe one. Watch the order of the printed lines:

<GoPlayground>

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

type Pokemon struct {
	Name           string `json:"name"`
	BaseExperience int    `json:"base_experience"`
}

type Area struct {
	Name string `json:"name"`
}

var cache = map[string][]byte{} // the real one has a lock and a TTL (Stop 4)

// fetchJSON downloads url (or takes it from the cache) and decodes it into a T.
func fetchJSON[T any](ctx context.Context, url string) (T, error) {
	var out T
	path := strings.SplitN(url, "/", 4)[3] // just the path, for printing
	body, ok := cache[url]
	if ok {
		fmt.Println("  from cache:  ", path)
	} else {
		fmt.Println("  from network:", path)
		req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
		if err != nil {
			return out, err
		}
		resp, err := http.DefaultClient.Do(req) // fine here: a local test server
		if err != nil {
			return out, err
		}
		defer resp.Body.Close()
		if body, err = io.ReadAll(resp.Body); err != nil {
			return out, err
		}
		cache[url] = body
	}
	err := json.Unmarshal(body, &out)
	return out, err
}

func main() {
	api := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		switch r.URL.Path {
		case "/pokemon/pikachu":
			fmt.Fprint(w, `{"name":"pikachu","base_experience":112}`)
		case "/location-area/1":
			fmt.Fprint(w, `{"name":"canalave-city-area"}`)
		}
	}))
	defer api.Close()
	ctx := context.Background()

	p, _ := fetchJSON[Pokemon](ctx, api.URL+"/pokemon/pikachu")
	a, _ := fetchJSON[Area](ctx, api.URL+"/location-area/1")
	p2, _ := fetchJSON[Pokemon](ctx, api.URL+"/pokemon/pikachu")

	fmt.Printf("%+v\n%+v\n%+v\n", p, a, p2)
}
```

package main

import (
	"context"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"time"
)

// PokeClient knows the API's address, owns the HTTP client, and keeps a cache.
type PokeClient struct {
	baseURL string
	http    *http.Client
	cache   *Cache
}

func NewPokeClient(baseURL string, ttl time.Duration) *PokeClient {
	return &PokeClient{

// fetchJSON is the one place that talks to the network. T is whatever
// struct the caller wants the JSON decoded into.
func (c *PokeClient) fetchJSON[T any](ctx context.Context, url string) (T, error) {
	var out T
	body, ok := c.cache.Get(url)
	if !ok {
		var err error
		body, err = c.download(ctx, url)
		if err != nil {
			return out, err
		}
		c.cache.Add(url, body)
	}
	if err := json.Unmarshal(body, &out); err != nil {
		return out, fmt.Errorf("decode %s: %w", url, err)
	}
	return out, nil
}

// download GETs url and returns the raw body bytes.
func (c *PokeClient) download(ctx context.Context, url string) ([]byte, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
	if err != nil {
		return nil, err
	}
	resp, err := c.http.Do(req)
	if err != nil {
		return nil, fmt.Errorf("GET %s: %w", url, err)
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("GET %s: status %d", url, resp.StatusCode)
	}
	return io.ReadAll(io.LimitReader(resp.Body, 10<<20)) // 10 MiB cap
}

You'll see that older shape in a lot of existing code; it does the same job.

**Recap.** Structs with tags describe the JSON; pointer fields keep `null` distinct. One generic `fetchJSON[T]` does cache-check, download and decode for every endpoint.

### Step 1: follow the links the server gives you

<Define term="Pagination (next/previous links)">
**Pagination** splits a long list into pages. PokeAPI's pages each carry a `next` and a `previous` URL. You don't compute page URLs yourself; you follow the ones the server hands you, and `null` means there's no page in that direction.
</Define>

PokeAPI's links are **offset** links: `?offset=20&limit=20` means "skip 20, give me the next 20". That's worth knowing, because offset paging has a flaw: if items are inserted or deleted while you're paging, everything shifts and you can see an item twice or miss one. Some APIs instead hand out **cursor** links, an opaque token pointing at the last item you saw, which stays correct under changes. For a mostly static list like PokeAPI's locations, offsets are fine. Either way, the client code is the same: store the links, follow them.

## The Cache

*Stop 4 of 5.*

### Step 1: why cache, and why it must forget

Paging back and forth re-downloads pages you saw seconds ago. That's slow for you and rude to a free API. So keep each response for a while: a map from URL to bytes.

<ELI5
  concept="A cache needs a way to forget"
  analogy="A notebook you never tear pages from eventually fills the room."
  role="reader"
>

A plain map never forgets. Every URL you visit adds an entry that stays until the process exits, and the data inside can go stale. So a cache needs an eviction rule. The common ones:

- **Time-based (TTL, time to live):** an entry expires N minutes after it was stored. Bounds staleness.
- **Size-based (LRU, least recently used):** keep at most N entries; drop the one untouched longest. Bounds memory. (Exercise 5.)
- **Both:** what most production caches do.

We use a TTL of five minutes, with a background goroutine that deletes expired entries.

</ELI5>

### Step 2: two goroutines, one map, one lock

The moment a background goroutine deletes entries while your commands read them, the map is shared between goroutines. Go maps aren't safe for that: a read racing a write is a data race, and the runtime may stop the program with `fatal error: concurrent map read and map write`. So every access goes through a `sync.Mutex`. Only one goroutine holds it at a time; anyone else who calls `Lock` waits.

### Step 3: the code

```go
// cache.go
package main

import (
	"sync"
	"time"
)

type cacheEntry struct {
	createdAt time.Time
	val       []byte
}

// Cache maps a URL to the response bytes, for at most ttl.
// The zero value is not usable: call NewCache.
type Cache struct {
	mu      sync.Mutex
	entries map[string]cacheEntry
	ttl     time.Duration
}

func NewCache(ttl time.Duration) *Cache {
	c := &Cache{entries: make(map[string]cacheEntry), ttl: ttl}
	go c.reapLoop()
	return c
}

func (c *Cache) Add(key string, val []byte) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.entries[key] = cacheEntry{createdAt: time.Now(), val: val}
}

func (c *Cache) Get(key string) ([]byte, bool) {
	c.mu.Lock()
	defer c.mu.Unlock()
	e, ok := c.entries[key]
	if !ok || time.Since(e.createdAt) > c.ttl {
		return nil, false // missing, or expired but not yet reaped
	}
	return e.val, true
}

// reapLoop wakes every ttl and deletes expired entries, so memory
// doesn't grow forever. It runs for the life of the program.
func (c *Cache) reapLoop() {
	ticker := time.NewTicker(c.ttl)
	defer ticker.Stop()
	for range ticker.C {
		c.reap()
	}
}

func (c *Cache) reap() {
	c.mu.Lock()
	defer c.mu.Unlock()
	for key, e := range c.entries {
		if time.Since(e.createdAt) > c.ttl {
			delete(c.entries, key)
		}
	}
}
```

Three idioms to read slowly:

- `c.mu.Lock()` followed by `defer c.mu.Unlock()`: the unlock is scheduled to run when the function returns, whichever `return` it takes. You can't forget it on an early exit.
- `for range ticker.C`: a `time.Ticker` sends the current time on its channel `C` every interval. Ranging over the channel means "do this on every tick, forever".
- Deleting from a map while ranging over it is allowed in Go: entries removed before the loop reaches them are simply not visited.

<Define term="Cache reaper goroutine">
The **reaper** is a background goroutine started by `NewCache`. It wakes on a `time.Ticker` every TTL, takes the mutex, and deletes entries older than the TTL. It keeps memory bounded; `Get`'s own age check keeps answers fresh in between sweeps. Here it runs for the life of the program, which is fine for a CLI. Anything that creates and discards caches needs a way to stop it (Exercise 4).
</Define>

<UnderTheHood title="What Lock actually does (Go 1.27)">

`sync.Mutex` is two small integers: a state word (locked? starving? how many waiters?) and a semaphore. Locking a free mutex is one atomic compare-and-swap, with no system call.

If it's already held, `Lock` spins briefly, betting the holder is about to finish. If not, the goroutine **parks**: the scheduler takes it off its thread and runs other goroutines meanwhile, so a waiting goroutine costs no CPU.

If a waiter has waited more than 1 ms, the mutex switches to **starvation mode**: newly arriving goroutines stop competing and queue at the back, and each unlock hands the mutex straight to the goroutine at the front. That keeps a busy goroutine from winning the lock over and over while an old waiter starves. The 1 ms figure is an implementation detail; don't design around it.

</UnderTheHood>

**Recap.** A cache is a map, a clock and a lock. Lock every access, never hold the lock across I/O, check age on read, and let a reaper free memory in the background.

		t.Errorf("server saw %d requests, want 2 (the third page view should be cached)", got)
	}
}
```

Things worth reading twice:

- `var srv *httptest.Server` is declared *before* it's assigned because the handler needs `srv.URL` to build its links, and the handler is created before the server exists. By the time any request arrives, `srv` has been set.
- `fmt.Sprintf("%q", ...)` wraps the link in double quotes, making it a JSON string; `link` returns the bare word `null` otherwise.
- `hits` is an `atomic.Int32` because the server runs each request on its own goroutine. A plain `int` incremented there and read by the test would be a data race.
- `t.Cleanup(srv.Close)` shuts the server down when the test finishes, however it finishes.

**`TestSecondFetchComesFromCache` is the test that found the bug from Stop 3.** The first version of `ListLocationAreas` fetched page 1 as `/location-area`, the test reported `server saw 3 requests, want 2`, and the fix was to spell page 1 the way the API links to it. That's what tests are for.

<Exercise n={4} title="A reaper you can stop" level="medium">

The reaper runs forever. Add `Stop()` so a cache can be shut down, make calling it twice safe, and prove the goroutine really exits using `testing/synctest` (Go 1.25), which fails a test if any goroutine it started is still blocked when the test function returns.

<Solution>

```go
// cache.go changes
type Cache struct {
	mu      sync.Mutex
	entries map[string]cacheEntry
	ttl     time.Duration
	stop    chan struct{}
	once    sync.Once
}

func NewCache(ttl time.Duration) *Cache {
	c := &Cache{
		entries: make(map[string]cacheEntry),
		ttl:     ttl,
		stop:    make(chan struct{}),
	}
	go c.reapLoop()
	return c
}

func (c *Cache) reapLoop() {
	ticker := time.NewTicker(c.ttl)
	defer ticker.Stop()
	for {
		select {
		case <-ticker.C:
			c.reap()
		case <-c.stop:
			return
		}
	}
}

// Stop ends the reaper goroutine. Calling it twice is safe.
func (c *Cache) Stop() {
	c.once.Do(func() { close(c.stop) })
}
```

```go
// stop_test.go
// synctest.Test fails if any goroutine started inside the bubble is still
// blocked when the function returns. If Stop didn't end the reaper, this
// test would fail with a deadlock report.
func TestStopEndsReaper(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		c := NewCache(time.Minute)
		c.Add("k", []byte("v"))
		c.Stop()
		c.Stop() // safe to call twice
	})
}
```

Closing a channel wakes every receiver, now and later, so `close` is the standard "stop" signal. Closing it twice would panic, which is what `sync.Once` prevents. Remove the `close` and the test fails with `deadlock: main bubble goroutine has exited but blocked goroutines remain`: proof that the test really watches the goroutine.

</Solution>

</Exercise>

<Exercise n={5} title="LRU eviction" level="hard">

Build a size-bounded cache: at most `max` entries, and when it's full, adding a new key evicts the **least recently used** one. Make `Get` and `Add` O(1) using `container/list` (a doubly linked list) alongside a map.

<Solution>

```go
package lru

import (
	"container/list"
	"sync"
)

// LRU keeps at most max entries. When it's full, adding a new key evicts
// the least recently used one.
type LRU struct {
	mu    sync.Mutex
	max   int
	order *list.List               // front = most recently used
	items map[string]*list.Element // key -> its node in order
}

type item struct {
	key string
	val []byte
}

func New(max int) *LRU {
	return &LRU{max: max, order: list.New(), items: make(map[string]*list.Element)}
}

func (c *LRU) Get(key string) ([]byte, bool) {
	c.mu.Lock()
	defer c.mu.Unlock()
	el, ok := c.items[key]
	if !ok {
		return nil, false
	}
	c.order.MoveToFront(el) // touched: now the most recent
	return el.Value.(*item).val, true
}

func (c *LRU) Add(key string, val []byte) {
	c.mu.Lock()
	defer c.mu.Unlock()
	if el, ok := c.items[key]; ok { // already there: update and touch
		el.Value.(*item).val = val
		c.order.MoveToFront(el)
		return
	}
	if c.order.Len() >= c.max { // full: drop the back (least recent)
		oldest := c.order.Back()
		c.order.Remove(oldest)
		delete(c.items, oldest.Value.(*item).key)
	}
	c.items[key] = c.order.PushFront(&item{key, val})
}
```

```go
func TestEvictsLeastRecentlyUsed(t *testing.T) {
	c := New(2)
	c.Add("a", []byte("A"))
	c.Add("b", []byte("B"))
	c.Get("a")              // a is now more recent than b
	c.Add("c", []byte("C")) // full: b must go

	for key, want := range map[string]bool{"a": true, "b": false, "c": true} {
		if _, ok := c.Get(key); ok != want {
			t.Errorf("Get(%q) present = %v, want %v", key, ok, want)
		}
	}
}
```

The list keeps entries in recency order; the map finds any entry's list node in O(1). Touching an entry moves its node to the front; eviction removes the back. `el.Value.(*item)` is a type assertion: `list.Element.Value` is an `any`, and we know we stored `*item` there. Combine this with the TTL cache and you have the "both" policy from Stop 4.

</Solution>

</Exercise>
