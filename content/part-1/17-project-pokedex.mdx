## REPL Scaffold

<Define term="REPL (read-eval-print loop)" since="Concurrency: Goroutines, Channels & Select (Part 1)">
A **REPL** is an interactive shell: it **R**eads a line of user input, **E**valuates it (looks the command up and runs it), **P**rints the result, and **L**oops back. Every interactive CLI — from the Python shell to `psql` to this Pokedex — is a REPL. Without it you'd have to restart the process for every command. The Pokedex REPL is a single `for` loop around a `bufio.Scanner`.
</Define>

Before you touch a network, you need a shell. A REPL — **Read, Eval, Print, Loop** — is the heartbeat of any interactive CLI: read a line of input, figure out which command it maps to, run it, print the result, and loop. The Pokedex CLI lives entirely inside one of these.

Here's the real-world framing: a developer-tools team is building an internal catalog browser. The catalog is a paginated API. The team wants a local CLI so engineers can page through locations, look up entries, and poke around without firing up a browser or crafting `curl` commands. That's your Pokedex. Same shape, different domain skin.

### The command registry

Every command gets an entry in a `map[string]cliCommand`. This is the idiomatic Go approach — no giant `switch` on strings, no reflection magic. A map of function values, keyed by name.

```go
// main.go
package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
)

// cliCommand holds one registered command — its name, a short description,
// and the function to call when the user types it.
type cliCommand struct {
	name        string
	description string
	callback    func(cfg *config, args ...string) error
}

// config is the shared mutable state threaded through every command.
// No globals — we pass this explicitly so every command is testable.
type config struct {
	// pagination cursors (filled in the Pagination section)
	nextURL string
	prevURL string

	// the typed API client (filled in the API Client section)
	client *PokeClient

	// caught Pokemon by name (filled in Exercise 2)
	caught map[string]PokemonResp
}

// getCommands builds the command registry. It's a function, not a package-level
// var, so the registry can reference its own entries (e.g. the help command
// lists all commands) without initialization-order headaches.
func getCommands() map[string]cliCommand {
	return map[string]cliCommand{
		"help": {
			name:        "help",
			description: "Display a help message",
			callback:    commandHelp,
		},
		"exit": {
			name:        "exit",
			description: "Exit the Pokedex",
			callback:    commandExit,
		},
		"map": {
			name:        "map",
			description: "Display next page of locations",
			callback:    commandMap,
		},
		"mapb": {
			name:        "mapb",
			description: "Display previous page of locations",
			callback:    commandMapb,
		},
		"explore": {
			name:        "explore",
			description: "Explore a location area for Pokemon",
			callback:    commandExplore,
		},
		"catch": {
			name:        "catch",
			description: "Attempt to catch a Pokemon",
			callback:    commandCatch,
		},
		"inspect": {
			name:        "inspect",
			description: "Inspect a caught Pokemon",
			callback:    commandInspect,
		},
		"pokedex": {
			name:        "pokedex",
			description: "List all caught Pokemon",
			callback:    commandPokedex,
		},
	}
}

// startREPL is the main loop. It reads a line, splits it into words,
// looks the first word up in the registry, and calls the matching command.
func startREPL(cfg *config) {
	commands := getCommands()
	scanner := bufio.NewScanner(os.Stdin)

	for {
		fmt.Print("Pokedex > ")
		if !scanner.Scan() {
			break // EOF or error — clean exit
		}
		words := cleanInput(scanner.Text())
		if len(words) == 0 {
			continue
		}
		name := words[0]
		args := words[1:]

		cmd, ok := commands[name]
		if !ok {
			fmt.Println("Unknown command. Type 'help' for options.")
			continue
		}
		if err := cmd.callback(cfg, args...); err != nil {
			fmt.Println("Error:", err)
		}
	}
}

// cleanInput trims whitespace and splits on any whitespace run.
// Returns lowercase tokens — this is your command parser.
func cleanInput(text string) []string {
	lowered := strings.ToLower(strings.TrimSpace(text))
	if lowered == "" {
		return nil
	}
	return strings.Fields(lowered)
}
```

## API Client

<Define term="API client (typed JSON decode)" since="HTTP Clients (Part 1)">
An **API client** is a thin wrapper around `http.Client` that knows one server's URL scheme and turns its raw JSON bodies into typed Go structs. "Typed JSON decode" means you define a Go struct whose fields mirror the JSON keys exactly, then call `json.NewDecoder(resp.Body).Decode(&result)` — the decoder fills the struct from the stream. If a field is missing in JSON you get its zero value; if the JSON has an extra field, Go ignores it. The payoff: callers get strongly typed data with compile-time safety instead of `map[string]any` soup.
</Define>

The catalog lives behind a real REST API. We need typed structs to hold the responses, an `http.Client` with a timeout, and a JSON decoder. This is the HTTP-clients chapter made concrete — if any of this feels new, flip back to HTTP Clients.

### The response types

The catalog API returns paginated location pages and location-area details. Define typed structs that match the JSON exactly:

```go
// types.go
package main

// LocationAreaResp is what the /location-area endpoint returns.
// The JSON fields must match exactly — Go's decoder is case-insensitive
// for simple names, but json tags are explicit and safer.
type LocationAreaResp struct {
	Count    int     `json:"count"`
	Next     *string `json:"next"`     // pointer: null in JSON → nil in Go
	Previous *string `json:"previous"` // same
	Results  []struct {
		Name string `json:"name"`
		URL  string `json:"url"`
	} `json:"results"`
}

// ExploreResp is what /location-area/{name} returns.
type ExploreResp struct {
	PokemonEncounters []struct {
		Pokemon struct {
			Name string `json:"name"`
		} `json:"pokemon"`
	} `json:"pokemon_encounters"`
}

// PokemonResp is what /pokemon/{name} returns.
type PokemonResp struct {
	Name           string `json:"name"`
	BaseExperience int    `json:"base_experience"`
	Height         int    `json:"height"`
	Weight         int    `json:"weight"`
	Stats          []struct {
		BaseStat int `json:"base_stat"`
		Stat     struct {
			Name string `json:"name"`
		} `json:"stat"`
	} `json:"stats"`

		Type struct {

		} `json:"type"`
	} `json:"types"`
```

### The API client

A thin wrapper around `http.Client`. It owns the base URL, the HTTP client (with timeout), and the cache. Every method takes a `context.Context` first — the standard rule for anything that does I/O.

```go
// PokeClient wraps http.Client and the response cache.
// No globals: inject the cache so tests can supply a fake.
type PokeClient struct {
	baseURL    string
	httpClient *http.Client
	cache      *Cache
}

// NewPokeClient constructs a client with a sane timeout.
// interval is the cache TTL — passed through to NewCache.
func NewPokeClient(interval time.Duration) PokeClient {
	return PokeClient{
		baseURL: "https://pokeapi.co/api/v2",
		httpClient: &http.Client{
			Timeout: 30 * time.Second,
		},
		cache: NewCache(interval),
	}
}

// GetLocationAreas fetches the paginated /location-area list.
// url is the full URL (including query params); passing "" uses the first page.
func (c *PokeClient) GetLocationAreas(ctx context.Context, url string) (LocationAreaResp, error) {
	if url == "" {
		url = c.baseURL + "/location-area"
	}

	// cache hit — return immediately without a network round-trip
	if data, ok := c.cache.Get(url); ok {
		var result LocationAreaResp
		if err := json.Unmarshal(data, &result); err != nil {
			return LocationAreaResp{}, fmt.Errorf("unmarshal cached: %w", err)
		}
		return result, nil
	}

	resp, err := c.get(ctx, url)
	if err != nil {
		return LocationAreaResp{}, err
	}
	defer resp.Body.Close()

	var result LocationAreaResp
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return LocationAreaResp{}, fmt.Errorf("decode location areas: %w", err)
	}

	// cache the raw bytes so future calls don't hit the network
	raw, _ := json.Marshal(result)
	c.cache.Add(url, raw)
	return result, nil
}

// GetExplore fetches /location-area/{name} and returns Pokemon encounters.
func (c *PokeClient) GetExplore(ctx context.Context, name string) (ExploreResp, error) {
	url := c.baseURL + "/location-area/" + name

	if data, ok := c.cache.Get(url); ok {
		var result ExploreResp
		if err := json.Unmarshal(data, &result); err != nil {
			return ExploreResp{}, fmt.Errorf("unmarshal cached explore: %w", err)
		}
		return result, nil
	}

	resp, err := c.get(ctx, url)
	if err != nil {
		return ExploreResp{}, err
	}
	defer resp.Body.Close()

	var result ExploreResp
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return ExploreResp{}, fmt.Errorf("decode explore: %w", err)
	}

	raw, _ := json.Marshal(result)
	c.cache.Add(url, raw)
	return result, nil
}

// GetPokemon fetches /pokemon/{name}.
func (c *PokeClient) GetPokemon(ctx context.Context, name string) (PokemonResp, error) {
	url := c.baseURL + "/pokemon/" + name

	if data, ok := c.cache.Get(url); ok {
		var result PokemonResp
		if err := json.Unmarshal(data, &result); err != nil {
			return PokemonResp{}, fmt.Errorf("unmarshal cached pokemon: %w", err)
		}
		return result, nil
	}

	resp, err := c.get(ctx, url)
	if err != nil {
		return PokemonResp{}, err
	}
	defer resp.Body.Close()

	var result PokemonResp
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return PokemonResp{}, fmt.Errorf("decode pokemon: %w", err)
	}

	raw, _ := json.Marshal(result)
	c.cache.Add(url, raw)
	return result, nil
}

// get is a shared helper that builds and fires the HTTP request.
func (c *PokeClient) get(ctx context.Context, url string) (*http.Response, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
	if err != nil {
		return nil, fmt.Errorf("build request: %w", err)
	}
	req.Header.Set("Accept", "application/json")

	resp, err := c.httpClient.Do(req)
	if err != nil {
		return nil, fmt.Errorf("http get %s: %w", url, err)
	}
	if resp.StatusCode < 200 || resp.StatusCode >= 300 {
		resp.Body.Close()
		return nil, fmt.Errorf("unexpected status %d for %s", resp.StatusCode, url)
	}
	return resp, nil
}
```

<UnderTheHood title="Why *string for nullable JSON fields">

When you decode JSON `null` into a `*string`, Go sets the pointer to `nil`. When you decode a real string, Go allocates a new string and points to it. A plain `string` field has no way to distinguish `null` from `""` — they both become the empty string. The pointer carries the distinction. This has worked this way since Go 1.0; it is not version-specific behaviour.

You can also use `any` or a custom type implementing `json.Unmarshaler`, but `*string` is the zero-ceremony idiom the standard library itself uses. The cost is one heap allocation per non-null field, which for rare pagination cursors is completely inconsequential.

`json.NewDecoder(resp.Body).Decode(&result)` streams the HTTP response body through the decoder without buffering the whole body into a `[]byte` first. For large responses this means lower peak memory. `json.Unmarshal` requires the full bytes in memory — fine for cached data, but prefer the streaming decoder for live network responses. (As of Go 1.26, `io.ReadAll` is faster than earlier releases when you do need to materialise a body into `[]byte`, but for JSON decoding the streaming path is still preferable.)

</UnderTheHood>

## Pagination

<Define term="Pagination (cursor / next-URL)" since="Auth & API Design (Part 1)">
**Pagination** is how an API returns a large dataset in small, sequential pages instead of one huge response. **Cursor-style pagination** gives you an opaque `next` URL in each response — you follow that URL to get the next page, instead of computing `?offset=40` yourself. The server controls what "next" means: it can encode a database cursor, a timestamp, or a sort key inside the URL. You can't skip to page 10; you can only walk forward. The trade-off is predictable latency and stability under concurrent writes (no row-skip/duplicate problem that offset pagination has). If `next` is `null`, you're on the last page.
</Define>

The catalog API is cursor-style: every page tells you the next page's URL. Your `config` tracks two cursors — `nextURL` and `prevURL` — updated every time you call `map` or `mapb`. By this section `config` also holds `client *PokeClient`; make sure it's wired up in `main`.

### Cursor-style pagination vs. offset pagination

Offset pagination (`?offset=20&limit=20`) is simple but breaks under concurrent writes: if a row is inserted before your next fetch, you get a duplicate or skip an entry. Cursor-based pagination follows opaque URLs the server mints — you can't compute them yourself, which means you can't skip pages, but every page is stable.

```go
// commands.go (updated map / mapb)
// Add "context" and "fmt" to your import block if not already present.

func commandMap(cfg *config, args ...string) error {
	ctx := context.Background()
	// nextURL starts empty → first page; subsequent calls use the cursor
	resp, err := cfg.client.GetLocationAreas(ctx, cfg.nextURL)
	if err != nil {
		return fmt.Errorf("map: %w", err)
	}

	// advance the cursors — next call to map uses resp.Next,
	// and mapb can now go back via resp.Previous
	if resp.Next != nil {
		cfg.nextURL = *resp.Next
	} else {
		cfg.nextURL = "" // last page — map will start over
	}
	if resp.Previous != nil {
		cfg.prevURL = *resp.Previous
	} else {
		cfg.prevURL = ""
	}

	for _, loc := range resp.Results {
		fmt.Println(loc.Name)
	}
	return nil
}

func commandMapb(cfg *config, args ...string) error {

		fmt.Println("You're on the first page.")
		return nil

		return fmt.Errorf("mapb: %w", err)
	}

		cfg.nextURL = *resp.Next
	}
	if resp.Previous != nil {
		cfg.prevURL = *resp.Previous
	} else {
		cfg.prevURL = ""
```

## The Cache

<Define term="In-memory cache + TTL" since="Caching & Redis (Part 1)">
An **in-memory cache** stores the results of expensive operations (here: HTTP round-trips) in a `map` inside the process, so the same request can be answered from RAM in microseconds instead of going to the network. A **TTL (time-to-live)** is a maximum age for each entry — after `interval` has passed the entry is stale and must be re-fetched. Without a TTL the cache grows unbounded and serves forever-old data; without the cache every `explore` hammers the same API endpoint, burning your rate-limit budget and adding hundreds of milliseconds of latency per REPL command. The combination — fast reads, bounded staleness — is why caches exist at all.
</Define>

Here's where this project earns its concurrency stripes. You don't want to hammer the catalog API for the same location every time the user types `explore`. You want a cache: fast, in-memory, with a TTL so entries don't live forever.

This is a preview of the Caching & Redis chapter (coming later in Part 1), but we're building a real one right now because the Pokedex needs it today, not in five chapters.

### The Cache struct

```go
// cache.go
package main

import (
	"sync"
	"time"
)

// cacheEntry holds one cached value and the wall time it was added.
type cacheEntry struct {
	createdAt time.Time
	val       []byte
}

// Cache is a TTL cache backed by a map, protected by a mutex.
// The reap goroutine runs in the background and evicts stale entries.
// Zero value is NOT usable — call NewCache.
type Cache struct {
	mu       sync.Mutex
	entries  map[string]cacheEntry
	interval time.Duration
}

// NewCache creates a cache with the given TTL interval and starts
// the background reaping goroutine. The goroutine runs for the
// lifetime of the process (no stop channel here — see the exercise
// for the lifecycle version with a stop channel).
func NewCache(interval time.Duration) *Cache {
	c := &Cache{
		entries:  make(map[string]cacheEntry),
		interval: interval,
	}
	go c.reapLoop()
	return c
}

// Add stores val under key. If key already exists, it is overwritten.
// Safe for concurrent use.
func (c *Cache) Add(key string, val []byte) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.entries[key] = cacheEntry{
		createdAt: time.Now(),
		val:       val,
	}
}

// Get retrieves val for key. Returns (val, true) on hit, (nil, false) on miss.
// Safe for concurrent use.
func (c *Cache) Get(key string) ([]byte, bool) {
	c.mu.Lock()
	defer c.mu.Unlock()
	e, ok := c.entries[key]
	if !ok {
		return nil, false
	}
	return e.val, true
}

// reapLoop runs forever, waking up every interval to delete entries
// older than interval. It holds the mutex only long enough to scan
// and delete — it does not block Add/Get for the full sleep.
func (c *Cache) reapLoop() {
	ticker := time.NewTicker(c.interval)
	defer ticker.Stop()
	for range ticker.C {
		c.reap()
	}
}

func (c *Cache) reap() {
	c.mu.Lock()
	defer c.mu.Unlock()
	deadline := time.Now().Add(-c.interval)
	for k, e := range c.entries {
		if e.createdAt.Before(deadline) {
			delete(c.entries, k)
		}
	}
}
```

<Define term="Cache reaper goroutine">
The **reaper** is a background goroutine started once by `NewCache`. It sleeps on a `time.Ticker`, wakes up every `interval`, acquires the mutex, scans every entry, and deletes those whose `createdAt` timestamp is older than `interval`. Without it, a TTL is just a policy on paper — entries never actually leave. The reaper is the enforcement mechanism. It runs for the process lifetime in this CLI; in a server that creates and destroys caches you'd add a stop channel so the goroutine can exit cleanly and not leak (see Exercise 4).
</Define>

<UnderTheHood title="sync.Mutex internals and the reap goroutine lifecycle (Go 1.26 baseline)">

`sync.Mutex` is a two-word struct: a `state` int32 and a `sema` uint32. The `state` word packs several bit fields: whether the mutex is locked, whether it's in starvation mode, and the count of goroutines waiting. When `Lock()` is called on an unlocked mutex, it's a single atomic CAS on `state` — no syscall, no kernel involvement. Fast.

When a goroutine calls `Lock()` on an *already-locked* mutex, it first spins briefly (calling `runtime_doSpin`) hoping the holder releases before the spin budget runs out. If it doesn't, the goroutine is parked on a semaphore (`runtime_SemacquireMutex`) — it goes to sleep and its M (OS thread) is freed to run other goroutines. No thread is wasted waiting.

**Starvation mode** (added in Go 1.9, still present in Go 1.26): if a goroutine has been waiting for more than 1 ms, the mutex enters starvation mode, where incoming `Lock()` callers are placed at the back of the wait queue rather than the front. This prevents convoy formation where a hot goroutine perpetually wins the lock over older waiters. The 1 ms threshold is an implementation detail — do not rely on it in application logic.

The **reap goroutine** runs for the process lifetime in this implementation. That's fine for a CLI. A server would want a stop channel or a `context.Context` so the goroutine can be torn down cleanly during graceful shutdown — see Exercise 4.

`time.Ticker` allocates a channel and an internal runtime timer. Ticks are delivered on the channel by the runtime. `defer ticker.Stop()` is mandatory for a live `Cache`: without it, a reachable ticker keeps scheduling ticks after the cache should be stopped. Since Go 1.23, unreachable tickers can be garbage-collected, but long-lived services should still stop tickers when their owner shuts down.

</UnderTheHood>

<UnderTheHood title="Why httptest.Server beats testing against the live API">

Testing against the live PokeAPI fails in a dozen ways that have nothing to do with your code: the API is rate-limited, it changes its schema, CI has no outbound internet, the response takes 2 seconds and flakes the test run. These failures break your build in ways you can't control, can't reproduce locally, and can't fix.

`httptest.NewServer(handler)` spins up a real TCP server on `127.0.0.1` with a random port, right in your process. Your HTTP client dials it over a real socket — no mocking at the transport layer, no monkey-patching, no fake `http.RoundTripper`. The full `net/http` stack runs. What changes is *only* the server being dialed. When you override `baseURL = srv.URL`, every request goes to your handler instead of the internet.

This means you test exactly what ships — the real `http.Client`, the real `json.NewDecoder`, the real error paths — while keeping tests hermetic, deterministic, and fast. This is idiomatic Go testing, not a shortcut.

The `atomic.Int64` request counter is deliberate: the test server handler runs on its own goroutine (the `httptest` server has its own goroutine pool), so a plain `int` would be a data race under `-race`. `sync/atomic` gives you lock-free, race-safe increments.

</UnderTheHood>

<Exercise n={2} title="Add a 'caught' store to config" level="easy">

<Exercise n={4} title="Add a stop channel to NewCache" level="medium">

The current `reapLoop` goroutine runs for the process lifetime. In a server that creates and discards caches (e.g. per-tenant caches that are torn down when a tenant is removed), this leaks goroutines and the underlying `time.Ticker`. Add a `Stop()` method to `Cache` that signals the reap goroutine to exit cleanly. Use a `chan struct{}` for the signal. The goroutine must exit within one ticker interval of `Stop()` being called. Write a test that verifies the goroutine exits.

<Solution>

```go
type Cache struct {
	mu       sync.Mutex
	entries  map[string]cacheEntry
	interval time.Duration
	stopCh   chan struct{}
}

func NewCache(interval time.Duration) *Cache {
	c := &Cache{
		entries:  make(map[string]cacheEntry),
		interval: interval,
		stopCh:   make(chan struct{}),
	}
	go c.reapLoop()
	return c
}

func (c *Cache) Stop() {
	close(c.stopCh) // closing a channel signals all receivers simultaneously
}

func (c *Cache) reapLoop() {
	ticker := time.NewTicker(c.interval)
	defer ticker.Stop()
	for {
		select {
		case <-ticker.C:
			c.reap()
		case <-c.stopCh:
			return // exit the goroutine — no more work to do
		}
	}
}

// Test:
func TestCacheStopExitsGoroutine(t *testing.T) {
	// Use a very short interval so the test is fast
	c := NewCache(10 * time.Millisecond)
	c.Add("k", []byte("v"))

	c.Stop()

	// After Stop, the reap goroutine should exit. Wait longer than two intervals
	// and verify that a new Add/Get still works (the lock shouldn't be held forever).
	time.Sleep(50 * time.Millisecond)

	c.Add("k2", []byte("v2"))
	if _, ok := c.Get("k2"); !ok {
		t.Error("cache should still work after Stop")
	}
}
```

`close(c.stopCh)` is the idiomatic Go broadcast signal: closing a channel unblocks *all* goroutines receiving on it simultaneously. Sending on the channel would only unblock one goroutine. For a single reap goroutine either works, but `close` is the canonical idiom for "everybody stop."

</Solution>

</Exercise>

<Exercise n={5} title="Add LRU eviction to the cache" level="hard">

The current cache grows unbounded until the TTL fires. In production, a cache serving many unique Pokemon entries could grow very large. Add a `maxEntries int` field to `Cache`. When `Add` is called and the cache is already at capacity, evict the **least-recently-used** entry before inserting the new one. Track recency by updating a `lastUsed time.Time` on every `Get` and `Add`. Write table-driven tests for eviction order.

<Solution>

```go
// Add to cacheEntry:
// lastUsed time.Time

func (c *Cache) Add(key string, val []byte) {
	c.mu.Lock()
	defer c.mu.Unlock()
	now := time.Now()
	if c.maxEntries > 0 && len(c.entries) >= c.maxEntries {
		// evict the entry with the oldest lastUsed timestamp
		var oldest string
		var oldestTime time.Time
		for k, e := range c.entries {
			if oldest == "" || e.lastUsed.Before(oldestTime) {
				oldest = k
				oldestTime = e.lastUsed
			}
		}
		delete(c.entries, oldest)
	}
	c.entries[key] = cacheEntry{
		createdAt: now,
		lastUsed:  now,
		val:       val,
	}
}

func (c *Cache) Get(key string) ([]byte, bool) {
	c.mu.Lock()
	defer c.mu.Unlock()
	e, ok := c.entries[key]
	if !ok {
		return nil, false
	}
	// update lastUsed — this is what makes it LRU
	e.lastUsed = time.Now()
	c.entries[key] = e
	return e.val, true
}

// Test (abbreviated):
func TestCacheLRUEviction(t *testing.T) {
	c := &Cache{
		entries:    make(map[string]cacheEntry),
		interval:   5 * time.Minute,
		maxEntries: 2,
		stopCh:     make(chan struct{}),
	}

	c.Add("a", []byte("A"))
	time.Sleep(time.Millisecond) // ensure distinct timestamps
	c.Add("b", []byte("B"))
	c.Get("a") // touch 'a' — now 'b' is the LRU

	// Adding 'c' should evict 'b' (LRU)
	c.Add("c", []byte("C"))

	if _, ok := c.Get("b"); ok {
		t.Error("'b' should have been evicted as LRU")
	}
	if _, ok := c.Get("a"); !ok {
		t.Error("'a' should still be present — it was accessed recently")
	}
	if _, ok := c.Get("c"); !ok {
		t.Error("'c' should be present — it was just added")
	}
}
```

This is O(n) eviction — fine for small caches. A production LRU uses a doubly-linked list (`container/list`) and a map so eviction is O(1). The standard library's `container/list` docs are your next stop.

</Solution>
