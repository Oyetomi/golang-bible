# Accuracy audit — context-package

Chapter: `content/part-1/07-context-package.mdx`
Mode: REPORT ONLY (no edits applied). Audited every falsifiable claim: the Context interface + semantics, Done()-is-closed-not-sent, the four constructors, ctx.Err() values, WithCancelCause/Cause (1.20), WithoutCancel/AfterFunc (1.21), the NotifyContext-cause change (1.26), and the package-internals claims in the UnderTheHood blocks.

The context *mechanics* are excellent and almost entirely correct — Done() broadcast-via-close, the first-arg convention, the two classic leaks, the typed-key pattern, and the value-chain walk are all right. The version attributions for WithCancelCause (1.20), WithoutCancel/AfterFunc (1.21), and the NotifyContext cause (1.26) all check out. **Two internals claims are not supported by primary sources and should be flagged:** (a) a fabricated "Go 1.22 overhauled context propagation from a global mutex to per-cancelCtx fine-grained locks" (no such change exists in the 1.22 notes; `cancelCtx` always had its own per-context mutex — there was never a global tree mutex), repeated twice; and (b) "Since Go 1.21, `context.WithValue` panics if key is nil or not comparable" — the panic behavior is original (since Go 1.7), not new in 1.21.

## Tally
- Claims logged: 31
- CORRECT: 28 (the entire mechanism — Done() close-broadcast, four constructors, ctx.Err values, value-chain walk, first-arg convention, leaks, and the 1.20/1.21/1.26/1.7 version pins)
- Flagged rows: 2 WRONG-version internals claims (#18 and its restatement #29 — the fabricated "Go 1.22 context locking overhaul") + 1 WRONG-version claim (#27 — WithValue panic "since 1.21"); plus pedantic notes on #21 and #22 (not defects).
- WRONG: effectively 2 distinct errors (the 1.22-locking fabrication, appearing 3×; and the WithValue-panic-since-1.21 misattribution).
- Worst finding: **#18/#29** — the chapter twice asserts that "Go 1.22 overhauled context propagation, replacing a **global `sync.Mutex` over the tree** with per-`cancelCtx` fine-grained locks." This change does not appear in the Go 1.22 release notes, and it misdescribes the implementation: `cancelCtx` has carried its own per-context mutex since the package's introduction (Go 1.7) — there was never a single global tree mutex to remove. This is exactly the failure mode the audit targets: a confident, specific, version-pinned internals claim that is fabricated, handing the reader a clean but false mental model of how context locking evolved. Recommend deleting the version-pinned locking sentences (UnderTheHood + Recap) or replacing with an accurately-cited refactor if one is intended.
