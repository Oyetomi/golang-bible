# Accuracy audit — dsa-arrays-strings

Chapter: `content/appendix/02-dsa-arrays-strings.mdx`
Mode: REPORT ONLY (no edits applied). Tier-3 (appendix/DSA); complexity, in-place-ness, and Go string/byte/rune internals audited rigorously.

Summary: Two-pointer / sliding-window / prefix-sum complexities are all derivable-correct. The `string`/`[]byte`/`[]rune` semantics are stated carefully and correctly — crucially the chapter says a Go string is "commonly UTF-8 but **not required to be valid UTF-8**", dodging the UTF-8-guarantee landmine, and `len` counts bytes. The one genuinely WRONG claim is the pdqsort version-pin ("As of Go 1.24, `slices.Sort` uses pdqsort") — the algorithm is right but the version attribution is wrong (pdqsort predates 1.24). A second item (LongestUniqueSubstring space "O(1)" vs "O(k)") is internally inconsistent. **1 WRONG (version pin), 1 IMPRECISE/inconsistent, ~25 CORRECT.**
