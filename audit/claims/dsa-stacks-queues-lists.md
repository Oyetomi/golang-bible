# Accuracy audit — dsa-stacks-queues-lists

Chapter: `content/appendix/04-dsa-stacks-queues-lists.mdx`
Mode: REPORT ONLY (no edits applied). Tier-3 (appendix/DSA); structure complexities, the slice-queue memory-leak claim, container/list, and monotonic-stack amortization audited rigorously.

Summary: Stack/queue/linked-list/monotonic-stack complexities are all correct, including the subtle ones (slice pop O(1) exact, two-stack queue amortized O(1), Floyd's O(1) space, monotonic stack O(n) by push-once/pop-once accounting). The "naive `q = q[1:]` leaks the backing array" claim is correct and well explained. `container/list` is correctly described as a doubly linked list with O(1) ends. The one real defect is a code↔prose mismatch: the two-stack-queue UnderTheHood says the inbox is "reset to `inbox[:0]`," but the actual code drains it element-by-element to `inbox[:n-1]` and never resets to `[:0]`. A few slice-growth phrasings repeat the "double" framing (correct for the small examples shown). **0 WRONG (mechanism), 1 WRONG-detail (prose/code mismatch), 2 IMPRECISE, ~22 CORRECT.**
